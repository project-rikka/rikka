- Root: `MODULE.bazel` (rules_rust, rules_cc, rules_shell, skylib; `include`s `third_party/rust/crates.MODULE.bazel`, `third_party/comparators/comparators.MODULE.bazel` and `third_party/comparators/crates.MODULE.bazel`), `.bazelrc` (configs `remote`, `cache`, `local`, `release`, `installer`, `bench`, `clippy`, `rustfmt`, `check` = both, `gpu`, `machine`; `--symlink_prefix=.bazel/`; `--experimental_isolated_extension_usages` for the benchmark crate universe), `.bazelversion` = nixpkgs' `bazel_9`. `MODULE.bazel.lock` is committed. No Cargo manifests exist.
- `clippy`, `rustfmt` and `check` only add aspects and output groups (`clippy_flag` sits in `common`), and `.bazelrc` sets no `--run_under`, so toggling configs or switching between `build` and `test` keeps the analysis cache; a label `--run_under` would discard it.
- `nix/bazel.nix`: `toolchain` is a JSON written inside a derivation with the shell's build inputs, so it captures the setup hooks' `PKG_CONFIG_PATH`, `NIX_CFLAGS_COMPILE` (minus its self-referential `-frandom-seed`), `LIBCLANG_PATH`, `BINDGEN_EXTRA_CLANG_ARGS` beside every core tool and asset path; `languages` (`RIKKA_BAZEL_LANGUAGES`) holds `language_path` (core tools plus Go, JDK, Python, .NET, Node on `/bin`), `go`, `java_home`, `python`, `dotnet`, `node`, `website_modules`. Two `streamLayeredImage`s share the repository `ghcr.io/project-rikka/rikka-rbe` with conf-hash tags: `image` (core `tools` env + `toolchain`, `RIKKA_RBE_IMAGE`) and `languagesImage` (`languageTools` + both JSONs, `RIKKA_RBE_LANGUAGES_IMAGE`). `env.toolchain` has no rust-analyzer/rust-src; `env.analyzerToolchain` (with them) is the shell's.
- The core image tag sits in every action key and `NIX_CFLAGS_COMPILE`/`PATH` sit in every rustc env, so anything added to `toolchain` or core `tools` rebuilds everything: paths an image does not carry (Gecko) belong in `local`, language-only paths in `languages`.
- `local` in `nix/bazel.nix` is a third JSON (`RIKKA_BAZEL_LOCAL`) of store paths only programs run on this machine need (`minecraft_library_path`, `gecko`, `rust_analyzer`); `@nix` merges all three into `NIX`, and `local` never changes an image.
- `bazel/nix/extension.bzl` makes `@nix` from those variables: bash wrappers for rustc/rustdoc/clippy/cargo/rustfmt over `NIX["rust"]` and rust-analyzer/proc-macro-srv/`rust/src` over `NIX["rust_analyzer"]`, `paths.bzl` (`NIX` dict, also `image` and `languages_image`), and `BUILD.nix.bazel` calling `bazel/nix/toolchains.bzl` (rust gnu+musl, cargo, rustfmt, rust-analyzer, cc gnu+musl through rules_cc's unix config with absolute tool paths, sh). No toolchain file is an action input: executors carry the same `/nix/store` paths, and the paths in command lines key the cache. `toolchain_generated_sysroot=false` lets rustc use its own Nix sysroot (Cranelift backend included).
- `//bazel/platforms`: `linux` (host/target), `linux_musl`, `linux_portable`, `windows` (`--config=windows`), `rbe` and `rbe_languages` (exec platforms with their image as `container-image` and `recycle-runner`), `libc` constraint defaulting to gnu, `languages` constraint defaulting to `with_languages` (only `rbe` is `without_languages`). Language rules (go, csharp, java, python, astro, minecraft) set `exec_compatible_with = LANGUAGES` (`//bazel/platforms:defs.bzl`); `hermetic_test(languages = True)` also sets `exec_group_compatible_with = {"test": …}` because the test action resolves its own exec group, and puts `language_path` on the launcher's `PATH`.
- Windows: `x86_64-pc-windows-gnullvm` through the pinned llvm-mingw release (`nix/packages/llvm-mingw.nix`, nixpkgs' own llvm-mingw cross is broken), described as `NIX["windows"]` (clang, ar, windres, dlltool, sysroot, target); `toolchains.bzl` declares `rust_windows` (`-Ctarget-feature=+crt-static`, `.exe`/`.dll`, gnullvm stdlib link flags, no Linux env) and `cc_windows` (clang, `-static`, so executables import only system DLLs). `nix/dist/windows-runtime.nix` (`NIX["windows_runtime"]`) pins the Gyan FFmpeg 9 shared DLLs, the Slang Windows DLLs and the bundled Inter/JetBrains Mono fonts with their licences. `rikka_test` targets carry `target_compatible_with` Linux; `linkage()` adds nothing on Windows.
- Execution is chosen per command: `.bazelrc` sets no execution config itself and `try-import`s `.bazel/execution.bazelrc`, which `bazel/buildbuddy/wrapper` (the launcher's `BAZEL_WRAPPER`, set by `nix/shell.nix`) rewrites to `--config=remote` or `--config=local` depending on whether `bazel/buildbuddy/api-key` finds a non-empty `BUILDBUDDY_API_KEY`; `cache` includes `remote`. `api-key` reads the main checkout's `.env`, located through `git rev-parse --git-common-dir` so worktrees need no copy; `credential-helper` sends its value as `x-buildbuddy-api-key`. `.github/workflows/rbe-image.yml` pushes the image when nix inputs change; the GHCR package `project-rikka/rikka-rbe` is public, so executors pull it without registry credentials.
- `.github/workflows/rbe-image.yml` starts from path filters, and GitHub evaluates them over the first 300 changed files only. After a larger push that changes the image, start it by hand: `gh workflow run rbe-image.yml --ref main`.
- `//bazel/rust:defs.bzl` macros default the crate layout: libraries, proc macros and shared libraries take `src/**/*.rs` with root `src/lib.rs`, binaries root `src/main.rs`, and `rikka_test(name)` takes `tests/**/*.rs` with root `tests/<name>.rs` and every other file under `tests/` as `data`; `srcs`, `crate_root` or `data` override. They add edition, `//bazel/rust:lints`, version 0.1.0, RIKKA_LOCALES for `locales/`, and in fastbuild `-Copt-level=1`, line tables, debug assertions, overflow checks, share-generics and Cranelift (`cranelift = False` for crates Cranelift cannot compile and for compute-heavy crates, e.g. all of `crates/text`; tests always compile with LLVM); binaries, shared libraries and tests get `-Wl,-rpath,<NIX runpath>` except on musl. Third-party crates use the toolchain's opt-level 2 without debug info; exec-config crates `-Copt-level=2`. The cc toolchain links with mold (`-fuse-ld=mold -B<mold>`) and `-z pack-relative-relocs`; rustc gets `-Clinker-features=-lld -Clink-self-contained=-linker`.
- `//bazel/rust:lints` warns on `unused_crate_dependencies`, `unreachable_pub`, `missing_debug_implementations` and all of clippy; clippy runs with `-Dwarnings`, so `--config=check` rejects any dependency a target lists but does not use.
- Public libraries (`//visibility:public`) get a manual `<name>_doc` rustdoc target with `-Dwarnings`. `rikka-test-*` targets are `testonly`; benchmark targets are `testonly` and `manual` (see the benchmarks note). Visibility encodes the layers; compositor crates also admit `//system/rikka-compositor`, nix crates `//installer`.
- Third-party crates: `third_party/rust/crates.MODULE.bazel` holds the product `crate.spec`s and their annotations, `third_party/rust/Cargo.lock` and `cargo-bazel-lock.json` the lock; specs no target names, kept only to hold a dependency's resolution (`cc` with `parallel`), are the `_RESOLUTION_PINS` list expanded by a comprehension at the end. crate_universe uses `crate.from_specs` with `host_tools = @nix//:rust/host_tools` and the triples `x86_64-unknown-linux-gnu` and `x86_64-pc-windows-gnullvm`; `windows` (windows-rs 0.62) carries every Win32/WinRT feature the Windows backends use in one feature list. A narrow `CARGO_BAZEL_REPIN=1 bazel build --nobuild <target>` may not re-render the lock; repin over `//...`. Aliases replace `-` with `_` where the lib name differs (`md_5`, `rustls_webpki`). Annotations: aws-lc-sys's build script gets `NUM_JOBS`/`EstimatedCPU` 16; libspa-sys's gets `CARGO_MANIFEST_DIR=.` because it bakes it with `env!`; each tree-sitter grammar adds a `queries` filegroup. `nix/packages/grammars.nix` reads tree-sitter versions from that Cargo.lock, so the RBE image tag depends on it.
- Benchmark comparators are a second universe, `@bench_crates`: `third_party/comparators/crates.MODULE.bazel` uses the crate extension with `isolate = True` (its specs never mix with the product's, and a stale bench lock cannot break `@crates`), with `Cargo.lock` and `cargo-bazel-lock.json` beside it; the reference UI sys crate's build script is off there, and its own `zbus` spec adds `p2p`. `CARGO_BAZEL_REPIN=1` keeps locked versions and only adds or prunes, so seed a fresh lock from an existing one rather than an empty file.
- Generated code: `rikka_shaders` (`//bazel/slang:defs.bzl`) runs `//crates/graphics/rikka-shader-build:compile` once per `.slang` (tree artifact `src/spv/<stem>/`; entries compile concurrently with slangc's SPIR-V validation on; slangc's depfile becomes the action's `unused_inputs_list`, so a module edit reruns only the shaders importing it), and writes `src/shaders.rs` with relative `include_bytes!`/`include_str!` (rules_rust symlinks sources next to generated files); each entry is a `pub static <STEM>_<STAGE>: rikka_spirv::Shader { spirv, hash, uses_storage_images, push_bytes }` reflected at build time (the rule adds the `rikka-spirv` dep); `exclude` names `.slang` files other rules compile. `rikka-renderer-3d/shaders/programs.bzl` runs `programs-tool` once per built-in material template and effect program into `src/programs/` and lists them in `src/programs.rs`. Wayland protocols come from the `rikka_wayland_protocols(side = shared|server|client)` rule of `//crates/foundation/rikka-wayland-protocols:defs.bzl`; symbol tables (`rikka-symbols-scanner`) and syntax queries use `run_binary`; rikka-theme's list is a `write_file`. Store paths reach Rust through `rustc_env` from `NIX` (grammars, icon fonts, Gecko, Krisp, slangc).
- Test launcher: `hermetic_test` (`//bazel/test:defs.bzl`, script `hermetic.sh.tpl` expanded with `NIX` paths) is the test target `<name>` of every test macro (Rust, C/C++, Go, C#, Java, Python) around the program `<name>_bin`; it forwards the program's runfiles and `RunEnvironmentInfo`, passes test arguments through, and its `binary` attribute applies the clippy and rustfmt aspects and re-exports their output groups, so `--config=check //x:main` lints the test crate. Fixed PATH/fonts/XDG_DATA_DIRS/SSL_CERT_FILE, session variables unset unless `--config=machine` passes `XDG_RUNTIME_DIR`. Runner `libtest` (Rust) lists the tests and starts each as its own process with a fresh scratch home/XDG/runtime/tmp tree under `/tmp` and `limit` seconds, `jobs` at once (4, with `cpu:4` and `EstimatedCPU` 4; 1 for `gpu`, `machine` and `shared`), output printed per test, over `shard_count` (topic files / 3, at most 8); only the driver shader caches (`MESA_SHADER_CACHE_DIR`, `__GL_SHADER_DISK_CACHE_PATH`) are shared by a shard's tests, which keeps GPU suites from recompiling every pipeline cold. Runner `program` runs the binary once (other languages, `shared = True`). The Rust `<name>_bin` is a `rust_test` tagged `wrapped`, which `.bazelrc`'s default `--test_tag_filters` drops so only the launcher runs. Tags `gpu` (`resources:gpu:1`, 4 at once) and `machine` (`exclusive`) sit on the launcher only and are filtered out by default; `--config=gpu` runs `TestRunner` sandboxed here and `--config=machine` unsandboxed here, while their binaries still compile remotely. Never tag a test `local`/`no-remote-exec`: Bazel copies tags onto the compile actions too.
