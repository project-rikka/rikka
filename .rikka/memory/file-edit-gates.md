---
title: Anchored line edits and their refusals (rikka-file-edit)
description: Files::edit over hash-anchored line Edits, Files::anchor for listings, stale/overlap/echo/syntax refusals.
about: crates/foundation/rikka-file-edit
tags: [ai, editing]
---

- An `Anchor` is `N#tt`: line number plus a two-letter tag, FNV-1a of the line number and the line's content without its `\r` (`anchor.rs`). It certifies "line N read like this"; edits verify it, there is no relocation. `Anchor::from_str` also accepts a bare `N`, which is always refused as untagged.
- `Files::anchor(&Listing, output)` (`listing.rs`) tags numbered rows of command output: `cat -n`/`nl` (`  N\t`), `path:N:` / `path-N-`, bare `N:`/`N-` for named files. Paths resolve against the listing's folders (root first) and must stay inside the root, outside `except` folders, regular and under 8 MiB; the tag is added only when the printed text equals line N (BOM ignored on line 1), so a tag is never wrong.
- `Files::edit(&EditRequest { path, edits })` → `EditOutcome { path, summary, excerpt, change }`. `Edit::{Replace { first, last }, InsertAfter, InsertBefore}` all anchor in the file before the call (`placement.rs`), so edits never shift each other; they are sorted and refused when they overlap (an insertion strictly inside a range overlaps, one at either end does not). `text` is split by `lines_of`: one final newline ignored, empty deletes, `\r\n` accepted.
- Mixed-ending files keep each line's `\r` through `eol.rs` `Returns`: replaced lines inherit the ending of the same-numbered old line (else its last), insertions their anchor line's; uniform CRLF files are handled by `Text`'s `Eol`.
- Every refusal writes nothing and is an `Error` whose text starts `error: <kind> <path>: nothing was written.` followed by the lines involved with current anchors: `stale_anchor` (untagged, past the end or not matching, showing four lines either side; the span must stay within `Excerpt`'s `MAX_FULL_SPAN` or its middle is elided), `reversed_range`, `overlap`, `listing_prefix` (a text line starting with a copied `N#tt` prefix), `unchanged`, `echoed_line`, `broken_syntax`. Several edits are named `Edit N's`.
- `Edited` (`edited.rs`) keeps the splices for the echo gate and a line diff for the excerpt, `Change` and fault shifting. `Excerpt::current` tags rows (file as it is), `Excerpt::proposed` does not (unwritten text in syntax refusals).
- `seam.rs` (`echoed_line`): a text whose first line repeats the kept line above, or whose last line repeats the kept line below, is refused unless a neighbouring edit touches that line or the range's own first/last line already equals it; lines without letters or digits are exempt. Insertions repeating their anchor line are refused the same way.
- `structure.rs` (`broken_syntax`): files with a loadable `rikka_grammars::Grammar` are parsed after the edit, and before it only when the result has faults. Old faults are carried through `Edited::shifted_line`. A clean file refuses any new fault; a file that was already broken refuses only when its fault count grows. A parse refusal starts with the bracket imbalance `Grammar::depths` counts.
- Shader-like files without a grammar (`brackets.rs` `BRACKET_CHECKED`) only have `{}`, `()` and `[]` lexed into `rikka_grammars::Depths`; a balanced file may not become unbalanced. Other files get only the echo gate.
- The file is written atomically against the bytes read (`Error::ConcurrentModification` otherwise). `Files::with_history(&history)` gives `RecordedFiles`, whose `write`/`edit` first `History::record` the before-image for the checkpoint set by `History::set_checkpoint`; `History::rewind` returns a `RewindReport`.
- `text::cut_line` is the one long-line cut (`… [N more characters]`), used by `Excerpt` (2000 characters).
