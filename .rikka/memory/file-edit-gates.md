---
title: Text-replacement edits and their refusals (rikka-file-edit)
description: Files::edit over exact-text Replacements: matching, no_match/ambiguous reports, echoed-line and broken-syntax gates.
about: crates/foundation/rikka-file-edit
tags: [ai, editing]
---

- `Files::edit(&EditRequest { path, replacements })` → `EditOutcome { path, summary, excerpt, change }` applies each `Replacement { old, new, all }` in order to the result of the ones before (`editing.rs`), on the LF-normalized content (`\r\n` in `old`/`new` becomes `\n`; `Text` re-renders the file's endings and BOM). `old` must be non-empty, differ from `new` and occur once unless `all`. Then one `Edited::between(before, after)` takes its `Splice`s from the line diff (`diff.rs`), the syntax gate runs, and the file is written atomically against the bytes read (`Error::ConcurrentModification` otherwise). `Files::with_history(&history)` gives `RecordedFiles`, whose `write`/`edit` first `History::record` the before-image for the checkpoint set by `History::set_checkpoint`; `History::rewind` returns a `RewindReport`. `Files::write` returns `WriteOutcome { path, relative_path, lines, created }`.
- Matching runs on content with every `\r\n` stripped to `\n` (`eol.rs` `Returns`, which also covers mixed-ending files that `Text` keeps raw) and the `\r`s are restored on write; a newline written by `new` takes the ending of the same-numbered newline in the replaced text, else its last one. Uniqueness counts overlapping occurrences (`matching::overlapping`); `replace_all` replaces non-overlapping ones. Offsets of later edits move through `cut.rs` `Cut`.
- Every refusal writes nothing and is an `Error` whose text starts `error: <kind> <path>: nothing was written.` followed by the lines involved (`refusal.rs`, naming `Edit N's` and the state after earlier edits when there are several), so a model can retry without reading the file again. `no_match` shows the closest place (`matching.rs` `closest`: whitespace-squeezed line votes for blocks, containment or bigram similarity for one line, whole span numbered) or says nothing resembles it, and spots line-number prefixes (`cat -n` tabs, `rg -n` `N:`/`N-`) copied into `old`. `ambiguous` lists the lines of each occurrence. There is no fuzzy application.
- `seam.rs` (`echoed_line`): for a single, whole-line match, a `new` whose first line repeats the line above the match, or whose last line repeats the line below, is refused unless a later edit in the same call rewrites that neighbour. A match whose own first or last line already equals it, and lines without letters or digits (blanks, closing brackets) are exempt.
- `text::cut_line` is the one long-line cut (`… [N more characters]`), used by `Excerpt` (2000 characters).
- `structure.rs` (`broken_syntax`): files with a loadable `rikka_grammars::Grammar` are parsed after the edit, and before it only when the result has faults. Old faults are carried through `Edited::shifted_line`. A clean file refuses any new fault; a file that was already broken refuses only when its fault count grows.
- A parse refusal starts with the bracket imbalance `Grammar::depths` counts from the tree's anonymous tokens, because tree-sitter often reports a dropped bracket as a wide unparsed span.
- Shader-like files without a grammar (`brackets.rs` `BRACKET_CHECKED`: glsl, comp, vert, frag, wgsl, hlsl, cu…) only have `{}`, `()` and `[]` lexed into `rikka_grammars::Depths`, skipping comments and `"`/`'` literals. A balanced file may not become unbalanced.
- Other files (plain text, unknown extensions) get only the echo gate.
- The grammar shipped for Rust misses Rust 2024's `safe fn` in `unsafe extern` blocks; otherwise the workspace's own files parse without faults.
