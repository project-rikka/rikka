- `src/space/` owns the look's scene effects: `occlusion.rs` (half-res GTAO, then a full-res joint-bilateral denoise/upsample), `screen_shadows.rs` (wavefront screen shadows, see renderer-shadows), `reflections.rs` (half-res GGX-jittered screen-space trace, full-res bilateral resolve), `lines.rs` (depth/normal/figure edge filter), `particles.rs` (instanced sprites drawn in the shade pass), `emitters/` (GPU side of `Look::emitters`, see renderer-emitters).
- GTAO (`space_occlusion.slang`) integrates per slice the cosine-weighted visibility and the bent normal analytically (Jimenez 2016 Algorithm 2, XeGTAO's terms via sincos identities) and writes at half res `(visibility^strength, octahedral world bent normal, view distance)`, distance 0 = no surface. The denoise (`space_denoise.slang`) loads the group's 8×8 half-res footprint (decoded, plus the G-buffer normal at each tap) into groupshared once, then filters visibility and visibility × bent normal with the same bilateral weights.
- The occlusion image (full render res, RGBA16F, sampled through `rikka_render_uv`) is the same for both tiers: `.x` visibility with strength applied, `.yzw` the world-space bend `B̂ − V·n`, where B̂ is the visibility-weighted bent normal and n the G-buffer normal there; empty pixels are `(1, 0, 0, 0)`. Everything that filters it (denoise, RT temporal/spatial/upsample, bilinear taps) stays linear; readers recover the bent normal for any normal m as `normalize(V·m + bend)`. RTAO writes `bend = 1.5·mean(seen·ω)·(V/raw) − V·n` over its cosine-distributed rays (1.5 = 1/E[ω·n] of the open hemisphere), so open surfaces give bend ≈ 0 in both tiers.
- Shaders: `shaders/space_*.slang`, `particles.slang`; helpers in `rikka.space.view` (`lib/rikka/space/view.slang`: projection-generic view positions, distances, noise, hash, float octahedral `space_encode_direction`/`space_decode_direction`).
- `rikka.space` (`lib/rikka/space.slang`) is the shared contract: `rikka_occlusion(frame, uv)` returns the occlusion image texel above (`float4`, AO in `.x`), `rikka_screen_shadow(frame, frag_xy)` the screen-shadow visibility, and `rikka_reflectance(reflection, roughness, n_dot_v)` is the mirror weight (F0 = reflection²) the SSR resolve and the stage materials share. Materials use it through `RikkaIndirect` (material-system.md).
- Tests: `tests/look/space.rs` (corner darkening, bent normal picks the open side's sky colour, specular occlusion in a crease with the open plane bit-identical, multi-bounce), `tests/look/tracing.rs` `traced_and_screen_space_occlusion_agree_on_a_crease`.
- SSR owns the mirror layer: output = mix(shaded, mix(sky specular, hit, confidence), reflectance × strength), driven by the G-buffer gloss written by each model's `gbuffer` hook (built-ins: the `gloss.roughness`/`gloss.reflection` parameters).
- Every Look parameter the GPU needs (occlusion, screen shadows, lines, particles) travels in `GpuSpace` (`look/gpu/space.rs` ↔ `RikkaSpace` in `lib/rikka/common.slang`, 128 bytes), not push constants.
- Particles are stateless: position = hash(seed, instance) + wind·time + sway, wrapped in a `reach` cube around camera + forward·`Particles::focus`; count = amount × 16 000, capped at 65 536.
- Built-in stage materials: `FloorParams` (plain/tiles/planks on world XZ, `rikka/floor`; `FloorPattern::Shadow` uses `rikka/shadow_catcher`) and `WaterParams` (animated wave octaves, sun glints, `rikka/water`) build a `MaterialDesc` by name (`material()`); live edits pass `p.values()` to `Renderer3d::set_material_values`. SSR gloss is the `gloss.roughness`/`gloss.reflection` parameters.
- Record methods added by an area must carry that area's prefix (`space_*`), since all `impl Record` blocks share one namespace.
