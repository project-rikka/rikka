- The host implements `SurfaceHost` (`surfaces() -> &mut Surfaces`, plus defaulted hooks `committing` (right before a commit takes the pending state, for staging host `Cached` values once per commit), `committed`, `destroyed`, `import_dmabuf`, `wants_refresh(OutputId)`, `output_of(&WlOutput)`) and installs `SurfaceProtocols`.
- `SurfaceProtocols` serves every surface-related interface and publishes the hardware-independent globals. The GPU-dependent globals are published with `Surfaces::enable_dmabuf`, `enable_syncobj` (takes a DRM fd) and `enable_color_management`, each returning a removable `Global`.
- Surfaces, buffers, pools and blockers live in slotmaps. `SurfaceId`/`BufferId` are stored as object data; resolve them with `Surfaces::lookup(&WlSurface)`.
- Commit pipeline: validate, then the role's `pre_commit`, then either cache (effectively synced subsurface) or queue a transaction holding the surface plus its synced descendants' caches (gathered iteratively, so nesting depth is unbounded).
- Colour: `ImageDescription` (`Rc`, compared by identity) wraps `Parametric { transfer, named_primaries, description: rikka_colorimetry::Description }`; `Surfaces::describe`, `set_output_image_description` (sends `image_description_changed`; the host follows with `wl_output.done`), `set_preferred_image_description(surface, …)` (the compositor sets every member to its main output's description), `forget_output`. A complete parameter set with degenerate primaries or an unimplemented transfer function fails with cause `unsupported`; only TFs/primaries/features in the host's `ColorSupport` are accepted. Reads: `Surface::image_description()`, `color_representation()`.
- Commit-time checks (viewport fit and integrality, scale divisibility, colour representation vs format) run against `Surface::latest` (`latest.rs`), the state the newest commit leaves; `take_pending` advances it. `Current` lags while transactions wait, so checks never read it.
- Updates are pooled `Box<Update>`s: `take_pending` swaps in a spare, `apply` drains fields into `Current`, and the box is reset and returned. Pending damage is a bounded `Damage`; subsurface positions are keyed by child.
- `transaction::Queue` indexes transactions: per-surface FIFO lines, a blocker→transaction map with remaining counts, a candidate heap ordered by enqueue order, a constrained set with a deadline heap. Work happens only for transactions something woke; dead surfaces are dropped in `Surfaces::remove`. More than 256 waiting transactions on one surface kills the client.
- A buffer's fences (`Update::fences`) belong to that buffer use and are released when a synced cache replaces the buffer; explicit `Surfaces::block` blockers stay in `Update::blockers`.
- Transactions apply in FIFO order per surface. Each waits for its blockers, fifo barriers and commit-timing targets; every applied surface emits one `Committed`, parent first.
- Roles are types implementing `Role<S>` (payload plus hooks), assigned with `assign_role`; `end_role` lets the same role be re-assigned. `Subsurface` is one such role.
- `Cached<S>` values staged with `Surfaces::stage` follow the same double-buffering and fire `applied` hooks; role crates use this for extra state.
- Fd-based waits and the commit-timing alarm are registered with the reactor by one per-turn hook installed by the module, holding a `WeakReactor`. Implicit fences are exported once per distinct dma-buf (planes deduplicated at import); syncobj acquire points use one persistent eventfd per surface, re-armed per commit.
- Renderer side: `tree(root)` (bottom to top, allocation-free), `flatten_into(root, &mut Vec<PlacedSurface>)`, `frame_done_for(&[PlacedSurface])`, `take_feedback_for(&[PlacedSurface])` (root-walking `frame_done` remains), `Feedback::presented(presentation, |client| outputs)` (the host yields that client's bound `wl_output`s), `take_damage_into(id, &mut SurfaceDamage)` (swaps buffers), `content(id)` → `Shm`/`SinglePixel`/`Dmabuf`, `hold`/`release`/`uploaded`. `surface_under` is a reverse DFS stopping at the first hit; `bounding_box(root)` is cached per subtree and invalidated up the parent chain on size, mapping, position or stack changes. Syncobj release points are signalled when the buffer's last hold drops.
- `wl_region` snapshots are `Rc<Region>` (copy-on-write); `Surfaces::region` returns one, and `Surface::opaque()`/`input()` borrow them.
- Presentation feedback is discarded only by a later update that brings content (buffer, damage) or feedback of its own; NVIDIA's WSI follows each FIFO frame with an empty `wait_barrier` commit, and spurious discards make it schedule commit-timing targets seconds ahead.
- `Surface::tearing()` and `content_type()` give the applied hints as `rikka_compositor_types::{TearingHint, ContentType}`; preferred scale and fifo barriers stay internal (the host sets the scale, `refreshed` clears barriers).
- Outputs are `rikka_compositor_types::OutputId`s; `SurfaceHost::output_of(&WlOutput)` resolves a wl_output (rikka-nested also allocates one unpublished head per view as its pacing target). The compositor sets `set_main_output(surface)` and calls `refreshed(state, output, next_presentation)` once per output refresh; this clears fifo barriers and releases commit timers.
- Shm reads go through a process SIGBUS handler with a thread-local guard; a truncated pool is zero-mapped and the client gets `wl_shm.invalid_fd`.
- Tests: threaded harness in `tests/common`, shared by `tests/main.rs` and `tests/machine.rs`; `Server::await_commits(id, n)` blocks on a channel fed by `SurfaceHost::committed`; the machine binary holds `syncobj`, which needs `/dev/dri/renderD128`.
