---
title: UI toolkit crate layering
description: symbols → rikka-ui → rikka-widgets → markdown, with syntax beside rikka-ui, and where a new widget or mechanism goes.
about: crates/ui
tags: [ui, architecture]
---

- One-way chain: `rikka-symbols` → `rikka-ui` → `rikka-syntax` → `rikka-widgets` → `rikka-markdown`. `rikka-ui-macros` provides `#[derive(State)]` and the child macros.
- `rikka-picture` (graphics, over `rikka-gpu` only) sits under `rikka-ui`: the picture hand-off handles (`Feed`, `FeedDevice`, `ImportedBuffer`/`ImportedFrame`/`ImportedPlane`, `Lease`, `ComputedImage`, `VideoController`), `Pulse`/`Tick`, `RefreshRate`, `SharedGpu`, `Waking`/`Sleepers`, `Changes`/`Repaint`. Producers (nested, web, remote, Cut, Paint) name it directly; rikka-ui re-exports only the handles widgets draw (`Feed`, `ImportedBuffer`, `ComputedImage`, `VideoController`, `VideoState`, `Pulse`, `Waking`, `Changes`, `Repaint`).
- `rikka-ui-host` (public) is the host stage beside `rikka-widgets`: `Embedder`/`Hosted`/`Drawing`/`FrameOutcome`/`Presenting`, `Composer`/`Composed`, `TaskSink`, `WakeHint`, `Resources`/`ResourceFrame`, `ImageCache`/`CacheResolver`, plus the private painter, viewport thread and offscreen store. Video playback is an opt-in seam: the `VideoPlayback` trait (`advance`, `resolve`, `is_starting`, `has_work` → `VideoFrame`), installed with `Embedder::plays_video`/`Composer::plays_video`; without one a drawn video fails with "this program does not play video". Public `rikka-ui-video` implements it as `VideoStore` over `rikka-video-play`, and only programs that install it (`App::plays_video(VideoStore::default())`, `Embedding::plays_video`, the shell's embedder) link the player and FFmpeg. Only rikka-ui-host reaches `rikka-image`; rikka-app and the shell depend on it explicitly.
- The host seam is explicit: `rikka_picture::consume` (`FeedConsumer`, `ImportedConsumer`, `ComputedConsumer`, `VideoConsumer` extension traits, `Arrival`/`Content`, `VideoCommand`, `DamageLog`, `on_arrival`/`announce_arrival`) and `rikka_ui::consume` (`OffscreenConsumer`, `live_offscreens`, `any_offscreen_live`, `register_wake`), with `Ui::{take_pulses, shows_image, scale_factor}` and `SourceKey::is_unreachable`.
- `rikka-symbols` (graphics layer) is icon-font vocabulary only: `MaterialSymbol`, `BrandSymbol`, `IconGlyph`. Its constant tables are generated at build time from the pinned, shipped icon fonts (see the icon fonts note).
- `rikka-ui` is the framework: `Element`, `View`, `State`, `Widget`, handlers and effects, the retained tree, layout, paint, the text and search models, scrolling, fetch, drag, `ImageSource`/`TextureResolver`, and the `Offscreen` handle. Its only widget is `text()`, because `impl View for &str` must live there.
- `rikka-ui` source is grouped by responsibility: `view/ style/ paint/ motion/ task/ input/ text/ search/ scroll/ picture/ runtime/`, plus `offscreen.rs` and the host seam `consume.rs`. `task/` also owns the helper-thread pool (`in_background`, text pre-laying batches).
- `rikka-widgets` holds every other widget, the collection engine and the `column!/row!/page!` macros. No framework mechanics. Toolbars are `toolbar()` with priority overflow (see the toolbar note).
- `rikka-timeline` sits above `rikka-widgets` and holds the keyframe-timeline pieces Animate and Cut share; see the timeline-keyframe note.
- `rikka-widgets` folders: `blocks/ controls/ text/ lists/ navigation/ media/`, with `control.rs`/`rows.rs` as shared vocabulary.
- New widget = a file in the right folder plus one line in `rikka-widgets/src/lib.rs`. A new mechanism goes into `rikka-ui` and never names a widget.
- Window-level dialogs: `sheet(content).width(..).on_dismiss(..)/.on_chord(..).keyed(..).centered_on(STAGE)` is the shared modal panel (surface, outline, pane, fade + scale-from-0.88 motion), a `container(..).modal()` (`Behavior::MODAL`, swallows presses, releases and scrolls inside itself), so it owns the keyboard while presses outside fall to the scrim or the window chrome; `.with_scrim()` returns `[scrim, sheet]`, `.build()` the panel alone (Animate keeps its own outside catcher). `dialog(title, body)` frames an app's form sheet on top of it: title, optional `.summary(..)`, the body, and one footer row of `.aside(..)` elements, a spacer, `.cancel(label, handler)` (ghost; also Escape unless `.on_dismiss` overrides), `.action(..)` elements and `.accept(label, handler)` (primary; also Enter), both gated by `.ready(bool)`; Cut's and Paint's sheets use it. `unsaved_prompt(name, saving, on_answer)` is the Save / Don't Save / Cancel sheet answering `Unsaved`. `shortcuts(child, pressed, enabled, run).standard(..).holding(key, ..).paused(..)` is an app's keyboard home: it dispatches resolved chords and standard commands, calls `skip_view()` for disabled ones, and reports a held key (Paint's Space pan). `rule()`/`rule_upright()` are the 1 px outline hairlines.
- Shared states: `status_page(symbol, message).action(..)` is the centred icon-and-message empty or trouble page (`.tint` recolours the icon); `banner(message).on_dismiss(label, handler)` is the inline danger line (`.symbol`, `.tint`). Apps use these instead of hand-built notice rows.
- `copy_button(text)` is the one copy-to-clipboard control: icon-only ghost button with a Copy/Copied tooltip, `.labeled()` adds the text; it flips to a check for a moment after pressing (strings `widgets.copy.*`). rikka-markdown puts a labeled one in every code block's header row beside the fence's language; rikka-chat's person turns use the icon-only one.
- Menus: `menu()` is an anchored panel, `menu_bar()` a self-contained caption menu bar (`.menu(title, items)`), and both run a `MenuItem::on_press` handler; `combo` and `menu_bar` draw their panel themselves through `Behavior::OVERLAY`.
- `menu`, `menu_bar`, `ContextMenu` and `combo` share one key and pointer dispatch in `navigation/menu/cascade.rs`: `Cascade::key(laid, key, modifiers) -> Keyed` (arrows, Home/End/PageUp/PageDown, typeahead, Enter/Space, Escape; `Aside` for an arrow that leaves the panel: next title in `menu_bar`, next group tab in `combo`) and `Cascade::pointer(laid, event) -> Pointed`. The self-drawn panels (`menu_bar`, `ContextMenu`, `combo`) close when focus leaves; `menu()` is closed by its app. A combo keeps its listed `MenuItem`s in its state, rebuilt only when the combo is re-viewed or its shown span changes.
- `context_area(child, || items)` gives any child a right-click / Menu-key context menu, building its `MenuItem`s when it opens.
- Every menu panel pops (see the motion note): `menu()` carries `pop()` itself, so an app only anchors it and removes it to close (the ghost plays the exit); `.still()` drops that for a menu inside a popup that already moves (the shell's popover). `ContextMenu`, `combo`, `menu_bar`, submenus and code completion pop in paint through `Panel::paint(.., shown, pivot, ..)`, submenus from the row that opened them.
- `command_item(Command)` is a localized menu row (label, icon, chord) that `send_command`s when chosen. `ContextMenu` is the right-click menu a widget keeps in its state: `open`/`open_by_keys`, `event` first in the host's event (true = consumed), `paint` anywhere in its paint. Items are chosen on release, a press outside dismisses and swallows its release, and focus stays on the host.
- Every text editing widget (`Editing`), selectable `rich_text`/markdown (only over its selection), the terminal grid, Files' rename box, the calculator, and Paint/Cut on-canvas text open a `ContextMenu`; `text_menu(&TextDocument)` is the standard editing item list, and `text_field(..).on_command(..)`/`.context_items(..)` let an app take a command or add rows.
- rikka-widgets owns the `widgets.*` catalog (`rikka_widgets::CATALOGS`); rikka-app and the shell embed it with every app's catalogs.
- `segmented` fills its width but never shrinks below its natural width (widest label × segments plus padding), so it stays readable in content-sized rows such as toolbars. `combo` and `dropdown` only fill and elide in tight rows. `combo(..).more(first, label)` lists only the first options plus a More row that unfolds the rest in place; a choice past the fold opens unfolded.
- Value entry: `number_field(value)` (`.range/.step/.decimals/.unit`, commits on Enter or blur) edits through the shared editing engine with its own `TextDocument`; `color_picker(color)` is an inline HSV panel (`.on_change` while dragging, `.on_commit` per gesture) and `color_well(color)` opens it in an anchored `popover(content).on_dismiss(..)`, the public modal surface that dismisses on outside press or Escape.
- `rikka-terminal` builds on `rikka-ui` and `rikka-widgets` (for its context menu). Models and their UI are separate crates: `crates/graphics/rikka-effects` (serde effect model, no UI deps) with `crates/ui/rikka-effects-forms` (forms, editors), and `crates/graphics/rikka-figure` (figure model) with `crates/ui/rikka-figure-editing` (overlay painting, on-canvas typing, lettering controls, `figure.*` catalog). App model crates (`cut-project`, `cut-render`, `paint-document`, `paint-assistant`) depend only on the model halves. `rikka-app` also takes widgets for window chrome. `Caption` (the caption-row builder over `CaptionBar`) lives in `rikka-widgets`, and `rikka_app::prelude` re-exports it.
- Naming rules for widget builders: every handler is `on_<event>` (`on_press`, `on_select`, `on_toggle(bool)`, `on_dismiss`); `on_change` is live and `on_commit` is the finished gesture or edit (`slider`, `number_field`, colour pickers); `.control_size(ControlSize)` picks the size token, `icon/spinner/gauge(..).extent(length)` their square size, and `Styled::size(width, height)` is never shadowed. Builder types are `#[must_use]`; their methods and the functions returning them carry no attribute. A handler that comes with its own glyph or label takes both: `list_item(..).on_action(symbol, handler)`, `banner(..).on_dismiss(label, handler)`. Handler props are `Action<Args>`, and `Action<Args, R>` for handlers that answer a value (`on_key -> bool`, `context_items -> Vec<MenuItem>`).
- `Grab<T>` + `GrabStep` (`rikka_widgets`) is the shared pointer-drag state machine (capture, move, release, `PointerCancelled`); a widget calls `begin(held, ctx)` on its own press and matches `update(event, ctx)`. `Sums<T>` (`sums.rs`) is the one prefix-sum tree (collection spans, editor rows). `text/field.rs` `paint_frame(.., FieldMood)` draws every field frame.
- Each crate builds once with every feature it has; there are no `cfg(feature)` gates in crates/ui.
- Modules a widget author reaches past the facade: `rikka_ui::{text, motion, scroll, search, font}`.
