- Reconcile: in place by type and key, keyed fallback when the shape changes; state never crosses widget kinds. A widget whose `Widget::same` holds (and whose style, visual, env and theme epoch did not change) stays clean: no measure, build or paint. `same` covers only a widget's own fields. When the count of unkeyed children changes, `PositionalMatch` (`reconcile.rs`) aligns their common tail by `same` over the whole subtree, so content inserted above leaves the widgets below on their nodes, only moved.
- Children match against the key an instance got after resolution, while a new `component`/`local_state` element is matched before it resolves: one whose view returns a keyed root never matches its old node, so every parent rebuild remounts it (fresh local state, lost presses). Key the element around the component or `local_state`, never its returned root.
- `Element::retained(key)` (a zero-sized `Kept` widget) keeps the standing child with that key without building or diffing; a `build` may emit it only while `rikka_ui::can_retain()` (a rebuild within one theme epoch).
- `lazy(digest, ..)` skips unchanged subtrees; theme and language generations always rebuild. `Widget::build` runs again whenever a key it read (tracked state, `Observers`, a landed `fetch`) changes or its handle asks, so a widget never consumes what it builds from: `lazy` and lazily held collection cells take `Fn` builders.
- Components live on the instance their view produced (`runtime/holding.rs`). `Readers` (`runtime/readers.rs`) maps each key to the root, component views and widget builds that read it; every render pass takes the global change log (`view/observe/log.rs`), marks stale readers, and `rebuild_walk` re-runs a stale component in place. A surface polled by `needs_render` skips logged changes none of its readers read.
- Node table (`runtime/table/`): instances live in a slab keyed by the layout `Node` slot; an id is `generation << 32 | slot`. Hot columns (behavior, flags, relative geometry) sit beside it; tree structure is `Layouts`' parent/children.
- Table geometry is relative (`table/geometry.rs`): `placed` is a node's bounds in its parent's children frame, `inner` the children offset it applied, `extent` its subtree hit area, `clipping` its clips. Window bounds are resolved by walking parents (`Table::seen`/`bounds`/`clip`/`contains`); descents carry a `Seen` frame. Nothing stored per node changes when an ancestor scrolls.
- Islands (`table/islands.rs`) are automatic: the root, scrollers, anchors/inset/ghosts, `Behavior::TRAVELS` widgets (`AnimatedPosition`, collection `Rider`s, so every collection cell is an island from birth), widgets offsetting their children (`Page`), subtrees seen moving as a unit (on the 1/1024 px grid) and px-sized boxes of at least 4 nodes. A node joining an island later has its primitives re-inserted in the island's group, so things known to move should travel from the start. Each island owns one renderer group holding its owner's descendants and a DFS order only the paint walk reads.
- Paint is a diff walk over island DFS orders: a subtree whose context is unchanged and holds no `PAINT`/`VISIT`/`BELOW` flag is skipped, as is one whose context only moved with its frame (`Context::carries`), unless it holds `TRACKS`/`TRACKS_BELOW` (reads the clip or viewport, drew under a volatile clip, `TRACKS_PLACE`, hosts glass/opaque/windows, paints topmost or zooms) or its `Reach` says culling would change. So scrolling, page turns, rider drift and layout moves revisit only nodes entering view and tracking nodes.
- `paint` runs only for new or changed nodes, delivered events, rebuilds, active motions, due wakes, handles, size/room/content/scale/hover/focus changes and reads flagged in `PaintCtx` (`child_rect`, `visible`, `viewport`, an entirely hidden `clipped` region). A pure move re-places retained primitives; `Widget::relocated(state, by)` runs lazily before the next re-place or event so a skipped widget's state catches up.
- Primitive order is `(z, stack, label)`: z is 1 for `topmost` paint; stack is the label of the innermost stacking root (an anchored element or an `OVERLAY` widget, at any depth, 0 outside them), so every overlay draws above all of its enclosing context, nested ones above their parents, and later roots above earlier ones (CSS stacking-context order); relabelling a root revisits it (`Table::relabel`). Stacking roots also escape every ancestor clip; the label the node's sparse pre-order label `<< 20 | index` (`table/labels.rs`). The effective clip (`Context::clip`) and the loose part not yet enforced by a group (`Context::loose`) are split; at each island the loose clip becomes the island group's `GroupClip`, so a page turn, glide or scroll edits no node. Placed coordinates snap to 1/1024 px.
- Every clip combination (rikka-ui `narrowed`, the renderer's `resolve_clip`, `bound_clip` in `shaders/primitive.slang`) uses `RoundedRect::intersect`: each corner keeps whichever shape's rounding still reaches it. The shader must stay in step with the Rust rule. Scene primitives diff field by field, so an unchanged frame means no damage.
- A walk `Clip` carries its `Space`: two clips of the same group intersect in that group; only clips of different spaces become `Space::Volatile`, which places descendants' scene clips in target space, so such a subtree must never be skipped by `Context::carries` while its group moves.
- `PaintCtx::scrolled(by, draw)` draws into a node-owned renderer group offset by `by`, and `PaintCtx::part(key, draw)` keys primitives so they keep their scene nodes when what is painted before them changes (`Regrouping` in `scene_sync.rs`); self-scrolling widgets use both. Group offsets must be whole device pixels: `Frame::at` rounds an island's `origin` and keeps `exact`; `scrolled` callers pass `ctx.snap`ped offsets.
- A moving island's group reports its extent plus `BLEED` as what it shows; the renderer cuts that by the group's resolved clip, so a transition inside a scroller damages only around itself.
- Off-clip subtrees are neither painted nor hit, except a revealing container (`container.reveal(Reveal::…)`), anchored elements and their ancestors; their primitives are hidden with the renderer's `visible` flag. Culling tests closed edges, so a zero-height node inside the clip still paints. A paint requested while culled stays pending until shown again; so does a repaint of everything (theme, language, `request_frame`).
- Images: the tree interns each image source and counts its visible primitives; `Ui::shown_images` is the set the cache keeps, `Ui::images_arrived` re-resolves waiting primitives without repainting.
- Post-layout hook: `Widget::arranged(state, Arranged)` runs after each layout that placed the node, for scrollers and widgets declaring `const ARRANGES: bool = true`; answering `true` rebuilds before paint. Size-dependent side effects (the terminal's PTY resize, the node canvas's first framing) belong there, never in paint.
- Anchors (`runtime/arrange.rs`) are re-placed from their targets' window bounds every arrange, so they follow scrolls. `Anchor::offset(x, y)`: for above/below edges y is a gap away from the target, and the element flips sides when it does not fit. Anchored elements paint and hit-test above all normal content, later over earlier, nested ones above their holder's later content, so a full-window modal layer must itself be anchored with `Anchor::covering(target)`.
- Tooltips are a runtime mechanism (`runtime/tips/`, `runtime/tipping.rs`): the deepest hovered node naming one is aimed only when the pointer itself moves, shows after a 500 ms rest (at once within 400 ms of leaving a shown one), and any press, scroll, key or drag hides it. The bubble is painted `topmost` by the root, flips away from window edges and is never hit.
- `PaintCtx::request_build` rebuilds one widget; `request_view` re-views the surface; `request_frame` keeps that node painting every frame; `wake_at(instant)` repaints it once then (`Ui::next_wake()`), one wake per node. `Ui::request_frame` repaints everything, `Ui::request_redraw` only asks for a frame. Decorative loops run at full rate with `request_frame` and stay cheap because each frame damages only their own primitives.
- Handles: `PaintCtx::handle()`, `EventCtx::handle()` and `NodeHandle::current()` name one node; `repaint()`/`rebuild()` work from any thread and wake the embedder. `Watchers` gathers handles for shared state. Marks are taken at the start of every render pass.
- Discarded instances go to the tree's `Graveyard`, dropped in idle time through `Ui::prefetch`; widget and state `Drop` therefore runs late, and anything that must happen at removal belongs in `release`.
- Frame-path buffers persist on `UiTree`; layout sweeps and `match_children` collect into `Scratch<T>` (`runtime/scratch.rs`, eight inline, larger lists from a per-thread pool, `pooled!`), so a steady lazy-list scroll frame allocates nothing in the ui stage.
- Hot paths: `ambient::with_env` returns at once when current, `Instance` is `#[repr(C)]` with reconcile-hot then walk-hot fields (measure any reorder), the walk prefetches instances, prim slots and scene nodes ahead (`Walk::prefetch_ahead`), and `warm_measurements` primes text leaves before a solve. Store-forwarding stalls dominate per-node cost: destructure big values into locals, mutate primitives in place; `perf stat -e cpu_core/ld_blocks.store_forward/` finds them.
- Layout, scroller settling and hover refresh are skipped when nothing was reconciled, resized or dirtied. `rikka_ui::stats::snapshot()` reads the UI thread's counters. `Ui::dump()` prints every instance; `rikka-widgets/tests/rendering/layout_golden.rs` compares views against `tests/golden/mod.rs`, rewritten with `RIKKA_BLESS_GOLDEN=<absolute path> bazel test --config=gpu //crates/ui/rikka-widgets:main --test_arg=layout_golden`.
- Elements a widget returns from `Widget::build` are reconciled under `Producer::Build(widget)`, so reads of deferred content (`local_state`, its setter) rebuild that widget. A widget that wraps view-built content passes it as static children (`Element::with_children` in `View::build`, as `DropZone` and `Popover` do); a one-shot content element emitted from `build` panics or goes stale on that rebuild. State-dependent decoration over static children uses a sibling widget repainted through `Watchers` (`DropZone`'s glow).
