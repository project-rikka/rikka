---
title: Browser application
description: rikka-browser is the vertical-tab browser on rikka-web (Gecko): shared model, runtimes per profile, store persistence.
about: apps/system/browser
tags: [application, web]
---

- `rikka-browser` (default for http/https/html in the session `mimeapps.list`): vertical left sidebar, top bar as caption with the address field, Spaces with icons and profiles, Favorites, Pinned tree, Today, archive, Split View (2–4), Peek, Little Arc, private windows.
- Sidebar (`sidebar::side`): one in-flow strip without outline, coloured by `Corners::sidebar`. Only the topbar toggle (or `Ctrl+Shift+B`) switches the 52 px rail and the 280 px panel through the persisted `sidebar-expanded` preference; hovering never opens it. The rail (`sidebar/rail/`) is a full sidebar in icons keyed by `rail::key_of(RailCell)`.
- Tooltips of the chrome are the framework's: `grip(..).tip(label, TooltipSide)` sets `rikka_ui::Tooltip` on the built element. Page tooltips and the hovered-link bubble are `status.rs`, drawn from `Meta.tooltip`/`Meta.hovered` inside `requests::framed`.
- Menus and popups pop: `menus::view` (sidebar/tab context menus, the ⋯ main menu, back/forward history), `overlays::view` (downloads, site info), the rail rename field, extension popups and the omnibox dropdown are keyed elements inside `widgets::presence`, a slot their component always returns so they leave as ghosts; the command bar (`fade_scale`) sits in one too. Panes are `rikka_widgets::popover`; `widgets::floating` is the paneless modal for panels that draw their own card.
- `corners.rs` owns the rounded look behind `rikka.browser/rounded-corners`; the page card keeps one widget structure in both states so the web view never remounts.
- Engines (`engines.rs`): one `rikka_web::Runtime` per `ProfileKey` (`Persistent(id)` or `Private`): `Profile::Persistent($XDG_DATA_HOME/rikka/browser/profiles/<id>)` per kept profile, `Profile::Ephemeral` for private windows. `Browser::engine` starts or returns a running one (a dead runtime restarts on next use) and then `PageServices::attach_runtime` takes its `RuntimeEvent`s, loads the profile's grants and pushes them into Gecko's permission store (`requests::share_all`), and `https::allow_http_on` pushes HTTPS-Only exceptions (`https-only-load-insecure`). `Browser::running_engine` never starts one.
- `page.rs`: tabs hold `rikka_web::Session` directly (identity equality). Tabs are `Page::{Unloaded, Discarded(SavedState bytes), Live}`; `Live::open(&runtime)` uses `page::settings()` (`handle_load_requests(true)`), `Live::adopt(session)` wires translation user content; `Live` also keeps `muted`, the chosen favicon (`LiveIcon`: URL plus its fetched picture) and pending new-window `openings`.
- The model lives in `browser-model` (`Model<Live>` through the aliases in `src/model.rs`, default names in `model::NAMES`); internal routes in `browser-pages` with titles and symbols from the app's `internal::route::Presented`.
- Every window shares one `Rc<Browser>` (`RefCell<Model>`, engines, preferences, services, window senders). `Shell` is per window. Ids are `browser-store` ids (only `WindowId` is local). Model mutations write through to the store; sessions save 2 s after a change, every 60 s and at exit; page state is read synchronously from `Session::state()` (after `flush_state`). Private windows write nothing.
- Events (`shell/events.rs`): `LoadRequest` decides by `link::opening(OpenWhere)`: explicit background/foreground tabs are denied and opened fresh, current-window loads may become a Peek, page-asked new windows are allowed and the `NewSession` is adopted (`NewWindow` or a requested popup → Little Arc popup sized from the popup's width/height, else tab or Peek). History comes from the history delegate: `Event::Visit` → `browser_pages::VisitTracker::visited` (cause set by the app through `set_cause`, else remembered policy decisions; redirect flags) → `store.record_visit`; `VisitedQuery`/`HostVisitedQuery` are read and answered on a blocking task. A one-shot request that must survive a task travels through the task's output, never through a `Cell`.
- Favicons (`favicons/`): rikka-web reports `PageState.icons`; `browser_pages::best_icon` picks one (fallback `/favicon.ico` once loaded), `fetched()` downloads with a cookie-less rikka-net client (1 MiB; `data:` URLs are decoded by `data_url_payload`) and decodes with rikka-image to ≤64 px; an SVG favicon is rasterized in the window's scheme (`Shell::color_scheme`: private windows dark, else the appearance) and also keeps its document in `Favicon::svg`, which `widgets::favicon` draws as `ImageSource::vector` so it follows theme changes live (stored copies keep only the raster); an unchanged icon URL is reused across navigations without refetching; the favicon store keeps them per page URL. Extension icons (`moz-extension:`) are read through `Extensions::icon` instead.
- Page requests land in `requests/`: Gecko prompts become a `Dialog` queue (alert/confirm/prompt with Gecko's own check box, beforeunload, repost, popup, redirect, folder upload, color, date/time, autofill selects), sign-in, GeckoView choice prompts (`ChoiceRequest`, a centered menu), files, context menus (selection read in isolated world `rikka-menu`), permissions remembered per `Requester { origin, top_site }` (content and media requests; Gecko's store is kept in step), error pages (`interstitial/`: native overlay plus an app-made HTML document answering `LoadError`), hangs. Closing a tab or window and quitting never ask: they save tab state and close at once; `Dialog::Leave` only answers Gecko's beforeunload prompts during navigation.
- `<select>` dropdowns (`requests/dropdowns.rs`): one `DropdownSlot` per `DropdownOwner` (`Tab(id)` in `TabRequests`, `ActionPopup` in the extension popup); the view is a spacer keyed at the select's rect plus a `rikka_widgets::menu` anchored `BelowStart` to it (`highlighted` selected row, `fit_content`, min width of the select, `on_choose` with `Activation`). Hiding a tab dismisses its dropdown. `TabRequests::holds_page_focus` (dropdown, date/time or autofill dialog) drives `web_view(..).retain_focus`, because Gecko closes those pickers when the field blurs.
- Downloads: `Event::Download` → app picks the path (`save_to`; names through `rikka_format::safe_file_name`/`unique_name`, folder from `UserDirs::downloads`); `RuntimeEvent::Download` progress is matched by path, then by `DownloadId`; cancel/pause/resume/remove go through `runtime.downloads()`. Desktop notifications (page and download) are kept in a `rikka_notify::Ledger`.
- Extensions (`extensions/`): service holds installed lists, default and per-tab toolbar actions and pending install/update/permission asks (shown as a sheet in the focused window). Toolbar buttons sit right of the address pill; clicks return a popup URI that opens a `extension_popup` session in a popover. Internal page `rikka://extensions` and settings section `extensions`; extension tabs, options pages and service-worker windows open as normal tabs.
- A tab is unloaded, discarded or live; `Browser::activate` revives it (`shell/sync.rs`). Memory Saver (`memory_saver/`) discards idle hidden tabs (state bytes from `Session::state`) by `browser_pages::discardable_tabs` and tightens under PSI pressure. Dropping a profile's engine goes with `PageServices::forget(key)`; deleting a profile waits for `rikka_web::wait_for_closed_runtimes()` before removing its folders.
- Work moved to another window goes through `Shell::raise(target, work)`. Quit (`Shell::quit`) gathers every kept tab's state, freezes the session and closes all windows.
- Internal pages are native: add a variant in `browser_pages::Internal` (and its title/symbol in `internal/route.rs`), render in `internal::view`, state in `Shell.pages`, setup in `Shell::prepare_page`; settings sections go into `Section`/`LISTED`.
- Default browser (`default_browser/`), Home (`home/`) and Translation (`translate/`) as before; translation per-tab state lives in `Services.translations` and resets on `PageStarted`.
- Gestures: `gestures::catch_gestures` acts on yielded `Gesture::Swipe` (back/forward indicator) and `Gesture::Pinch` (app zoom) that bubble past the web view.
- Keys are one table in `keys.rs` (conventional browser chords, `Ctrl+P` command bar, `Ctrl+S` save as PDF, `F9` reader); the web view reserves them. Super chords belong to the compositor.
- Hosts and origins normalize only through `browser-pages` (`host_key`, `web_host`, `Origin`); certificates (`browser_pages::Certificate`) are parsed from Gecko's base64 DER with x509-cert.
- Preferences domain `rikka.browser` (global: appearance, HTTPS-Only, find options, …) is split under `preferences/`. Locale tables are per feature (`[browser.<feature>]`); en and ja keep the same lines.
- Engine settings are per profile (`engine_settings.rs`): `Services.engine_settings` (`EngineBook`) holds a `browser_engine_settings::EngineSettings` per `ProfileId`, loaded at start from `Store::profile_settings`; private windows follow the first profile. `Browser::{web_preferences, web_locales}(key)` feed `RuntimeBuilder` at start; `Browser::change_engine_settings(profile, …)` saves, then pushes `set_preferences`/`set_locales` to that profile's live runtimes and re-dresses live sessions when the user style changed. Every new `Live` is dressed with `Browser::dress(key, session)` (user style). Requests fall back to `EngineSettings.permissions` (Block denies without a prompt); autoplay permission requests follow `EngineSettings.autoplay`.
- Settings pages for them live in `sections/` (`protection` inside Privacy plus Permissions, `content`, `network`, forms state `sections.web: EngineForms`, reset in `prepare_page`; `engine::choice_field` renders a `Choice` combo that writes one field).
- `Event::OpenLink` (middle/Ctrl/Shift link clicks from rikka-gecko) opens by `link::opening`: tabs load `OpenLink::load()` (Gecko's referrer), a window opens a new browser window, current loads in place. Tabs opened from a page keep a prepared `Load` in `Shell.referred` until their first activation.
- The interface locale reaches running runtimes: every window's `on_language` calls `Browser::follow_interface_locale`, which pushes `set_locales` once per change.
- Automatic engine wiring: shown tabs get `set_high_priority(true)` in `shell/sync.rs::show`; links opened from a page into a new tab, split or Peek load with `Load::referrer_session(opener)` (`Shell::refer`/`referred_load`); clearing History for all time purges back/forward lists of the profile's live tabs; ranges clear engine data with `Storage::clear_between`.
