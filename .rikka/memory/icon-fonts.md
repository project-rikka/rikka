---
title: Shipped icon fonts and generated symbol tables
description: Material Symbols / Font Awesome Brands pinned in nix/dist/icon-fonts.nix, shipped, tables generated by Bazel.
about: crates/graphics/rikka-symbols
tags: [icons, build]
---

- Rikka never draws icons from system font packages; codepoints drift between font releases, so the table and the font must come from one pin.
- `nix/dist/icon-fonts.nix` (shared with the distribution flake, which links it as `share/rikka/fonts`) pins six files by URL and sha256: the Material Symbols Rounded variable font, its `.codepoints` listing and license at a google/material-design-icons commit; Font Awesome Brands, its `metadata/icons.json` listing and license at a Font-Awesome tag.
- The dev shell exposes them as `RIKKA_ICON_FONTS` (fonts and licenses, `share/rikka/fonts`) and `RIKKA_ICON_LISTINGS` (the two listings); Bazel gets the same paths from `@nix//:paths.bzl`.
- `rikka-text`'s `icon_files.rs` opens each `IconFont::file()` once per process through a `rikka_shipped::Shipped` lookup (`$RIKKA_ICON_FONT_PATH`, `<exe>/../share/rikka/fonts`, then `RIKKA_ICON_FONTS` baked in at compile time) and `rikka_text_catalog::mapped_font`; the catalog's same-named system faces are ignored.
- `rikka-symbols/BUILD.bazel` runs the `rikka-symbols-scanner` binary through `run_binary` (`<material|brands> <listing> <font> <out>`) and generates `src/names/material.rs` and `src/names/brands.rs`, which `src/material.rs` and `src/brand.rs` `include!`; they are not committed.
- The scanner fails the build when any listed codepoint has no glyph in the pinned font, or two names collide as one constant. Brand constants include Font Awesome aliases.
- Bumping a font = change URL and sha256 of the font and its listing together; a removed icon name then fails to compile at its users.
- Rikka's apps also get generated symbolic icons: `xtask/src/components.rs` lists `icon("rikka-<app>", "<material name>")` per app, and `tree::lay` (session trees and distribution archives) draws each with `rikka_symbols_scanner::symbolic_icon` (FILL 1, wght 400, opsz 24) into a 16-px symbolic SVG.
- They are installed as `<app>-symbolic.svg` under `SYMBOLIC_ICON_DIRECTORY` (`share/icons/hicolor/symbolic/apps`) for symbolic uses such as Music's PipeWire icon. A `.desktop` `Icon=` names a freedesktop icon the user's icon theme draws in full colour (e.g. `utilities-terminal`), never the symbolic one.
- `xtask compositor` links `RIKKA_ICON_FONTS` as `share/rikka/fonts`, `xtask app` and the Bazel rules pass it as `RIKKA_ICON_FONT_PATH`, and the distribution links its own icon-font package there.
- The dev shell's `nix/packages/fonts.nix` still lists material-symbols and font-awesome only as test corpus for crates/text tests.
