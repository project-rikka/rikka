- `rikka-dirs` (public, no workspace deps) is the only reader of `HOME`, `XDG_*_HOME`, `XDG_RUNTIME_DIR` and `XDG_*_DIRS` (absolute values only, else the spec fallback; Known Folders on Windows): free functions `home`, `{config,data,state,cache}_home`, `runtime_dir`, `{data,config}_dirs`; `Paths::resolve()?` (fails without a home) gives the `rikka/` folders `{config,data,state,cache}_dir()` and `runtime_dir() -> Option`, plus theme and system config search paths; `UserDirs` (including `wallpapers()`); `passwd`.
- Every crate at any layer uses `rikka-dirs`; files under `rikka/<name>` are `Paths::resolve()?.<kind>_dir().join("<name>")`. Readers never create dirs; writers `ensure` their own target only.
- `rikka-shipped`: `Shipped { variable, installed }` finds a file Rikka installs beside its programs: the env override, then `<installed>` under the install root of the running executable and of the shared object holding the code (dladdr / GetModuleHandleEx, so librikka finds its own tree). The install root is the program's parent folder on Linux (`<prefix>/bin/..`) and the program's own folder on Windows (flat layout). Nothing is baked in at compile time; grammars, Linux icon fonts and Gecko use it.
- `rikka-fs` (rustix only) is the one atomic file replacement: `rikka_fs::replace(path, bytes)` (unique staging file beside the target, writes through symlinks, fsyncs file and folder, makes parents; keeps an existing file's mode, new files 0644), `Replace::new(path).default_mode(m)` for new files only, `.private()` always 0600 (anything holding secrets), `.stage()` → `Staged: io::Write + AsFd` with `path()` for writers that take a path (`.keep_extension()` when the writer picks a container by file name), `commit()` or `commit_unused(candidates)` (first name not taken, never overwrites); removed on drop. `rename_new(from, to)` is the no-replace rename, `set_modified(path, time)` sets an mtime and `resolve_symlinks` follows links.
- `rikka-watch` is the only file watcher, over inotify (ReadDirectoryChangesW on Windows): `Watches` (no thread; `watch(path, Reach)`, `unwatch`, `read() -> Vec<Event>`, `AsFd`/`AsHandle` for callers with their own poll loop) and `Watcher::spawn(sink)` (one `rikka-watch` worker calling `sink(Event)`).
- `Reach::{Uses (open/close of one node), Entries (names only), Contents (names and writes), Tree (Contents, recursively; new and moved-in folders are watched and their contents reported as `Created`)}`; `Event::{Changed(Change { path, kind }), Lost}` with `ChangeKind::{Created, Removed, Modified, Written, Metadata, Opened, Closed}` (renames are a `Removed` and a `Created`); `Lost` means rescan. Debouncing stays with each caller.
- `rikka-deflate` (internal) is the in-house DEFLATE: `Inflater::{inflate, zlib, gzip}(data, &mut out, limit)` append at most `limit` bytes and verify trailers, `Deflater::new(Level::{Fast, Balanced, Best}).{deflate, zlib, gzip}(data, &mut out)` compress one buffer (hash chains, lazy matching, per-block stored/fixed/dynamic choice), plus `adler32`, `crc32` and the incremental `Crc32`. Both work on whole buffers; there is no streaming interface.
- `rikka-encoding` is the only user of `chardetng`/`encoding_rs`: `decode(bytes) -> Decoded { text, encoding, bom }` (BOM, then UTF-8, then a guess), `Decoder::new().declared(..).top_level_domain(..).truncated(..)`, `guess(samples, tld)`, and re-exports `Encoding`, `UTF_8`, `UTF_16LE`, `UTF_16BE`, `WINDOWS_1252`, `SHIFT_JIS`.
