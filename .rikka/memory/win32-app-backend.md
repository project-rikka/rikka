- `lib.rs` picks the backend once (`use wayland as backend` / `use win32 as backend`); shared code (`app.rs`, `launch.rs` `Launch`, `window/`, `sender.rs`, `tasks.rs`, `instance.rs`) calls `backend::run(Launch)`. Wayland-only pieces (activation tokens `wayland/token.rs`, seam settings `wayland/settings.rs`, `LoopEvent::{Theme,Language,Drag,Presented}`) are `#[cfg(unix)]`.
- Start (`win32/mod.rs`): per-monitor-v2 DPI (manifest may already set it), AppUserModelID `Rikka.<app name>` (`process::app_model_id`), `OleInitialize`, window class `RikkaWindow` (no class icon), compositor `Clock`, `rikka_clipboard::Clipboard::connect()` as the session clipboard.
- Loop (`looping.rs`): the `Runner` sits in `Rc<RefCell>`; each pass runs `turn()`, then deferred modal calls (`ModalCall`: system move/size via `WM_SYSCOMMAND`, window menu) and `DoDragDrop` with the runner unborrowed, then `MsgWaitForMultipleObjectsEx` on the wake event and clock tick, then pumps messages.
- Window procedures never touch the runner directly: they translate messages into `heard::Heard` events (thread-local queue) and answer synchronous messages from `window::shared::Shared` (frame flags, pointer, caret, input translators). Only `WM_NCHITTEST` (`Ui::window_part_at`), modal timer/`WM_SIZE` during sizing, OLE drop-target callbacks and `IDropSource::QueryContinueDrag` borrow the runner, through `active::with_runner` (`try_borrow_mut`).
- Custom frame (client-side caption): `WM_NCCALCSIZE` keeps invisible left/right/bottom resize borders and removes the caption, maximized insets all sides and leaves a reveal strip for an auto-hide taskbar; `WM_NCHITTEST` maps `rikka_ui::WindowPart` (Caption, Minimize, Maximize, Close, Resize) to HT codes so Windows 11 snap layouts appear; NC mouse messages over caption buttons are fed back to the UI as pointer events. Server decorations keep the standard frame.
- DWM (`window/dwm.rs`): dark mode from the window's theme, round corners and the palette outline as border; no frame extension, so DWM draws no caption buttons. Windows are opaque without `WS_EX_NOREDIRECTIONBITMAP`; a `transparent` window request is logged and drawn opaque.
- Presenting: one `rikka_swapchain::Presenter` per window (created after the first measure); frames are answered on compositor clock ticks (`DCompositionWaitForCompositorClock` loaded dynamically, else `DwmFlush`), armed only while some window awaits a frame; `take_presented` feeds `Hosted::presented`. Windows show after their first presented frame (maximized ones at once).
- Input: keys from `rikka_input::win32` tables plus the queued `WM_CHAR`s for `Key::Char` (AltGr's fake Ctrl swallowed), stray `WM_CHAR`/IME results become `Commit`, IMM32 composition gives `Preedit` and the candidate window follows `ui.caret()`; wheels via `rikka_input::win32::wheel_offset`, touchpad (`IMDT_TOUCHPAD`) wheels are `Continuous` with a synthesized `Ended`; pen/touch via `WM_POINTER*`; pointer lock = raw input + 1-px `ClipCursor`; `ui.grabs_keys()` installs a `WH_KEYBOARD_LL` hook that delivers Win/Alt+Tab/Alt+Esc/Ctrl+Esc to the focused window.
- Drag and drop (`drag/`): every window registers an `IDropTarget`; outgoing drags are an own `IDataObject` (text, `CF_HDROP`, MIME-named formats, a "Rikka Drag Owner" pid marker) with a click-through layered ghost window (offscreen render, `read_pixels`, `UpdateLayeredWindow` premultiplied BGRA); in-process drops read the carried `Offer`, foreign drops are read into memory at drop time. Tab tear-off moves the origin window under the cursor or places a withheld new window at the drop point.
- Appearance messages (`rikka_appearance::is_appearance_change`) re-read `Appearance::current()`.
