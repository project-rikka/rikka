title: ADE conversations
description: ADE's use of desktop accounts, per-thread model selection, storage folders, jobs, notices, compaction and attachments.

- Accounts and sign-in belong to `rikka_llm_accounts::Llm`; ADE's settings screen opens on the shared `rikka_llm_settings` page (`Section::Llm`), the same one the Settings app shows. `ade_config::Config` (`rikka.ade`) keeps only recent projects. `src/setup.rs` holds `Setup { llm, config }`. Web search and fetch are the provider's hosted tools (server-tools note), offered on models that host them; there is no setting.
- ADE follows `Llm::changes()`, so Settings sign-ins arrive live.
- The model picker hides models without tools; the person's OpenAI-compatible endpoints appear in it like any other account, headed by their names. One control (`rikka_chat` `models.rs`: `Models`, `Picking`, wired in ADE's `project/chat.rs`) picks model and reasoning from the shared `Offering`.
- Storage: `$XDG_DATA_HOME/rikka-ade/projects/<leaf>-<digest>/<id>/` via `thread::Store`. `project/threads.rs` holds bodies only for the open and running threads.
- Each thread persists a `Selection` resolved against current credentials through `Summary::selection_in`; `Llm::selection` seeds new threads.
- Runs use `Ttl::Long` (every cache mark held 1 h) with the thread as cache key (plus job id for subagents); on Anthropic backends that key also names the server message thread, so later turns send only new messages. Compaction is `rikka-agent`'s with `keep(0)` and ADE's `compact` prompt (folded framing, focus/resume text and the revising heading are the shared defaults). The skill tool survives folds.
- Tool declarations are fixed for a thread: anything that changes (skills, agent models in `environment.md`, deferred tools, memory) lives in standing blocks and reaches a running thread as an appended revision.
- The context gauge compares the newest usage with model capacity and turns red once `rikka_thread::is_near_context_limit`.
- `/compact [focus]` is a built-in (`project::command::Builtin`, shadowing custom commands of that name) running `Desk::compact`. Enter or a click on a built-in offer runs it at once; Tab only completes it, leaving room for a focus. A summary turn is a toggle opening its stored text (`Transcript::toggle_summary`); a fold in progress shows the folding part in the live tail.
- Custom commands (`.rikka/commands/*.md`, `ade-command`) never rewrite the draft: `Project::expanding` turns typed `/name args` once per send or resend into an `Ask` expanded to the filled template, so the transcript shows `/name args`; mentions read the expanded text.
- A job reporting after the model stopped becomes a `Notice` turn and starts a new run, so the person can type while jobs run. This holds after the person pressed stop too: `Runner::stop` stops only the main run and `Notices::hold`s what was already posted, so only later reports wake it (`is_woken` = not answering and `is_waking`).
- The `Agent` tool with `job` posts into a running agent's mailbox or resumes an ended one (reported, failed, stopped by the person, or closed with the app). The person's stops go through `Jobs::interrupt` and reach the model as a held notice that starts no run; the model's own `Jobs` stop stays silent.
- `Runner::is_occupied` (`Desk::is_occupied`: answering, a job still holds a pledge, or a waking notice is unread) keeps the runner's assistant from being replaced, so a background job ending on an unopened thread can still wake it. Held notices do not occupy; `attach_runner` re-equips the existing runner (`Desk::equip` carries held notices). `is_busy` (answering, waking notices, running agents) only gates amending. Deleting a thread (`Runner::halt`) also stops its agents.
- Subagents persist per thread through `Assistant::keep_agents_in(store.crew(id))` (beside `keep_files_in`, in `attach_runner` and when the store arrives), so they resume across assistant rebuilds and restarts.
- While an agent chip is watched, the composer's stop button, its running state and the context gauge (`Subagent::model`, `Runner::shown_filled`) belong to that agent; a question form's stop still stops the main run.
- MCP prompts (`/<server>:<prompt>`), their argument completions and `@<server>:<uri>` resources come from the project's `Hub` (`state/offers.rs`); `send` and `amended` run `rikka_chat::gather` first when `needs_mcp`, then read the remaining path mentions and catalogs off-thread. A failed prompt keeps the draft (or redrafts a resend). The deferred `McpResources` tool sits in every toolbox, subagents included.
- Sending while the agent runs interjects (`state/waiting.rs`): the runner mirrors `Desk::queued()` for the composer; stop or a failed run puts undelivered messages back into the draft, a run that ends with some unheard starts a new run with them. Built-in commands are refused while running.
- Editing a sent message (`state/amending.rs`) is allowed only when the runner is not busy, not asking, not sending and no agent is watched; it rewinds the thread at once, then off-thread restores files through the thread's `History` (when chosen) and re-reads `@` mentions, and converses in that thread if it is still open (otherwise, or on failure, the text goes to that thread's draft). `start_in(thread, setup, begin)` starts a run on any thread's desk (woken notices, unheard follow-ups). Prompt `prompts/interjected.md` leads mid-run messages.
- Attachments: bytes are sniffed (pictures measured, PDFs and UTF-8 files become documents, other binaries refused). Pasted images beat HTML. File URI lists attach, other URI lists paste as text. Drops on the composer follow the same rules through a `drop_zone`; plain text drops go to the editor.
- Agents run with full access: there are no approval prompts or settings, and `McpServers` changes are kept without asking.
