---
title: Daemon integration layer
description: One public crate per system daemon over the rikka-bus runtime (Handler, Service, Monitor, Signals); no aggregate.
about: crates/daemons
tags: [daemons, architecture]
---

- `rikka-rtkit` (public, no rikka-bus) promotes the calling thread: `make_thread_realtime(priority, budget)` and `make_thread_high_priority(nice)` try the syscall first and RealtimeKit second, returning a `Grant { level, grantor }`; `drop_sys_nice()` removes CAP_SYS_NICE from the calling thread. The KMS commit thread, the hifi ALSA writer and the compositor's frame loop use it.
- Crates: `rikka-sound` (PipeWire), `rikka-network` (NetworkManager), `rikka-bluetooth` (BlueZ), `rikka-power` (logind), `rikka-battery` (UPower), `rikka-timedate`, `rikka-polkit`, `rikka-notifications`, `rikka-tray`, `rikka-mpris`, `rikka-privacy`, `rikka-power-profiles`, `rikka-location`, `rikka-accounts` (AccountsService, async, see the Settings Users note), `rikka-boost` (client of the GPU boost service), `rikka-keyring` + `rikka-keyring-vault`. All but the vault are public; apps and system binaries depend on the ones they use.
- `rikka-bus` holds the runtime plus the proxies two crates share: `login` (logind Manager/Session, `current_session`, `session_proxy`) for power and polkit, `polkit` (`Authority` proxy, `Subject::{session, bus_name}`) for the polkit agent and rikka-nixctl, and the `Daemon` names used in `Fault`.
- A crate implements `Handler` on a private session type (`Config, Request, Notice, Event: Clone, State`, `THREAD_NAME`, `UNAVAILABLE`, `open`, `handle_request`, `handle_notice`, optional `replaces` to collapse bursts). Requests that never occur use `std::convert::Infallible`.
- `Service::start(config, events, unavailable)` returns at once: `H::open` (bus connection and first read) runs on the `rikka_worker::Worker` thread and a failed open goes to the `unavailable` callback. It owns the job channel, stop-on-drop and `Notifier<H>`. Events go out through `EventSink::emit`. Sound (PipeWire) and privacy still open synchronously inside their own `Backend::start`.
- `Monitor<B: Backend>` is the one facade per daemon: `start`, `start_with(|events, unavailable| …)` for a non-default config, `state`, `read`, `changes`, `events()` (every event from subscription on; read state first, use it for what is not state: answers, prompts, revealed secrets), `unavailable()`/`unavailable_changes()`, `edit`, `request`, `backend()`. `Apply` folds events into state (blanket replace-if-changed for `PartialEq` values). There are no separate callback services: `Network::send`, `Bluetooth::answering()`/`send`/`answer`, `Sound::send`/`peaks` cover what Settings needs.
- `Signals::new().rule(Rule::new().sender(..).interface(..).path(..)/.path_namespace(..).member(..).arg(..)/.arg0_namespace(..))` watches on the handler's own connection as a task of that connection's executor (no extra thread or connection) and returns a `Watch` the handler keeps; dropping it ends the watch. `listen(conn, parse, deliver)` coalesces through `Coalesce` (400 ms after a burst stops, at most 2 s; `debounce(quiet, max_delay)`), `each(conn, parse, deliver)` delivers every signal, and `hear(conn, parse, deliver)` delivers `Heard::Signal(T)` plus one `Heard::Closed` when the connection ends (not when the `Watch` is dropped); `rikka-nix`'s `Monitor` and rebuild follower use it. `deliver` must not block or call the bus: it forwards to the handler's worker (`Notifier::notify`), where blocking calls belong. The logind lock watcher (`LoginSession`, a `Service` whose requests are LockedHint writes), the sleep watcher (`SleepWatch`, a `Service` holding the delay inhibitor) and the polkit agent (owner changes wake its worker) all work that way; none owns a dedicated thread.
- `rikka_bus::Properties` is the one reader of a D-Bus property map (`Properties::read` = `GetAll`, `From<HashMap<String, OwnedValue>>`). Every accessor returns `Option` (`string_ref`, `string`, `strings`, `boolean`, `int64`, `uint32`, `uint64`, `double`, `object_path`, `object_paths`, `list<T>`, `maps`, `value<T>`), so absence is decided at the call (`unwrap_or(..)` with the daemon's documented default). Nested variants are unwrapped, integers widen, `"/"` reads as no object path.
- `ManagedObjects` is an incremental `GetManagedObjects` cache, path-ordered so snapshots compare stably (`get(path, interface)`, `implementing(interface)`). `ManagedObjects::watch(conn, service, root, deliver)` subscribes to `InterfacesAdded`/`InterfacesRemoved`, `PropertiesChanged` under the root and the service's `NameOwnerChanged`, coalescing them into `ObjectChanges` (50 ms after a burst, at most 250 ms: applying deltas is cheap); subscribe first, then `read`, then `follow(conn, changes) -> bool` (whether anything moved). Every entry remembers the receive position (`Message::recv_position`) of the reply that filled it, so signals older than the read are skipped; invalidated properties are re-read with `GetAll`; a vanished owner empties the tree and a new owner rereads it. NetworkManager and BlueZ rebuild their snapshot from it; NetworkManager additionally keeps parsed saved connections by path and rereads one only on its `Settings.Connection.Updated` signal.
- `rikka_dirs::passwd` is the one passwd reader (zbus-free, so Task Manager, rikka-remote and `rikka_nix::login` use it too): `current()`, `current_uid()`, `lookup(uid)`, `Entry { name, gecos, home }` with `full_name()`/`display_name()`/`initial()`.
- Blocking-only `#[zbus::proxy]` traits set `gen_async = false`, so their type is `XProxy`; `XProxyBlocking` exists only where both flavours are used (NetworkManager's Manager, SettingsStore and SavedConnection, polkit's Authority).
- zbus (async-io backend) runs connects and socket closes on the `blocking` pool, so `third_party/rust/crates.MODULE.bazel` pins `blocking` to `=1.6.2`: 1.7.0 never retires idle pool threads, leaving a `blocking-N` thread waking every 500 ms in every D-Bus process.
- `Fault::from_zbus(Daemon, &zbus::Error)` classifies a bus error. A crate with its own error enum (`Bus(#[from] Fault)` plus its variants) writes `rikka_bus::daemon_error!(Error, Daemon::X)` or `daemon_error!(Error, Daemon::X, names = named)` for a daemon-specific error-name table; the macro implements `DaemonError` and `From` for `zbus::Error`, `zbus::fdo::Error` and `zvariant::Error`.
- A refused request is one shape and one rule everywhere: `State.error: Option<rikka_bus::Refused<A>>` (`action`, `reason`, `Display` = reason), and every such `State` implements `rikka_bus::Refusing` (`refused()` names the slot). Facades send operations with `Monitor::attempt(request)`, which withdraws the shown refusal before sending; every operation answers with the crate's `Answered { action, error: Option<String> }` event, which `Apply` folds through `Refusing::answer` (a failure records its refusal, a success clears only a refusal of the same action). `A` is `rikka_network::Action`, `rikka_bluetooth::Action`, `rikka_power::Operation` (`Ask(Action)`, `Brighten`), `rikka_power_profiles::Profile`, `rikka_timedate::Action`, `rikka_battery::Action`.
- The shell's `Daemons` (`system/rikka-shell/crates/shell-feeds/src/daemons.rs`) bundles `sound, network, bluetooth, power, battery`. Polkit, notifications and tray are hosted singletons the shell starts.
- A missing daemon means empty state, logged once at debug, and `unavailable()` set. Writes are optimistic. Daemon state is never mirrored into settings files.
- Bus tests use `rikka-test-bus` (`PrivateBus::start()` sets a private session bus; `stand_in_for_system_bus()` also points system-bus clients at it) and run on the remote executors. `rikka-test-objects` (testonly, `crates/daemons`) is a scriptable fake ObjectManager service on it: `FakeService::serve(name, root)`, `add`/`remove`/`set`/`invalidate` (each emits the matching signal), `set_before_next_read`, `answer(path, interface, member, body)` for other methods, `signal`, `leave`. rikka-bus and rikka-network test their object following against it.
- Facades have no test-double constructors; tests that need a bus use `rikka-test-bus`.
- `rikka-ime` (fcitx5: kimpanel host, controller proxy, process start) is a daemons crate too; it uses `Signals::each` directly on its own connections rather than a `Handler`.
