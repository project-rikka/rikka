title: Proton application
description: apps/system/proton is one window over a Proton account: Mail, Drive, Pass, Codes and Account over private crates and cache.
about: apps/system/proton
tags: [proton, application]
---

- A left rail turns between Mail, Drive, Pass, Codes and Account over one sign-in.
- Private crates: `proton-{config,session,mailbox,files,vaults,codes}`, each over the product crates it names (`rikka-proton-mail`, `-drive`, `-pass`, `-authenticator`, `-api`, `-cache`, …); only `proton-session` and `src/` use `rikka-proton-client`. `src/` draws. One account; it does not use the client's `Accounts`.
- `src/clients.rs` is the app's own wiring: `Clients::new(session)` builds `MailClient` (with a `ContactsClient` that carries `KeyTransparency::for_account`), `DriveClient`, `PassClient` and `AuthenticatorClient` (the last two as `Result<_, Failure>`); `renewed(session)` re-keys them with `with_keys`; `event_loop()` registers mail and pass as feeds into `Update::{Mail, Pass}`. `Workspace` holds `Clients` and hands clones to Mail, Drive, Pass and Codes (Account keeps the `Session`).
- `Desk` starts one `EventLoop` per workspace (keyed `desk.events`): `Change::Product(Update::Mail)` → `Mail::apply_event` (`Mailbox::apply_event` takes folder counts from the event and asks for a folder reload only when labels changed), `Update::Pass` → `Pass::apply_events` (touched shares re-sync), `Renewed(renewal)` → `access.adopt(renewal)` (persists only, no second fetch), `SignedOut` → forget and sign-in.
- `proton-session`: `AccountStore` takes its root key from the keyring (schema `os.rikka.Proton`, attribute `store` = the store folder; generated on first open) and keeps the sealed session (`session.sealed`, `rikka_proton_client::SealedSessionStore`) and the sealed `SavedAccount` (`account.sealed`, username + passphrase under `stay-signed-in`) under `<state>/proton` at 0600, written through `rikka_proton_api::private_file`. No key file reaches the disk. The app version is `cli-pass@2.4.1`. `Access` signs in, resumes, unlocks and signs out, handing back a `rikka_proton_client::Session`. `Failure` (from any error) and `ErrorBanner` (a dismissible last failure, `capture`/`set`/`clear`) carry every failure; `pane::error_banner(&x.error, |x: &mut X| &mut x.error)` draws the banner.
- The account `Profile` lives only in the library cache (`account.profile`); keeping the passphrase flushes the cache so a kept start finds it.
- `resume()` answers `Cached` (opened from the cached profile, no network), `SignedIn`, `Locked(user)` or `SignedOut`. After `Cached`, `Desk` runs `access.renew(&session)` → `Renewed::{Current, ProfileChanged, KeysChanged, SignedOut}`: ProfileChanged re-keys the workspace's `Clients` (`Workspace::describe`), KeysChanged rebuilds the workspace keeping the product, SignedOut returns to sign-in. SSO is refused.
- Startup: `Desk::new` touches no disk beyond config; `start` opens the store in `spawn_blocking`, then warms the API and resumes concurrently. Store writes run through `offload`.
- The app's cache is the library's `rikka_proton_cache::Cache` opened by `AccountStore` at `<state>/proton/cache` under the machine key; `Access` builds every session with `store.cache()`, so product caches work too. `AccountStore::forget` runs under `WriteGate::invalidate()` (generation bump + wipe), writes holding an older `WriteTicket` are dropped, and each Workspace gets `cache.fresh()`, so late writes after sign-out never resurrect data.
- Mail and Pass show what was cached from the library's own product caches (no `app.` copies). Drive and Codes keep `app.` tables (`app.drive.root`/`entries`, `app.codes.pending`) written through `Slot`s: `stage(value)` on the UI thread, `write()` in `spawn_blocking`; the newest staged write wins.
- Mail readings live only in memory: `proton_mailbox::ThreadCache` keeps the latest 48 `Arc<OpenedThread>`s (messages carry `MessageAttachment`s and a `Verification`), runs each fetch as a detached tokio task shared by its askers (abandoned askers never stall it), and drops entries that events report changed (`apply_event`; flag-only updates keep them; the row is the truth for unread/starred/labels). `prefetch_candidates`/`prefetch` read the selection's neighbours and the top 10 rows two at a time, stopping on the first failure. `Mailbox` remembers each folder's last plain listing for instant folder switching. Mail loads in `spawn_blocking` from `cached_folders`/`cached_page` (library `cached()` of the same query), applied only until the folder's listing lands. Mail operations are imperative free functions (`mark_read`, `set_label`, `move_rows`, `trash`, `delete`, `save_draft`, `send`, `discard_draft`). App models carry `jiff::Timestamp`s; `src/` calls library methods directly where an op would only forward (Drive create/trash/delete, Pass mark-used).
- `proton-mailbox` turns mixed message and conversation row ids into one `Selection` that issues both rikka-proton-mail batches, and reads MIME bodies with the library's `MimeMessage`: HTML becomes `Body::Markdown(Markdown::from_html)` (rikka-html `to_markdown` source for the view plus `to_text` plain text), else `Body::Plain(Plain)` with its http/https/mailto ranges found up front. `Body::text()` is the plain text (links kept as `text <url>`) that replies, forwards and draft edits use.
- Every link in a message goes through `Mail::follow` → `proton_mailbox::Link::parse`: http/https open with `rikka_open::open`, mailto (RFC 6068 fields) opens the in-app composer, anything else shows the error banner.
- `proton-vaults`: `SortKey`, `Strength::estimate` (composition only), `HistoryEntry`/`Change` history, `IdentitySection`/`IdentityField` field naming, `ItemScope` (all or trash), the password generator. `Entry` carries no password. Operations are `create_item`, `update_item`, `trash_items`, `restore_items`, `delete_items`, `create_vault`, `rename_vault`, `delete_vault`, `create_alias`.
- `Vaults` holds every listed item's decrypted `OpenedItem` in memory only (`DecryptedItem` = entry + opened), so `Pass::open` shows an item without a fetch; it falls back to `open_item()` only for items not yet synced. `sync_items(client, share)` is the library's `sync_items` (cached revisions + share events, whole listing on failure); `load_cached(client)` opens `cached_shares`/`cached_items` offline.
- Pass `recall`s on first `opened()`, then `refresh` starts item syncs for known vaults alongside the vault call and syncs new vaults when it lands.
- `proton-files`: Drive `Tree`, transfers and `Thumbs` (in-memory only; thumbnails come through `DriveClient::thumbnails`, which keeps them sealed in the library cache; `Thumbs::request` hands out `ThumbRequest`s). `mount` opens the root from the cached `app.drive.root` (`CachedRoot`: volume, share, root) in one round trip (`open_root`), else walks volumes; `listing` streams `Listed` pages and writes `app.drive.entries` when whole. `DriveCache` owns Drive's cache records: one `Slot` per name, staged in order and written in blocking work, so the newest write wins.
- `Tree` keeps the crumb path plus the 16 most recently listed folders (entries, `Folder`s, `File`s; `folder_cache.rs`), and a finished listing drops ids it no longer has: entering or going back shows the folder cache or the disk record at once, then `read()` refreshes. Pages show progressively only into an empty view; otherwise the list swaps when the listing finishes.
- `preview(path)` makes upload thumbnails via `rikka_media::still`. `save_download` keeps downloads inside the downloads folder.
- `view` opens files in a 0700 directory under `$XDG_RUNTIME_DIR/rikka-proton/viewing` and launches `rikka-viewer`. `clear_viewing_dir()` runs on start and sign-out.
- `Desk` is `#[derive(State)]` holding `#[state] workspace: Option<Workspace>`; `Workspace` (`src/workspace.rs`) holds the `Session` and each product as a `#[state]` field, so handlers take `&mut Mail`, `&mut Drive` and so on. Sign-out is `workspace = None`.
- Products start tasks through `workspace::ProductState` (`self.spawn`, `spawn_keyed`, `spawn_blocking`, `stream`, `after_keyed`, `every_keyed`): results land on `&mut Desk` and reach the product only while the workspace with the same `WorkspaceId` exists, so late answers after sign-out (or into a newer sign-in) are dropped.
- Lists are `lazy_column` with `.place()`. Long work uses `self.spawn_keyed` (the `ProductState` form). Stores hand `Arc<Vec<_>>` snapshots. Selection is held by id (`RowId`, `LinkId`, `(ShareId, ItemId)`).
- Pass and Codes tickers start in `opened()` and stop in `rest()`.
- Drive reuses the Files look: `layout.rs`, `cell.rs` (`fitted_line`, `column_header`; fitted text is cached in the cell state), `menu.rs` anchored to `MARK`, `backdrop.rs`, `sheet.rs` on `STAGE`. Thumbnails are requested only from `showing(range)`, newest first, in waves of 30 (two slots, keyed per folder and cancelled when the shown folder changes; queued asks outside the shown entries are dropped). The listing runs as `Part::stream_keyed("drive.children", …)`.
- Pass follows the official mobile layout: `list.rs`, `rows.rs`, `detail.rs`, `history.rs`, one `Option<Popup>`, and `pass/marks.rs` (30 icons, 10 shades); `pass/ops.rs` holds the network and cache operations, `pass/mod.rs` the view state. No security centre or kind filters.
- Menus give each `menu_item(..).on_press(..)` its own handler; no index-to-action tables.
- Forms stack labels with `pane::input`, `pane::prose`/`pane::code`. rikka-widgets' `field()` suits switches only. Use `combo` for choices; a bare `dropdown` opens nothing by itself.
- Codes form = `proton_codes::Setup`. Migration links import whole. `app.codes.pending` holds only codes not yet synced (`Pending`/`PendingDelete`); synced codes are recalled offline through `proton_codes::recall` (the authenticator's sealed cache) and `CodeStore::recall(synced, pending)` lays the pending ones over them. `StoredCode` holds a parsed `Otp` (`code_at(now)` does not parse).
- Settings `rikka.proton`: `conversations`, `drive-tiles`, `stay-signed-in`.
