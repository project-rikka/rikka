- Binaries: `rikka-files`, per-request `rikka-file-dialog`, UI-less `rikka-open` (its own package `files-opener` over `files-{core,open,vfs}` and `rikka-mime`, no UI crates), and `rikka-video-thumbnailer` (`files-video-thumbnailer`: `-s SIZE -- IN OUT`, a freedesktop thumbnailer over `video::poster`, also installed as `share/thumbnailers/rikka-video.thumbnailer`).
- `files-thumbs` decodes pictures in process; SVGs (`svg+xml`, `svg+xml-compressed`) are rasterized into the shared freedesktop cache always in the light scheme (`STORED_SCHEME`), and `Thumbnail::shown()` names the `.svg`/`.svgz` document itself so tiles and drag pictures draw it through the UI image cache in the window's scheme; conversions render SVGs in `Tuning::scheme`, which the window passes as the scheme it shows; videos go to the bundled thumbnailer (beside the running binary, else on PATH) and other types to `.thumbnailer` entries from data dirs. Helpers run in their own process group, killed with it after 30 s (pidfd poll), and write a dot-named staging PNG that `Generation::store` refits under the same pixel budget as pictures and stamps with `Thumb::*` fields. Cache paths, `Thumb::*` fields and the private-PNG store are the public `rikka-thumbnails` crate (`Cache`, `Size`), which the shell's wallpaper thumbnails share.
- Private crates (none draw): `files-{core,vfs,archive,find,open,places,thumbs,drives,portal,ipc,dialog,convert,undo,wallpaper}`. MIME typing is the public `rikka-mime` (`MimeType`, `Database`); local copy/move/trash/delete is the public `rikka-file-operations` (file-operations note), whose `EntryKind` and `Link` `files_core::Entry` uses.
- Set as wallpaper (`window/wallpaper.rs`, one local picture or movie by `rikka-media-format` kind): `files_wallpaper::Library::holding` reuses a library file with identical contents (or the file itself), otherwise the engine copies it into `Pictures/Wallpaper` with a standing `Keep` (keep-both names, no undo step), then `files_wallpaper::show(id)` writes `rikka.appearance/wallpaper`. The source is never moved.
- `files-convert` is quick conversion: `offers(names + mimes)` returns the `Target`s of a selection that is all one kind (picture, sound, movie, model), minus what every source already is, and nothing otherwise; `convert(Request { sources, target, tuning, suffix })` is a `TaskKind::Convert` operation. Each output is drafted as a dot-file beside its source and lands under a free name through `rikka_fs::rename_new` (never overwriting); the caller's localized suffix names outputs that keep the source extension. Pictures run on up to 4 workers; models with resources land as a folder. Metadata stripping edits JPEG/PNG/WebP containers losslessly, keeping ICC and a minimal Exif orientation.
- The context menu's Convert submenu (`window/items.rs::conversion_rows`) converts in one click with `Tuning::suited`; its More options… opens `Dialog::Convert` (`window/conversions.rs`) for format, quality and size.
- `files_vfs::Backend` (a `rikka_file_operations::Store` over `Location` plus `list`, `capabilities`, `create_file`, `rename`, `watch`, `browse`) owns one URI scheme. `Vfs` is the registry and itself a `Store`, so `rikka_file_operations::run(vfs, task)` runs every copy, move, trash, delete and restore; higher layers speak `files_core::Location` URIs, never paths. `files_vfs` aliases the engine's generic types for Files (`Task`, `Operation`, `Outcome`, `Placement`, `Conflict`, `Snapshot`, `Reporter`, `Error`).
- Walking, progress, cancel, collisions, links, cross-device moves and staged writes are the engine's (file-operations note). Capabilities mark special places such as trash. Walks list with `ListOptions::walk()` (`Detail::Bare`: no MIME sniffing, no `.hidden`). The `trash:` backend answers only for paths inside a trash store.
- `Store::read_each` batches reads so one refused file never ends the batch. Archives open once per mount and password. Copies batch at most 1024 per folder before metadata is applied.
- Archives mount read-only as `archive:` places with cached indexes.
- Specs followed: shared-mime-info, thumbnails, trash, mimeapps, desktop entries, GTK bookmarks, user dirs, UDisks2, portal FileChooser, FileManager1.
- `files-portal` owns FileChooser. `rikka-open` hands a local file to the default application of its type (`files_open::Applications::open`: `rikka_xdg::Associations` asked along the type's shared-mime-info ancestry) and passes other schemes to `xdg-open`; it never runs the file. Running a program is the manager's own step: `files_open::is_program` (executable bit and an executable type, never `.desktop`) opens a confirmation, then `files_open::run`. FileManager1 (`files_ipc::Request { reveal, activation_token }`) reveals in the newest window and activates it with the caller's `startup_id` as xdg-activation token.
- All windows share one `Services` (MIME db, catalogue, thumbnail pool, drives, automount). The shared places rows are `Observed`, so mounts and pins redraw every window's sidebar. Thumbnails are kept for the union of visible rows. Arrivals are queued per window and applied in one batch against visible rows; visible-range and arrival handlers call `skip_view`. Tiles read thumbnails from the tab's shared cache in paint, so a thumbnail change is only a repaint (`tab/thumbnails.rs`).
- Directory watch changes collect per tab in `PendingChanges` and flush after a 400 ms debounce (`tab/pending_changes.rs`): listing changes relist, entry changes restat only those entries, and a relist keeps selection and focus by location. Range changes read only empty thumbnail slots; the pool's workers skip what is already made or known bad.
- `programs.rs` reads `files_open::Applications` ahead on a thread when a manager window opens and reloads it through `MimeApps::watch`.
- `WindowState` (`window/mod.rs`) owns tabs, services, dialog and clipboard, and nests `#[state]` children: `Jobs` (running operation, its `Operation::updates()` stream, progress watchers, and one `After` follow-up: `Retry` a password, write a `Journal`, or `ShowWallpaper`), `Menus` (the open menu, keyed per opening so a replaced one leaves as a ghost) and `Devices` (UDisks commands, automount; also nested in the chooser `Dialog`). Each reports back to its owner through a handler given at construction. Other concerns are `impl WindowState` files beside it (strip, search, archives, places, commands, menu items, wallpaper).
- Window shortcuts live in `window/keys.rs` (and `chooser/view.rs::bind`) as `Window` bindings over standard commands plus Files chords; the listing widget handles only Enter and Escape. Copy/cut go to the session clipboard as `x-special/gnome-copied-files`, `text/uri-list` and the cut-flag type (`window/clipboard.rs`), so they paste across windows and file managers.
- Undo/redo: `files-undo` holds the model. `Step { kind, change }` records what now stands on disk; `Change::reversal()` gives the inverse `Task`. Copies and creations go to the trash, moves and renames go back through `Task::Relocate`, trashed items are restored and restored items trashed again. `History` (one per process in `SharedServices`, shared by all windows, 100 steps) pops a step for `begin`, takes the reversal's own outcome as the opposite stack's step at `finish`, and keeps only a cancelled reversal's untouched items. `files_vfs::Outcome::placed` lists every placement as it happened (Keep-both names, merge children), so a recorded step is exact.
- App side: `window/undo.rs` (`Journal::{Record, Reverse}` carried by `Jobs` to `job_finished`; a dropped `Reversing` abandons the step back). Rename and New folder/file record synchronously in `commands.rs`. Ctrl+Z/Ctrl+Y (standard Undo/Redo commands) and "Undo …/Redo …" rows in the background and ⋯ menus; nothing runs while the window has a job.
- Menus are `window::menus::Rows` of `menu_item(..).on_press(handler)`; every press closes `Menus` before running its command.
- The listing's context menu is the selection menu when anything is chosen, else the folder menu (`window/items.rs`); both carry `creation_items` (New folder/file in the current folder), so full folders can still create.
- `files_vfs::Operation` notifies changes: `updates()` is a coalescing `Stream<Item = Snapshot>` ending after the outcome, `wait()`/`wait_until(..)` block (tests use these). The job bar is `live_progress` over `Jobs`' fill, fed by `stream_keyed` over `updates()`; counts and fractions repaint through watchers.
- `Tab` fields are private; window and chooser go through its methods (`go`, `listed`, `choose`, `show_range`, `browser()`, …).
- The listing is one `list` of self-painted items plus a details header widget. Rubber-band selection and secondary clicks go through the surface hook. Context menus anchor to `frame::MARK`.
- `files-drives`: `Drives::open(changed)` subscribes `rikka_bus::ManagedObjects::watch` on UDisks2 and keeps one `ManagedObjects` cache that a `rikka-files-drives` worker `follow`s, calling `changed` when it moved; `snapshot` and the commands read the cache (the first use, or one after a failed follow, reads `GetManagedObjects`). UDisks2 calls run in blocking tasks, falling back to read-only `rikka-mounts`/sysfs discovery. Only removable media automount, once, if `rikka.files/automount`.
- Natural sort with a byte tie-break. The view mode is inferred until chosen. Columns fit their headings until dragged.
- A tab dragged to another window keeps its state and re-watches there.
- Rows drag out as `text/uri-list` plus paths as text (copy or move). The drag picture (`browser/lifted.rs`) is the held row's thumbnail or tinted type glyph on a card, stacked with a count badge for several rows. Drops land on a hovered folder row (the browser hook) or the listing (`drop_zone(..).content_first(true)`); a move becomes a copy across devices.
- Inline rename is a real `text_field` over the `TextDocument` in `rename.rs`'s `Renaming` (stem preselected), placed as the editing cell's only child (`browser/tile.rs`), so IME, undo and clipboard come from the shared editing engine; Enter, Tab, blur and presses elsewhere in the listing commit, Escape cancels.
- In-window dialogs (`frame::sheet`) are the shared modal `sheet` with a scrim; each passes its Escape handler. The chooser helper takes the portal's `parent_window` and `modal` (`files_dialog::Ask::{parent, modal}`, parsed in `files-portal`) and opens as a modal child of the requesting window.
- Gap: multi-file extraction may rescan compressed archives.
