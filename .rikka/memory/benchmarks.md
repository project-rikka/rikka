description: Suites comparing Rikka's physics, layout, UI, text and IPC with industry engines; UI tiers, fairness rules, running.
about: benchmarks
tags: [benchmarks, build]
---

- One package per subject: `physics` (box3d, Jolt, rapier3d, Bullet), `layout` (taffy, Yoga), `ui`, `text` (HarfBuzz, FreeType, harfrust, swash, fontdue, cosmic-text, parley, skrifa, ttf-parser, ICU4X, unicode-rs), `ipc` (zbus p2p, raw Unix socket), `render` (rikka-only GPU pass timings), `modeling` (rikka-only mesh library timings plus a `--digest` result hash; see the model performance note).
- Build: every target goes through `bench_library`/`bench_binary`/`bench_test`/`bench_cc_library` (`//benchmarks:defs.bzl`): `testonly`, `manual`, LLVM, and binaries and tests link with `--allow-multiple-definition` because a crate locked in both universes at one version (e.g. `pulp` via `exr`) exports the same unmangled symbols twice. Comparators are `@bench_crates//:<name>` (`third_party/comparators/crates.MODULE.bazel`); Rikka crates and the third-party crates whose types they share stay `@crates`, so the physics bench converts glam values to rapier's own `Vector`/`Rotation` in `engines/rapier.rs`, and the ipc bench takes `zbus` (with `p2p`) from `@bench_crates`.
- Run: `bazel run --config=bench //benchmarks/<suite>:<target> [-- filter]`; `--config=bench` is `-c opt` + `x86-64-v3` + line tables for every crate, Rikka and third-party alike. `//benchmarks:parity` (test_suite) runs every suite's parity test, `//benchmarks:programs` lists every benchmark program (binaries are visible to that package only; add new ones there). C/C++ comparators are `http_archive`s in `third_party/comparators/` with a `<name>.BUILD.bazel` each.
- UI has two tiers over shared scenes in `benchmarks/ui/scene` (`ui_scene`): the js-framework-benchmark table (`Table`, its word lists and ops, seeded so every framework gets identical rows), the BUI/gpui-fast cell grid (`Grid`, `Motion::{Anim, One, Idle}`, 100/1000/3000 cells in 1000×800), the scroll ping-pong every app uses (`Bounce`), the shared sizes and colours, `FRAME_INTERVAL`, and E2E `Scenario` names (`startup`, `cells-<n>-<motion>`, `scroll`, `hover`).
- Views are written once per framework and shared by both tiers: `views/{rikka,gpui,egui,iced}`; `views/gpui` compiles twice (`ui_gpui_upstream` over `gpui-pre`, `ui_gpui_fast` over `gpui-fast`, both aliased to `gpui`). Rikka cells and rows use the animation-free `Tile`. `apps/bui` keeps its own copy of the gpui-style views because BUI is a different crate.
- `:frames` (divan over `ui_frontends` in `src/frontend`, in-process, ends at each display list: Rikka scene diff, egui shapes, iced tiny-skia layers, gpui `Window::draw` in `HeadlessAppContext` with `CosmicTextSystem`; gpui draws inside the entity update's effect flush, so `Frontend::update` must not draw again): the nine js-framework-benchmark operations, each sample on a frontend warmed by drawing 1000 rows first (`sample_size = 1`), plus per-frame grid cost; `AllocProfiler` counts allocations. BUI has no display-list boundary and is E2E only.
- `:compare` (E2E, `ui_compare` in `src/compare`) starts an isolated `rikka-compositor --headless=1920x1080 --no-shell` (60 Hz, scratch XDG dirs) and launches one real app per run (`apps/{rikka,gpui,bui,egui,iced}`; `:gpui_fast` is the gpui source again; `bui` runs as CPU raster on Wayland and, with `BUI_GPU=1`, OpenGL over XWayland). Every child is a `Supervised` process (parent-death SIGKILL, pidfd stop on drop). Apps stamp a shared-memory `Probe` (memfd from `UI_BENCH_PROBE_FD`) once per animation tick; the driver takes process CPU from the kernel's per-process CPU clock (exited threads included), main-thread CPU and wakeups from `/proc/*/task/*/schedstat`, `smaps_rollup`, NVML GPU memory and compositor + Xwayland CPU, interleaves framework order per repetition and prints Markdown (`--json` dumps raw runs).
- E2E fairness rules: animation and scrolling are driven in-app once per frame (gpui `on_next_frame` + a synthetic wheel event toward the `Bounce` offset like gpui-fast's own harness, egui `vertical_scroll_offset`, iced `scroll_to`, BUI `set_scroll_offset`, Rikka a `Ticker` widget that ticks once per `PaintCtx::now()`); hover is real virtual-pointer motion at 60 Hz. Each window is clicked first so it is active (gpui throttles inactive windows to 30 fps). gpui binds only the last `wl_seat`, which is the compositor's `rikka-agent` seat, so gpui runs get their click and hover on that seat. Startup ends when the driver sees the window: the toplevel appearing for Wayland, BUI's first `presented_frames() > 0` probe stamp for `bui-gpu` (X11 windows map before they draw).
- E2E reading notes: the client scratch cache dir lives for one `compare` invocation, so the first launch compiles pipelines cold and later launches load them warm (a single-scenario run shows ~40 MB more RSS from the driver compiler); compare runs at the CPU governor's partial-load clock, so E2E ms are ~2.4× the in-process ms. The ~104 wakeups/s every Vulkan client shows at idle come from an unnamed NVIDIA driver thread, not the app's own loop.
- `:frames` reading notes: results depend on the glibc heap left by earlier benches (a full run, every frontend in alphabetical bench order, is the comparison; Rikka's many small heap objects make it slower there than when run alone). Compare two builds by copying both `frames` binaries beside a symlink to the same `frames.runfiles` and running them alternately pinned to one core with `taskset`; `perf stat` cycles and instructions on that core are steadier than divan medians.
- `apps/bui` links `@bui//:kit` (BUI's C kit built by `third_party/comparators/bui.BUILD.bazel`, Wayland glue from `wayland.bzl` running the shell's `wayland-scanner`); the reference UI sys crate's build script is off.
- Physics: scenes are box3d's suite written once as an engine-neutral `Blueprint`; native engines implement `native/engine.h` (one `bench_engine` table each). Parity: CCD off, one sleep threshold (`Blueprint::sleep_below`), friction sqrt and restitution max everywhere, rapier `simd8`, each engine's default iterations, Bullet single-threaded.
- `benchmarks/text` is six libraries under `src/<name>/lib.rs`: `text_shaping` (corpora, engines, HarfBuzz/harfrust oracle), `text_parsers`, `text_raster` (masks, FreeType), `text_paragraphs` (cosmic-text, parley), `text_unicode` (ICU4X, unicode-rs) and `text_samples` (shared paragraph texts); each program and the `main` parity test link only the ones they use.
- Text `rasterize_prepared` groups the two rasterizers that pre-extract outlines; unicode-rs has no dictionary breaking; IPC `connect` connects to an already-running server. `render-bench` (`benches/gpu.rs`) prints per-pass GPU µs (mean, p50, max; compare p50, means carry pipeline-compile spikes) and asserts zero allocations per steady 3D frame; `three: miku styled <preset>` restyles the PMX figure with a prebuilt shader preset. `render:materials` (`benches/materials.rs`) times graph-material builds (draft, drawable, built; `--breakdown` per variant and level with time/peak-resident growth per compile, resetting VmHWM through `/proc/self/clear_refs`); samples include `closures-2`/`closures-4` (mixed OpenPBR closures).
- Every suite has a test proving engines do the same work; UI's checks the table ops against js-framework-benchmark, the grid against BUI's formula, scenario names, `Bounce`, the probe and that every in-process frontend renders both screens.
