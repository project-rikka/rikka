- `sh.rikka.client.translate` is Minecraft-free and mirrors the browser's Google adapter (`apps/system/browser/crates/browser-translators/src/google`): `GoogleTranslate` scrapes the `x-goog-api-key` from Google's translate_http script (`GoogleKeys`: 20 min lifetime, 1 min back-off, invalidated and retried once on 401/403) and POSTs `[[html…],"auto",code],"te"]` as `application/json+protobuf` to `translate-pa.googleapis.com/v1/translateHtml`; answers are `[[texts],[detected]]`. 5xx is retried once, 429 never.
- `Languages` holds Google's BCP-47 targets, the tag↔service code aliases (`zh-Hans`↔`zh-CN`, `fil`↔`tl`, `iw`→`he`…), Minecraft language code mapping (`forGame`), JDK display names with fallbacks for names the JDK lacks, and `sameLanguage` (primary subtag, script-strict for `zh`).
- `TranslationQueue` is main-thread confined: it dedups, caches 512 results, keeps urgent (`USER`) and background keys pending and, whenever one of its 4 HTTP slots is free (`flush()`, called on each request, completion and tick), packs the next batch (100 strings / 5000 chars, one target) urgent first; calls run on virtual threads and complete futures on the owner executor (`Minecraft`). A 429 fails the pending background keys and refuses new ones for a minute.
- `markup/Markup<S>` encodes styled `Segment<S>`s as `<a i=N>` runs and `<code i=N translate="no">` kept tokens (`Protection`: URLs, e-mails, @mentions, /commands, online player names), and decodes Google's HTML back to segments with the run styles, restoring kept text from the plan, re-inserting dropped keeps and removing URL fragments Google echoes after a kept token.
- `mods/translate`: `ChatListenerMixin` wraps `ChatType.Bound.decorate` to remember each player message's body (and sender), so only the body is translated; `ChatComponentMixin` swaps the `GuiMessage` right after `logChatMessage` in `addMessage` (logs stay clean) for one carrying a `[✎]` button (`ClickEvent.Custom` `rikka:translate` with an `IntTag` entry id). `ChatScreenMixin.handleComponentClicked` consumes that id locally, so it never reaches the server.
- `IncomingTranslations` keeps up to 256 `MessageEntry`s; completions only mark entries changed and the mod's tick re-renders them in one pass through `ChatLines` (`ChatComponentAccessor`: replaces in `allMessages`, refreshes once and restores the scroll): translation as an extra ` ↳ ` line inside the same message, toggled by the button; disabling the mod restores every original. `PlayerNames` builds the name `Protection` at most once per tick.
- Sending: with `outgoing` on, `ChatScreen.handleChatInput` is cancelled and `OutgoingTranslations` translates the chat text or the body of /msg /tell /w /whisper /pm /me /teammsg /tm /r /reply (`OutgoingText`); while a translation is pending, untranslated input joins the same chain, so everything is sent in input order on the same connection. Failures (or > 256 chars) are not sent and show an Edit link (`SuggestCommand`). `TranslateBar` is a vanilla widget above the chat input (toggle chip, language chip cycling `outgoing_languages`).
- Settings use `LanguageSetting` (single tag, optionally `GAME`) and `LanguageListSetting`, edited in the menu by `menu/settings/LanguageControl` (searchable popover list).
