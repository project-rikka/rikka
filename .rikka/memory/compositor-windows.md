- `windows/` is the policy over `Desktop<Record>` (`Record` = per-window `wanted` xdg configure, pacing time, `mode`, `floated` preference, foreign handle, `stretch`). `windows/mode.rs`: `Mode::{Free { restore }, Snapped(Snapped), Enlarged(Enlarged)}` is exclusive; `Free.restore` is the pre-tile shape, `Enlarged` keeps the restore shape and the `Snapped` it returns to; tiled membership is only the tiling layout; `Mode::placement(tiled)`/`states(tiled)` compute placement and xdg states. `desktop_changed()` = surface frames + `session_changed()`; `relayout(output)` = retile, reshape enlarged, refocus, X restack, pointer refocus; `work_area_changed(output)` = retile, reshape enlarged, refit snapped. Files: `arrive` (plan at InitialCommit, map, depart, cascade), `shape` (`stand`, `move_window`, `close_window`; X11 geometry only changes on `ConfigureAccepted`), `configures` (100 ms ack pacing), `arrange`+`tiling/` (per-workspace `Layout::{Dwindle(Tree), Columns(Strip)}`; `lay_out` places tiles by `Placing::{Travel, Stretch, Follow, Glide}`; enlarged windows are placed by a strip but shaped by `enlarge` under dwindle), `columns` + `strip_swipe` (scrolling commands, focus following and swipes), `enlarge`, `focus`, `stacking` (+X restack), `workspaces`, `minimize`, `displays` (`announce_outputs` snapshots the desktop's layouts before publishing, then adds, removes or shifts desktop outputs by comparing them with the published `LayoutView`; lock surfaces are reconfigured on resize), `output_anchors` (on any display change each shown free window returns to the same offset on the display it covered, kept inside the work area), `around` (`drawn_on`, fullscreen/overview `Around`), `hidden_pace` (frame-callback pace of an undrawn root), `announce` (`rikka.toplevels` in stacking order, shown first), `committed`.
- `shell/` answers `ShellHost` events: toplevel, popup, layer (`arrange_layers`, overview namespace list), lock (`Locking`; `locked` is sent once every output drew a lock surface), activation, x11 (`XwmEvent`s, serial association both ways).
- Workspace switches do not slide, and windows sent to another workspace are not put away visibly, while an overview hides the display's windows.
- Window motion: grabs in `input/grabs/` (`moving`, `resizing`, `dividing` snapped shared lines, `retiling` tile edges) are `PointerGrab<Compositor>`s that only record one `GrabRequest` in `grabs.requests`; `apply_grab_requests()` applies it once per frame in `dispatch_frames` and when a grab ends. `press.rs` starts them (Super+left move, Super+right resize, snap divider, tile edge) before the press reaches the seat; `requests.rs` serves xdg move/resize (serial via `grab_start`) and X11 `_NET_WM_MOVERESIZE` (a held button). Interactive resize uses `ask_size` + `Record::stretch` (stale buffer stretched until the anchored commit; `stretched_committed`).
- Snap (`snap/`): the pure zone templates, bar, dividers and assist card slots are `rikka-compositor-snap`; `snap/` keeps the drag state (`state.rs`), motion, colours, plus `offer.rs` (assist), `staged.rs` (preview, bar, assist panels and card flights into `Staging`); `Mode::Snapped` holds zone/area/restore; snapped floating windows get all four tiled states in `stand`.
- Animation (`animation/`): one `Animations` owns open/reshape/resize motions, exits (`exit_animated` → `desktop.exit_window` + `Scenes::freeze`, which also keeps the window's blur panes as `glass::Frost`), put-aways (minimize, send to workspace) and workspace slides; `StageContext::stage` builds a per-output `render::Staging` (moved targets, `hidden` targets carried by another display's slide, exiting/leaving snapshots, panels, lifted cards) during `Parts::compose` and records whether that output owes another frame (`frames_done` requests it). `finish_animations` removes exited windows and thaws snapshots. Motion only changes render placement (`Moved::placement`).
- `wayland/workspaces/` serves privileged `ext_workspace_manager_v1`, Full profile only: one group per display (entering the client's `wl_output`s, also when bound later via `OutputHost::output_bound`), ten workspaces named `1`–`10` with 1-D coordinates `number-1`, the shown one `active`. Only `activate` is advertised and applied on `commit` through `show_workspace_on`; deactivate, assign, remove and create are ignored. `announce_session` feeds it `displayed_workspaces()` alongside `rikka.workspaces`.
