---
title: Native Wayland application runtime
description: rikka-app runs typed windows on its own xdg-shell backend and poll loop: handoff, session capabilities, appearance.
about: crates/ui/rikka-app
tags: [app, runtime]
---

- Entry: `App::new(name).theme(..).i18n(..).instance(..).window(..).run()`. `App::draws_3d()` builds the renderer with mesh support, `App::decodes_video()` with a Vulkan Video decode queue (remote viewer, Cut), `App::plays_video(rikka_ui_video::VideoStore::default())` adds the queue and installs the host's video player for `video(controller)` views (Viewer, Discord, the SDK; other apps do not link the player), `App::computes()` with compute support (rikka-image-edit, rikka-physics-fluid) and `App::computes_in_background()` adds the async compute queue (physics bakes) (`device.rs`). Other apps get a 2D-only device without extra queues.
- Each app's `main.rs` invokes `rikka_app::mimalloc!()` (mimalloc with `no_thp` and `local_dynamic_tls`, the latter for the SDK's dlopened `librikka.so`), and `preload::fonts` warms the font catalog and default face on a thread at `App::run` so font loading overlaps Vulkan start-up.
- `Window::new(factory, view)` is typed as `Window<S: State>`. Builder methods: `.title .title_from(|s| Label) .size .maximized .min_size .resizable .transparent .parent(WindowParent) .modal(bool) .on_start(handler) .on_open(|s, LaunchRequest|) .on_focus(handler) .on_blur(handler) .on_language(handler) .on_shape(|s, WindowShape|) .on_close_request(handler) .caption(|s| Option<CaptionBar>) .theme(|s| Option<Theme>)`. `on_language` runs after the session language switched the process locale (window titles are retranslated first).
- Parents and modality: `WindowParent::Window(WindowRef)` sets `xdg_toplevel.set_parent` on a window of this process, `WindowParent::Foreign(WindowIdentifier::Wayland(handle))` imports another client's toplevel through `zxdg_importer_v2` (an `x11:` identifier is logged and ignored); `.modal(true)` adds `xdg_dialog_v1.set_modal`. All are sent before the first commit. Every window is exported through `zxdg_exporter_v2`; the handle lands on its `Ui` as `rikka_ui::window_identifier()`, which handlers read to pass a portal `parent_window` (`rikka_dialog::Chooser::parent`).
- `on_open` runs only under `Instance::single()`, with each later start's `LaunchRequest`, on the first window that has the hook; a window reads its own start arguments itself (`LaunchRequest::from_arguments(std::env::args_os())`).
- `title_from` re-runs inside the root view. `WindowShape { size, restored, maximized, fullscreen }` fires on first map and on every change; sessions save `restored` and the flags. Wayland gives no window position.
- `WindowRequest::{Fullscreen(bool), Activate(token), Raise(WindowRef)}`: `Activate` uses an xdg-activation token (handoff `LaunchRequest::token()`, notification `ActivationToken`); `Raise` raises another window of this process named by `Sender::window()`, served before a `Close` asked in the same handler.
- `Window::on_command(command, handler)` / `on_chord(key, modifiers, handler)` bind around the whole frame, caption included; prefer them for window-wide shortcuts. Unclaimed `Close` asks to close the window, `Quit` asks every window, `Fullscreen` sends `WindowRequest::ToggleFullscreen`.
- Closing: the compositor's close request and the caption close button (`WindowRequest::AskToClose`) run the `on_close_request` hook instead of closing when one is set (`window/closing.rs`); `request_window(WindowRequest::Close)` always closes.
- A window becomes an erased `Opening` in `App::window`, `Instance::windows` or `open_window`, all of which take `impl IntoWindows`.
- `CaptionBar::columns` gives title-bar pieces shares of the full window width.
- Modules: shared `window/` (builder, chrome, closing, shape, `RequestedGeometry`), `launch.rs` (`Launch` handed to `backend::run`), `sender.rs`, `tasks.rs`, `instance.rs`; the Wayland backend is all of `wayland/` (`runner.rs` the `Runner`, `looping.rs` the poll loop, `hosting.rs` `Windows<'_>`, `session.rs`, `drag/`, `window_state.rs`, `open.rs`, `settings.rs`, `token.rs`, plus the client over `rikka-wayland`). The Windows backend is `win32/` (see the win32-app-backend note); `App`, `Window`, `WindowRequest` and hooks are the same on both.
- The loop (`looping::run`) owns one `rikka_wayland_client::Queue<Runner>` (handlers registered by `wayland::dispatch::listen`), and waits in `EventFd::poll_readable` (nanosecond `ppoll`) over the display fd and the loop's eventfd (rung by `LoopProxy` messages, the embedder and the queue's waker) until the turn's deadline (wake hints, `next_wake`, drag pictures, key repeat). Each turn: dispatch, take messages, repeat keys, settle configures/scales/closes, service touched windows, `Embedder::frame`, flush, then wait and `connection.read()`.
- `Client::connect` makes `Host::read_by_owner`, so the loop is the reader and fans events out to worker queues and taps; there is no `rikka-wayland` reader thread. Activation (`wayland/activation`) and presentation feedback are taps, not threads; the drag worker and the clipboard keep their threads. The renderer is built without WSI and the drag icon is a `rikka_present::Presenter` like every window. It binds blur, solids, shortcut inhibitor, activation, drags, presentation and the clipboard. Input serials come from the app's own seat (`Seats::serials` → `Host::set_serials`).
- Input comes from `rikka_seat::Seats` (with gestures and relative motion); `Runner` is its `SeatHost` and routes each `SeatEvent` to the window owning the surface. Keyboard enter/leave per seat drive focus/blur hooks and `chrome.focused`. `PointerTravelled` reaches only a window holding a `wayland/locked` pointer lock; relative pointers exist only while one does.
- Configures: `xdg_toplevel`/decoration events accumulate in `Configuring`; `xdg_surface.configure` keeps only the newest per batch. `WindowState::configure` resolves the size (0 keeps the current one, min size and bounds applied) into `rikka_wayland::Configures`. The `seals_with` hook remembers the size a frame is drawn at; `presents_with` (just before that frame's commit) acks the newest configure of that size, sets window geometry, asks the frame callback and presentation feedback. A configure whose size is already committed is acked with a bare commit when nothing is painting (`settle_unchanged`). So no buffer is ever committed under another size's ack.
- Windows present through `rikka_present::Presenter` (`Embedder<WindowId, WindowState, Presenter>`), created at the first configure; it owns `wp_viewport` and `buffer_scale`, rikka-app sets neither. `resize(.., interactive)` follows the xdg RESIZING state and a redraw refits the buffer when it ends. Each `Toplevel` owns a `rikka_wayland::Scaling` (fractional scale only when a viewporter exists; otherwise `preferred_buffer_scale` or the entered outputs' scale). `Outputs` binds xdg-output and, when every output has the same fine scale, `expected_scale()` seeds the new toplevel's `Scaling::expect`, so its first frame is drawn at that scale.
- `wayland/outputs` tracks wl_output modes; the fastest refresh among outputs the windows are on (else any) is `RefreshRate::publish`ed.
- `LaunchRequest` carries `arguments()` verbatim and `has_flag("--x")`; `uris()`/`paths()` hold only non-option arguments.
- `Instance::single()` activates the running process. `Instance::windows(|open| ..)` turns each second start into windows. `App::windows(make)` is that plus the first windows made from this process's own arguments.
- The bus name is claimed before display, Vulkan or catalogs. Handoff goes over `org.freedesktop.Application` with xdg-activation tokens, falling back to `rikka.toplevels`.
- `rikka_instance::TAG_ENV` renames the process `<name>-<tag>` (bus name, app id) and is removed so children do not inherit it.
- `settings.rs` runs one watcher thread (`rikka_appearance::ResolvedAppearance` plus language) so default windows follow session appearance and language. Per-window themes opt out of appearance. Language cannot be opted out of.
- Tasks live and die with their window. `Sender<S>` is marked closed before teardown.
- Each turn follows `ui.grabs_keys()` per window and holds a `wayland/inhibit` inhibitor while it is true.
- One `wayland/data_device` seat per process carries drags and paints the drag icon itself. Drops from this process read the carried `Offer` directly; others read through the wire offer, which finishes when the last `DragOffer` clone drops. Tab tear-off attaches the window's own `XdgToplevel`.
- `Dragging::settle_within` runs each turn after input, so a leave and an enter in one batch do not tear anything off. Escape cancels a drag this process carries.
- `run` installs a warn-level tracing subscriber unless one already exists. Client-side decorations are the default.
- Client-side chrome reaches the window's `Decorated` state as a `Framing` update (`window::set_chrome`), so the host holds a plain `Ui`.
- Client-side decorations are asked through xdg-decoration and followed when the compositor decides otherwise (`WindowState::decorate`).
- Gap: no offscreen `App::run` for whole-app pixel tests.
