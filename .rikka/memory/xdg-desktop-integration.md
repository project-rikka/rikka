- `rikka-open`: hands files and URIs to their program (`open`), shows a file in its folder (`reveal`), finds programs on PATH, converts file URIs ↔ paths byte-exactly (`path_to_uri`/`uri_to_path`, and `encode_path`/`decode_path` for the bare percent-encoded path trash records and Files locations use). `open` prefers `rikka-open` (the Files opener binary) over `xdg-open`.
- `rikka_open::spawn_detached(&mut Command)` is the one way to start a program that outlives its caller: null stdio, own process group, one shared reaper thread, `Error::NotInstalled` when it is not installed; it returns the pid. Files' launcher and opener and the shell's `rikka.launch` use it; Proton shows decrypted files through `open`.
- `rikka-dialog`: blocking FileChooser portal call returning local paths: `Chooser::open` (OpenFile) or `Chooser::save` + `.current_name(..)`/`.current_folder(..)` (SaveFile); `.parent(window_identifier())` makes the dialog a modal child of the calling window, so build the chooser on the UI thread; `.run()` returns `ChooserResponse::{Files, Cancelled}`. Run it in `spawn_blocking`. It subscribes before requesting.
- `rikka-clipboard-core` is the Wayland-free vocabulary (`Offer`, `Selection`, `Files`, mime helpers, `Error`) and the `Session` trait (`mime_types`, `read`, `publish`, `watch`, `close`) rikka-ui talks to; `rikka-clipboard` re-exports it and implements `Session`.
- `rikka-clipboard` is a Wayland clipboard on a `rikka-worker` thread: `Clipboard::for_host(&host)` beside rikka-app (shares the app's connection, whose only reader is the app's loop) or `Clipboard::connect()` with ext-data-control for the shell (own connection via `Host::with_reader`); both sleep until their queue or mailbox wakes them. When ext-data-control is offered it is the only device the worker creates (no `wl_data_device`/primary device, so drags never hand it offers); the seat devices are the fallback. Every read, publish and listing takes a `Selection` (`Clipboard`, `Primary`). While the process's own source holds a selection, listings and reads answer from the published `Offer` without a compositor round trip, because a read blocking the connection's only reader could never be served by its own source. `share()` gives another handle on the same connection and thread; `Change::is_ours` means published by the watching handle; `close()` stops it for all handles.
- On Unix `Clipboard::publish_deferred(selection, mime_types, deliver)` publishes a source without data: every request (a compositor `send` or the process's own read) calls `deliver(mime, fd)` on the worker thread, which must not block it; rikka-nested forwards Gecko's selections this way. `withdraw(selection)` clears a selection only while this handle still owns it.
- On Windows `rikka-clipboard` has the same API without `for_host`: `Clipboard::connect()` runs a message-only owner window on its own thread with delayed rendering. MIME mapping: text types ↔ `CF_UNICODETEXT`, `text/uri-list` (file URIs) ↔ `CF_HDROP` + `Preferred DropEffect` (cut/copy, synthesizes `x-special/gnome-copied-files`), `image/png` ↔ registered `PNG` + `CF_DIBV5` (read also from `CF_DIB`), the secret hint ↔ `ExcludeClipboardContentFromMonitorProcessing`/history/cloud opt-outs, every other MIME a format registered by its name. `Primary` is process-local there. The pure `dib` and `hdrop` codecs live in rikka-clipboard-core.
- A fresh clipboard worker sends one `wl_display.sync` and holds every command (reads, listings, publishes, watches) until it is answered, so the selection current at start is known to the first read and a watcher hears only selections made after it began watching.
- `rikka_ui::clipboard` is the process clipboard every widget and the web engine use: the installed session clipboard, else an in-process `Offer` per selection that also notifies `watch`ers.
- `rikka-instance` does single-instance handoff over `org.freedesktop.Application`; a second start with arguments arrives verbatim through `ActivateAction("command-line")`.
- `rikka-xdg`: key files, desktop entries, `Exec` parsed without a shell (field codes via caller `Codes`), locale keys, the catalogue.
- `rikka_xdg::MimeApps` is the mime-apps spec, keyed by `rikka_mime::MimeType`: `session()` (or `new(config_home, data_home)` + `config_dirs`/`data_dirs`/`desktops`) gives the layered lookup including `<desktop>-mimeapps.list`; `read()` → `Associations::{default_for, handlers, is_chosen, types, application}` per exact type, and `default_for_any`/`handlers_for_any` over `Database::ancestry(type)` (Files, its opener and Settings' defaults page all ask this way) (`is_chosen` = the person's own list names a default); `set_default(id, &[MimeType])` edits `$XDG_CONFIG_HOME/mimeapps.list` losslessly (Default and Added first, out of Removed) plus any shadowing desktop-specific user list; `forget_default(types)` drops the person's defaults from both; `watch` covers every list and application dir.
- `rikka_xdg::Terminals` is the xdg-terminal-exec spec: `xdg-terminals.list` / `<desktop>-xdg-terminals.list` over config dirs then `xdg-terminal-exec/` data dirs (first word on an id wins; `-id` excludes, `+id` protects, `id:action`), else the first `TerminalEmulator` entry shown here. `preferred()` → `Terminal`, whose `launch().dir(..).app_id(..).run(argv)` honours `X-TerminalArg*` (`-e` when absent) and gives a `Command`; `prefer(id)`/`forget_choice()` edit the person's lists. `Terminal=true` entries, Super+Enter and Files' Open in Terminal all launch through it; Rikka ships `share/xdg-terminal-exec/rikka-xdg-terminals.list` naming `rikka-terminal.desktop`.
- `rikka-mime` is the one shared-mime-info resolver and type: `MimeType` (validated RFC 6838 essence, lowercased, `kind`/`subtype`, `DIRECTORY`/`SYMLINK`/`UNKNOWN`/`EMPTY`/`TEXT`) and `Database` (`load()` from the data dirs or `from_dirs`, `builtin()` for the carried table; `for_file` = unambiguous glob, else magic over the first 64 KiB, else text/binary; `for_name`, `for_content`, `resolve` aliases, `ancestry` with the implied `text/plain` and `application/octet-stream`, the latter never for `inode/*` or `x-scheme-handler/*`; `globs_for` the reverse lookup; `describe` reads the localized `mime/<type>.xml` comment for the tag given to `set_language`, cached). `matches_glob[_folding_case]` is its shell-glob matcher, also used for portal filters.
- `rikka_xdg::RecentFiles` is the freedesktop `recently-used.xbel` shared with other desktop toolkits: `used_by(&RecentApplication)` lists existing local files newest first, `add` rewrites the list atomically, keeps other programs' namespaces, metadata and elements verbatim, caps it at the 1000 newest entries and refuses to touch a malformed list; `used_by` takes a limit and stats only until it is reached.
- `Hidden=true` deletes an entry, while visibility stays inspectable. The catalogue shadows by desktop-file id across ordered data dirs.
- `Watch::applications` and `Watch::folder` coalesce changes on a `rikka-xdg-watch` worker over `rikka_watch::Watches` (a watched file's parent is watched for contents, other parents only for entries), never opens or reads, so scanning a watched tree cannot wake it. Events are filtered to paths on a root, so neighbours never fire. Staleness tracks symlink targets and watches symlink parents, because NixOS relinks profiles with fixed store timestamps.
- `rikka-thumbnails` is the freedesktop thumbnail cache (`Cache::shared()`, `path_of(uri, Size)`, `failure_path(uri, app)`, `describing` checks `Thumb::URI`/`Thumb::MTime`, `fields`, `store` writes a private PNG atomically); Files and the shell share it.
- `rikka-trash` is the freedesktop trash spec: `trash` (home trash or a volume's `.Trash/<uid>`/`.Trash-<uid>`, returning the trashed path), `entries`, `restore`, `erase`, `holds`, `is_top_level`; it reads the mount tops itself from `rikka-mounts`, and restore/erase also recognise a volume store from the item's own path. `trash` picks a volume's top by `st_dev` change, so a store on a btrfs subvolume or overlay that is not a mount point is restorable but not listed (known gap). The store is chosen by the filesystem of the item's folder (a file's own `st_dev` differs on overlayfs). `erase` refuses anything outside a store, removes the item first and its record only for a top-level item, so erasing inside a trashed folder never touches another item's record.
- `rikka-mounts` is the one `/proc/self/mountinfo` reader: `mounts()` (`Mount { at, source, filesystem, read_only, no_setuid }`, octal escapes undone, `is_storage()`), `containing(path)` and `top_directories()` (storage mount points, deepest first).
- File copy/cut on the clipboard: `Offer::files(uris, cut)` writes `text/uri-list`, `x-special/gnome-copied-files` and the cut-flag type; `rikka_ui::clipboard::{files, has_files}` read them back (`rikka_clipboard::files_in`). Files and ADE use it alongside `rikka-trash`.
- `rikka-xcursor` is the one Xcursor reader (compositor and rikka-seat): `Theme::load(name)` (or `load_from(name, search)`) walks `XCURSOR_PATH` or the default icon folders, `index.theme` `Inherits` and last the `default` theme, `Theme::find(cursor)` gives the file, `Cursor::read(path, size)`/`parse(bytes, size)` keeps the frames of the nominal size nearest the asked one (`Frame`: premultiplied BGRA bytes, hotspot, delay).
- `rikka-icons` implements freedesktop icon themes: inheritance, scalable preference, hicolor fallback, cached misses, tray private roots. Each theme lists its directories once on first lookup (`read_dir`, name → spots) and stats only candidates; `Icons::clear_cache` drops those listings too, so call it after installs.
