title: GPU picture editing (rikka-image-edit)
description: rikka-image-edit decodes, edits on Vulkan compute and encodes pictures: Picture, Recipe/Step/Mask, operations, marks.
about: crates/graphics/rikka-image-edit
tags: [graphics, imaging]
---

- A public crate; marks, `Sketch` undo and `Tool` live here.
- `Imaging` is the engine (`Clone + Send + Sync`): `Imaging::new(compute)` on the UI renderer's device, or `Imaging::headless()` (owns a renderer). Apps take the process-wide engine on the UI's device with `Imaging::shared(&compute)`, the compute coming from `rikka_picture::SharedGpu::compute(timeout)` or `SharedGpu::on_compute`; it submits on the background compute lane (a real async-compute queue only for apps built with `App::computes_in_background()`, as Paint is), so picture work need not occupy the graphics queue.
- `Picture` is GPU-resident and immutable, equal only to itself (identity): `imaging.open/picture(&Image)/blank/upload_rgba8(w, h, &[u8])`, `develop(&Recipe)`, `to_image()`/`save`, `shown()`/`shown_area()` → `ComputedFrame`, `histogram()`, `with_profile`. Uploads, `develop` and `shown` only submit; the one wait is `Work`'s held-memory budget. Per-frame planes come back from the compute pool (see renderer note), so steady video develops make no Vulkan images.
- Storage follows depth (8→Rgba8, 16→Rgba16 or Rgba32F, float→Rgba32F); intermediates are Rgba16F (8-bit) or Rgba32F. Integer depths clamp after every step. Mode Gray is stored as RGB and written back as luma.
- Pixels live in a tiled virtual image (`Plane`): square tiles of 512 px, doubled up to 4096 until a plane needs at most 256, each tile its own compute image in one contiguous slot run (`PlaneRef.across` packs the tile shift above bit 16). Edge tiles at least half full are padded to the full side so the pool can reuse them; `placed()`/`areas()` give each tile's valid rectangle. Every kernel goes through the Slang `Plane` struct of `shaders/lib/plane.slang` (`load`/`store`/`bilinear`/`bicubic` methods; each push block starts with `Head head`, the 64-byte header mirrored by Rust `PushHeader`), so pictures may exceed the device's image limit.
- Picture versions share tiles copy-on-write: `rewrite::rewritable(work, source, format, area)` makes a plane that keeps every source tile outside `area` and copies the rest, and writes after it must stay inside `area` (`Io::within` declares only those tiles). Windowed develops, `patched` and `resized_since` build their results this way, so a brush stroke allocates only the tiles it touches; `changed_area` compares only unshared tiles. Writing into a kept tile would change earlier versions (`tests/regions.rs`, `pictures.rs`, `resizing.rs` guard this).
- `Picture::show(earlier: Option<&Shown>) -> Shown` gives the display frame (`Shown::frame()`): opaque 8-bit pictures whose display conversion is the identity show their own tiles with no copy, others convert only the tiles whose source pixels changed since `earlier`. `shown()` is `show(None)`; `shown_area` always converts (`tests/showing.rs` draws both through a test renderer).
- Work is recorded through `work::Work` (`pass` for 16×16 2D kernels banded by cost, `groups` for fixed dispatches); push structs start with `head: PushHeader` (src, dst, origin, flags, mode) and are listed in `work::push_header!` to be passed. `Work` submits early once ~1 GiB of planes is allocated, so intermediates of long recipes free as the GPU finishes.
- `work::Io` declares a dispatch's tile reads and writes (`Io::new(src, dst)`, `input`, `output`, `.read`, `.read_buffer`, `.write_buffer`, `.limit_writes(area)`); shared GPU passes (premultiply/straighten, Gaussian pyramid, separable resample, `adjust`, `arith`, `composite_over`) live in `ops/passes.rs`.
- `Imaging::space(profile)` caches colour spaces (curve tables, display conversion, sRGB→profile transform) per engine; never build a `Space` per call.
- Adjustments match rikka-psd-render's math in the document's encoded space; blurs, resampling, warps, glow and lens blur run premultiplied in linear light via the profile's transfer (`Space`); USM, surface blur, median, noise stay encoded.
- `Group::new(recipe)` runs a sub-recipe on a transparent layer of the same size and composites it over (blurred shadows, isolated effects); it refuses reshaping steps.
- A new operation = a param struct implementing `ops::Effect` (`apply`, `scaled` for previews, `reshapes`) plus one line in the `operations!` list in `ops/mod.rs`; per-pixel ones add a kind to `adjust.slang`. Kernels are one `.slang` file per `Shader` (one compute entry each, constant `<STEM>_COMP`); shared code lives in `shaders/lib/` (`plane`, `color`, `floating`).
- `Step` adds a `Mask` (rectangle, ellipse, spans, coverage, `path(Path, FillRule)` rasterized by `marks::coverage` in frame px; `feathered`, `inverted`), opacity and one of 27 PS `Blend` modes; reshaping or profile-changing steps cannot be masked.
- `Recipe::scaled(f)`/`Step::scaled(f)` scale every pixel-distance parameter and mask for a frame `f` times the size; `Preview` renders a recipe on a power-of-two proxy with them and caches each step's result for the unchanged prefix.
- `Place::new(picture, matrix)` composites another picture: `matrix` (row-major, may be projective) maps placed-picture px to frame px, `scaled` pre-multiplies it by the frame scale (the placed picture shrinks too). It converts the picture into the frame's profile, resamples premultiplied in linear light (triangle prefilter below ½ size, ≤4×4 supersamples, analytic AA edge and `radius` in placed px) and blends with `opacity`/`Blend` in the frame's encoded space like layers (`place.slang`). `.replacing()` leaves only the placed picture (transparent elsewhere), so a masked/faded replacing step is a true premultiplied crossfade; `.mirrored()` reflects the picture beyond its edges.
- `Mask::luma(picture)` / `Mask::alpha(picture)` are track mattes from another picture (resampled to the canvas, always `Reach::Global`).
- Generators/distortions: `FractalNoise` (fBm Perlin; scale, detail, seed, evolution, contrast, brightness, offset, `.colored()` for independent RGB), `Displace` (map: R→x, G→y, 0.5 neutral, mirrored edges) and `LensDistortion` (barrel/pincushion about a centre) run in `fractal.slang` / `distort.slang`.
- Video ops: `ChromaKey` (Rec.709 CbCr distance, tolerance/softness/spill 0–100), `LumaKey`/`Lumas`, `Clipping` (cut edges only, `feather` inward) run in `key.slang` on encoded straight pixels and set `alpha`; `ChannelShift`, `DropShadow` (blur = Gaussian sigma like `GaussianBlur`) and `Outline` (jump-flood distance, `width` at half strength, `softness` fade), both under the picture, run in `matte.slang` premultiplied in linear light. Angles are degrees counter-clockwise from screen right.
- Colour: `Profile` (ICC via moxcms; built-ins sRGB, P3, Adobe, ProPhoto, Rec.2020, linear sRGB). Untagged means sRGB. Display converts to sRGB; `ConvertProfile` converts pixels (matrix/TRC tables, or a 33³ cube).
- `Marks` holds `Marking`s: annotation `Mark`s (pen…ellipse, `Sketch`), `BrushStroke`s (`Brush` size/hardness/opacity/flow/antialiased, `Ink::Paint` or `Ink::Erase { background }`) and `PathMark`s (a `Path` of polyline `Subpath`s from `Path::builder()` move/line/quad/cubic/close flattening, filled by `FillRule` and/or stroked by `StrokeStyle` width/`Join`/`Cap`). All rasterize in `marks.slang` from shapes binned into 16 px tiles (`marks/shapes.rs`), one owner (ink, 8 floats with a mode) per painted layer, so fills sit under outlines.
- Owner modes: solid marks take the max SDF coverage; brushes take the falloff of the distance to the smoothed path times a flow build-up from the path length within the radius (opacity caps a stroke, it never darkens itself); paths and their outlines (`marks/outline.rs` turns strokes into same-orientation polygons) accumulate exact signed area coverage from edges binned into every tile to their right.
- Erasing ink removes alpha on frames with alpha and paints its `background` on alpha-less pictures (paint-document places PSD Background layers without alpha). `marks_overlay(&Marks, View, Erasing)` draws the live overlay; `Erasing::Checkerboard(Checkerboard)` paints erased coverage in the canvas checker, `Erasing::Background` paints the background. `marks_layer(marks, live, View)` remains for `Mark` sketches.
- `Gradient` (`GradientShape` linear/reflected/radial/diamond/conical, `GradientInk::Colors` composited over or `Fade` alpha multipliers, refused on alpha-less pictures) runs in `gradient.slang` with ±1 LSB TPDF dither inside the ramp.
- `Stamp::new(w, h, straight sRGB RGBA8)?.with_position(left, top)` converts a CPU raster (e.g. Paint's typeset text) into the picture's space and composites it source-over (`arith.slang` OVER mode).
- GPU tests own one headless engine per test thread, serialized by a `GPU_LOCK` mutex, so devices are destroyed before the process exits.
- `Picture::changed_area(&earlier)` finds the bounding box two same-sized pictures differ in (`differ.slang`, exact compare); `piece(area)` cuts it and `patched(&piece, at)` writes it back bit-exactly (`copy.slang` PASTE mode), the basis of Paint's patch undo.
- `Picture::to_rgba8()` downloads straight RGBA8 in the picture's own space (8-bit planes directly, alpha forced opaque when the picture has none), for encoders.
- `develop` runs a recipe whose every step changes only an area (`Effect::reach` → `Reach::Within`; marks by their binned tiles, pointwise ops by their unfeathered or feathered mask, direct Gaussian blurs with a `3σ` halo) over that area plus its halo alone: a window-sized `Work::windowed_on` run whose position-dependent kernels add `PushHeader::window`, then a copy of the source with the area pasted back. It is bit-identical to the whole develop (`tests/regions.rs`); other ops stay `Reach::Global`.
- `Resize` streams (`ops/resizing.rs`): the output is cut into 16-aligned pieces whose source footprint stays ≤2 Mpx, and each piece copies, linearizes and resamples only its footprint into reused planes, so no full-size linear intermediate exists. `resample.slang` takes absolute output `start`, source `offset` and clamp `limit`, keeping pieces bit-identical to a whole pass.
- `Picture::resized_since(&earlier, changed, resampling)` re-resizes only the outputs a changed source rectangle reaches, bit-identical to `develop(Resize)` (`tests/resizing.rs`); Paint's detail levels and thumbnails update this way.
