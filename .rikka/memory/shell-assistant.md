---
title: Desktop assistant sidebar
description: One left-edge assistant panel whose conversation outlives the panel, drives the desktop and works apps' own tools.
about: system/rikka-shell/crates/shell-assistant
tags: [shell, agent]
---

- The `AssistantPanel` feature registers `AssistantService` (`rikka.assistant` 1.1: presence methods plus `summon {kit}`) and one left-anchored panel flush on the screen edge, toggled by the taskbar's Nix snowflake. Escape closes it.
- `Assistance` (owned by the feature, not the panel) holds accounts, store, the `rikka_thread::Desk` (thread, run, questions, jobs), `ReportedContext` and a requested kit behind one mutex, plus the apps `ToolKitSet` (shelved before the hub's by `Hub::equip`), the `Apps` watcher and the MCP `Hub` (`Assistance::hub`). Desk events go through an mpsc drained on the work runtime (watchers fire inside desk calls made under the lock). It beats a `rikka_worker::Observable`, runs on rikka-ui's work runtime, and follows `Llm::changes()` and `Hub::changes()`. The assistant runs with full access; it has no settings domain.
- MCP: `fitting::servers()` builds one `Hub` over the place `assistant` (`$XDG_CONFIG_HOME/rikka/assistant/mcp.json`), folder = home, personal vault; it starts on the work runtime. `fitting::fit` equips the toolbox with `hub.equip` and adds `hub.instruction()` between the system and environment instructions. The composer offers server prompts after `/`, their argument completions, and resources after `@`; `Panel::send` runs `rikka_chat::gather` before reading home paths, and `Assistance::send_message` takes the finished `Ask`.
- Pages: `Tab` is Conversation, Threads or Servers, toggled by the header's HISTORY and EXTENSION buttons; other pages show a back button and Escape returns to the conversation before closing. Servers (`view/servers.rs`) scrolls the shared `rikka_chat::servers` over a nested `Servers` state, hides the composer, and calls `Servers::follow` when shown.
- `Assistance::beats` yields `LayoutChange::Moved` for structural changes and `LayoutChange::Grew` for a text delta; reasoning deltas do not beat. On `Grew` the panel calls `Transcript::stream` through `Assistance::answering` and skips the view. Anything the stream cannot take refreshes the whole snapshot.
- The panel is rebuilt on each show; it binds the shared `rikka-chat` UI as `ShellChat` (`chat.rs`) and keeps the draft, attachments, per-thread `Drafts`, offers, open question, `Models`/`Picking` and a nested `Transcript`. It gets the conversation as an `Arc` snapshot; a animated kit is put into the draft as `@ToolKit ` on the next refresh.
- `fitting::fit` uses `system/rikka-shell/crates/shell-assistant/prompts/*.md`, root = home, `ComputerUse::desktop(seam)` and the rack. Tools are the shared `rikka-tools` set plus racked app and MCP server kits.
- Apps: `amid::ReportedContext` adds hidden context to the person's turn (`Ask::with_context`), committed only once the turn starts: an `<apps>` note (`apps.md`) whenever the set of running kits differs from what this thread was told, and an `<app>` note (`pointed.md`, with the kit's instructions the first time) for each `@ToolKit`/`@title` the person wrote, peeked with `Assistant::toolkit` and revealed with `open_toolkit` after the conversation is built. Opening a thread resets `ReportedContext`.
- `@` completes running apps first (`Offer::mentioned`), then home paths off-thread, folders first (`mention::offers`). On send, mentioned paths that name no running app are read relative to home and attached (folders as listings). `/compact [focus]` summarises via `Assistance::compact`.
- `chat::Calls` describes calls: app tools show `title · Tool` and a gist from the app's gist paths; MCP server tools show `server · tool` (via `rikka_mcp::ToolCall`), `McpServers` shows `action server`; desk tools use `rikka_tools::ToolAction`. Every call's shown pictures are drawn (View, Computer screenshots, Paint/Animate tools).
- The model picker is the shared `Models`; a choice becomes the desktop default. Questions are the desk's mirror and the panel tracks them into a `QuestionQueue`, showing one at a time. Ctrl+F opens the transcript find bar; Escape closes it first.
- Opening, beginning or discarding the open thread reads the store and refits (`Assistant::fresh`) on the work runtime; a sequence number drops stale reads, and the panel swaps drafts when the shown thread id changes. Switching is refused (with `shell.assistant.busy`) while answering, notices are pending or jobs run, since the assistant would be replaced. The outgoing thread's summary is folded into the list. `Assistance` refits when `rikka.llm`'s reply language changes; its toolbox asks for hosted web tools (`ToolboxBuilder::web()`).
- Every fit goes through `Assistance::fit_assistant`: one fit runs at a time (the `fitting` flag), and a fresh refit (reply language or hub instruction differs from what the assistant was fitted with) is marked `refit_due` and taken only when idle; it is retried when a run ends. A fit finished while busy is dropped and marked due, so a live conversation's questions and jobs are never orphaned.
- When a turn ends, the agent ring is removed. Store: `rikka-shell/assistant`.
- Gaps: home folder only. No skills, memory or agents of its own.
