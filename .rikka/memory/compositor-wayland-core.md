- `crates/foundation/rikka-wayland-scanner` is a library with three entry points over the same XML: `shared(xml, runtime)` (per interface `INTERFACE` metadata and enums), `server(xml, runtime, shared)` (handles, event methods, `Request` enums) and `client(xml, runtime, shared)` (proxies, request methods, `Event` enums). The `rikka_wayland_protocols` Bazel rule (`//crates/foundation/rikka-wayland-protocols:defs.bzl`, `side = shared|server|client`) runs it over every vendored file, so the dense `Interface::index` is the same in all three outputs. `tests/golden/{shared,server,client}.rs.golden` pin the output; regenerate one with `bazel run //crates/foundation/rikka-wayland-protocols:generate -- <side> <out> <xml…>`.
- `crates/foundation/rikka-wayland-protocols` vendors XML under `xml/{wayland,protocols,wlr,rikka}` (add a protocol by dropping its XML there) and is the shared crate. `rikka-compositor-protocols` is the generated server side and `rikka-wayland-client` the generated client side; each re-exports the shared module, so one flat module per interface holds everything (`rikka_compositor_protocols::wl_surface::{WlSurface, Request, Error, INTERFACE}`), and server and client name the same enum types.
- Requests with string/array/untyped-new_id args are `Request<'m>` borrowing the receive buffer (`&str`, `&[u8]`); handlers take `Request<'_>` and copy only what they keep. All-word requests decode through `Args::words::<N>()`.
- Event methods open `Object::event(opcode)` → `EventWriter` and `finish()`; an event named like an accessor (`key`, `id`) gets a `send_` prefix (`wl_keyboard.send_key`). fd params take `impl Into<wire::Fd>`: pass an `OwnedFd` to skip the dup.
- Interfaces never created by a typed `new_id` and not `frozen` are globals: they get `wire::Bindable`, so they can be published and their `bound` hook runs per bind.
- Vocabulary several compositor crates share is not in the codec: `rikka-compositor-types` holds `OutputId` (the one output id, a slotmap and wire key), `OutputLayout` with the shared `Layouts`/`LayoutView` table, `XWindowId`, `MimeList`, `Fourcc` (open `u32` newtype with the DRM format constants)/`Modifier`/`Format`/`FormatSet` (the one pixel-format vocabulary; only rikka-compositor-kms converts to `drm_fourcc` for the `drm` and `gbm` crates), `unguessable()`, the presentation hints and the input vocabulary (`Press`, `AxisSource`, `Gesture`, `ToolKind`, `ToolCapabilities`, `ToolInfo`, `ToolAxes`, `PadSource`, `PadInput`) that rikka-compositor-input produces and rikka-compositor-seat consumes; `rikka-compositor-server` holds `ByClient<T>` (resources grouped per client). `rikka_wayland_wire::serial_not_before` is the wrapping serial order.
- `ClientOptions::xwayland()` marks the Xwayland connection; globals meant only for it use `.only(Client::is_xwayland)`.
- `crates/foundation/rikka-wayland-wire` owns bytes, fds, `Interface` metadata, `Peer` (connection + per-client object table), the `Object` handle (peer, interface, client, id, generation, version; no per-object allocation) and `Objects`, the concrete table view generated `decode` uses. Its `client` module is the client half (see the Wayland client note). `MessageSpec::children` lists the interfaces a message's typed `new_id` arguments create.
- Objects carry only Copy keys: `set_key`/`key::<K>()`/`take_key` with `K: wire::Key` (u64 round trip). Slotmap ids implement it via `rikka_wayland_wire::slot_keys!(Id, ..)`. Rich per-object state lives in the owner's arena (`SlotMap<Id, T>`) removed in the `destroyed` hook, like `Surfaces::objects` or `Shell::positioners`. Keys stay readable during `destroyed` and vanish after.
- `rikka-compositor-server` owns `DisplayHandle<S>`, `Client`, globals and dispatch; dispatchers sit in a Vec indexed by `Interface::index`. `display.serve::<R>(request_fn)` is the one way to serve an interface; chain `.destroyed(fn)` and `.bound(fn)` on what it returns. Handlers are plain fns generic over the module's host trait.
- `display.global::<R>()` publishes at the vendored XML version unless `.version(n)` lowers it; `.privileged()` and `.only(filter)` hide it from other clients. `GlobalBuilder::key(k)` tags bound objects; `on_bind(|r| ..)` runs per bind for config that is not a key. `clients()` returns a shared `Rc<[Client]>` snapshot.
- Side effects that need `&mut S` (destructor events, `Client::destroy`, binds, kills) are queued on the peer (`Peer::defer_destroy`) or core and settled right after the current handler or in the display's maintenance task (`Reactor::task` + `wake`), which also flushes.
- `wl_display`, `wl_registry` and `wl_fixes` v2 (global always published) are built-ins in `rikka-compositor-server/src/builtins`.
- Global removal follows libwayland 1.26: `global_remove`, still bindable until every offer is acked via `wl_fixes` or its registry dies, or 5 s pass.
- `rikka-compositor-reactor` tokens are generational slab slots; timers are a heap with lazy cancellation. `after_each(hook)` runs one hook after every callback (watch, mailbox, timer, idle, woken task, turn hook) and `settle(state)` runs it on demand; the display calls `settle` after every client request.
- Tests: `rikka-compositor-server/tests/common` runs a display on a thread; `RawClient` speaks the wire directly for malformed-input cases, since libwayland-client does not expose protocol error messages.
