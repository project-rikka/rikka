---
title: Desktop LLM accounts
description: rikka-llm-accounts owns the rikka.llm domain, browser sign-in, model selection, the model roster and the picker.
about: crates/ai/rikka-llm-accounts
tags: [llm, settings]
---

- Sits over `rikka-llm` and `rikka-llm-providers` with no agent knowledge and no UI toolkit (no `rikka-ui`/`rikka-widgets`), so `rikka-thread` stays UI-free. `rikka-thread` uses both. It localizes only through `rikka-i18n`.
- Re-exports `Backend`, `Credential`, `SignIn`, `Prompt` and the endpoint types (`Endpoint`, `Wire`, `EndpointCredentials`, `Header`, `Listing`, `Offered`, `Checkup`) from `rikka-llm-providers`, so apps import them from `accounts`.
- `Llm::load()` opens `rikka.llm`: `backends`, default `backend`, `effort`, reply `language`. Every process declares the same schema.
- An account is named by `AccountId` (opaque, `Copy`, serialized as the backend id or `endpoint:<16 hex>`; `From<Backend>`, `from_id`, `backend()`). Accounts are one per registered backend (`Backend::all()` order) followed by the person's OpenAI-compatible endpoints in the order added; `Account::{id, label, backend, endpoint, endpoint_credentials}` tell them apart. Settings key `backends` keeps backend id, model and fetched models; `endpoints` keeps id, name, `endpoint {base, wire}`, model and the person's models with their capabilities. Credentials live only in the keyring (schema `os.rikka.Llm`, attribute `backend` = id, or `endpoint` = hex holding key and extra headers), read on load and written by `set_credential`/`set_api_key`/renewals and the endpoint edits. `backends` entries and keyring items naming an unregistered backend are skipped on read and vanish on the next save, so removing a provider needs no migration.
- Endpoints: `add_endpoint(name, Endpoint, EndpointCredentials) -> AccountId`, `edit_endpoint`, `remove_endpoint` (drops the keyring entry and the default if it was chosen); models through `add_model`/`set_model`/`remove_model(AccountId, …)`. An endpoint is ready once it has a model. `Llm::changes()` also yields keyring changes, so other processes re-read credentials; keyring failures show through `unavailable()`.
- `sign_in(backend, cancel)` streams `Step::{Prompt, Done, Failed}` over `Backend::login()` and opens the page itself. Callers store results with `signed_in`.
- Renewed OAuth tokens are persisted by `Llm` itself (`account_store.rs`): its `Renewal` keeps one `SharedTokens` per backend over a `CredentialStore` that locks `$XDG_RUNTIME_DIR/rikka/llm/<backend>.lock`, re-reads and writes the keyring entry; every load and credential edit `hold`s the current tokens. `bench`/`connect`/`meter` re-read accounts once a renewal landed. Callers wire nothing. `Llm::revision()` changes with every take-up or edit (cache key for pickers).
- `Selection` (account, model, effort; the account is stored under the key `backend`) is what a conversation persists. It resolves against current credentials, not the default. `Llm::select(&selection)` makes a picked selection the desktop default; `Llm::restore_selection(model)` is the selection for a model that spoke last.
- `Llm::roster()` → `ModelRoster` (shared `Arc` accounts). `connect(selection)` hires the conversation model. `connect_named(name, effort)` matches name or id loosely. `summary()` lists models in registry order.
- `ConnectedModel` holds client, name, window, clamped effort, and its `ModelRoster`.
- `ModelOptions::new(llm, selection)` is the one model picker (picks, rows by account, levels); `Row::Account(at)` heads the account of `options()[at]`, whose `account()` is its label. `effort_label(Effort) -> Label` is the one localized reasoning-level name (`llm.effort.*` in its `locales/`; every process that shows it embeds `rikka_llm_accounts::CATALOGS`: Settings, ADE, the shell). Callers supply all other wording.
- Errors are its own: `Unconfigured`, `Keyless`, `SignedOut`, `Modelless`, `Unoffered`, `Refused`, `Unmetered`, `Stopped`; the account variants carry the account's label; provider errors are translated.
- `Llm::changes()`, `apply_change()` and `reload()` keep processes in sync; `AccountsChanged::from_delivery(&Delivery)` turns a watched seam event into an `apply_change` without a round trip. `language()`/`reply_language()` feed `{{language}}`.
- Every backend but OpenRouter is listed (`Backend::is_listed`): a ready account has no models until its listing lands, then keeps it in `backends` with `listed` (unix seconds), superseded models included. `Account::models()` is the current ones (stored sorted current-first), `find_model(id)`/`model_info()` search all, so selections of superseded models still restore and connect; the first listing picks the newest model when none is chosen. `has_custom_models()` is true only for OpenRouter and endpoints. The stream of `Llm::changes()` also runs `listing.rs`: it checks at start, whenever `take_up`/a credential change wakes the store's `Notify`, and every 15 min, lists ready accounts (key, env variable or tokens) older than 3 h (failures wait 15 min) and yields the result; `apply_change` keeps it only if the account is ready with the same identity. A new or cleared sign-in forgets the listing. Callers wire nothing beyond following `changes()`.
- `Readings` (per-account `Reading`, generation-guarded; only registered backends are metered) is what Settings and the shell taskbar keep: `request(&Llm)` returns `UsageQuery`s whose `run()` future yields a `UsageReport` to hand back to `record`; meters that cannot be built are answered at once. They draw each window with `rikka_usage_bar::usage_bar`. `Reading::error()` is a `rikka_llm::Trouble`; when it carries a verification URL, Settings, the taskbar panel and `rikka_chat::Composer::error` (ADE and the shell assistant, fed by `Reply::Failed(Trouble)`) show a `verification_label()` button that opens it (`open_verification`, or the shell's seam spawn).
- The settings UI over it is `rikka-llm-settings` (its own note).
