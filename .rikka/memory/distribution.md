- Users install from the flake `github:project-rikka/packages`; nobody edits that repo by hand and only its writers can release. Its contents are `nix/dist/*` from this repo plus a generated `release.json` and a `flake.lock` pinning exactly this repo's nixpkgs, so the archives relink against the libraries they were built with.
- `--config=dist` = release + `--platforms=//bazel/platforms:linux_portable` (constraint `linkage=portable`; `//bazel/config:linkage.bzl` drops the RUNPATH and sets `/lib64/ld-linux-x86-64.so.2`) + `-Ztranslate-remapped-path-to-local-path=no` so std panic paths stay `/rustc/…`. Exec tools stay on the dev platform.
- `nix/dist/packages.nix` makes one derivation per component (`component.nix`: `fetchurl` or a local `file`, `autoPatchelfHook` over `runtime.nix` linked libs, dlopened libs as `runtimeDependencies`, `/run/opengl-driver/lib` appended, templates `@out@` substituted, `share/systemd/user` linked as `lib/systemd/user`, links to Gecko/icon fonts/pinned Mesa (`lib/rikka-mesa`)/asset trees). Assets (`asset.nix`) are autoPatchelfed trees such as grammars. `runtime.nix` links a libgbm whose backend path is the pinned Mesa's `lib/gbm` before `/run/opengl-driver/lib/gbm`, so Rikka's GBM never loads the system Mesa.
- `nix/dist/module.nix` is `rikka.nixosModules.default`: `rikka.enable`, `rikka.apps.<id>.enable` for every non-required component (all default off; the installer writes the choices), `rikka.autologin.user` (the tty1 kiosk unit, `display-manager.service` alias, getty fallback; asserts the user exists and no other unit is or aliases `display-manager`, and lowers NixOS's implicit LightDM with `mkOverride 900 false`), `rikka.configuration.{flake,modules}` (default `/etc/nixos` and `<flake>/rikka`, absolute, modules inside flake; `flake = null` turns NixOS editing off) written to `/etc/rikka/configuration.json`. It installs required + chosen packages into systemPackages/dbus/systemd, portals (FileChooser=Files, ScreenCast=cast) and `rikka-portals.conf`, PAM services from entries, `security.wrappers.rikka-compositor` with `cap_sys_nice+ep`, session file, desktop services and fonts with `mkDefault` (power-profiles-daemon only without TLP/auto-cpufreq), asserts each component's `requires` against base's version, and writes `/etc/rikka/catalog.json` (what the Packages app shows).
- The flake also has `templates.default` (`templates/configuration`: a `flake.nix` building `./configuration.nix` + `./rikka` with Rikka, plus the blank modules) and `templates.modules` (`templates/configuration/rikka`, run inside the empty modules directory). `checks.module` imports the template modules. `xtask` mirrors `nix/dist/templates` into the published flake. The user guide for both install paths is `docs/en/installation.md` (Japanese twin `docs/ja/installation.md`); keep them in sync with the module's options.
- `runtime.nix`, `gecko.nix` (+ its pin `gecko.json`) and `icon-fonts.nix` live in `nix/dist/` because both the dev shell (`nix/env.nix`, the flake overlay) and the distribution use them. FFmpeg is nixpkgs' `ffmpeg_9-full` (Hydra-built).
- `xtask release components|rebuild|installer|gecko` (see the xtask and gecko-engine notes) is the only way to publish: archives (content-addressed names), the Gecko engine and the installer (`rikka-installer-x86_64-linux` + `.sha256`, which `installer/install.sh` fetches) live in the `binaries` release of `project-rikka/packages`; `release.json` records versions, builds and source revisions, `gecko.json` the engine. This repository has no release tags or release workflows; CI only builds and attests the engine.
- The generated system flake has `rikka.url = github:project-rikka/packages`; on unstable `nixpkgs.follows = "rikka/nixpkgs"` so the system shares Rikka's libraries and Mesa; on stable it pins `nixos-<release>`. Rikka works either way because it draws with its own Mesa (gpu-drivers note). Updates are the normal `nix flake update` of nixctl.
- Windows ships separately as a portable ZIP of the five general apps (`xtask dist windows`, the Windows distribution note), not through the flake.
