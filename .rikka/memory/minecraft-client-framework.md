- `event/`: `EventBus` (one static instance, `RikkaClient.events()`) delivers to exact final event types only. `@EventHandler` methods are bound with `LambdaMetafactory`; each `EventChannel` keeps a copy-on-write snapshot sorted by `Priority`, so `post` takes no lock and allocates nothing.
- Cancellable events extend `CancellableEvent`; `receiveCancelled` is only valid on them. A listener that throws goes to the bus's `FailureHandler`: `RikkaClient` disables the owning `Mod` and rethrows for any other owner.
- `events/`: the game events plus `ClientHooks`, the code mixins call for events and the HUD (the Old Animations mixins call `mods/animation/AnimationHooks` instead). Tick, HUD, `LookEvent` (per-frame mouse turn deltas from `MouseHandler.turnPlayer`) and `ResourceReloadEvent` (a `resource/ReloadNotifier` registered last on the client resource manager, just before the first `createReload`, so it applies after textures, atlases and models) are reused singletons; key, mouse, packet, `ChunkLoadEvent` (`ClientLevel.onChunkLoaded`) and `BlockUpdateEvent` (`ClientLevel.sendBlockUpdated`) are allocated per post, only when listened. `PacketEvent` fires only on client-side connections, and splits bundles into their sub-packets on the network thread.
- `CombatTracker` (subscribed in `RikkaClient`) derives packet-based combat events on the main thread: `HitEvent(targetId, reach)` when a `ClientboundDamageEventPacket` caused and dealt directly by the local player matches a sent `ServerboundAttackPacket` (reach = eye to target AABB at send time, the server's metric; the attack whose age is closest to `net/TabListLatency`, else the newest, wins), and `HurtEvent(player, attackerId)` when the local player is damaged (`attackerId` empty for environmental damage). `JumpEvent` comes from `LivingEntityMixin.jumpFromGround` for the `LocalPlayer`.
- `target/TargetTracker` (`RikkaClient.targets()`) is the shared combat target of Target Info and Target Indicator: the living entity last attacked or under the crosshair, kept 3 s after the last engagement while alive, visible and within 16 blocks.
- Mixins hook `Minecraft.tick`/`close`, `KeyboardHandler.keyPress`, `MouseHandler.onButton`/`onScroll`, `Connection.send`/`genericsFtw`, and `Hud.extractRenderState` just before chat. `GameRendererMixin` calls `ClientHooks.drawHud`/`drawScreen` around `GuiRenderer.render()`; Vulkan mixins force the Vulkan backend, raise the instance to 1.3 and add `RikkaVulkan.FEATURES` to the required feature sets; accessors expose `FrontendGpuDevice.backend` and `VulkanDevice.enabledFeatures`. Classes a mixin implements (duck interfaces) live beside their mod, never in `mixin/`.
- `mod/`: subclasses of `Mod(id, Category)` declare settings in field initializers with the protected factories. `setEnabled` subscribes to the bus, calls `onEnable`, and posts `ModToggleEvent`. `HudMod` declares rikka-ui content in `view(View, HudLook)` for a `width()`×`height()` box (rikka logical px), placed at its `position` and zoomed by its `scale` on the HUD surface. `ModKeybinds` applies each mod's `bind` and `bindMode`; a `DefaultBind` (`Mod(id, category, icon, DefaultBind.hold(key))`) sets their defaults. Camera, mechanic and visual mods are in the gameplay-mods note. `onEnable` may run inside `ProfileManager.open`, before `RikkaClient` services exist, so it must not call `RikkaClient.mods()`; Fabric calls `onInitializeClient` right after `Minecraft.gameDirectory` is set, so that `onEnable` also precedes the pack repository, options and renderers, and work needing them waits for the first tick.
- `hud/style/`: the client-wide HUD style. `HudStyle` declares its `hud_*` settings inside the `Preferences` group (saved in `client.json`): surface (`HudSurface` NONE/BLUR/LIQUID/THEME), fill, outline, shadow/glow, corner radius, text ink and text shadow, the accent (`AccentPalette` presets, THEME or CUSTOM two colours) and gradient motion (`HudMotion` STATIC/ROTATE/PULSE/FLOW, speed, angle). `HudTemplate` (Rikka's Blur/Liquid/Theme/Minecraft and Soar v7's themes) holds a `HudPreset`; `apply` writes it, `template()` finds the one matching. `HudLayer` builds one `HudLook` per declare (`HudLook.of`, closed afterwards because it owns the frame's SDK `Gradient`s) and hands it to every HudMod; mods style panels with `look.panel(box[, radius])` and text/icons with `look.text`/`mutedText`, never with their own colours. `HudLayer` sets the HUD surface's own background from `HudSurface` (`EmbeddedSurface.setBackground`/`followBackground`) and re-views every frame while `HudStyle.isAnimated()`.
- Game-native HUD content (items, faces, entity models, the minimap) draws through `mod/OverlayHudMod.extract(HudCanvas)`: `ui/HudOverlays` calls it for every enabled OverlayHudMod from `HudRenderEvent`, with the pose mapped to the mod's box in HUD units (origin at its top-left, `HudMod.UNITS_PER_GUI_PIXEL` = 13/9, scale applied), so vanilla GUI elements land above the mod's rikka panel. `HudCanvas` has `item`, `face`, `entity` (PiP, absolute coords from the pose) and `pixel()` (box units per physical pixel). A HudMod whose `animating()` is true makes `HudLayer` re-view every frame; `HudMod.editing()` is true while the HUD editor (`mod/HudEditing`) is open, for previews. `ui/Smoothed` is the frame-rate-independent exponential approach used by animated HUDs.
- Minecraft replaces `Util`'s time source inside `Minecraft.<init>` (`RenderSystem.initBackendSystem()`), after mods are constructed, so a `Util.getNanos()` stored in a field initializer belongs to another clock: elapsed-time code must clamp negative steps to 0 (`ui/Smoothed` does), or it yields Infinity/NaN.
- The SDK aborts the whole game on a modifier the element does not support (the core dump's `rk_<modifier>` frame names it; `sdk/native/src/api/modifiers.rs` lists the kinds each accepts): `cornerRadius`, `glass`, `surface`, `border`, `borderGradient`, `backgroundGradient`, `shadow`, `shadowGradient`, `clipContent` only on `box` (`cornerRadius` also on images); `tintGradient` and `textShadow` only on text and icons; `alignItems`/`justify` only on row/column; `tint` only on text, icons, sliders, progress, spinners, gauges, list/nav items, tabs, banners and status pages, never on buttons (a tinted toggle is a `customButton` around a tinted `icon`); text styles (`textSize`, `tone`, …) only on text; colours must be finite in 0..1. A rounded or glass row is a `box` holding a `fillWidth`/`fillHeight` row.
- `render/GuiMesh` is a custom `GuiElementRenderState` (submitted through `GuiGraphicsExtractorAccessor`): rects, triangles, segments, feathered rings/discs and convex polygons with an optional `UvMap`, on `GUI`, `GUI_INVERT`, `GUI_TEXTURED` or any textured pipeline passed to `textured(graphics, pipeline, …)`. `circle` and `roundedRectangle` build outlines for `convex`. GUI pipelines cull back faces, so it reorders every quad to the front-facing winding itself.
- Each mod has two setting groups. `settings()` holds its own settings. `controls()` holds the shared `bind` and `bind_mode`, translated under `rikka.setting.*`. A mod in HOLD mode never persists or restores its enabled state.
- Released keys and mouse buttons always reach vanilla, even when a listener cancels them.
- `ModManager.register` happens in `RikkaClient.onInitializeClient` through `mods/BuiltinMods` (the table of built-in mods and their default positions), before `lock()`. Locking also freezes every mod's `Settings`.
- `mod/SimpleHudMod` is the one-line HUD base, styled after Soar Client v8's SimpleHUDMod (proportions scaled 13/9): icon + text in a `look.panel` box `HEIGHT` tall whose `width()` is the pill itself, measured from the current `label()` with `Rikka.textWidth`, so the HUD box (and the editor frame) hugs the content and anchors keep the anchored edge still as the text changes; shared `icon`/`background` settings; subclasses supply `label()` and optionally `shownIcon()`, and format with `translate(suffix, args)` under `rikka.mod.<id>.<suffix>`. The built-in text HUDs live in `mods/hud/`; `PingDisplayMod` measures RTT itself with `ServerboundPingRequestPacket`/`ClientboundPongResponsePacket` (`LatencyProbe`) and shows the tab-list latency when no pong arrived for 5 s.
- `setting/`: the sealed `Setting<T, S>` family. Each type has a primitive or typed `get()` and a DFU `Codec`, and clamps or snaps on `set`. Translation keys are `rikka.mod.<mod>.setting.<id>`, falling back to `rikka.setting.<id>`; lang files live in `assets/rikka/lang/`. Without Fabric API nothing loads mod assets, so `MinecraftMixin` adds `resource/ClientModPackSource`: a required built-in pack over the mod jar root, fixed just above vanilla, with metadata built in code (no `pack.mcmeta`).
- `config/`: `ProfileManager` keeps `config/rikka/profiles/<name>.json` and `client.json` (active profile plus the client-wide `Preferences` group under `preferences`: menu/HUD-editor keys, theme slug, `Background`, and the music player's keys, volume, mute, shuffle, `MusicRepeat`, last track and position). It saves 500 ms after a change on its own thread, writing only the side (profile or `client.json`) whose settings changed, writes atomically, preserves unknown JSON entries, and moves unreadable files aside as `*.corrupt`. `HudMod.bounds(screenWidth, screenHeight)` is the one placement rule the HUD layer and the HUD editor share.
- Server profiles: a profile's top-level `servers` array holds `ServerPattern`s (host or IP, optional port; a domain also matches its subdomains, the most specific pattern wins, one pattern belongs to one profile; at load a duplicate stays with the first profile by name). `ProfileManager` keeps them in a `ServerIndex` built at open. It separates the persisted `selected` profile (`switchTo`, written to `client.json`) from the `active` one: `override`/`clearOverride` switch without persisting, so a crash on a server reopens the selected profile; neither the active nor the selected profile can be deleted. `ServerProfiles` overrides on `ServerConnectEvent` (`ConnectScreenMixin`, after vanilla's disconnect inside `startConnecting`), except on a transfer after the person switched profiles on the server, and restores on the tick after a `DisconnectEvent` (`Minecraft.disconnect`, or `ConnectScreen.removed` without a live connection), so server hops and transfers switch once; it shows vanilla toasts. The menu edits them in `menu/ServerEditor` and the New Profile card.
- `ui/`: `RikkaUi` lazily makes one SDK `Embedding` on Minecraft's VkDevice (fails loudly when it cannot draw), wears the `Preferences` theme and background on it (`set_theme`/`set_background`, re-applied on change), splices handed command buffers into the single `VulkanCommandEncoder` (`waitSemaphore`/`execute`/`signalSemaphore`), and draws onto the main render target (bottom-up, GENERAL layout) so glass blurs the game. `HudLayer` is one surface beneath vanilla GUI holding every enabled `HudMod`, invalidated each tick, on toggles and on any HUD setting change; it follows Minecraft's GUI scale (13/9 HUD units per GUI pixel, so 13 px HUD text matches vanilla's 9 px line), so HUD sizes, positions and offsets are in those units. `RikkaScreen(title)` (abstract `view`, optional `opened`, `refresh`, `surfaceWidth/Height`, `hudUnit` = surface px per HUD unit) always uses the display scale, opens its surface in `added`, re-views on resize, draws above vanilla GUI, forwards input (GUI coords × guiScale / display scale), hands presses the surface did not use to `pressed`/`moved`/`released`/`scrolled`, keeps the panorama on the title screen, follows the caret with SDL text input and maps rikka cursors to SDL ones. `onClose` and `leaveTo(next)` play the exit (`EmbeddedSurface.leave`; views return nothing while `view.isLeaving()`, so `.transition`s play out), ignore input meanwhile, and switch screens on the next tick from `on_left`. `RikkaClient.shutdown` closes every surface before the device goes.
- `menu/` (ModMenu, `MenuKeys`: menu key, default Right Shift, and the HUD-editor key, in game only) and `hud/` (HUD editor) are described in the ModMenu note; `music/` (`RikkaClient.music()`) in the music player note.
