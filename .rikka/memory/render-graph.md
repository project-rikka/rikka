- Each 3D frame declares a `FrameGraph` (`graph/builder.rs`): images (`create(ImageSpec)`, `import(Import)`, `publish`), passes (`compute(name)` / `render(name)` with `read`, `write` (overwrite), `modify`, `color`/`depth(Attachment)` with load, store and resolve, `area`, `buffer(Buffer, BufferUse)`) and a recording closure `(&mut Record, &mut GpuFrameCtx, &PassScope)`. `PassScope` gives slots, views, extents, `fresh` and the frame addresses; nothing in a closure may borrow the viewport.
- Closures live in `graph/recorders.rs`, a 16-byte-unit arena (`RecorderStore`) reused across frames through `GraphScratch`; closures must be aligned ≤ 16. With `FrameScratch` (resolved look, shadow views, the `CompositePlan` with its parameter blocks, composite node outputs) and smallvecs elsewhere, a steady 3D frame allocates nothing; `benchmarks/render` (`Counting` global allocator counting the drawing thread only, steady from frame 16, `three: look frame [with effects | at 1080p | lit by an environment image]`, `three: every built-in effect at 1080p` (all 30 chained in one composite), `three: ray traced look frame [at 1080p]`; the bench renderer opts into ray tracing) asserts it.
- `grouped(name, …)` wraps consecutive passes in one outer label/timestamp; every pass also gets its own `ctx.begin_pass(name)`. Timed passes per frame are capped by `TIMED_PASSES` (128).
- Image kinds: transient (default, per frame), `history(key)` (per viewport, kept across frames, released when a frame stops declaring it), `current(key)`/`previous(key)` (a ping-pong history pair; `ViewGraph` flips its turn each realize, so the declared structure and plan stay constant), `shared()` (renderer-wide in `look_state.images`, never swept), imported (`Import`: viewport colour/depth/identity/outline/HZB targets, output texture, shadow atlas; when single-sampled the colour/depth target *is* the resolved image).
- `Size::Viewport`/`Divided` allocate against the capacity extent and resolve logically against the render extent (`Extents`, see render-resolution.md); after `FrameGraph::enter_display(display)` (temporal upscale) `graph.extent()` is the display extent and `create` turns relative sizes into fixed display sizes.
- Buffers are the fixed `Buffer` set (deform, draws, clusters, environment, history, scene = acceleration structures, particles = emitter particles per frame slot); hazards on them become one global `MemoryBarrier2` per pass. `Buffer::carried(traced)` is each buffer's state left by earlier frames (deform: read by shaders, transfer and, when tracing, AS builds; history: written by the end-of-frame transfer copy, read by the surfaces vertex shader), so cross-frame hazards are graph barriers too. Draws/clusters live per frame slot in `frame_data.rs` (`DrawScratch` inside `FrameSlot`), so they carry nothing; deform positions/attributes are one shared set.
- Image barrier stages come from the pass kind: compute passes use `COMPUTE_SHADER`, render passes `FRAGMENT_SHADER`; `PassBuilder::read_vertex` adds `VERTEX_SHADER` where a vertex shader samples (particles read the sky environment, fluid spray the shadow atlases via `SceneImages::shadow_reads`). Consecutive reads of an image share one merged stage set (`merge_read_stages`), and published images go to all shader stages after their last write. In debug builds `PassScope::sampled`/`storage` assert the pass declared the image (published images exempt), so a missing declaration fails tests instead of racing.
- `ImageStore::holds_shared(name)` says whether a shared image still has content (provisional tracking); write-once shared images (BRDF LUT, sky transmittance/multiscatter) declare their writing pass only when it is false or their inputs changed.
- `compile.rs`: passes live when they write imported, persistent or published images or any buffer, or feed a live pass; order is declaration order. The plan lists per-pass image transitions and buffer barriers; source states come from each `GpuImage`'s provisional tracking (`core/image/recording.rs`, generation-stamped reusable tickets) at execution, so abandoned frames still revert layouts.
- `ViewGraph::realize` (`store.rs`, on `Viewport::graph`) hashes the declared structure (not clear values or render areas) and recompiles only when it changes; a steady frame reuses plan, physical images and slots. Compiles log at debug under `rikka_renderer::graph`.
- Aliasing: transients with attachment usage or `publish` take lanes (same desc, disjoint lifetimes share one image); storage-only transients are placed into one per-viewport heap block (`heap.rs`). A placed image's first barrier in a frame also waits on every image overlapping its memory.
- `execute.rs` runs live passes: barriers merged into the next pass's batch, labels, `begin_rendering`, the closure, published images back to sampled after their last write.
- Sync validation cannot see bindless or buffer-address accesses, so only layouts and attachment hazards are checked by the layer; test with `--//crates/graphics/rikka-gpu:validation` plus `VK_ADD_LAYER_PATH` (the layer's `share/vulkan/explicit_layer.d`). The renderer reports layer messages through tracing (`rikka_renderer::vulkan`), so they show where a subscriber runs: `rikka_test_renderer::init_tracing` in tests; elsewhere (the bench) use `VK_KHRONOS_VALIDATION_LOG_FILENAME`.
- Physical graph images leave a `ViewGraph` only through `PhysicalImage::release` (timeline-deferred); several pool entries may share one `PhysicalKey` (identical aliased placements), so replanning keeps them per key and releases the leftovers rather than overwriting them.
- Effects are Slang compute or fragment programs used as `Operation::Effect` nodes of the compositor graph (renderer-composite.md). `ShaderCompiler::effect_code(name, source, entry)` compiles at runtime against the embedded library (`import rikka;` gives `rikka_effect_*` helpers and the parameter attributes); built-in steps come prebuilt from `shaders_3d::EFFECTS` (`rikka_shader_programs::EffectArtifact`: a `rikka_spirv::Shader` plus a serde `EffectLayout` of stage, workgroup, push and `Parameters` layouts), so an `EffectCode` is only ever libslang output (reflected and checked once in `EffectCode::compiled`) or a build artifact (never reflected at run time); it holds a ready `MaterialShader`, and compute steps share `MeshPipelines::material_kernel` keyed by content hash. `Effect::new(name).input(socket).optional(socket).target(name, EffectTarget[.kept()]).step(EffectStep::new(code).read(member, EffectInput).write(member, EffectOutput).output(..).uniform(member, EffectUniform))`. Exactly one step writes `EffectOutput::Image` (the node's output). Fragment steps (`output(EffectOutput)`, no `write`) draw a fullscreen triangle into their output with the built-in fullscreen vertex shader and read `SV_Position`.
- `EffectCode::members()` lists the push struct's member names, so callers can wire a user program's inputs by name (Animate does). `Frame::look_mut()` lets a caller edit an already set look's composite.
- Push constants hold only image slots (`uint`), builtins and one `Parameters*` pointer; any other unbound member is refused. `struct Parameters` is the effect's parameter block, read by the same rikka-slang `ParameterSchema::from_struct` as materials (one vocabulary, `rikka.parameters`); effect textures are `[Texture] uint` bindless indices (`ParameterKind::Texture { sampler: false }`). `Renderer3d::effect_schema(id)` returns it; `Effect::schema()` reads it from the first step's `EffectCode` parameter layout without a renderer and without validating the desc (`create_effect`/`reload_effect` validate). Blocks have no size limit: `EffectPool::resolve` packs each reachable enabled effect node's block (and the Glow/Grade blocks) into the `CompositePlan`, uploaded to the per-frame `rikka.three.effects` buffer and reached by device address.
- `Renderer3d::create_effect` validates (table bindings, push ≤ 128 bytes, member kinds, equal parameter layouts across steps, 2D workgroups, targets written before read, declared and unique inputs, one image write, an input when History is read); a first program not built yet is built inline at its first draw. `Renderer3d::reload_effect(id, &effect)` validates the same way and parks the new program as pending: frames keep drawing the old one until every step pipeline of the new one is built, then `EffectPool::adopt_ready` (before each frame) swaps it in. `Renderer3d::effect_readiness(id)` returns an `EffectReadiness` handle (`generation`, `is_ready`, `on_ready(notify)`; event-driven through `Compiling::when_ready`, shared `src/readiness.rs` with `MaterialTemplate`). Instance values and `effect_schema` follow the drawn program until the swap. `EffectInstance { effect, enabled, values: Vec<(String, Value)> }` (the material `Value`) is checked per frame against the schema (`Error::Parameter`, `Error::Unknown(Resource::Effect)`) and written with the material block writers (`material::value::{write_defaults, write_value}`).
- Every effect runs at display resolution after the temporal resolve; the shade pass splits only for refraction, scattering or the temporal opaque capture (restored with `scene_copy.slang`).
- Inputs: `Input(socket)` (a declared socket's link), depth, normals/velocity (decoded by `effect_surface.slang` on demand), layers (`Draw::layers`, default `DEFAULT_LAYERS` = 1, `RikkaInstance.layers`, written by the materials' `SurfacesLayers` variant only when read), history (own output last frame keyed by node key; the first socket on a fresh history), kept targets (`EffectInput::Kept(name)`: that target's content last frame, ping-pong keyed by node key and target index), emission (display-sized, exposed by the node's exposure context), targets. Geometry inputs are display-sized: nearest-upsampled depth (`effect_depth.slang`) and layers (`effect_layers.slang`), normals decoded through `ratio`; all cached per frame in `composite::LayerImages`.
- Built-ins (`BuiltinEffect`, `Effect::vignette()` …) are the effect pack: see effect-pack.md. Tests: `tests/look/effects.rs` (API), `tests/look/effect_pack.rs` (pack).
