---
title: Settings application
description: Adopts desktop schemas, drives daemons directly, owns rikka.llm, and stages all NixOS edits in one draft.
about: apps/system/settings
tags: [application, settings]
---

- Sections under four headings follow `Section::ALL` order; `section.rs`'s exhaustive `about(section)` gives each its `Group`, symbol and `Needs::{Nothing, Radio, Draft, Nixos}`, feeding `section::available`/`entries` → `nav_list`; the title key is `settings.section.<slug>`; `Draft` and `Nixos` pages show the draft panel, `Nixos` pages hide without `/etc/nixos`. `users` comes first (see the Settings Users note); Appearance stays the default.
- The Configuration and Backup & restore pages (both `Nixos`) embed the settings catalog through `RIKKA_SETTINGS_CATALOG` (`//:nix/dist/settings.json`).
- The command line is the shared contract `rikka_session::settings_app`: `Section` (identity and slug; the app's `section.rs` adds group, symbol and needs through free functions), `Spot` (a place inside a section) and `Link` (`argv()`, `from_arguments`), so `rikka-settings <section> [<spot>]` opens a section, also in a running instance (`Window::on_open` → `Settings::opened_with`). Everything that opens Settings builds a `Link`; only the control centre's gear and the weather widget open it plainly with `PROGRAM`.
- A `Spot` is revealed by `Settings::reveal` (an exhaustive match onto the owning page). Each such page keeps a `spot_reveal::SpotReveal<S>`: `request` it, `settle` once the content that places the target has arrived (wallpaper listing; audio once a default node or the default metadata is known, so a machine without that device still lands; at once for keyboard sources), and wrap the target with `SpotReveal::section`, a keyed `Reveal::Start` container; `closed` clears it. A new spot is a `Spot` variant plus that page wiring. The shell spawns links with `shell_kit::launch::Spawn::settings(impl Into<Link>)`.
- Every page state implements `page::Page` (`opened(&Pending, &Session)`, `closed()`, both defaulted). `Settings::open` closes the old page and opens the new one through `Settings::page`; views stay free `view` functions matched in `settings.rs`. Polling keys are private to their page and cancelled in its `closed`.
- Daemon pages start their daemon facade on first open and follow it with `stream_keyed`: `changes()` for state, `events()` for answers and prompts, `unavailable_changes()` for a missing daemon. Handlers needing a page and the draft at once are `Settings` methods (`choose_offer`, `apply`).
- Desktop sections hold a `domain::Domain` (appearance, language, windows, notifications, pointer, capture, colour picker, IME, shortcuts) adopted lazily in `opened` over the window's one shared `session::Session` connection; each page implements `DomainPage` (`announced` follows the desktop's `changes()` announcements), so external writes show at once. Key names, defaults and ranges come from `rikka_settings::session::*`; only the labelled choice tables are the app's.
- The colour picker page edits the `formats` list in place (show, reorder, edit, delete, add, restore) with an inline editor card that previews on Moccasin and lists `Parameter`/`Formatter` help; renaming or deleting the copied format keeps `copied-format` valid.
- `controls.rs` holds the generic domain-bound fields (`flag`/`flag_or`, `choice`, `Count`); pages use them instead of their own switch/picker/slider wrappers. Text settings save on blur or submit, never per keystroke.
- Displays poll `settings_displays::Store::adopt(seam)` off the UI thread every 5 s, because a display hotplug redeclares the schema without an announcement.
- An HDR-capable display (its `<slug>-hdr` key exists) gets `Monitor::hdr`: the HDR switch is staged with the draft like resolution, while the standard-content brightness slider writes at once and updates both copies, so the compositor shows it live.
- Wallpapers come from whichever socket serves `rikka.wallpaper`. Choosing writes the id to appearance, nothing is imported, and it offers to open `UserDirs::wallpapers()`; Files' Set as wallpaper is the import path.
- Shortcuts are generic over `rikka.input` and `rikka_session::shortcuts`. Names come from `settings.shortcuts.command.<name>`. Recording uses `shortcut_field`. Empty means unbound. A clash asks keep-or-move.
- Input sources sync fcitx5's group order (authoritative) with `rikka.ime.sources`; the app-private `settings-sources` crate converts between a fcitx5 `Group` and `InputSource`s (`sources_from_group`, `group_from_sources`). Adding one searches installed engines, xkb layouts and installable fcitx5 addons (staged to `i18n.inputMethod.fcitx5.addons`, live after rebuild and relogin).
- The AI section (slug `llm`) is the shared `rikka_llm_settings` page: `src/llm.rs` only implements `Page` for `LlmSettings` (`opened` → `open`, `closed` → `close`) and `settings.rs` draws `llm_settings`; ADE shows the same page (see the LLM settings note).
- Sound, Wi-Fi and Bluetooth read daemons through `rikka-sound`, `rikka-network` and `rikka-bluetooth`. Wi-Fi and Bluetooth sections appear only when `/sys` shows the radio; there are no wired, VPN or proxy pages. Settings owns BlueZ pairing prompts.
- Sound levels are `live_progress` bars (`audio::meter`) that read `Peaks` in paint; the 60 ms poll only asks `request_frame()` when a stepped level moved. Faders and balance are components over per-node `Tracked<Volume>`s; a graph report that only moved volumes leaves `Audio.shape` alone.
- The sound card section offers only formats and rates `Node.hardware` says the card plays (a held pin outside them shows as `settings.audio.unsupported`), hides ALSA-only fields for other sinks, and `Audio::tune` writes the drop-in then sends `Command::Tune`.
- Keyboard, Language, Date & time, Power, System and Remote desktop NixOS controls share one window-level `Pending` draft. `Pending` holds a `rikka_nix::Draft` (saved and edited `Modules`); pages read through `get::<T>(module, path)` or `edited`/`saved(module)` documents and write through `set(module, path, impl Into<Expr>)` or `change(module, |document| …)`, which commits several edits atomically. Apply is one `rikka-nix` `Rebuild` (ask sent via `spawn_blocking`), one prompt, one rebuild. Apply first rebases the draft onto the modules on disk, so other writers' changes are kept; modules edited on both sides lose the edits made here, are named in a notice, and nothing is sent until the person applies again. A `Stale` refusal rebases the same way; the draft reloads when `Outcome::changes()` is `Modified`. While it runs the draft panel only disables its buttons (spinner in Apply); progress, log and result belong to the shell notification and `rikka-updates`, and only refusals other than `Denied` show inline. These controls are not separate states.
- Remote desktop (`remote/`) edits the `rikka.remote` domain (owned by `system/rikka-remote`), follows `rikka_session::remote::statuses` over its own `remote.sock` connection (`Link`: reaching, unreachable, following, lost with a retry), shows the addresses and certificate fingerprint, and lists connector names for the display picker from `rikka_capture::Screen::outputs`. `remote/access.rs`'s `Opening { port, network }` stages, in the desktop module, `security.pam.services.rikka-remote` plus the UDP port in `networking.firewall.interfaces.tailscale0.allowedUDPPorts` (and in the global UDP list with LAN access) through `Document::include`/`exclude`; port and LAN changes go through `Settings::write_remote` so an opened draft follows them. Saved vs edited gives the open/opening/closing/closed state.
- Date & time (`date_time/`) stages in the system module `time.timeZone`, `services.automatic-timezoned.enable` (turning it on removes the zone; off writes back the live zone), `services.timesyncd.enable`, `networking.timeServers` and `time.hardwareClockInLocalTime`; status and the hand-set clock go live through `rikka-timedate` (`SetTime` only while NTP is off). Zones come from tzdata's `zone.tab` + `iso3166.tab` via jiff; the clock ticks on second boundaries with `after_keyed`.
- Default apps (`defaults/`) reads `rikka_xdg::MimeApps`/`Terminals` off-thread into a `Catalogue` (the `CATEGORIES` table, file types, `x-scheme-handler/*` links, terminal) and follows `MimeApps::watch`. Types are `rikka_mime::MimeType`; the current and offered apps are asked along `Database::ancestry` exactly as Files opens, and type names are `Database::describe` in the UI language (one lazily loaded database per page). A category writes its primary type plus each family type the chosen app opens; reset is `forget_default`/`forget_choice`.
- Power (`power/`) edits the `rikka.power` domain (hosted by the shell's power saving feature), drives logind brightness, power-profiles-daemon, UPower packs (charge limit, `State.history` chart), and stages `services.logind.settings.Login.Handle*` (system module; `lock` shows the Rikka lock screen) and `services.upower.*` critical levels and action (desktop module).
- Date & time is a `#[state]` page whose second tick lives in its own tracked `Ticking` child; only the clock card component reads it, so ticks never re-view the window.
- Disabled defaults are removed, not written false. The channel is display-only. NixOS pages stay visible without `/etc/nixos`.
- `settings-displays` models modes, arrangement, snapping and collisions apart from the canvas. Errors stay typed until drawn.
