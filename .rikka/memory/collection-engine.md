---
title: Collection engine
description: One lazy engine windows every list and grid; Flex holds eager children and never scrolls.
about: crates/ui/rikka-widgets/src/lists/collection
tags: [ui, layout]
---

- `lists/collection/` owns sum-tree spans, the visible window, scroll, place, selection, keyboard walking and the sliding highlight.
- A collection is always lazy: a count plus a cell builder. The builder gets a `Slot` with `index` and `selected`.
- Constructors are `lazy_column`, `lazy_row`, `lazy_grid(columns, ..)` and `lazy_tiles(width, ..)`. `list`, `nav_list` and `list_of(count, item)` build on them. Tabular rows self-paint against `ColumnSpec`s (`lists/columns.rs`), the one column model.
- `list_of` rows all share the first row's shape and have no headers.
- `Flex` (`column_of`, `row_of`, `grid_of`, `column!`, `row!`) is eager and never scrolls. `scrollable` wraps exactly one non-collection child.
- A collection scrolls only when its height is bounded; a hugging one grows past its parent. `split_view` fills its nav slot, but a nav wrapped in `lazy` needs `.fill()` on the inner list too.
- Every adapter passes the same `Props<M>` via `collection_methods!`: selection, place, subject, follow, focus, reveals, naming, reachability and `on_*`.
- The engine owns choosing a cell by press or key. The cell owns its own chrome, hover and state.
- `.lit(true)` slides one pill between chosen and hovered cells. `Highlights` paints them.
- Layout is one grid whose children are only the visible cells. Right after layout, `Widget::arranged` hands the collection its cell rects: it measures bands into the sum index and asks for a rebuild, which the runtime runs before paint. Spans store pitch (cell + gap), the grid is told the cell alone.
- `CollectionState::keep` shifts the scroll by how far the held node moved in content coordinates (`laid_top`, the top of the first laid band at the last layout, plus `ScrollAnchor::was`, against `spans.top(window.start)` plus `ScrollAnchor::is`), exactly and with no threshold, so content stays put across relayout and average-height changes even inside tall cells; the per-band anchor in `paint` is only the fallback.
- `Widget::content_length` reports the full length. A collection that just measured bands asks for a rebuild.
- A jump further than three windows opens at its target instead of building everything in between.
- Lookahead (`collection/ahead.rs`): a collection heading one way (from scroll events and the drawn travel; a list at its end heads back) wants one more screen past its overscan in that direction. It keeps built cells there and, in idle prefetch passes only, admits one more band per pass; normal frames never build into it. A width change sheds the lookahead.
- A `Place` publishes `ScrollPosition::away` (more than one screen above the end, cleared again under half a screen) and notifies observers only when it flips. `Place::end()` makes the collection, `scrollable` or editor holding it leap to one screen short of the end and glide the rest; a following list keeps gliding instead of snapping until it arrives.
- `jump_to_end(content, &place)` (`lists/jump_to_end.rs`) is the shared round jump-to-latest button anchored at the content's bottom end, shown while `place.is_scrolled_away()`; `.unseen(n)` badges it, `.more_beyond(true)` forces it, `.press` replaces `Place::end()`, `.above(key)` sits it over the end corner of another keyed element instead. The anchor is on the face itself, so its exit ghost stays put. Chat's message list uses it; the rikka-chat transcript (ADE, shell assistant) puts it `.above` the composer's `DOCK`.
- `.memo(|index| Some(Version))` builds a cell lazily and keeps it while its version is unchanged (`TrackedVec::versions()`). Without a memo, a rebuild of the same collection widget (the window moved) keeps the cells it already built (`cells::Keys`, digest of the widget's `made` id and selection) and builds only entering ones; a new view builds all. A lazily held cell (`blocks/cell_content.rs`, `CellContent::cell`) keeps the shared cell builder and its `Slot`, no boxed closure.
- A cell's own root key stays on the cell, so `Anchor`s and lookups can target a row; the seat wrapper is keyed by a hash of it (or of subject and index when the cell has none).
- Cell reads belong to the cell, never the collection: a cell built eagerly (for its key) is wrapped in `rikka_ui::Reads::record`, and its `AnimatedPosition`/`Rider` replays those reads when it takes the primed element, so a landed `fetch` or changed observed value rebuilds only that cell. Use `live_observed(..)` for a finer part inside a large cell (rikka-music's `artwork::cover`).
- When `rikka_ui::can_retain()`, a cell whose index, digest and place (band offset for `AnimatedPosition`, name, ride generation and home for `Rider`) match its last build is emitted as `Element::retained(key)` (`Cells::kept`), so a steady scroll rebuild builds no element for standing cells; `Cells::seat` builds and records the rest.
- `.named(..)` (filled by `list_item(..).keyed`) gives rows an identity: the engine tells a moved selection from a new one, reveals only new ones, and choreographs changes. Names must be unique within the list: riders are keyed and drift by name, so a duplicate shares another row's motion and breaks reconciliation. Build names of mixed row kinds from disjoint integer ranges, not `hash_of`: FxHasher hashes equal integers of any width, enum discriminants included, alike.
- Any change of count or window names diffs the remembered window names against the new list (`collection/shuffle.rs`: bounded search, LIS marks steady rows), remaps measured heights (`Spans::remap`) and anchors the view: a list at its top stays there, else the first visible steady row stays put; `follow` lists keep their last visible row. `Kept` pins the anchor in `arranged`.
- `.rearrange(Rearrange)` picks how a named list shows a change of names. `Ride` (default): named 1-D lists wrap cells in `Rider`s keyed by name and never let rows overlap: inserted rows slide out from under the row above, removed rows tuck under it, a reordered row tucks at its old place and slides out at its new one. `Settle` only makes a change of names seen in that build settle instead of starting a ride (a ride in flight finishes); the `Rider` wrapper and its per-name widget state stay. `Glide` (search results) uses name-keyed `AnimatedPosition` seats: kept rows glide from where they were drawn, new rows fade in at their final place, removed rows leave at once, so every result set shows at once.
- Unnamed lists and grids keep `AnimatedPosition` seats with the arrival fade for new keys in already-built bands; named `Glide` lists fade new keys only when names changed, never on scroll. Arrivals are held in `CollectionState::arrivals` until the collection paints, so a rebuild before paint keeps the fade.
- `Rider` and `AnimatedPosition` keep their box at the resting seat and draw their content displaced, so neither takes hits itself (`hit_test` is false): presses land only on the visible, clipped content, and a row clicked mid-ride (a folder reopened while its rows still tuck) gets the click.
- `twistie(open, side, color)` / `paint_twistie(ctx, rect, open, color)` (`lists/twistie.rs`) is the shared disclosure chevron that turns a quarter on `motion::MORPH`; ADE's explorer and the task manager's self-painted rows use it.
- One `Ride` (`collection/ride.rs`) holds every leg (rest, `Order`, settle, amplitude, velocity) on one analytic `GLIDE` clock. Each frame a piece is visible only below the drawn bottom of every piece earlier in `Order` (rows by band, leaving pieces after their gap's arrivals); that single occlusion rule replaces explicit clip bounds and makes overlap impossible. The paint publishes drift and visible start per name to `Riders`.
- A change mid-ride (`collection/shuffle.rs`) starts the new ride on the old ride's clock time and takes the drawn picture as its start: visible rows keep drift and velocity, still-visible ghosts join the gap their `Order` falls in and tuck with it, hidden ones are dropped. Every `Ghost` remembers its row `name`, so a row re-entering while its ghost still moves (a folder reopened mid-close, or a steady ghost back in the window) continues from where the ghost was drawn with its velocity instead of rising again. Removed rows are out-of-flow ghosts built from the previous build's `Cells`.
- Layout snaps each child to whole pixels independently, so riders take their fractional `home` and add the remainder to drift and clip; ghosts are placed on whole pixels. A measured list rebuilds during a ride whenever a band remeasures, since ghost seats depend on spans.
- During a ride the collection hides the hover pill and draws the selection pill on the moving row itself, clipped like it.
- `Surface::cell/at/visible` serve `on_pointer` gestures that span several cells.
- Self-painting rows use `fitted_line(&run, width)`, `fitted_lines(&run, width, lines)` (one layout with the framework's ellipsis, glyph wrapping) and `column_header` for shared truncation, wrapping and sortable resizable columns.
