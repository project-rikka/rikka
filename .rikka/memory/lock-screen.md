title: Screen lock (shell lock screen, compositor lock transition, PAM)
description: How Super+L, idle and sleep lock the session: ext-session-lock surfaces, PAM gate, compositor lock transition.
about: system/rikka-shell/crates/shell-lock
tags: [lock, security]
---

- The shell's `shell_lock::ScreenLock` is the only locker. It is a per-output `SurfaceDesc::session_lock(&SessionLock)`; the runtime (`shell-runtime/src/locking.rs`, `Locker`) owns the `ext_session_lock_v1` object and creates `ext_session_lock_surface_v1` roles instead of layer surfaces (`shell-runtime/src/role.rs`).
- `shell_kit::SessionLock` is the handle: `lock()`/`unlock()` set its presence; the runtime reports `Sealed::{Open, Locking, Locked}` through `on_change` and observed `sealed()`. A lock withdrawn before `locked` stays alive until `locked` then unlocks, so the client never destroys a lock the compositor already confirmed.
- Triggers all go through the local `rikka.lock-screen/lock`: the `Shortcut::LockScreen` (Super+L, announced by the compositor), `Shell::idle()` (ext-idle-notify v2, minutes from `rikka.lock/idle`, 0 = never) and logind `PrepareForSleep` via `rikka_power::SleepWatch` (held by the shell's `SleepInhibitor`), whose `Delay` inhibitor is released once `Sealed::Locked` (or at once when `rikka.lock/before-sleep` is off).
- `gate.rs` runs PAM through `rikka_pam::Authentication` (service `rikka-lock`, falling back to `login` when `/etc/pam.d/rikka-lock` is missing at shell start). PAM never loads into the shell: `Authentication` spawns `/run/current-system/sw/bin/rikka-pam-helper` (`system/rikka-pam-helper`, in base's `system` contents; the distribution module relinks it against the system's own nixpkgs with autoPatchelf so it uses the glibc and libpam the `/etc/pam.d` modules were built against) and talks to it over stdin/stdout frames (`rikka-pam` `wire.rs`). A session-built PAM caller refuses every password once the flake's glibc is older than the system's. After a grant the gate hands the conversation's first hidden answer to the keyring's `Login` (see the keyring note); `main.rs` shares one `SessionLock` between `ScreenLock` and `KeyringPrompt`.
- PAM steps never cross seam: the reader thread pushes them into the gate's in-process inbox and rings a broadcast that each `Guard` streams to `drain()`, so no IPC client can forge a grant. The one password `TextDocument` lives in the gate and is `reset` (history included) on `end`, `clear` (Escape) and submit.
- One conversation runs while the lock is wanted and sealed (`Locking`/`Locked`): `Gate::begin` is called on those transitions and by `LockService::lock`, an answered refusal begins the next one (an unanswered denial shows `Broken` and waits for Enter), and `Gate::end` (unlock, before sleep) drops it.
- The UI is a single stage over a constantly blurred wallpaper (`backdrop.rs`): clock and an always-English `%A, %-d %B` date in Inter Display, avatar ring, password pill, notes, and power buttons bottom-right. The wallpaper comes from the backdrop's decoded cache (`shell_wallpaper::shared`) so the first frame matches the desktop. Keyboard caps/layout come from `Shell::keyboard()` (`rikka_seat::Seats::typing`).
- Compositor (`system/rikka-compositor/src/shell/lock.rs`, `animation/lock_transition.rs`): on lock it freezes everything drawn and fades the lock surface in over it, sending `locked` only once the fade covers every output (frozen desktop dropped after 1 s regardless). On unlock it freezes the lock surface and zooms windows and layers above Bottom in while the snapshot fades out; Background and Bottom layers (wallpaper, desk widgets) stay still.
- `rikka.session-lock/state` (compositor, `rikka_session::lock`) reports `open|locking|locked|sealed|abandoned` and publishes each change as the latest-value `changed` event; `needs_locker()` is true for the last two, and a shell that sees either (at start or from `changed`) locks at once. When the locker dies while locked the compositor keeps the session locked (`abandoned`) and restarts the shell if it was started this session.
- While `rikka.display-power` has the displays asleep, a lock counts as covering every output (`Compositor::confirm_lock`), so `locked` and the sleep inhibitor's release do not wait for a frame; the first frame after waking draws only the lock surface. logind's `lock` lid/power-button action reaches the shell through the same logind `Lock` path.
- Start-locked: `Launch::locked(true)` (main sets it for KMS with a shell; nested, headless and `--no-shell` start open) seals the session before any client runs unless `rikka.lock/at-login` is false. Sealing (`Compositor::set_session_locked`, `rikka_compositor_shell::Shell::set_session_locked`) hides everything with no locker, so a locker that leaves before `locked` still leaves it locked; the first shell gets 10 s to take the lock before it is restarted.
- logind (KMS only, `rikka_power::LoginSession`, one `rikka-login-lock` worker that also writes LockedHint): `Guarded::set` mirrors the state into `SetLockedHint`. A `Lock` signal emits `rikka.session-lock/wanted`, which the shell turns into its own lock; if no lock is requested within 1 s the compositor seals itself. An `Unlock` signal opens the session from the compositor (`unlock_session` sends `finished` to the locker), the escape hatch for a broken shell.
- NixOS needs `security.pam.services.rikka-lock = { };` (the installer writes it in the desktop module). Settings exposes the `rikka.lock` domain on its `lock-screen` page.
