---
title: Embedding rikka-ui in another program's Vulkan frames
description: ExternalDevice/ExternalTarget, rikka-ui-host Composer, rikka_app::embedded and the SDK embedded_surface rules.
about: crates/ui/rikka-app/src/embedded
tags: [ui, vulkan]

- Layers: `rikka_gpu::{ExternalDevice, ExternalHandles, HostSubmit}` with `GpuBuilder::external`, then `Renderer::new(&gpu)` and `rikka_renderer::{ExternalTarget, ExternalImage}` → `rikka_ui_host::Composer<K>` (synchronous host: tasks, resources, render, glass panes, draw on the calling thread) → `rikka_app::embedded::{Embedding, Embedded<S>, SurfaceId}` (session theme, locale, data-control clipboard, `Sender<S>` routed by `Route::Embedded`) → SDK `vulkan_device`/`embedding`/`embedded_surface`.
- `RenderDevice::adopt` (rikka-gpu `core/device/adoption.rs`) borrows the host's instance, device and one queue (`Ownership::Borrowed`: nothing destroyed, `wait_idle` is a queue wait). The host passes its enabled extensions and its `VkPhysicalDeviceFeatures2` chain; `FeatureChain::enabled_in` (`core/enabled_features.rs`) reads core and extension feature structs, and missing ones fail with `Error::Unsupported`. A DRM node, video, background or upload queues, latency-critical queues and ray tracing are refused beside an external device (`Error::Invalid`).
- The renderer never submits on an external device: `RenderDevice::submit` hands `SubmitInfo2` batches to `HostSubmit`, which the host splices into its own queue order. A render waits on the frame three renders back, so the host submits at least every two renders.
- `ExternalTarget::onto(ExternalImage)` draws over the image's contents (`Canvas::over_contents` → no clears, whole-scene damage each draw so backdrop caches re-blur the changed underlay); the image stays in its layout (`ALL_COMMANDS` barriers both ways) and `transform` covers bottom-up hosts (`Flipped180`). Images need color-attachment and sampled usage.
- rikka-ui glass regions (`Ui::glass()`, logical px like Wayland regions) become backdrop nodes at z −1 placed at shape × UI scale (the scene is physical px), with the theme's blur radius × lens frost × scale and the lens scaled by the UI scale (rikka-ui-host `panes.rs`), as the compositor does for windows; solid themes draw no blur. `Composer` beats image pulses after each draw and shares rikka-ui-host's `tasks.rs` (`Tasks`, aborted on drop) with `Embedder`.
- `Embedding` takes `&self` everywhere: opens, closes, resizes, leaves, rejoins and re-themes requested from inside its own callbacks are deferred and applied when the running call returns; re-entering `handle_event`/`draw` panics, so hosts must never forward input (`pointer_leave`, key or pointer calls) from inside a surface's callback. Close and ask-to-close requests and the unclaimed close command run the surface's close handler; other window requests are ignored.
- Theme and background are embedding-wide (`set_theme`, `set_background`, held by `embedded/look.rs`); `Embedding::set_surface_background(id, SurfaceBackground)` gives one surface its own background (`Embedding` follows the embedding's, `Desktop`, `Fixed(Background)`), so a HUD can blur or refract differently from a menu over the same device. The SDK exposes it as `embedded_surface.set_background`/`follow_background`.
- Embedded surfaces `arrive()` (first-view transitions play) and have a transparent `Ui` background: rikka-ui turns a translucent background of a surface without its own glass into a whole-surface glass pane, which would blur the host's frame under glass themes. `leave(id)`/`rejoin(id)` drive `Ui::leave`/`rejoin`; after a draw where a leaving surface no longer `needs_render`, its `Embedded::on_left` handler runs once.
- `rikka_app::embedded` builds on Linux and Windows; `embedded/desktop/` is the one platform seam: on Linux `follow` applies the session locale and runs `wayland::settings::follow`, mapping `SessionChange::Appearance { appearance, theme }` (theme only when the resolved theme changed) to `Mail::Appearance`; on Windows it holds a `rikka_appearance::AppearanceWatch` (WinRT `UISettings.ColorValuesChanged` + `AccessibilitySettings.HighContrastChanged`) and posts `Appearance::current()` and its theme only when the appearance changed. `embedded/look.rs` (`Look`) wears that theme unless `set_theme(Some(slug))`/`set_background(Some(Background))` override it, re-deriving with `with_theme`/`with_background`, which both `Appearance`s offer (on Windows: a named theme dressed as a spec, or the Fluent theme through `Theme::glass`/`Theme::liquid`, with the default glass blur; high contrast always wins). Mail is collected only when the host enters the embedding (draw, input).
- `Ui::handle_event` returns whether a widget used the event; hosts route unused input themselves.
- `rikka_widgets::scaled(child, factor)` (SDK `scale` modifier) zooms a subtree's drawing about its top-left via `PaintCtx::set_subtree_scale`; hit routes (including anchored ones) and delivered pointer positions are unzoomed through `runtime/zoom.rs`, so zoomed controls are hit where drawn; the paint walk raises the `ZOOMED` table flag so unzoomed trees skip the lookups.
- Tests: GPU tests in `rikka-renderer/tests/external.rs` make their own host device (`tests/external/host.rs`).
