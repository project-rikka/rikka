- `system/rikka-compositor` builds the `rikka-compositor` library and binary (shipped in the session tree) over the `crates/compositor` compositor toolkit. Facade: `Launch::{kms,nested,headless}(..).profile(..).desktop(..).socket(..).start()`, then `run`; `inject(Injected)`, `snapshot()` and `x_display()` are test hooks.
- `Compositor` (state.rs) holds subsystems: `core`, `backend`, `outputs`, `surfaces`, `shell`, `seats`, `windows`, `locking`, `presence`, `frames`, `scenes`, `captures`/`capture`, `effects`, `leasing`, `cursor`, `input`, `policy`, `settings`, `session`, `x11`. One `rikka_compositor_types::OutputId` names a display everywhere (backends, render, capture, `Desktop`, `Surfaces`, the KMS cursor route): `outputs::Outputs::connect(head)` allocates it through the `rikka_compositor_output::Outputs` it holds (`outputs.wayland()`: `is_published`, `output_of(&WlOutput)`, `name`, `named`, `resources`), beside each head's backend record (`Head`, asked and applied `OutputConfig`, cursor plane) and the announced colour descriptions. `outputs/announce.rs` `announce_outputs` publishes lit outputs (their `OutputInfo` derived from the applied config), withdraws unlit ones and forgets disconnected heads.
- `split()`/`backend::<B>()` give a backend plus `Parts`; `render/compose.rs` gives `Parts` inherent `compose`, `frames_done`, `feedback`, `presented`, `refreshed`, `covering`. `backend::<B>()` downcasting is only for a backend's own reactor callbacks; DRM leases go through `Backend::leases() -> Option<&mut dyn Leases>`. Backends push input into `parts.input.pending` and call `frames.input_arrived()`.
- One idle `dispatch_frames` per turn: dispatch pending input into the seat (`dispatch_pending_input`) (then mirror the person's Caps/Num Lock onto keyboard LEDs through `Backend::show_leds`), run queued `KeyAction`s, update presence (enter/leave, main output, preferred scale) only when a frame was requested since the last update (`FrameScheduler::take_changed`), feed `rikka_compositor_surface::refreshed`, serve captures and confirm locks for finished outputs, then `Backend::schedule`. `FrameScheduler::request(output)`/`request_all()` carry no reason. `each_turn` flushes paced configures (one patience timer at the earliest unacked deadline) and publishes `rikka.toplevels`/`rikka.workspaces` when `session_changed()` was called.
- Methods live with the state they change. `Compositor` keeps the public facade (`socket_name`, `reactor`, `run`, `stop`, `x_display`, `snapshot`, `inject`), wiring (`split`, `backend::<B>()`, `settle`), the loops (`each_turn`, `dispatch_frames`, `answer`), input delivery through the seat's key filter and grabs (`dispatch_pending_input`, `pointer_*`, `gestured`, `touched`, `virtual_pointer`, `agent_*`, `person`/`agent_seat`), display configuration (`displays_detected`/`resized`, `arrange`, `configure_outputs`, `announce_outputs`) and settings application (`settings_changed`, `policy_changed`), plus the `*Host` impls. Everything else is a method of an owner (`Windows`, `Presence`, `Leasing`, `Sandboxes`, `Throttle`, `Resting`, …, taking collaborators as parameters) or of a per-area borrow context in `src/context/`: `WindowsCtx` (core, outputs, surfaces, shell, seats, windows, frames, scenes, cursor, input, selection, animations, snap, switcher, session, policy, x11), `InputCtx` (+ backend, throttle, resting, settings), `LockCtx` (+ locking), `CaptureCtx`, `SwitcherCtx`, `SessionCtx`, and read-only `WindowsRef`, `InputRef`, `CaptureRef`, `SwitcherRef`, `SessionRef` for `&self` queries.
- Contexts drive the seat and selection through borrowed parts (`person!(ctx)`, `agent_seat!(ctx)`, `seat_parts!(ctx)`, `selection_parts!(ctx)`; `parts!(ctx)` builds the backend's `Parts`), so their reports are queued; `Compositor::settle` flushes both crates until nothing is left. It runs after every reactor callback and client request (`Reactor::after_each`), between the steps of `dispatch_frames`, and before every host input delivery. Each has a macro (`windows_ctx!(host)`, `windows_ref!(host)`, …) that borrows the named fields of a `Compositor` or of a wider context, so arguments may still read the other fields; hoist an argument into a `let` when it reads a field the context borrows. A context method calls a narrower context through its macro; contexts never reach the host.
- Each `Output` keeps the config last `asked` for beside the applied one; `arrange` compares against `asked`, so a display that refuses part of a request (no VRR) is not reconfigured again.
- Session seams in `session/`: desktop, shortcuts (`Session::announce`), workspaces (Full only, `holding` ignores minimized windows), toplevels, switcher, activation. Every seam service is a stateless `Service<Compositor>` that acts on the compositor inside the call (`Compositor::answer` → `Seam::dispatch_within`); the hosted `SettingsService` is wrapped by `settings/service.rs`, which runs `settings_changed` after each settings call. Workspaces, toplevels, switcher, display power and the caret keep their published state in `session::Announced<State>`, attached to the publisher `SeamHost::register` returns. `wayland/sandboxes.rs` serves privileged `wp_security_context_manager_v1`: a committed context accepts on its socket with `ClientOptions::security_context` until its close fd hangs up.
- Test harness: `tests/common` `Harness::{headless, full(extent, settings)}` (waits are event-driven: `frame_where` hooks the reactor's `each_turn`, client waits poll the Wayland fd through rikka-test-display); `common::client::Client` derefs to `rikka_test_display::Client<Recorded>` and adds the compositor's own globals and `pixels` (a `rikka_test_display::Canvas`) with `click`/`inject`/`press` (pointer, keys, touch), `x11()`, `socket()` and `ask(Request)` over the session seam, plus `shows`/`mapped`/`tile`; client helpers for xdg, popups, layers, lock, seat, capture, and `common/input.rs` (both seats, virtual keyboard/pointer, text-input, input method, pointer lock, idle).
- Tests: one binary `tests/main.rs` over the headless harness (`gpu = True`) with topics `color`, `frames` (background, damage, frame callbacks, presentation, fifo, glass), `windows` (xdg, popups, layers, lock, tiling, Xwayland), `input`, `selection` (Wayland↔Wayland, X11→Wayland), `output_capture`, `window_capture`, `window_views`, `workspaces`, `switcher`, `virtual_input`, `desktop`, `sandbox`; `tests/machine.rs` runs the real KMS backend on vkms (`secondary_gpu`).
- Pure rules live in crates with hermetic tests, the binary keeps wiring: `rikka-compositor-tiling` (dwindle `Tree<T>`, `Gaps`, `Edges` + `EDGE_REACH`), `rikka-compositor-snap` (`Layout`/`templates`/`at_edge`, `Bar`, `Divider` + `between`/`pulled`/`shift`, `slots`/`fitted`), `rikka-compositor-panes` (`read_panes`: blur region → rounded panes, the inverse of `rikka_blur::rectangles`), `rikka-compositor-pixels` (`SHM_FORMATS`, `area_to_rgba`, `damaged_rects`, `write_rows`), `rikka-compositor-scrolling`, `rikka-compositor-planes`, `rikka-compositor-swipes` (`Swiping::handle(gesture, pointed) -> Outcome`: announce, scroll the strip or pass to the client), `rikka-compositor-restarts` (desktop crash back-off), `rikka-compositor-recency` (focus MRU with the pointer-glance dwell), `rikka-compositor-switcher` (Alt+Tab choosing, steps and modifier holding).
- Window policy is in the compositor-windows note, input, the agent seat, X11 and selection in compositor-input, rendering, glass, frame callbacks and capture in compositor-render.
