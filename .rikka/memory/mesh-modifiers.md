- Public crate `rikka_mesh_modifiers`, used by rikka-blend (`read/modifier/` parses SDNA records into these descriptions, keeps Armature as its own skin binding).
- Descriptions are plain data with the reference defaults (`Default`) and property names: `Modifier { name, show_viewport/render/in_editmode/on_cage/expanded, pin_to_last, kind: ModifierKind }` (`pin_to_last` only orders the stack); kinds Mirror, Subdivision, Solidify (Simple and Complex), Array, Weld, Triangulate (reuses polymesh `QuadMethod`/`NgonMethod`), EdgeSplit, Displace, Shrinkwrap, DataTransfer, SmoothByAngle, Bevel, Boolean, Decimate, plus Armature, which the stack never evaluates (`SkipReason::SceneEvaluated`; rikka-blend binds a skin instead). Every description implements `rikka_file_format::Codec`; decode rejects unknown tags, non-finite floats and out-of-range values.
- References are opaque ids (`ObjectRef`, `TextureRef`, `CollectionRef`, `MaterialRef`, u64 newtypes); vertex groups by name. `ModifierType` holds the reference's per-type flags (edit mode support/default, mapping support, deform-only, non-geometrical).
- `Context` (object matrix and material count required; other objects' matrices and meshes, `target()` cache hook returning `Arc<Target>`, textures through `Texture::sample`, bone matrices, deforming bones, opaque `armature()` as `&dyn Any`; Boolean reads `materials()` (own slots, default `None` × count), `object_materials(object)` and `collection_objects(collection)` (recursive members in the reference's order); without operand slots no remap table is applied). `Target` wraps an `Arc<Polymesh>` and lazily builds looptris, `TriangleBvh`, `PointTree`, `SegmentBvh`, the reference-layout k-DOP edge tree (`kdop.rs`, reference kdopbvh build and DFS ray cast, needed because edge spherecasts prune by box distance), normals and shrinkwrap boundary data. `Standalone` is the no-scene context.
- `evaluate(cage, stack, ctx, Purpose::{Viewport, Render, EditMode, EditCage})` returns `Evaluated { mesh, origins, control_edges, notes }`. `EditCage` stops after `cage_index(stack)` (the reference's rule). Disabled or failing kinds become `NoteKind::Skipped(SkipReason)` and pass the mesh through. Decimate reports `NoteKind::FaceCount` (the UI's face count); Boolean Transfer reports `NoteKind::MaterialSlots` (the result's slot list, which later Transfer booleans in the stack continue from); Manifold solver runs Exact with `NoteKind::ManifoldSolverAsExact`.
- Modifiers that need the editable mesh run on `rikka_mesh_edit::EditMesh` through `evaluators/editing.rs` (`Editing::new`/`finish`: active shape key cleared so positions stay the evaluated ones, origins sealed): Bevel (`rikka-mesh-bevel`), Decimate (`rikka-mesh-reduce` explicit-input functions), Edge Split (edge split with `separate_vert` in disk order) and the Mirror bisect (own bisect port). Boolean uses `rikka-mesh-boolean` (Fast collections step operand by operand like the reference). Custom normals that the reference keeps as short2 fan-space data are carried encoded (`normals::encode_custom`/`decode_custom`) through Triangulate, Bevel (unless harden normals) and Complex Solidify.
- Origin maps ride through every evaluator as hidden int attributes `.rikka_origin_point/edge/face` (value + 1, 0 = none) and `.rikka_control_edge` (optimal display); copies keep them, interpolated elements are cleared explicitly, weld unifies merge groups first. Around EditMesh and boolean evaluators `origins::seal`/`unseal` add hash check attributes so mixed (interpolated) origins clear themselves. `origins::strip` removes them for `apply`.
- `apply` refuses shape keys unless the kind is non-geometrical (the reference); `apply_as_shape_key` needs a deform-only kind, evaluates on the mixed key positions and adds a key named after the modifier (creating the basis). Deform-only evaluators also offset shape keys by the same displacement.
- Complex Solidify (`evaluators/solidify/complex/`) is MOD_solidify_nonmanifold: `adjacency` (merge by threshold, edge-shaped null faces, duplicate faces, sorted new edges with C's float/double angle mix), `groups` (edge groups, long-group splits, singularities, new vertex numbering), `placement` (Constraints/Fixed/Even, boundary fix, clamps), `output` (the reference's vertex/edge/face order, fill faces, rims, shells, creases, bevel weights, shell/rim groups).
- `evaluate_cached(…, &mut StackCache)` is `evaluate` with per-modifier state kept by the caller (Subdivision reuses its stencils and output when only positions changed; see the model performance note).
- Subdivision (`evaluators/subdivision/`) refines level by level through CSR stencils; levels ≥ 2 then `order.rs` permutes the result into the reference's `subdiv_foreach` layout (ptex parameters tracked per face corner and per coarse-edge point); Simple subdivision interpolates UVs linearly like the reference.
- Exactness: oracle tests in `tests/oracle/*.rs` are generated from the reference runs (inputs use the reference's edge order; `tests/compare.rs` `MeshData` builds inputs and compares order-independently, `assert_order` exactly). Known deviations: the corner UV-smooth variants are untested against the reference; rikka-mesh-boolean's Fast solver gives wrong results for some corner cuts (tests avoid them).
- Subdivision keeps rikka-blend's stencil refinement: limit positions use exact limit masks, except valence-2 boundary corners which the reference (end caps) leaves at their position after `quality` refinements.
- Data Transfer bool layers (sharp face/edge, seam) follow `data_transfer_layersmapping_add_item_attr`: nothing when the source lacks the layer, the destination layer is created when missing; face interpolated-normal-projected ray counts emulate C's out-of-range cast (0 rays) and never exceed the face's total, so self-overlapping faces finish like the reference.
- WeightedNormal, CorrectiveSmooth and Lattice are reference-exact (oracle `tests/oracle/deform.rs`, generated by a headless reference script that is not committed; corner normals match within two short2 quantization steps). WeightedNormal writes object-space `custom_normal` through `encode_custom_normals`/`decode_custom_normals`, keep-sharp items are `Polymesh::corner_fans`; face influence reads `__mod_weightednormals_faceweight`.
- CorrectiveSmooth's Original rest source reads `Context::original_positions` (the mesh data before the stack), falling back to the stack input; Bind uses `bind_coords`.
- Lattice has no lattice object: `LatticeGrid` embeds resolution (≤ 64 per axis, ≤ 32000 points), per-axis interpolation, `transform` (lattice space → object local; rest grid spans −0.5..0.5 like a fresh reference lattice) and editable `points`; `fitted`, `resized` (keeps the deformed shape) and `reset` are its editing API. rikka-blend folds a referenced lattice object into the grid on read and writes a lattice object parented to the mesh on write.
