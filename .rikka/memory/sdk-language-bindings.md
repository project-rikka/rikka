title: SDK Go, C#, Java and Python bindings
description: How the codegen projects rikka.ridl into Go, C#, Java and Python: shared rules, runtimes, Bazel rules and tests.
about: sdk/codegen/src/languages

- Each language is `sdk/codegen/src/languages/<language>/{mod,spelling}.rs` plus `templates/<language>/`; shared pieces live in `languages/projection.rs` (the `Linker` trait every `Spelling` implements for doc links, `items` per class, builder setters with `set_` stripped, trampolines per (callback, closure position), `Docs` with `with_param`/`with_returns`/`with_paragraph`, `literal`, `soname`, `single_error`, `callback_name`), `languages/keywords.rs` (reserved words per language), `languages::wrap` and `names::pascal_with_acronyms`.
- Name clashes are checked once by `projection::validate(api, Vocabulary, &dyn Naming)`: C#, Java and Python pass their reserved type and member names and implement `Naming` (flag and callback type names, the names one member claims) on their `Spelling`; Go keeps its own check because every exported name shares one package namespace. `projection::modifiers(items)` is the one walk over a class's modifier declarations.
- Generated calls do every check that can fail before taking ownership of an argument or retaining closures, so a failed call leaks nothing; Python hoists its conversions into locals only when the call takes or registers something.
- Shared rules: `usize` is the language's index type with `none` = -1; userdata is a key/handle to a pack of closures, freed by one destroy trampoline; scoped classes are lent wrappers expired after the callback; `Element` carries a declaration serial so a stale modifier fails instead of hitting the wrong node; local (thread-bound) handles released by a GC/finalizer/cleaner on another thread are queued and drained on their owner thread at the next trampoline or local constructor.
- Go (`sdk/bindings/go`, module `github.com/project-rikka/rikka/sdk/bindings/go`, Go 1.24+): cgo with `#cgo pkg-config: rikka`, `//export` trampolines in `callbacks.go`, `cgo.Handle` userdata, `runtime.AddCleanup` + `runtime.KeepAlive`, `init` locks the main goroutine's thread, `Status` implements `error` and `*Error` unwraps to it, enum constants are `<ValuePrefix><Variant>`, output is gofmt-clean (const blocks aligned per section).
- C# (`sdk/bindings/csharp`, `Rikka.csproj`, net8.0, C# 12): blittable `[LibraryImport]` with `DisableRuntimeMarshalling`, `[UnmanagedCallersOnly]` function pointers, `GCHandle` userdata, `SafeHandle` + `Lease` per call, properties, `XxxCallback` delegates, `RikkaException`, statics in `Sdk`; callback exceptions fail fast.
- Java (`sdk/bindings/java`, Maven `os.rikka:rikka`, module `os.rikka`, release 22): FFM downcall/upcall handles in `Native`/`Trampolines`, `Handle` (Cleaner, closure registry, deferred releases), JavaBeans getters, builder setters without `set`, flags as `Set<Flag>`, open enums as records, statics in `Rikka`; one file per type, so `TYPES` in its BUILD lists every generated file; callback exceptions go to the thread's uncaught handler.
- Python (`sdk/bindings/python`, src layout, 3.10+): ctypes (`usize` as `c_ssize_t`), `weakref.finalize`, `IntEnum`/`IntFlag` (open enums via `_missing_`), frozen dataclass structs, builder setters also as keyword arguments, containers are `with` blocks, a trailing callback after other parameters may be omitted to get a decorator; callback exceptions go to `sys.excepthook`, `SystemExit` ends the process, `App.run` restores default SIGINT while it blocks.
- Bazel: `//bazel/{go,csharp,java,python}:defs.bzl` drive the Nix toolchains (`NIX["go"|"dotnet"|"java_home"|"python"]`), which the RBE image carries; their actions run `NIX["bash"]` through `ctx.actions.run`, because `run_shell` uses Bazel's local `--shell_executable`, which the image lacks. Each language's `_binary` and `_test` rules share one program implementation (launcher `<name>.sh` setting `LD_LIBRARY_PATH` from `$PWD`, so they run from the runfiles root); `rikka_go_binary` builds its `package main` files as `cmd/<name>` inside a copy of the bindings module. Tests are `sdk/tests/<language>/` (Go `testing` with `go vet`, C# and Java main programs, Python `unittest` plus a `mypy --strict` target over a full view declaration). Each binding package has a `package` filegroup of its committed files, which the `sdk` component ships by label.
- Hermetic tests have no display, so callbacks only run on a real session; verify view code by running the language's example (`bazel run //sdk/examples/<language>:<name>`).
