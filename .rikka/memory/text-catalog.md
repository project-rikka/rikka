---
title: Font discovery and matching (rikka-text-catalog)
description: Fontconfig parsing, symlink-safe scan, persistent face index, CSS matching and cached script/emoji-aware fallback.
about: crates/text/rikka-text-catalog
tags: [text, fonts]
---

- Sits on `rikka-text-font`, `rikka-text-unicode`, `rikka-file-format` and `rikka-xml`; third-party deps are only `rustix` (mmap, Linux), `windows` (Windows), `rustc-hash` and `thiserror`. `rikka-text-layout` is its consumer.
- `catalog()` is the process-wide `&'static Catalog` from `CatalogConfig::from_env()`; tests and tools use `Catalog::load(&config)` with `cache_dir` in a temp dir.
- `CatalogConfig` has one font source (`catalog/config.rs` `Source`): `from_env()` gives `System`, `.fontconfig(file)` a fontconfig file, `default()` only the listed `font_dir`s. Platform code lives in `src/system/{unix,windows}` (system fonts, locale, generic preferences, fallback preferences) plus the `unix`/`windows` halves of `discovery/stamp`, `discovery/mapping` and `index/path`.
- Linux system fonts are the main fontconfig file. Discovery: `rikka_xml::parse_lenient` and a fontconfig subset (`src/config`): includes, conf.d, prefixes, `reset-dirs`, `selectfont` globs, `alias` prefer/accept/default. `match` rules are ignored.
- A face's `FaceSource` is a mapped file (path + stamp, indexed) or embedded bytes (`&'static [u8]`, scanned at every load, never indexed); `Face::path()` is `None` for embedded faces. `SystemFonts::embedded` comes first, so embedded faces win ties.
- Windows system fonts: the four UI fonts embedded through `rikka-embedded-fonts` (`UI`, bytes compiled in from `NIX["windows_runtime"]`) first, then the HKLM/HKCU `Fonts` registry lists, `FOLDERID_Fonts` and `%LOCALAPPDATA%\Microsoft\Windows\Fonts`; file identity is volume serial + file index. Built-in aliases send the Noto families Rikka names (`Noto Sans CJK JP/KR/SC/TC/HK`, `Noto Color Emoji`, `Noto Serif`, `Noto Sans`, `Noto Sans Mono`) to their Windows equivalents; the locale is `GetUserDefaultLocaleName`. rikka-text takes its icon fonts from `rikka_embedded_fonts::ICONS` on Windows and from `rikka-shipped` on Linux.
- Rikka's generic choices come first (`system::preferred_families`): Linux sans-serif and system-ui → Inter, monospace → JetBrains Mono, serif → Noto Serif, emoji → Noto Color Emoji, then fontconfig preferences; Windows Inter → Segoe UI Variable → Segoe UI, JetBrains Mono → Cascadia Mono → Consolas, Cambria → Times New Roman, Segoe UI Emoji, Comic Sans MS, Impact, Cambria Math.
- The index lives at `fonts/index` in the rikka-dirs cache dir (`$XDG_CACHE_HOME/rikka`, on Windows under `%LOCALAPPDATA%`): `BinaryFormat` `RKFONTIX` over the shared `Codec` reader (`index/format.rs`, edited in place; an unreadable index is rebuilt; Windows stores UTF-8 paths and leaves non-Unicode paths unindexed), checksummed (`index/checksum.rs`), written by temp file and rename, entries validated by size, mtime and inode (Windows file index).
- Faces are `FaceId`s into one immutable table. `catalog.font(id)` maps the file lazily; mappings are leaked for the process so fonts are `Font<'static>`.
- Matching follows CSS Fonts 4 (width, style, weight) over axis ranges; `FaceMatch` carries axis settings, `synthesis()` (rikka-text-font `Synthesis`), and the strong family chain used by fallback. `catalog.location(&match, px)` adds `opsz`. `Face::ascii_coverage()` is the face's ASCII bitmask straight from coverage page 0.
- Fallback per grapheme cluster: primary covers → primary; emoji presentation tries color faces first, text presentation monochrome first; then the query's strong families, script-named or script-declaring faces, then a lazy page → faces index. Candidates rank first by `system::fallback_families(script, region)` (empty on Linux; on Windows Yu Gothic UI/Meiryo UI/MS UI Gothic for Japanese, Microsoft YaHei UI/JhengHei UI, Malgun Gothic, Nirmala UI, Leelawadee UI, Segoe UI, then Segoe UI Historic, Ebrima, Gadugi, …). `CjkRegion::from_family` also knows Windows CJK families by prefix. Nothing covers → the primary (for .notdef). Answers are cached by a byte key.
- `LoadReport` lists config, font and index problems plus scanned and reused file counts.
