---
title: Keyring (Secret Service) and the secrets client
description: rikka-keyring serves org.freedesktop.secrets over an encrypted vault; rikka-secrets is the one client every app uses.
about: crates/daemons/rikka-keyring
tags: [security, secrets]
---

- Every secret Rikka keeps (LLM keys/tokens, MCP OAuth, Discord, music services, remote hosts, Minecraft accounts) lives in the keyring; nothing writes credentials to settings or 0600 files. Third-party apps reach the same store through libsecret.
- Layers: `rikka-secrets-protocol` (internal: D-Bus names, `WireSecret` `(oayays)`, `plain` and `dh-ietf1024-sha256-aes128-cbc-pkcs7` transports) ← `rikka-keyring-vault` (internal: file format and crypto) ← `rikka-keyring` (public: `Daemon::new(folder).binding(Binding::SystemdCredentials).serve()`) ← `system/rikka-keyring` (binary `rikka-keyring`: non-dumpable, core limit 0, D-Bus/systemd-user activated, folder `$XDG_DATA_HOME/rikka/keyrings`).
- Vault file `<name>.keyring` (JSON, 0600 in a 0700 folder, flock `.lock` for writes, reloads when another instance changed it): random 256-bit master in LUKS-like slots (Argon2id m=64 MiB t=3 p=4 password slot; `wrapped` slot by the login keyring; `bound` slot whose key systemd-creds seals with TPM2+host key); HKDF-SHA256 subkeys; XChaCha20-Poly1305 over the whole contents (labels and attributes too) and again per item secret, with AADs binding keyring id, creation time and item id. Keys sit in one mlocked, MADV_DONTDUMP page. Locked collections expose no items (locked search finds nothing, as in oo7).
- Collections: `login` (alias `default`/`login`, may be absent), user-created ones wrapped by login, in-memory `session`. Unlock happens only through `Login`/prompts; locking only by `Lock`/exit.
- Private interface `os.rikka.Keyring1` on `/org/freedesktop/secrets`: `Login(secret)` → created/unlocked/changed/refused (an open keyring follows a changed login password; a refused one remembers it and rewraps after the previous password answers a prompt), `Answer(prompt, secret)`, `Reset()` (only after a refusal), `SetAutoUnlock(b)`; properties `State` (absent/locked/refused/unlocked), `AutoUnlock`, `Asking` (shown prompts). Sessions belong to the caller's unique name; passwords travel sealed by the caller's session.
- `rikka-secrets` (public): `Secrets::shared()` (process-wide connection + DH session, reopened on NoSession), `Secrets::unlocked()` (shared, prompting if locked), `Entry::new(schema).attribute(..)`, `store/store_json`, `contains` (no secret fetched), `lookup/lookup_json`, `search`, `remove` (every match), `items`/`delete` (Settings), `unlock()` (prompts, waits), `changes()` (`Change::Items|Keyring`), `keyring()` → `Keyring` admin; `blocking::Secrets` for sync callers. Reads and writes on a locked keyring return `Error::Locked` and never prompt.
- Schemas are the constants in `rikka_secrets::schema` (`LLM` by backend, `MCP` by server URL, `DISCORD` by account folder, `MUSIC` by folder + kind, `REMOTE` by host pin, `MINECRAFT` by kind device/account + id; `ALL` lists them, `ATTRIBUTE` is the `xdg:schema` attribute); Settings names apps from them and backups carry exactly these items (`Found` has the label, `Entry::from_attributes` rebuilds an exact match). discord-core and music-core wrap them as `keep_secret`/`kept_secret` (prompting) and music-core's `renew_secret` (background renewals, never prompting). Account removal in discord-core/music-core also removes the folder's secrets.
- Shell: the lock gate hands the first hidden PAM answer to `Login` after a grant; `features::keyring::KeyringPrompt` (sharing the lock's `SessionLock`) shows the unlock/create/changed dialog only while the screen is open, opens a prompt itself after a refusal, and calls `SetAutoUnlock(!rikka.lock/at-login)`. Settings has a "Passwords & keys" page (state, items, delete, unlock).
- Tests: `rikka-test-keyring` (`TestKeyring::unlocked()`: private bus + in-process daemon logged in with `PASSWORD`); `rikka-keyring` tests libsecret's `secret-tool` (dev shell) as oracle; `tests/machine.rs` checks real systemd-creds auto-unlock.
