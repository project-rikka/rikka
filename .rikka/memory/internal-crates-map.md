title: Internal crate ownership map
description: Every crate folder under crates/<layer>/ with a one-line role or the note that documents it.
about: crates

- Dependencies point toward `foundation`. `session` may use `desktop`, never the reverse; `status` sits above `daemons` and `session`; `physics` above `model` and `graphics`. Names drop the `rikka-` prefix; which crates are public is in the public-crates note.
- `foundation`: types, input (core-types-and-input note); dirs, shipped, fs, watch, deflate, encoding (foundation-files note); worker, sync, heap, log, format, interfaces (foundation-runtime note); pipewire (pipewire-helpers note); wayland-wire, wayland-scanner, wayland-protocols, wayland-client, wayland (wayland-client-codec and wayland-client-layer notes); i18n, i18n-catalog, i18n-macros, languages (internationalization note); net (network-client note), oauth (oauth-library note), certificate-transparency, archive (archive-processing note), file-edit (file-edit-gates note), file-format (file-formats note), simd (simd-library note), fuzzy (fuzzy-matching note), xml, color-formats (their notes); keyframe (timeline-keyframe note); color-lookup (`.cube`/`.3dl` LUTs into `ColorLookup` for the renderer and rikka-image-edit); emoji (CLDR emoji table, localized names, tones, search); public-suffix (in-house PSL matcher: `suffix`/`icann_suffix` → `Suffix { as_str, section }`, `registrable_domain`, `site`, `is_public_suffix`; the committed `data/public_suffix_list.dat` is compiled into a sorted blob by the binary package public-suffix-compiler through `run_binary`; tested against the official `tests/test_psl.txt`; used by rikka-omnibox, browser-pages and rikka-fido); grammars (tree-sitter grammar identity, lazy dlopen and `Grammar::syntax_errors`, for rikka-syntax and rikka-file-edit); test-bus, test-certificate-transparency (testing note).
- `desktop`: open, dialog, clipboard, clipboard-core, instance, mime, xdg, trash, mounts, thumbnails, xcursor (xdg-desktop-integration note); file-operations (file-operations note); screencast (screencast-capture note); fido, test-fido (fido-client note); secrets, secrets-protocol (shared with the keyring daemon), test-keyring (keyring note); notify (client of `org.freedesktop.Notifications`: `Notifications::notify/close/events`; never hosts it); pam (`Authentication::start(service, user, report)` runs one libpam conversation on a `rikka-pam` thread; `system/rikka-pam-helper` serves it through `rikka_pam::serve`); portal-request (the portal `Request` handshake `ask(connection, |token| call)` → `Answer`, for dialog and screencast); account-book (`Accounts<R: Record>` of signed-in accounts with 0700 folders, `PendingAccount`, `Removal` off the caller's thread, `Vault`/`FolderSecret` keyring entries; used by Discord and Music).
- `session`: seam (session-ipc note), session (session-protocols note), settings (session-settings note), appearance, blur (themes-and-glass note), present (surface-presenter note), virtual-input (virtual-input note), portal and portal-backend (system-portals note), capture (screen capture and the `BufferPool` shared by replay, remote and record), record (screen recording to a file over capture, video and audio, dmabufs through Vulkan Video when it can; the shell uses it), window-view (client of the private `rikka_window_view_v1`: compositor-drawn live windows inside a shell surface), test-seam (`Host` running a `Seam` on a thread).
- `daemons`: bus (the D-Bus runtime; daemon-integration note) and one crate per daemon, no aggregate: sound, network, bluetooth, power, battery (daemon-crates note); notifications, tray, polkit (hosted-daemons note); mpris, privacy, power-profiles, location (mpris-privacy-profiles note); keyring over keyring-vault (keyring note); ime (input-method note); accounts (AccountsService: `Accounts::current`, `Account`); timedate (timedated `State`); rtkit (realtime thread grants, `drop_sys_nice`); boost (gpu-boost note); test-objects (fake ObjectManager service for bus tests).
- `status`: sysmon (system-monitor note), nvml (loads NVML at run time and re-exports `nvml_wrapper` device types), weather (weather-and-activity note).
- `text`: `text-{unicode,font,shape,raster,catalog,layout,document}` (`text-<name>` notes), the UCD generator text-unicode-gen, test-fonts (text-test-fonts note), embedded-fonts (Windows only: the Inter, JetBrains Mono and icon font bytes compiled into Windows programs; text-catalog note).
- `graphics`: gpu (gpu-core note) → renderer (renderer note) → renderer-3d (renderer-3d note); picture (`SharedGpu`, `Pulse`, `RefreshRate` picture hand-off over gpu only; ui-crate-layering note); colorimetry (color-management note); text (Rikka layer over `crates/text`; text-shaping note); shader-build (the slangc driver behind every `shaders/` package); spirv (SPIR-V walker, shared slangc settings, `reflect`, build-time `Shader`/`Facts`/`content_hash`); shader-programs (material template entries, `Variant`, `BuiltinTemplate`, program compilation shared by renderer-3d and its shader build); slang (rikka-slang note), shader-graph (shader-graph note); ltc (GGX LTC fitter and committed table); ies (IES profiles); symbols, symbols-scanner (icon-fonts note); image, image-ffmpeg (image-codecs note); image-edit (imaging-engine note); png, image-resample, material-color, barcode (graphics-cpu-crates note); psd (psd-format note), psd-render, svg (svg-renderer note), vector (vector-library note), theme (themes-and-glass note), theme-seed (wallpaper-material note); icons (freedesktop icon theme lookup `Icons`; xdg-desktop-integration note); path-data (SVG path `d` into absolute `segments`); effects, figure (effects-shared and figure-shared notes); test-renderer, test-renderer-3d.
- `media` (media note unless named): audio (audio-engine note), audio-decode (audio-decode note), audio-tags (music-local note), ring, playout (playout note), resample, opus, coded, annexb, rate-control (remote-protocol-transport note), ffmpeg, fft, media, media-format, movie, video-core, video-play (video-playback note), video, dmabuf-convert (video-coding note), vulkan-video (vulkan-video-encoder note), hifi, hifi-core (hifi-output note), apm over apm-audio, apm-aec3, apm-ns, apm-agc2 (apm note).
- `model`: model, model-core, model-gpu (model-import note); gltf, vrm, fbx, mmd, blend, stl (`<name>-codec` notes), humanoid (humanoid-recognition note); the mesh libraries polymesh, mesh-edit, mesh-reduce, mesh-bevel, mesh-boolean, mesh-modifiers, spatial (their own notes; performance rules in the model-performance note) and test-meshes (mesh-robustness-sweeps note). They layer one way: spatial → polymesh → mesh-edit → the mesh-* operator crates → mesh-modifiers → blend (which evaluates .blend modifier stacks on import).
- `physics`: the CPU rigid engine `physics-{math,core,geometry,collision,rigid,world}`, the GPU fluid physics-fluid, liquid presets and throws physics-liquid (`Liquid`, `Preset`, `Throw`), compute helpers physics-gpu (`Pass`, `Ring`, `Scan`, `kernels!`), cloth data physics-tailor, GPU cloth physics-cloth and the coupled scene physics (physics-layer and `physics-*` notes).
- `ai`: tool (vocabulary: `Tool`, `Schema`, `Function`, `Reply`, `ToolKit*`, `Image`, `Media`, `Picture`, `Usage`; no network) → llm → agent → mcp; tool + seam → assist; llm → llm-catalog (models.dev metadata and the latest-generation rule) → llm-adapter → `providers/rikka-llm-{anthropic,antigravity,claude-code,codex,compatible,openai,openrouter}` → llm-providers → llm-accounts (llm-providers note); prompt (TOML front matter + Markdown with `{{placeholder}}` from `Facts`) → tool-docs (standard tool documents, `facts()`, `Naming`) → tools → thread; computer (a headless machine or the person's desktop through the agent seat) → computer-use (the Computer tool); thread + widgets → chat; usage-bar (usage gauge widget); test-llm, test-mcp.
- App assistants and `rikka-assist` depend only on `rikka-tool`, `rikka-tool-docs` and `rikka-prompt`, so offering tools links neither the HTTP client nor screen capture into an app.
- `ui` (ui-crate-layering note): animation, ui, ui-host, ui-video, ui-macros (`#[derive(State)]`, `#[derive(Widget)]`), syntax and the binary package syntax-queries (embedded tree-sitter queries), widgets, markdown, seat, app, terminal, timeline (timeline-keyframe note), nested (compositor-nested note), effects-forms, figure-editing, viewport (`Viewport3d`, `SceneCtx`, `viewport` over `rikka_ui::Offscreen`; the only ui crate on renderer-3d).
- `compositor` (`compositor-*` notes): server, protocols, reactor, geometry, types, surface, seat, shell, output, selection, desktop, kms, xwm, input, the pure rule crates tiling, snap, scrolling, planes, panes, pixels, swipes, restarts, recency, switcher (Alt+Tab choosing rules; window-switcher note), caption (server-side caption layout and hit parts; server-side-decorations note), and test-display (testing note).
- `nix`: nix (configuration, `Draft`, the nixctl client, `Monitor`), nix-protocol (wire records shared with the daemon), nix-log (internal-json decoding, progress tally), nix-journal (nixctl's run records and paged logs), nix-edit, nixos-layout (nix-libraries note), test-nixfmt (shared with the installer).
- `proton` (proton-library note): proton-client beside `proton-{pgp,api,account,key-transparency,cache,mail,contacts,calendar,contentline,names,drive,drive-sync-state,drive-sync,pass,authenticator,vpn}`; contentline is vCard/iCalendar content lines, names numbered file names, drive-sync-state the sync plan and SQLite state; test-proton, test-proton-drive.
- `remote`: remote-wire, remote-link (remote-protocol-transport note). `web`: web (web-engine note), web-crx (CRX3 packing and signing under the Rikka identity), web-pack (build tool zipping the extension), test-chrome (testonly Chrome launcher for machine tests), omnibox (browser-crates note), html (html note).
