---
title: rikka-compositor-kms display backend
description: Native libseat/udev/DRM/GBM crate with a per-GPU rikka-kms-N commit thread, vblank timeline and frame pacer.
about: crates/compositor/rikka-compositor-kms
tags: [compositor, kms]
---

- `rikka-compositor-kms` depends only on `rikka-compositor-reactor`, `rikka-rtkit`, `rikka-colorimetry` (EDID and metadata vocabulary) and thin FFI crates; it knows no Wayland, renderer or compositor state type.
- State thread owns `Session` (libseat), `Hotplug` (udev, every card on the seat: `Added(Gpu)`, `Changed(dev)`, `Removed(dev)`), `Device` (enumeration, `Swapchain`s, client dmabuf `import`, per-CRTC cursor buffer pools) and `Output`s. `Gpu::all(seat)` lists cards boot GPU first; `Gpu::name()` is the sysfs name (`card1`).
- `Device::enable_output(connector, OutputConfig, Buffers)` picks where scan-out buffers come from: `Rendered(formats)` (GBM, for a renderer on this device), `Shared(formats)` (linear, for a renderer on another device; dumb + PRIME export when GBM is missing), `Imported(dmabufs)` (another device's buffers, PRIME-imported, moved into the swapchain) or `Mapped(fourccs)` (CPU-written dumb buffers in the first listed fourcc the plane scans, `Swapchain::mapped`). GBM is optional; without it cursors use dumb buffers too. `primary_formats(connector)` previews the plane formats enabling would use. `reconfigure_output` changes mode/bpc/VRR of an enabled output, `disable_output` turns it off; `FrameOutcome::{Committed, Empty}` is one frame attempt.
- `Session::opener` gives a Send `DeviceOpener` whose `open` blocks on a reactor mailbox serviced by the state thread; calling it from that thread errors.
- Each `Device` spawns one `rikka-kms-<minor>` thread with its own `Reactor`; it alone issues atomic commits (reset at start, modesets, flips, cursor, restore on resume). Property ids, connector lists and probes are read on the state thread and handed over.
- Commands go in as `Present`, `Device::set_cursor_pixels/clear_cursor/set_vrr/pause/resume/disable_output`; results come out as `KmsEvent` on a caller-made `Sender`.
- `CursorControl::cursor_at` only writes a per-CRTC atomic slot and rings the thread's own eventfd when the slot was not already pending; the commit reads the latest position.
- Every `Present` ends in exactly one `Retired`, alone or inside `KmsEvent::Flipped`, which hands its `Framebuffer`s back; `Framebuffer` is an Arc and RMFB runs on the last drop. Cursor pools outlive the KMS thread, so it never frees cursor buffers.
- A swapchain slot or cursor pool buffer is free when no one but its owner holds its `Framebuffer`.
- Fixed-refresh outputs commit at `next vblank - lead`; VRR and phase-less outputs commit when ready. Cursor moves never wait for unfinished content; async cursor-only commits come at most twice a refresh.
- `Present::flip(Flip::Async)` asks for a tearing flip: when the card has `DRM_CAP_ATOMIC_ASYNC_PAGE_FLIP` (`Output::async_flips`), no modeset or VRR change is pending, a frame is already shown and the cursor plane has nothing pending, the newest ready frame commits at once with `PAGE_FLIP_ASYNC`, carrying only the primary plane. A refused TEST_ONLY or commit records the config in the screen's `async_refused` and the frame flips on vblank instead. Async flips report `now` without `VSYNC`/`HW_CLOCK` and keep the MSC.
- A VRR change the driver refuses without a modeset is reverted and the screen keeps its VRR state until it is re-enabled (`vrr_fixed`); async cursor commits never carry a VRR change.
- `FramePacer::set_pacing(Pacing)`: `Immediate` plans like VRR (start at once), `LowLatency` and `Immediate` never draw ahead, `Steady` always keeps a second frame in flight, `Balanced` draws ahead by its budget and misses.
- `Output::timeline()` is a seqlock-shared `Timing`; `FramePacer` (state side) turns it plus render cost (CPU time from `finished`, GPU completion from `rendered`) into when to start drawing.
- `Presented::sequence` is the MSC sent in presentation feedback: the driver's flip counter while it advances, otherwise counted from vblank times (nvidia-drm always reports 0). NVIDIA's Vulkan WSI derives commit-timing targets from it, so a stuck MSC holds clients' commits for as long as they idled.
- Hot commits are typed `FrameCommit`s over property ids resolved at open, encoded into a reused `AtomicRequest` and sent with a raw `DRM_IOCTL_MODE_ATOMIC`. The BTreeMap `Plan` only merges cold commits (reset, disable, resume).
- HDR: `OutputConfig::signal(Signal::Pq(HdrMetadata))` lights PQ over `Colorspace` = BT2020_RGB plus an `HDR_OUTPUT_METADATA` blob (`HdrMetadata::blob`, the 32-byte uapi layout), raises `max bpc` to at least 10 and allocates only 10-bit fourccs (XR30, XB30, AR30, AB30; SDR uses XR24/AR24); `Error::HdrUnsupported` when the connector lacks the properties (`Connector::signals_pq`) or imported or CPU-mapped buffers offer no 10-bit format. Colour properties ride only in `Modeset`: every modeset writes both (SDR = Default and no blob), the reset plan detaches connectors to SDR so a previous session's HDR never lingers, a signal change goes through `reconfigure_output`'s modeset path, and a commit carrying a modeset is never asynchronous. `Edid` also parses base-block chromaticity (`primaries`) and the CTA-861 HDR static metadata and colorimetry blocks (`HdrCapabilities`: EOTFs, BT2020_RGB, max/frame-average/min luminance).
- `PlaneProps::blending` resolves `pixel blend mode` = Pre-multiplied and `alpha` when a plane has them; every shown plane sets both.
- Each screen remembers its last 8 TEST_ONLY-validated `Config`s (everything except FB, fence, damage and cursor position); a queued frame is pre-tested when it arrives, and test time counts toward the lead.
- Each lit output claims one primary, cursor and overlay plane; an overlay is claimed only if it stacks above the primary (higher `zpos`, or same `zpos` and higher object id, or no `zpos`), and is hidden at every modeset. `Present::new(crtc, frame, framebuffer)` shows one framebuffer on the primary plane; a refused TEST_ONLY frame carrying a client buffer comes back as `Rejection::Scanout`.
- The KMS thread is promoted through `rikka_rtkit::make_thread_realtime` (direct `SCHED_FIFO`, else RealtimeKit) and then drops any CAP_SYS_NICE it inherited (`rikka_rtkit::drop_sys_nice`).
