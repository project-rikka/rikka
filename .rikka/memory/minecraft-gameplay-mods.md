- Hold-style mods (FreeLook Left Alt, TapLook V, Zoom C) pass `DefaultBind.hold(key)` to the `Mod` constructor, so the framework's own `bind`/`bind_mode` controls make "enabled" mean "active"; switching the mode to Toggle gives the toggle variant. Mods without a default bind use the three-argument constructor.
- Each mod keeps a `static volatile active` (or boolean) set in `onEnable`/`onDisable`; mixins call only the package's public `*Hooks` class (`CameraHooks`, `MechanicHooks`, `VisualHooks`), which returns the vanilla value when nothing is active.
- `camera/`: `CameraHooks` overrides `Camera.alignWithEntity`'s `getViewYRot/XRot` (FreeLook, local player only), `Camera.calculateFov` (Zoom) and `Options.getCameraType` (TapLook wins over FreeLook; FreeLook only swings out from first person). The real camera option is never written, so nothing needs restoring.
- FreeLook never turns the body: `MouseHandler.turnPlayer` wraps `LocalPlayer.turn`, and `FreeLookMod` keeps its own yaw/pitch (seeded lazily from the player, optional yaw limit around that anchor). The same wrap multiplies the turn by `Zoom.sensitivity()`.
- `Zoom` is a log-magnification, critically damped spring (closed form, frame-rate independent) kept outside the mod so it keeps easing after the mod is disabled; fov is `2·atan(tan(fov/2)/magnification)`. Scroll while zoomed cancels `MouseScrollEvent` and moves the target.
- `mechanic/`: SnapTap records press order in `KeyMapping.setDown` and rewrites the four movement reads in `KeyboardInput.tick` through one `WrapOperation` on `KeyMapping.isDown` (last pressed wins, older key resumes on release); HitDelayFix turns `MultiPlayerGameMode.hasMissTime()` false inside `Minecraft.startAttack`; NoJumpDelay zeroes `LivingEntity.noJumpDelay` for the `LocalPlayer` in `aiStep`.
- `visual/`: Fullbright replaces the `Math.max` brightness in `LightmapRenderStateExtractor.extract`; ForceMainHand changes `Avatar.getMainArm` for `RemotePlayer`s only. BloodParticle and Particles react to `HitEvent` (server-confirmed own melee hit); Particles' NATURAL trigger multiplies the server's `ClientboundAnimatePacket` critical/enchanted-hit signals, ALWAYS adds bursts to each own hit. ProjectileTrail spaces particles along the last tick's path within 32 blocks (the particle engine's own cut-off).
- Crosshair wraps the first `blitSprite` in `Hud.extractCrosshair` (VANILLA style keeps it) and its `isFirstPerson` check; custom shapes are a `GuiMesh` drawn in physical pixels (pose scaled by 1/guiScale, sizes are GUI px rounded to device pixels), outline first, `GUI_INVERT` for the vanilla-style blend; dynamic spread from speed, airborne, attack cooldown and bow/crossbow draw.
- HitColor rewrites the red rows of `OverlayTexture`'s `DynamicTexture` (accessor) on the next tick after a change, every tick for chroma, and restores 0xB2FF0000 on disable; the setting's alpha is tint strength (vanilla = 0x4D).
- TargetIndicator remembers the world `EntityRenderState` that `EntityRenderDispatcher.extractEntity` made for `RikkaClient.targets()`'s entity and, after that state's `EntityRenderer.submit`, submits a bobbing gradient ring with `RenderTypes.debugQuads()`; GUI entity previews use `createRenderState` directly and never match.
- TimeChanger overrides `ClientClockInstance.totalTicks()` only for the overworld clock (marked from `ClientClockManager.getInstance` through the `OverworldClock` duck), keeping the day count so moon phases stay; FIXED hour or REAL_TIME local clock. Timelines sample `totalTicks()`, so sky and light follow; gameplay stays server-side.
- `item/`: ItemPhysics and 2D Items disable each other in `onEnable` through the other's static `active`. `ItemEntityRenderer.extractRenderState` advances a per-entity `ItemTumble` (`TumblingItem` duck on `ItemEntity`) into the state (`DroppedItemState` duck); `submit`'s bob translate and spin rotate are wrapped: physics lays flat models (depth ≤ 1/16) on their face and blocks upright, settling to 180°/90° steps on the ground and tumbling in air; 2D Items replaces the spin of flat models with the camera orientation.
- Enum setting labels live under `rikka.mod.<id>.setting.<setting>.<constant>`; `Viewpoint` labels are shared under `rikka.setting.perspective.*`.
- `weather/`: WeatherChanger (CLEAR, RAIN, THUNDER, SNOW with rain/snow/thunder intensity, optional visual lightning) is client-only and touches no server state. `LevelMixin` wraps `Level.getRainLevel/getThunderLevel` and `ClientLevelMixin` wraps `ClientLevel.getPrecipitationAt`, both through `WeatherHooks`, so sky, fog, cloud attributes, rain columns, splash particles and rain sounds follow with no further hooks; `ClientLevel.tick` calls `WeatherHooks.tick`. `WeatherBlend` steps the levels 0.01 per tick like the server does, fades from and back to the server weather on toggle (`LevelWeatherAccessor` reads the server's levels), snaps on a new `ClientLevel`, and stays off where `canHaveWeather()` is false. Thunder is stored as the effective level (thunder × rain). `LightningStrikes` adds visual-only `LightningBolt`s with negative entity ids at a Poisson rate scaled by the thunder level.
- ChunkBorders emits vanilla `Gizmos` lines from `LevelExtractorMixin`, injected right after `DebugRenderer.emitGizmos` inside the main-thread gizmo collector (`VisualHooks.emitGizmos`); `setAlwaysOnTop` draws through terrain.
- TNT Timer writes a coloured `Component` into the `TntRenderState`'s `nameTag` (or `scoreText` when the TNT already has a name) from `EntityRenderDispatcher.extractEntity`, so vanilla's name-tag drawing shows it; remaining seconds are `(fuseRemainingInTicks - 1) / 20`.
- `quickswitch/`: `HotbarItem` is the table of kinds, each a scorer over `ItemScores` (attack damage with Sharpness, mining speed on a representative block with Efficiency, counts); a keybind per kind selects the best hotbar slot with `Inventory.setSelectedSlot`, cycling on repeat presses.
- `privacy/` (Streamer Mode): `NameFilter` is a streaming `FormattedCharSink` (one reusable instance per thread in `PrivacyHooks`) that buffers runs of `[A-Za-z0-9_]` (≤16) and swaps whole-word matches found in `NameTable` (open addressing on two longs packing 6-bit codes, case-insensitive), decoding § codes in the replacement. `FontMixin` (both `prepareText`s, `prepare8xTextOutline`) and `StringSplitterMixin` (the three `stringWidth`s) wrap text through `PrivacyHooks.text`, so drawn text and measured widths agree; line breaking and truncation (`splitLines`, `headByWidth`) still measure the real names, because they cut by offsets into the original strings. rikka-ui HUD text calls `PrivacyHooks.text(String)`. `PlayerInfoMixin.getSkin` swaps own (session and in-world UUID) and optionally others' skins. The table rebuilds on the tick after the roster or a setting changes; aliases are numbered per connection.
