- The app owns the look: `cast.look().motion: Arc<Look>` (animate-look note). animate-shader depends on animate-look and holds no graphs of its own.
- `Workbench::new(Arc<Library>)` is the editing layer: `sync(&Look) -> Vec<Synced::{Changed(GraphRef), Renamed{from,to}, Removed(key)}>` detects changes by graph `Arc` identity (it keeps a clone, so `Arc::make_mut` always copies) and bumps per-graph revisions; `world_plan(look)`/`composite_plan(look)` are cached per revision (`Planned<T>` with `Diagnostic`s) for status chips; `change(look, at, |graph, library| ..) -> (value, LookEdit::Replace)`, `set_socket(key, value) -> LookEdit::Graph`, `add_material`/`duplicate_material` (fresh valid names, kind and validity checked) build forward `LookEdit`s the app applies.
- Undo rule: one app-wide stack. Every look change goes through `Animate::change_look(merge, |look, library| ..)` (binary `animate/look.rs`), which clones the `Look` (graphs and tracks are shared `Arc`s), applies `Look` edits (so stale socket tracks drop and material renames carry slots and tracks), installs it and records `Edit::Replaced` snapshots in `animate-edit`'s `History`. Slider and drag gestures pass a `Merge(u64)` and coalesce through `History::record_gesture` until `seal`. Ctrl+Z, the node editor's undo buttons and canvas undo all call the app's `undo`/`redo`; assistant calls are one group.
- `Shaders` (`SharedShaders`) is the material compile registry: `request(key, revision, graph, library) -> Option<Job>` compiles only when the source signature (set numbers zeroed) changes; `Job::run(&ShaderCompiler)` on `spawn_blocking`; `finish(outcome)` returns the queued job; `rename` follows `Synced::Renamed`; the last good `material(key)` stays live; `status(key)`. Listeners (`watch(&Listener)` with weak refs, `listeners()`) rouse every stage render, live or export replica, when a compile finishes.
- `SharedCompiler` lazily creates the one `ShaderCompiler` off the UI thread; the binary's compile jobs and the stage's composite pixel passes share it.
- `functions.rs`: group (function) edits that keep graphs valid (`collapse`, `expand`, `rename_function`, …). `empty_material` = Principled → surface; presets come from `rikka_shader_presets::presets()`.
- `animate-shader-editor`: `node_editor(desk)` is docked under the viewport (World/Composite/Material tabs, material menu, groups breadcrumb, undo/redo, arrange, status chip, canvas with catalog and context menu). With a figure as subject the Material tab shows `views/slots.rs`: the figure's material slots (model name, class = `rikka_model_gpu::class_preset` name of the toon surface, assigned graph or Imported) with check marks for multi-select, select all / by class, Assign (existing graph, new graph from empty or a preset, Imported), Make Unique and Reset to Imported (`actions/slots.rs`, each one `LookEdit`). Choosing slots highlights them in the viewport (`MaterialGraphs::highlight_slots` → `Stage::highlight` → `ModelDrawing::selected`).
- `node_properties(desk)` fills the inspector's Node tab: node docs, payload editors, one row per input (`Target::Socket`) with key diamond and reset; with nothing selected on a material: per-slot instance values of the graph's declared parameters (`views/instances.rs`, `Target::Slot`), the parameter editor and groups. `ShaderEditing::reveal_properties` (called on a non-empty selection or slot choice) opens the Node tab.
- `Workshop = ShaderEditing + MaterialGraphs + ShaderCompiling + LookValues` (`traits.rs`), implemented in the binary's `animate/workshop.rs`. `LookValues` speaks `SocketValue`; the binary converts with `Look::value_from_socket`/`value_to_socket` and writes through `Look::set_value` (keys when the target is keyed) and `Look::toggle_key`.
- Pure tested models: `node_graph` (canvas data), `socket_rows`/`parameter_rows` (`Field`, incl. `Field::Text` for `Hint::Text` names), `catalog_lines`. Tests in animate-shader cover Workbench sync/rename/removal, Replace edits dropping and restoring tracks, fresh material names and signature-only compiles (`limit = 180`).
