- `rikka-colorimetry` (public, no dependencies) is the one colour-science crate: `Primaries` (named sets, `to_xyz`, `is_valid`), `bradford`, `TransferFunction::{Power, CompoundPower24, Linear, Pq, Hlg}` (`GAMMA22`, `BT1886` = power 2.4), `Description` (primaries, transfer, `Luminance { min, max, reference }`, optional `Mastering`, max CLL/FALL; `SRGB`, `BT2100_PQ`), `Intent::{Perceptual, Relative}`, `Eetf` (BT.2390 in PQ space on max RGB), `BlendSpace`, `Mapping`. `Mapping::apply` is the CPU definition that `shaders/lib/canvas/color.slang` mirrors; tests check it against BT.2087, BT.2100/BT.2408 and IEC values.
- Relative units everywhere: 1.0 is the reference white of the source; PQ is decoded to nits/reference, HLG gets its OOTF with Lw = luminance max. Minimum luminance is ignored (black maps to black), which is why Relative and relative+BPC coincide.
- `BlendSpace::Sdr` blends gamma-2.2-encoded sRGB in the target's UNORM format (sRGB content is the identity fast path). `BlendSpace::Hdr(HdrSpace { reference, peak })` blends linear BT.2020 where 1.0 = `reference` nits (the SDR brightness); the output is PQ(v · reference / 10000). Tone mapping happens only with Perceptual when the source's relative peak (max CLL, else mastering max, else luminance max) exceeds the target headroom (peak/reference; 1 on SDR).
- Renderer: `renderer.colors().acquire(ImageColor { description, intent, alpha })` → refcounted `ColorId` (`retain`/`release`; `ColorId::SRGB` is free), `ImageSource::color(id)`; destinations take `set_blend_space`. Slot 0 converts every fill, stroke, glyph and colour glyph; image nodes use their own slot (see the renderer note).
- Protocol (rikka-compositor-surface): the host supplies `ColorSupport` (compositor: `system/rikka-compositor/src/color/support.rs`, every named primary, srgb/compound_power_2_4/gamma22/gamma28/bt1886/ext_linear/PQ/HLG, power, luminances, mastering, extended target volume, scRGB, BT.2100; intents Perceptual and Relative; no ICC) and `RepresentationSupport` (all alpha modes, identity full, BT.601/709/2020 full and limited).
- Compositor (`src/color/`): `HdrDisplay::from_edid` (KMS head only when the connector `signals_pq` and the EDID lists PQ), `output_signal`, `blend_space`, `AnnouncedColors` (sets output image descriptions in `announce_outputs`, then `wl_output.done`), `image_color(surface)`, `ycbcr(representation)`, `scans_out_unchanged` (SDR: identity mapping; HDR: BT.2020 PQ at the output's reference white, no tone mapping), `encode_cursor` (cursor-plane pixels for HDR screens). `render/colors.rs` holds each surface's `ColorId`; frozen snapshots retain theirs.
- HDR is per display in `rikka.displays` (`<slug>-hdr`, `<slug>-sdr-brightness` 80–500 cd/m², default 203), declared only for HDR-capable displays, applied live through `configure_outputs`; every display tier lights HDR (see the multi-GPU note), and an HDR configuration refused by the TEST_ONLY modeset, or a later rejected HDR frame (remembered in `Kms::hdr_refused` until the output disconnects), falls back to SDR with `hdr = false` in the applied config.
- Nested and headless outputs are always SDR but convert client descriptions with the same code; `system/rikka-compositor/tests/color.rs` checks a PQ window tone-mapped on headless. Captures (screenshots, screencast, replay, remote) draw onto SDR targets, so HDR content reaches them tone-mapped.
