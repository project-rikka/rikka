description: render/skin: retained model and item meshes, bone palette, instanced draws through twin pipelines, ordering rules, hooks.

- With `BoostFeature.GPU_ENTITIES` active, model cubes and item quads live once in a static vertex pool (`SkinMeshPool`, 32-byte `SkinLayout.VERTEX`: position, uv, axis normal, slots = bone row, tint row, light emission). Each drawn model is one 32-byte instance (`SkinLayout.INSTANCE`: colour, overlay, light, palette base, uv transform) plus palette rows in a uniform buffer (`SkinPalette`, 16-byte rows, 6 per bone: pose 3x4 and normal 3x3 with a normalize flag; item tints follow as colour rows).
- `ModelSkin` is built per root `ModelPart` (cached on the part with a generation that resource reloads bump); a bone is a part with cubes, numbered depth-first; hidden parts keep zero rows so their quads collapse. `ItemSkin` is built per `ItemQuads` list identity, split into runs of equal render types; lists with a `sortOnUpload` render type or more than 16 tints stay on the vanilla path.
- `SkinPipelines.twin` derives a pipeline from any vanilla pipeline whose vertex shader is `core/entity`, `core/item` or `core/glint` (same fragment shader, defines, blend and depth state; vertex shader `rikka:core/skin_*`, bindings 0 and 1, plus the palette layout). Nothing is listed by hand; twins compile at reload and on enabling. The path turns itself off when a resource pack replaces one of those vertex shaders or a twin fails to compile.
- Every skin vertex shader computes `gl_Position` through `skin_clip_position` (`include/skin.glsl`) with `invariant gl_Position`, so layers that redraw one model (trims with depth EQUAL, glint, eyes) get identical depth. All layers of a model must take the same path: a submit that cannot be skinned (crumbling decal, non-affine pose, unsupported pipeline) falls back as a whole, and an overlay pipeline with another vertex shader needs its own twin shader or it z-fights.
- Hooks (`mixin/entity`): `ModelFeatureRendererMixin` and `ItemFeatureRendererMixin` wrap `prepareModel`/`prepareMainSubmit`; `RenderTypeGroupMixin` gives each group `SkinBatch`es behind an empty placeholder `StagedVertexBuffer.Draw`, which keeps vanilla's draw order (first appearance when reorderable, strict otherwise); `RenderTypeFeatureRendererMixin` draws a batch when `executeGroup` reaches its placeholder; `StagedVertexBufferMixin` owns the per-buffer `SkinFrame` (scratch, persistently mapped transient buffers, upload at `upload()`).
- A `SkinBatch` draws chunks: instances of one mesh with contiguous instance records and palette rows (capacity doubles from 1 to 64, bounded by the 1024-row window), one instanced `drawIndexed` each with its own palette slice.
- Vanilla sorts the quads of `sortOnUpload` render types per draw; the skin path does not. Blended pipelines without culling are drawn twice instead (`SkinFaces.BACK` then `FRONT`, faces rejected in the vertex shader), which matches vanilla for convex parts; improved transparency (OIT) draws once.
- `SkinWriter` walks the part tree with its own flat matrix stack (same operation order as `PoseStack`) and a small cache of Euler rotations (`PartRotations`), so armour layers reuse the body's trigonometry. `UvTransform` turns any `UvMapping` into scale and offset, assuming it is affine.
- Check changes with the benchmark's `wardrobe`, `hand` and `inventory` stills against a Boost-off run, in fancy and fabulous presets.
