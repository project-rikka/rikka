---
title: Language-model client
description: rikka-llm is the vendor-free core: message types, four wire protocols, transport and the wire kit for providers.
about: crates/ai/rikka-llm
tags: [llm, ai]
---

- Holds no endpoints, logins, credentials or model catalogue; those live in the adapter crates under `crates/ai/providers`.
- Wire protocols are folders named by protocol: `messages` (Anthropic Messages), `responses` (OpenAI Responses), `completions` (Chat Completions), `cloud_code` (Antigravity's Cloud Code envelope). Codecs stay private.
- `rikka_llm::wire` is the provider kit: protocol builders `Messages`, `Responses`, `Completions`, `CloudCode` that end in `build() -> Model`, plus `Transport`, `Authorize`, `Settings`, key and endpoint helpers.
- Headers are built fluently and checked at the end: `wire::headers().user_agent(..).set(name, value).text(name, value, what).bearer(key).json().build()`; insertion order is kept, which pinned CLI mirrors rely on.
- Protocol quirks are dialects: `ResponsesDialect::{OpenAi, Codex, Compatible}` and `CompletionsDialect::{Compatible, OpenRouter}`. `Compatible` is any OpenAI-compatible server: no `prompt_cache_key`, no `include`, no reasoning replay, `strict` only on strict tools, and a leading `<think>…</think>` in Chat Completions content becomes reasoning. Wire tests in `tests/` drive each protocol builder against a local HTTP server (`tests/support`) that records request bodies and replays SSE frames. `Vendor::{Xai, Meta}` have no dialect any more but stay because stored conversations name them in reasoning and signatures.
- Chat Completions reads tool calls tolerantly for every dialect: missing ids are minted (`call_<hex>`), calls without `index` or reusing one with another id become new calls, object `arguments` are serialized, and tool calls under `finish_reason: stop` end as `Stop::ToolUse`.
- `wire::translate` reads error bodies as `{error:{message,type,code}}` (code string or number), `{error:"…"}`, `{detail}` or flat `{object:"error",message}`; overflow phrases of vLLM, llama.cpp and LM Studio map to `ContextOverflow`. Streamed `error` frames read the same shapes.
- Provider hooks: `Messages` takes `betas`, `shape` (body edit), `listed_output`, `thinking_off` (`ThinkingOff::{Disabled, BetweenTools}` per model for `Effort::Off`) and `threaded()`; `Responses` takes per-request `headers`. Non-OpenAI Responses dialects send through the stream. Messages refuses `temperature`/`top_p` (`Unsupported`, API 2026-10-21 removed them).
- `Model` is a cheap clone. `chat()` builds a reusable request, then `send` or `stream`. A stream ends with `Event::Done` carrying the full response.
- Messages carry text, images, documents, tool calls and results, opaque reasoning and usage. `Tool`, `ToolBuilder`, `Schema`, `Image`, `Media`, `Picture` and `Usage` live in the network-free `rikka-tool` and are re-exported; inline image and document bytes are `Arc<[u8]>`, so messages clone cheaply.
- Every `Transport` clones one process-wide HTTP client. A tool call cut off by the output limit is dropped (the answer ends `Stop::MaxTokens`) rather than failing the stream; unreadable arguments with any other stop are `Malformed`.
- Tool schemas accept shorthand or full JSON Schema. Strict providers get optional → nullable rewrites.
- `Vendor` tags reasoning and signatures; they replay only to their issuer. Gemini keeps tool signatures, and unsigned history uses the skip-validation sentinel.
- Cloud Code numbers its own `call_<n>` ids because Gemini's repeat.
- Caching: unthreaded Messages marks the last system block and up to two message boundaries (last and the user message before it; never thinking); threaded Messages marks system/tools and sends a top-level `cache_control` instead of message marks (`breakpoint::Placement::Automatic`). `Ttl::Short` holds every mark 5 min, `Ttl::Long` 1 h (conversations use Long); OpenAI Responses gets 30 min for Long.
- Message threads (`messages/thread.rs`, beta `message-threads-2026-08-12`): a `threaded()` Messages with a `cache_key` creates a server thread, then sends only new messages plus `previous_message_id`. A process-wide table keyed by (endpoint, cache key) holds the last response id, a fingerprint of every non-free field plus betas, and per-message digests; a request continues only when that prefix and fingerprint match and the thread is under 5 min old, else it creates again with the full conversation. Entries are taken while a request is in flight, put back when a continue fails for a non-thread reason, and recorded at `message_stop` (never after a refusal). `thread_not_found`/stale codes replay as create; not-found right after a replay, `thread_unsupported_request` or a 400 naming the beta sends unthreaded and marks the conversation unthreaded for an hour. Errors' `error.details.error_code` is read through `failure::Failure` from `Transport::try_post`/`try_events`.
- Deferred tools: `Tool::deferred()` plus `ToolResult::reference(name)` (`Output::Reference`) say where a tool loads; `deferral.rs` decides per protocol. Messages declares all with `defer_loading` and emits `tool_reference`; OpenAI Responses omits them and adds an `additional_tools` item after the loading output; other protocols declare only referenced ones. The prefix stays byte-stable on the native paths.
- Anthropic refuses a `tool_result` mixing `tool_reference` with other blocks, so such a result carries references only and its text and images follow all tool results of that user message.
- `cache_key` is conversation identity for Codex and Antigravity, so conversations must not share one. Chat Completions sends no cache policy.
- Provider-hosted tools (web search and fetch) are described in the server-tools note. Messages folds blank text blocks into the previous text, since the API refuses them back.
- No request edits history server-side (`context_management`, compaction on demand): any edit to an earlier turn moves the cache prefix and starts a new thread, so later turns re-send the whole transcript once. Context is bounded only by `rikka-agent` compaction.
- Errors are semantic: rate limit, context, auth, quota, overload, rejection. A 401/403 whose Google `ErrorInfo` says `VALIDATION_REQUIRED` with an https `accounts.google.com` `validation_url` is `Error::Unverified { url }` (`verification_url()`); other 401/403 stay `Unauthorized`. `Trouble` (reason + optional verification URL, `From<&Error>`, `caused_by`) is what callers keep to show a failure; `rikka_agent::Error` converts to it too. Usage separates cached and uncached input. Prices are caller data.
- `Meter`/`Window` are the usage-window types; providers build them through `wire::meter`, `posted_meter`, `window` and `span_of`. `Window::usage_level()` (`UsageLevel::{Normal, Warning, Critical}`) is the one usage threshold apps colour by.
- rikka-llm ships no test code. The test-only crate `crates/ai/rikka-test-llm` offers `Server` (a local HTTP server that records request bodies and replays frames for any wire builder; `Server::routed` answers each `Exchange` (method, path, headers, body) with a `Reply::{json, events, text}` and `exchanges()` lists them) and `Scripted` (queued answers served as real Messages frames, with `requests()` giving the sent bodies as `Asked`/`Turn`); rikka-llm, rikka-agent and rikka-thread tests use it. Secrets never appear in `Debug`.
