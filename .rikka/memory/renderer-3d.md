- `rikka-renderer-3d` is the 3D pipeline as its own crate over `rikka-gpu` and `rikka-renderer`; nothing in the UI stack depends on it. Users: Animate, Viewer, `rikka-viewport`, `rikka-model-gpu`, `rikka-shader-graph`, `rikka-physics`, `rikka-physics-cloth`, `rikka-physics-fluid`, `benchmarks/render`.
- Entry: `use rikka_renderer_3d::Three;` then `renderer.three()` gives a `Renderer3d<'_>` borrowing a `rikka_renderer::Renderer` (meshes, materials, effects, light profiles, viewports, picks, `render`). The device must be built with `Gpu::builder().with_3d()` (or `.ray_tracing()`), else calls fail with `NotEnabled(Capability::ThreeD)`.
- State is a `Renderer3dState` (`src/state.rs`) kept in the 2D renderer's typed extension slot (`rikka_renderer::{Extension, ExtensionSlot, RendererParts}`, `Renderer::parts()`); `Renderer3d` creates it on first use. The slot's `Extension::reclaim` receives this crate's `reclaim::Reclaimed::{Mesh, Material, Viewport}`; `Reclaim3d` adds `mesh(id)`/`material(id)` to `Reclaimer`.
- The facade is flat and names no `rikka-gpu` type: import `ComputeBuffer`, `Ticket`, `Filtering`, `TextureId` from `rikka_gpu` or `rikka_renderer`. It re-exports `glam`, `rikka_ies` and the rikka-slang schema types (`ParameterSchema`, `ParameterSpec`, `ParameterKind`, `Bounds`, `Hint`, `Literal`, `Preset`, `Role`, `TextureKind`).
- Errors (`rikka_renderer_3d::Error`): `Gpu(rikka_gpu::Error)`, `Invalid`, `InvalidShader`, `Unknown(Resource::{Mesh, Material, Effect, LightProfile, OverlayBuffer})`, `Slang`, `Schema`, `Parameter(ParameterError)`.
- Shaders: `shaders/` (crate `shaders_3d`) holds `*.slang` (entries `vertex_main`/`fragment_main`/`compute_main`) over the module library `shaders/lib/rikka/`, effect programs in `effects/`, and `programs.bzl` + `tools/programs.rs`, which build every built-in material template and effect program in its own action into `src/programs.rs` (`TEMPLATES`, `EFFECTS`). It imports nothing from the 2D package; full-screen passes use `shaders_gpu::FULLSCREEN_VERT`.
- Code map: one module per area directly under `src/` (`graph/`, `look/`, `sky/`, `space/`, `post/`, `fluid/`, `ray/`, `shadow/`, `light/`, `material/`, `effect/`, `temporal/`, `overlay/`); passes live in `src/record/`, pipeline keys are built in `src/recipes.rs`, `src/renderer.rs` is `Renderer3d`. Editor overlays (`Frame::overlay`), in-place mesh updates (`update_mesh`, `replace_mesh`, `replace_mesh_indices`) and the workbench/unlit templates are in renderer-overlay.md.
- Tests: `tests/three/`, `tests/look/` (GPU) with `rikka-test-renderer` (`renderer_3d`, `fluid_renderer`, `ray_renderer`) and `rikka-test-renderer-3d` (`sphere`, `standard`, `minimal_look`).
- 3D (`GpuBuilder::with_3d()`) is built on first mesh, material or viewport use and needs compute subgroup ballot, checked at device selection. It covers indirect culling (separate early and late ranges, single-pass HZB), reversed depth, clustered lights (directional lights first; see renderer-lighting), shadow atlases planned per frame by `shadow::Plan` (see renderer-shadows), deformation and viewport textures. A `Viewport` keeps its render-extent targets (`viewport::Targets`) apart from the display-sized output texture; antialiasing modes (MSAA, TAA, temporal upscale, dynamic resolution) are in the temporal-antialiasing note.
- Drapes (simulated cloth): `Frame::drape(&ComputeBuffer, &Ticket) -> Drape` (held like wetness, `src/compute_inputs.rs`), `Drape::starting_at(first_vertex)`, `Draw::draped(drape)`. `drape.slang` runs after `skin.slang` and, where `blend > 0`, mixes position, normal and tangent toward the drape (tangent w from the drape). Layout (`DRAPE_VERTEX_BYTES` = 48, `RikkaDrapeVertex` in `shaders/lib/rikka/drape.slang`, mirrored by the cloth solver's `rikka-physics-cloth/shaders/drape.slang`): `float3 position; float blend; float3 normal; float pad; float4 tangent;` in WORLD space, mesh vertex order. Skin output is in the draw's local space (before `Draw::transform`), so the pass converts with the inverse transform (normals by its transpose); the deform job key includes the transform when draped.
- Materials are templates (see the material-system note): built-in or Slang compiled at runtime by `ShaderCompiler::template` (rikka-slang with the embedded `shaders_3d::SLANG_LIBRARY`; failures are `Error::Slang`/`Error::Schema`); every variant's SPIR-V is reflected (`src/reflect.rs`, capability allowlist). There are no raw SPIR-V materials or custom vertex shaders; hull buckets (`MaterialDesc::hull()`) skip the prepass and draw with depth write.
- Pick is `create_pick`/`start_pick`/`poll_pick`; `Renderer3d::pick` is the blocking shortcut.
- Material shaders output straight alpha; `MaterialState::transparent()` blends straight (`Blend::Alpha`) and `rikka_coverage` forces alpha 1 outside blended draws. The viewport holds premultiplied colour, which the tone pass un-premultiplies.
- Transparent draws sort by `Draw::order`, then back to front. `Frame::tone_mapping` picks ACES (default) or `Clamp` for painted/toon content.
- Draws sharing a mesh, skin and morph weights share one deformation job.
- Culling, shadow culling and transparent sorting use posed bounds (`src/reach.rs`): mesh upload keeps per-submesh joint spheres in bind space and per-morph reaches, and `build` encloses the bone-moved spheres grown by the weighted morph reach. Draped or `deformed_by` draws are unbounded (radius infinite), so never culled.
- A `MaterialId` is generational, so draws naming a dead one are refused. Only changed table ranges upload.
- Slang module library (`import rikka.<name>`; `rikka` re-exports the material-facing ones): `common` (constants, bindless tables, every GPU struct and `*Ref` pointer alias, helpers incl. `rikka_mod` = GLSL `mod`, `rikka_columns`/`rikka_column` for column-major construction and access), `push` (the standard `rikka_push`), `fragment` (varyings structs), `shadow` and `shading` (explicit-frame shadow lookups, `RikkaShadowPoint`, light iteration, BRDF), `wet`, `parameters` (the one attribute module: `[Default]`, `[Range]`, `[SoftRange]`, `[Group]`, `[Order]`, `[Label]`, `[Color]`, `[Srgb]`, `[Options]`, `[Texture]`, `[Hint]`, `[Preset]`), `material` (+ `material.texture/context/surface/model/entries`), `standard`, `npr`, `closure`, `graph`, `characters`, `stage` (floor, shadow catcher, water, wire, unlit), `templates.*`, `sky` (+ `sky.environment/atmosphere/noise/clouds/dome/bodies/fog/fog_light`), `space`, `space.view`, `surface`, `depth`, `outline`, `stage`, `particles`, `drape`, `fluid` (+ `fluid.strand/style/splat/composite`), `post` (+ `post.focus/tone`), `outline`. Shaders with their own push constants must not import `push` or anything above it. Matrices keep GLSL's memory layout (column-major) and meaning: write `mul(M, v)`, and remember Slang `m[i]` is row i.
- Effect modules: `effect` (`rikka_effect_*` load/sample/store helpers; re-exported by `rikka`), `effects.film_grain`. Built-in effect programs are `shaders/effects/*.slang`, compiled at build time into `shaders_3d::EFFECTS` (SPIR-V plus reflected layouts per entry).
- `Frame::grid(Grid)` is a full-screen pass, not geometry: a bounded floor of `spacing` cells out to ±`reach`, red X and blue Z floor axes, and a green Y axis rising `reach` (off with `vertical_axis: false`), each with real depth. Animate sets its 5-unit cells to ±50.
- Deliberately absent: mesh shaders, OIT, parallel recording. Hardware ray tracing is the opt-in tier of the ray-tracing note (`GpuBuilder::ray_tracing()`, `Gpu::traces_rays()`).
- `Frame::look` turns on the cinematic pipeline; see the renderer-look, renderer-composite, renderer-sky, renderer-space-effects, figure-shading (graph presets) and render-graph notes. 3D frames are recorded through the render graph (`src/graph/`).
