- Public as the module `rikka_widgets::node_canvas` (its `Selection`/`Item` would clash with prelude names); only `node_canvas`, `NodeCanvas`, `NodeCanvasState` sit at the crate root.
- Callers hand plain data: `NodeGraph { nodes: Vec<CanvasNode>, links: Vec<CanvasLink>, frames: Vec<CanvasFrame> }` behind an `Arc` (kept across views so `same` holds). Nodes carry `NodeKey`, title, graph-space position, width, accent, `CanvasPort { label, color, many }` lists, optional detail/swatch and a `problem` badge (tooltip). Links join `PortAddr { node, side, index }` (output → input). Frames are groups `FrameArea::Around(keys)` or comments `FrameArea::At { position, size }` (resizable by the corner grip).
- A `CanvasPort::many()` input is a list input: it draws as a tall pill, the links into it fan out over its height (`Geometry` link ends), and pressing it always starts a new link (nothing is picked up), so `Connect` arrives with `replacing: None`; single links leave it through link selection and `Delete`.
- Port colours, titles and validity are the caller's: the widget only enforces output→input between different nodes and reports `CanvasEdit::Connect { from, to, replacing }`; the caller validates and refuses.
- Events go out through `on_select(Selection)`, `on_edit(CanvasEdit)` (`Move` on release only, `MoveFrame`, `ResizeFrame`, `Connect`, `Disconnect`, `Delete`, `Copy`, `Cut`, `Duplicate`, `Paste(at)`, `Undo`, `Redo`), `on_menu(CanvasMenu { at, local, hit, from })` (right click, Shift+A/context-menu key, or a link dropped on empty space with `from`) and `on_activate(Item)` (double click). `local` is canvas-relative, so apps anchor popups below a zero-height marker at the canvas top with that offset.
- Interaction: primary drag on empty = box select (Shift adds, Ctrl toggles), on a node = move the selection, on a port = link (a connected input picks its link up for rerouting), on a frame title = move (group frames move their members); middle or Alt drag pans; wheel/Ctrl-scroll/pinch zoom at the pointer; touchpad scroll pans. Keyboard when focused: arrows walk node focus spatially (`Geometry::neighbour`), Enter/Space select, Ctrl+arrows nudge, Alt+arrows pan, F/Home frame all, +/- zoom, Delete, Escape, Ctrl+D duplicate; standard commands handle select-all, copy/cut/paste and undo/redo.
- View state (pan/zoom) lives in the widget; it frames everything on its first paint (`CanvasView::framing`). Key the element per document so a new document reframes.
- Repaint is per layer: the canvas paints only background grid and focus ring; children are `Frame`s, one `Wires` layer, one `Card` per node and an `Overlay` sketch (pending link or marquee), all `hit_test` false, positioned out of flow at graph × zoom. Pan is `children_offset` (no rebuild); hover/drag changes rebuild children so only cards whose props changed repaint (`Card::same` ignores position).
- The paint walk culls a node by its own laid-out box (clip + 64 px `BLEED`), never by what it drew, so `Wires` and `Overlay` size themselves to the box enclosing every point they draw (`enclosing` in `layers.rs`). `Rect::union` treats zero-size rects as empty, so never fold points into a box with it.
- Pure geometry is public for tests and apps: `Geometry::new/moved(graph, keys, by)`, `hit(graph, view, local) -> Hit` (ports beat nodes beat links beat frame grip/title/body), `anchor`, `nodes_within`, `bounds`; `link_curve` samples the cubic link curve. Links are drawn with `PaintCtx::draw_segment` capsules.
- Tests: `tests/node_canvas.rs` (hit tests across views, selection rules, framing, a drag/link/box/delete interaction through `TypedUi`, list-input fanning and linking) and `tests/rendering/segments.rs` (capsule coverage).
