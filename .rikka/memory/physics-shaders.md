title: Physics Slang kernels and their shared modules
description: crates/physics kernels are Slang: shared physics.* modules, buffer views, memory-model helpers, matrix and codegen.

- Every kernel in `crates/physics` is one `.slang` entry file under `<crate>/shaders/` (constant `<STEM>_COMP`); modules live in `shaders/lib/`: `physics.*` in rikka-physics-gpu (memory, matrix, scan, triangle, reaction, octahedral: the one normal codec of cloth and fluid), `cloth.*` (common, world, job, bind, draping, solve + `solve/*`) and `fluid.*` (umbrella `fluid` re-exports settings, grid, listed, random, walls, shape, slab, foam, viscous; plus collision, bonds, reduction). Cloth and fluid `shaders/BUILD.bazel` import `//crates/physics/rikka-physics-gpu/shaders:lib` and set `vulkan_memory_model = True`.
- `physics.memory` buffer views over device addresses: `Buffer<T, ALIGN>` (get/`[nonmutating] set`, `at(i)` for partial writes and atomics), `NonWritableBuffer<T : INonWritable, ALIGN>` (plus `ReadFloats`/`ReadUints`/`ReadUvec2s`/`ReadVec4s`/`ReadUvec4s`/`ReadIvec4s` and `NonWritableReference`, used for all read-only tables and buffers across cloth and fluid), `Reference`, `Exchanged` (NonPrivatePointer loads/stores), `QueueCoherent`. Push blocks hold these views in the Rust field order; scalar layout matches `repr(C)` records.
- Slang emits no `NonWritable` for pointers, and an asm view struct cannot hold a Slang struct (`$$T` is the layout-free type), so `load_non_writable<ALIGN>(T*)` goes through `INonWritable.load_from`: scalars and vectors (generic `IArithmetic` extension) and view pointers (`Buffer`, `Exchanged`, `NonWritableBuffer`, `NonWritableReference`) load through an asm view decorated `NonWritable` (`load_non_writable_plain`), and each record struct implements `load_from` field by field with each field's own alignment. A new read-only record type implements `INonWritable`. Fluid `Settings` reads every field through `load_non_writable`; dropping that made `visc_start` ~2× slower on NVIDIA.
- `physics.scan`'s `scan_exclusive` uses `subgroupInclusiveAdd` + final-lane broadcast, `Scan::run` skips `scan_top`/`scan_add` for single-group inputs, and `scan_add` updates 4 elements per thread skipping block 0.
- Barriers and atomics with explicit scopes are spirv_asm helpers in `physics.memory` (`exchange_barrier` = cloth `sync()`, `buffer_barrier`, `group_barrier`, `queue_arrive`/`queue_reset`, `queue_atomic_*`, `shared_atomic_*` with `Workgroup` scope, `shared_load`/`shared_store`; the `shared_*` ones take a workgroup pointer and are `[ForceInline]`, which the build-time SPIR-V validation needs and leaves the optimised output unchanged), matching what glslang emitted under `use_vulkan_memory_model`.
- Matrices: a Slang `float3x3` row is a GLSL column, so GLSL `M*v` is `mul(v, M)`, `v*M` is `mul(M, v)`, `A*B` is `mul(B, A)`. Use `physics.matrix` `scaled` and `outer_product` (OpMatrixTimesScalar/OpOuterProduct): Slang scalarizes those and NVIDIA results change bitwise.
- Codegen rules that cost time on NVIDIA: walking the 27 grid cells through an iterator struct (`while (walk.next(..))`) was ~2× slower than visitor callbacks (`for_cells`, `for_neighbours` with `ICellVisitor`/`INeighbourVisitor`), while `listed`'s `ListWalk` iterator is fine; a short-circuit `while (a && (b || c))` over local arrays (bond_propose insertion) was ~5× slower than `for (; a; ..) { if (!(..)) break; }`; `[ForceUnroll]` matches glslang unrolling where `[unroll]` does not.
- Profiler spans are timestamp deltas, and dispatches without a hazard between them overlap (fluid `visc_start` and `bond_propose`), so a kernel's span can absorb a neighbour's time; compare frame totals.
- `NamedKernel::load(compute, Shader, name)` takes the size of the kernel's push-constant block from the build-time `Shader::push_bytes`; `Pass::run` fails the batch, naming the kernel, when the bytes pushed differ from it, so a `Push` struct and its `Pass` chain cannot drift apart silently.
