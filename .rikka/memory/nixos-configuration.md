---
title: NixOS configuration model and privileged service
description: rikka-nix edits Rikka-owned modules losslessly; rikka-nixctl authorizes, applies, updates and rolls back as root.
about: crates/nix/rikka-nix
tags: [nix, privilege]
---

- The person's `/etc/nixos/flake.nix` and `configuration.nix` are read-only after install. Rikka owns `/etc/nixos/rikka/default.nix` plus the `apps, boot, desktop, ime, nix, integration, packages, system` modules. The flake names its one configuration after the evaluated `networking.hostName`, so plain `nixos-rebuild switch` works and follows a hostname changed in Settings; `nixctl-task` asks `nix eval` for the configuration names and targets the only one (several or none: no fragment, nixos-rebuild's hostname rule).
- `rikka-nixctl`, rikka-boost and the PAM helper come from the `base` component of the distribution flake (`rikka.enable`); there is no privileged tree in `/etc/nixos`. `Distribution` (`/etc/rikka/catalog.json`, written by the module) lists components; `chosen`/`choose` read and write `rikka.apps.<id>.enable` in the `apps` module. `Channel::from_flake` reads `nixpkgs.url` or `nixpkgs.follows = "rikka/nixpkgs"` (unstable).
- Reading and editing come from `crates/nix` (see the Nix editing libraries note). `rikka-nix` re-exports `Document`, `Expr`, `Set`, `AttrPath`, `Modules`, `Packages` and `Module`, and its `Error` takes `rikka_nixos_layout::Error` and `rikka_nix_edit::Error` through `#[from]`. Nix is never evaluated.
- `Rebuild` is the apps' apply lifecycle: `start(request)` returns a `PendingRequest` whose blocking `send(report)` runs off the UI thread and subscribes only to `Finished`; `Progress::{Started, Finished(Outcome)}`; `handle_progress` returns the `Outcome` once, and `fail(&Error)` refuses a request that never reached the service. `Rebuild` keeps the last refusal worth showing (`refusal()`, `dismiss_refusal()`). `Stage::{Idle, Requested, Running}`. Apps keep no log and show no result: the shell announces runs (see the System updates note).
- `Outcome::{Done, Failed { reason, changes }, Refused(Refusal::{Denied, Busy, Stale, Invalid, Unavailable})}`; `Outcome::changes()` says whether to reread the draft. Apps stay silent on `Refused(Denied)` (the person cancelled polkit) and show other refusals inline.
- `Request::Apply` is a compare-and-swap: it carries only the edited modules (closed `Module` names, never paths, never the root), each as `ModuleFile { module, base, contents }` where `base` is the text the edit started from. `rikka_nix::Draft` (saved + edited `Modules`) builds it with `request(action)`; `Draft::rebase(current)` moves a draft onto freshly read modules and returns the modules edited on both sides, whose edits it drops. `Channel::detect` reads the flake and never changes it.
- `system/rikka-nixctl` is root and D-Bus-activated. Before authorization it checks only module names, sizes and the action. It authorizes the caller with polkit (`auth_admin_keep`, one prompt for everything, no pkexec), then refuses contents that do not parse (`Invalid`) and modules whose on-disk text is not the request's `base` (`Stale`; a missing file counts as the blank module).
- One change at a time: a `RunGuard` is taken after authorization, travels with the request and releases on drop, so others get `Busy` (also at once while a run is going). A failed restore is reported in the reason and makes the residue `Modified`.
- The work is `system/rikka-nixctl/crates/nixctl-task` (`execute(request, &Site, &mut dyn Report)`, `Directory`): `Apply` snapshots the directory, writes the root module itself, the named modules and a blank for any missing one, rebuilds, and restores only while `Report::is_activating()` is false (or the action is `Build`). A failure after activation began keeps the files and ends `Modified`. `Update` treats `flake.lock` the same way. `Rollback` activates an existing generation.
- After activation, rollback is the only recovery.
- The unit keeps `switch-to-configuration` from stopping it (`X-StopOnRemoval` in `[Unit]`, `X-RestartIfChanged`/`X-StopIfChanged` in `[Service]`, the sections switch-to-configuration-ng reads; `tests/shipped.rs` checks them) and uses explicit child paths with `HOME=/root`. It exits after 30 s idle and rejects non-root runs.
- The installer writes the same `/etc/nixos` shape with the same builder (`Module::document(Set)`). The module bodies are still written separately on each side, so change both together.
