---
title: Installer architecture
description: The isolated ratatui NixOS installer, layered core → sys → tui, built static for musl.
about: installer
tags: [installer, architecture]
---

- Partitions a machine and writes its flake before any Rikka session exists. It depends on no Rikka layer, only its own crates.io deps, `crates/nix/{rikka-nix-edit,rikka-nixos-layout}` and `crates/session/rikka-backup` (with rikka-age and rikka-file-format; plus `rikka-test-nixfmt` in installer-core's tests). Its first step restores from a backup or repository.
- Layers run `installer → installer-tui → installer-sys → installer-core`. Core: answers, validation, rendered Nix, no machine access. Sys: the only layer touching commands and filesystems, through `Host` (real, scripted or read-only). `src/main.rs` only wires.
- `--config=installer`: `-c opt` with `opt-level = "z"`, fat LTO and unwind panics (terminal cleanup) on `//bazel/platforms:linux_musl`. `install.sh` refuses to run unless `/` is tmpfs/ramfs/overlayfs/squashfs (a live medium; `RIKKA_FORCE=1` overrides) and points installed systems at the existing-NixOS guide; it downloads `rikka-installer-<arch>` plus `.sha256` from `project-rikka/rikka`'s `releases/latest/download` (every `xtask release` uploads them), else builds from source with `bazel build --config=local --config=installer //installer:rikka-installer` inside `nix develop`.
- `https://install.rikka.sh` (the command in `website/src/site.ts`) is a Cloudflare Single Redirect (302, proxied `AAAA 100::` record) to `raw.githubusercontent.com/project-rikka/rikka/main/installer/install.sh`; nothing in the repository serves it.
- `installer/test/qemu.sh` tests on real media. `--demo` runs the whole flow without writing. A VM proves the install and the boot but not the desktop: the compositor needs a Vulkan 1.3 device matching the DRM card through `VK_EXT_physical_device_drm`, which Mesa's Venus hides on NVIDIA hosts and lavapipe lacks, so the session's autologin unit fails there and falls back to the console.
- Each module body is a `rikka_nix_edit::Set` built in `installer-core/src/rikka/*`. `Rendered` wraps it with `Module::document`; `flake.rs` and `configuration.rs` render through `Document`. `installer-core/tests` parse every locale's answers through `generate` and check representative ones against nixfmt; `installer-sys/tests` drive `install` and `Environment::probe` on `DemoHost` and a failing `Host`. installer-tui has no tests.
- `NvidiaDriver::for_device` picks the NVIDIA line: Turing and newer get open modules on `nvidiaPackages.latest`, Maxwell to Volta proprietary `legacy_580`, Kepler and older no driver offer (nouveau). `Answers::nvidia_offer` is the hardware's line, `nvidia_driver` adds the toggle.
- `Environment::probe` reads the distribution's `Catalog` with `nix eval --json github:project-rikka/packages#catalog` (`Command::nix()`); `Answers::offer` preselects `Selected` components and the `Apps` step toggles the rest (`choose_app`, required ones are never written). `rikka/apps.rs` renders `rikka.apps.<id>.enable` into the `apps` module.
- `Kernel` (default Zen, also Latest and the nixpkgs Default) becomes `boot.kernelPackages = pkgs.linuxPackages_*` in the boot module, whose formals therefore take `pkgs`. `stable_release` maps the live medium's `nixos-version` to the newest stable branch (`26.11pre…` → `26.05`) for the flake URL and `stateVersion`.
- The generated flake has inputs `rikka` (`PACKAGES_FLAKE`) and `nixpkgs` (`follows = "rikka/nixpkgs"` on the default unstable channel, `nixos-<release>` on stable); its outputs `let system = nixpkgs.lib.nixosSystem { … }` (modules `rikka.nixosModules.default` and `./configuration.nix`) and expose `nixosConfigurations.${system.config.networking.hostName}`; `nixos-install` targets `#<hostname>`. Passwords and the LUKS passphrase need only be non-empty and confirmed; `Strength` is advisory. The desktop module holds only graphics/NVIDIA plus `rikka.enable` and `rikka.autologin.user`; services, portals, fonts, PAM, wrappers and the tty1 login unit come from the distribution's module (see the distribution note).
