- Stack: `rikka-proton-pgp` + `rikka-proton-api` → `rikka-proton-account` → `rikka-proton-key-transparency` and `rikka-proton-cache` → products (`contacts` over `contentline` and KT, `mail` over contacts, `calendar` over mail and contacts, `drive` over `rikka-proton-names`, `drive-sync-state` (also over names) → `drive-sync`, `pass`, `authenticator`, `vpn`). `rikka-proton-client` sits beside the products, over account/api/cache/pgp only: `Proton`, `Session`, `Accounts`, the event loop. Product-to-product edges are domain ones only: mail needs contacts (send preferences, pinned keys), contacts needs KT (recipient verification), calendar needs mail and contacts (invitations), drive-sync needs drive.
- No facade: apps depend on each product crate directly. Public (used by apps/system/proton): `account, api, authenticator, cache, client, contacts, drive, key-transparency, mail, names, pass, pgp`; calendar, contentline, drive-sync(-state) and vpn stay internal until an app uses them.
- `rikka-proton-names` is the pure name rule: `NAME_LIMIT`, `split_extension`, `numbered(stem, n, ext)`, `numbered_name`, `numbered_local_name` (shortens the stem so ` (n)` fits 255 bytes), `fitted_name`.
- Events: the interface is owned by rikka-proton-account: `Feed` (`type Change`, `apply_core(&CoreEvent)` run blocking for core-event projections, `poll(&Poll)` for own cursors), `Poll` (`keys()`, `emit`, generic `walk(cursor, latest, fetch, apply)` over an `EventPage`), `Cursors::for_account` (persisted in `account.event-cursors`), `FeedError` (`SignedOut`/`Failed`/`InvalidEvent`; each product has `From<Error> for FeedError` via `FeedError::new(error, Error::api)`). Feeds: `MailClient`, `ContactsClient` (core), `CalendarClient` (core + model cursors, `CalendarUpdate`), `PassClient` (user events, rekeyed from `poll.keys()`), `DriveFeed::new(drive).observe(..)` (volumes, `VolumeEvents`; drive-sync's `VolumeFeed::follow(drive)` publishes every page), `KeyTransparency` (self-audit when due, `AuditReport`).
- Notes: `proton-cache-and-client.md` (cache, client). Per crate: `proton-api-transport.md`, `proton-account.md`, `proton-key-transparency.md`, `proton-mail.md`, `proton-contacts-calendar.md`, `proton-drive.md`, `proton-drive-sync.md`, `proton-pass.md`, `proton-authenticator.md`, `proton-vpn.md`.
- Products take `for_account(&Account, &Arc<AccountKeys>)` (pass/authenticator return `Result` because they need `AccountKeys::user_signing()`), or `new(api, keys)` / `with_pgp(api, pgp, keys)`. VPN takes only `Api`. Mail, contacts, calendar, drive and pass have `with_keys(&Arc<AccountKeys>)`, which swaps the key view and keeps the client's caches. Every product client holds one `Account` (api, pgp, cache), so `api()`, `pgp()`, `cache()` and `with_cache` mean the same everywhere. Address lookups go through `AccountKeys::{primary_address, known_address, address_ring, signer}`, which answer `account::Error::{NoAddress, UnknownAddress, NoAddressKey}`. Every wire time is a `jiff::Timestamp` (`rikka_proton_api::unix_seconds` on the wire, the Unix epoch where Proton sends 0); builder inputs take `Timestamp` or `Duration`.
- `crates/proton/UNIMPLEMENTED.md` lists what is still missing and why.
- `rikka-proton-pgp` is the crypto site: OpenPGP, SRP, `random_bytes`/`random_hex`/`random_uuid`, `sha256/sha512/Sha1`, `hmac`, AES-GCM `SymmetricKey` (`NonceLength::Long` for fork payloads), zeroizing redacted `Secret`/`SecretBytes` (`random_hex`, `random_base64` for generated passphrases and tokens). It wraps Proton's MIT crates `proton-rpgp` and `proton-srp`. Product crates hold no rand/hmac/sha/aes-gcm deps; rikka-proton-vpn's ed25519/x25519/PKCS#8 handling is the exception.
- `Pgp` is a `Copy` handle with a `Clock`; verify against Proton's clock with `Pgp::with_clock(Clock::fixed(server_time))`.
- Builders `encrypt/decrypt/sign/verify/generate_key` have whole-message and streaming forms (`stream`, `split_stream`, `detached_stream`; `Error::Io` means the caller's reader or writer failed). `Decryption::with_detached_signature`/`with_encrypted_detached_signature` verify in the same pass; `allow_forwarding()` opens Proton forwarding keys (group shares).
- Keys: `KeyGeneration::kind(KeyKind::PostQuantum)` makes v6 keys; `change_expiration` re-signs user IDs and every subkey binding (back-signatures for signing subkeys); `revoke` makes revocation certificates; `PublicKey::{user_ids, sha256_fingerprints, with_revocation_certificate}`, `PrivateKey::with_user_id`. Expiry and revocation are written against rpgp 0.19 directly because proton-rpgp's `KeyModifier` lacks them.
- `Encryption::split` gives key and data packets apart. `Verification::detached` returns `SignatureStatus`; the caller decides whether `Missing`/`UnknownKey` is fatal. Contexts carry `context@proton.ch`.
- SRP: `Srp::authenticate()` → `SrpProofs` (constant-time `verify_server_proof`, `Error::ServerProof`), `register()` → verifier. `Modulus::from_signed` is the only constructor, so every modulus has passed the embedded Proton modulus-key check. `SrpChallenge` deserializes every Proton SRP info shape (sign-in, Pass extra password, Drive public links).
- The repo-root `reference/` holds Proton's clients: `android-{pass,mail,drive,vpn,authenticator}`, `protoncore_android`, `proton-pass-common`, `webclients` (Drive) and `webclients-full` (sparse: key-transparency, shared lib, mail, pass, calendar), `go-vpn-lib`, `python-proton-vpn-*`, `windows-drive`, `proton-drive-sdk`. GPL: read for endpoints and constants, never copy.
- Verbs: `open_*(id)` fetches and decrypts (`open_message`, `open_contact`, `open_share`, `open_device`, `open_root`, `open_public_link`); `decrypt_*(value)` only decrypts what the caller holds (`decrypt_link`, `decrypt_share`, `decrypt_event`, `decrypt_attachment`); `unlock_*` derives keys from a passphrase. `PublicKey::{expires_at, flags}` fail on a key without a valid primary self-signature.
- CPU-heavy work goes through `rikka_proton_api::{offload, parallel_map, parallel_map_each}` (`blocking.rs`, chunked `spawn_blocking` aborted on drop; `parallel_map` keeps at least 8 items per chunk, `parallel_map_each` splits down to one), never directly in a future.
- No test reaches the network: local dummy APIs, generated keys, `proton_srp::ServerInteraction`.
