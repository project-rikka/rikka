- `Light { kind, color, intensity, shadow, channels, two_sided, source_size, photometry }`; `LightKind` adds `Rect`, `Disc`, `Sphere`, `Tube` to directional/point/spot. `intensity` is renderer units: lux, candela or nits divided by `LUX_PER_UNIT` (32 000; the sky's 4-unit sun is ~128 klux). `Light::{lux, candela, lumens, nits}` convert and return `Error::Invalid` for the wrong kind.
- IES profiles: `crates/graphics/rikka-ies` (public, re-exported as `rikka_renderer_3d::rikka_ies`) parses LM-63-1986…2019 `TILT=NONE` type C files into `IesProfile` (`candela(vertical, horizontal)` folds symmetry and interpolates). `Renderer3d::create_light_profile` bakes it normalised to its peak into a 128 (vertical 0–180°) × 64 (horizontal 0–360°) float table in `LightProfilePool` (slot + generation ids, deferred reuse, one GPU buffer at `RikkaFrame.profiles`). `Light::profile`/`oriented_profile` attach it to point and spot lights only (others are `Error::Invalid`; destroyed ids are `Error::Unknown(Resource::LightProfile)`). On the GPU `GpuLight.profile` is the slot, `direction` the nadir and `tangent` the 0° axis; `rikka_light_profile` multiplies attenuation in `rikka_sample_light` (which now takes the frame) and in fog.
- `RikkaLightSample` (`rikka.light`): `direction`/`attenuation` are a representative direction and unclipped π·|F| for area lights so any model's `attenuation · N·L` gives their irradiance; exact paths are `irradiance(frame, n)` (clipped diffuse, E/L) and `specular(frame, ltc, n, v)` (any `RikkaLtc`: the GGX table from `rikka_ltc` or the sheen fit from `rikka_pbr_sheen_ltc`); `radiance()`, `window`, `leading`. `RikkaOpenPbrModel` (`rikka/standard`, skin) and `RikkaStandardModel` use the exact paths in their `area` methods (see realistic-shading).
- LTC tables: `rikka_ltc::GGX` lives in the `RikkaFrame.ltc` buffer only as the source; the shared graph pass `rikka.three.ltc` (`record/ltc.rs`, `ltc_table.slang`) copies it once into two 64² RGBA16F images (`rikka.three.ltc.inverse`/`.amplitude`, in `SceneImages::sky_reads`; RGBA16F because linear filtering of 32-bit float formats is optional in Vulkan), and `rikka_ltc_mix` samples them bilinearly through `RikkaScene.ltc_inverse`/`ltc_amplitude` (published every 3D frame, looked or not).
- Light linking: `Light::channels` and `Draw::light_channels` (default `DEFAULT_LIGHT_CHANNELS` = 1); a light lights and shadows only draws sharing a bit (`rikka_light_reaches` in the loop, `casts_into` in cull for shadow views).
- Figure rigs: `Figure::rig: LightRig { key: Option<KeyLight>, lights }`. Rig lights get `GpuLight.figure` = figure id and are skipped for other figures; a key replaces light 0 (the leading directional, flag `LEADING`) for that figure via `RikkaFigure.key_light`. A key that turns the direction (`turned`) shadows from its own figure map and loses world shadows and screen shadows (no `LEADING`).
- GPU list order (`build::write_lights`): world directional (first = leading), rig directional, world local, rig local, then keys past `light_count` (never clustered). `look/resolve.rs` builds `Resolved { lights, owners, keys, leading }`.
- Loop shape matters for cost: `rikka_light_next` stays a flat if/else and callers `continue` on `rikka_light_reaches`; nested while loops there cost ~15% shade.
