---
title: Shared adjustments and effects (rikka-effects)
description: rikka-effects is the UI-free serde effect model; rikka-effects-forms holds the forms and editors Paint and Cut share.
about: crates/graphics/rikka-effects
tags: [graphics, effects]
---

- Two public crates: the model `crates/graphics/rikka-effects` (deps: image-edit, types, i18n, serde; no UI) and `crates/ui/rikka-effects-forms` (`form`, `Tuning`, `ScaleControls`, editors, and the form rows `form_sheet`/`labelled`/`note` Paint's own dialogs use). `Scale`/`Unit` (incl. `Seconds`, `Frames`) are also Cut's panel and transition-knob scales. `cut-project`/`cut-render` take only the model.
- `Effect` is one enum over 43 parameter structs (17 `Family::Adjust`, Blur, Sharpen, Noise, Stylize, Photo, and `Key` for ChromaKey/LumaKey/Clipping); `Kind` mirrors it (`ALL`, `name`, `family`, `default_effect`, `wants_histogram`), `Family::kinds()` lists members in `Kind::ALL` order.
- `Effect::recipe()` is unmasked steps at 1:1 pixels (empty for a ColorLookup without a table), `padding()` the px content may spread, `knobs()/value/set` the animatable scalars, `checked()` clamps everything after loading.
- Knob keys are field names, grouped ones `group.part` (`rgb.black`, `reds.hue`, `shadows.cyan_red`, `red.constant`, `whites.cyan`, `colorized.saturation`); `set` clamps to the knob `Scale` and runs the struct's `Parameters::normalize` (rounding, Levels black < white). `rikka_effects_forms::ScaleControls` adds `Scale::field(value)`/`Scale::slider(value)`, which build the number field and the stepped, clamped slider every scaled row uses (also Paint's dialog forms).
- Serde: internally tagged `kind` in snake_case, every struct `#[serde(default)]`, colours as `#rrggbb` (`hex.rs`), curves as `[[x, y]]`, gradient maps as `stops`, lookup tables as `name` + `source` text; bad tables, curves or stops load as defaults.
- Each struct lives in its own public module (`rikka_effects::adjust::levels`, `filter::radial_blur`, …) holding its knob keys and choices, implements the public `Parameters` trait (`operation`, `normalize`, `padding`, `knob`, `set`) and gets its `Knobs` (table, `slot`, `peek`) from one declaration in `parameters.rs`: `knobs! { for Owner; CONST = "key" => field.path: label, scale; .. }` or, for group × part knobs, `grouped_knobs! { for Owner as KEYS; [group: "label key", ..] { part: "label key", SCALE; .. } .. }` (several blocks for per-group scales). Both emit `KnobKey<Owner>` constants (or a `KEYS[group][part]` array) that `Tuner` takes, so a form can only name its own declared knobs; `tests/effects.rs` pins every saved key name. `BrightnessContrast` swaps its table with `legacy` and implements `Knobs` by hand. In rikka-effects-forms each struct implements the private `Form` trait in `adjust/`/`filter/` beside the model module of the same name, built through `Tuner<S, P>` (`tuner.rs`): sliders, dials, pads, ramps, curve points and gradient stops preview while dragged and commit once on release (`Tuner::staged` gives the pair); fields, combos, toggles, inserts, removals and keyboard nudges commit; colour wells preview then commit.
- Host API: `rikka_effects_forms::form(&effect, &Tuning::new(preview, commit).submit(..).adorn(|key| ..).histogram(..))`; `adorn` puts an element after a knob's control. Hosts should ignore commits equal to their current effect.
- View-only choices (shown channel/range, selected curve point or gradient stop, lookup load failure) are `local_state` with a distinct type per effect; key the form element to reset them.
- Never read `palette()`/`theme()` inside a `local_state` closure: it can resolve outside the ambient scope; read it in `form` before.
- Editors (rikka-effects-forms `editor/`; the `Curve` and `Gradient` models are in rikka-effects): `Ramp` + `Notch`, `CurveGraph` + `Curve`, `GradientStrip` + `Gradient`, `Dial`, `Pad`, `HueBars`, quad drawing in `plot.rs`; `Ramp` and `GradientStrip` share `notched.rs` (`NotchedTrack`: track rect, x ↔ fraction, nearest notch, notch painting). Editors take `on_change` and `on_commit` actions, drag through `rikka_widgets::Grab`, and implement `same`, so unchanged editors are not repainted.
- Strings are `effects.*` in the model crate's `locales/` (the forms crate reads the same keys); `rikka_effects` exports `CATALOGS`, which every host adds with `I18nBuilder::embedded(effects::CATALOGS)`.
- A new effect: a struct file in the model's `adjust/` or `filter/` with its `knobs!` declaration, one line in `catalog!` (`effect.rs`), its `Form` impl in the forms crate and a line in `form.rs`, its name and family in `kind.rs`, its keys in the saved-name test, strings in en/ja/zh-Hans.
