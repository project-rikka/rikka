---
title: Nested in-process compositor (rikka-nested)
description: Nested/View/nested_view: a private Wayland display on a rikka-nested thread whose toplevels show zero-copy in a widget.
about: crates/ui/rikka-nested
tags: [compositor, embedding]
---

- Internal crate in `crates/ui` (it is a rikka-ui widget host) for embedding one trusted client tree (Gecko for rikka-web) in rikka-ui. It is a host of the policy-free compositor modules (surface, seat, xdg shell, selection, output), never of `system/rikka-compositor`.
- `Nested::builder().gpu(SharedGpu).clipboard(Clipboard).start()` binds `$XDG_RUNTIME_DIR/rikka-nested-<128-bit hex>/wayland` (dir 0700) on the caller, then runs the server on the `rikka-nested` thread. `socket()` is the absolute `WAYLAND_DISPLAY`. Dropping the last `Nested` stops, joins and removes both.
- Without `.gpu`, a detached `rikka-nested-gpu` thread blocks in `SharedGpu::wait` (5 s) and mails `Command::Gpu`; the server runs its reactor meanwhile (so `Stop` ends it at once) and only enables dmabuf, connects the clipboard and starts accepting once that arrives.
- Peers are admitted only with the same uid (SO_PEERCRED) and as `ClientOptions::unprivileged()`, so privileged module globals (layer shell, lock, IM, virtual input, data control, capture) stay hidden.
- `nested.view(app_id)` returns a Send+Clone `View` handle at once; any xdg toplevel whose app_id equals it attaches, also when the app_id arrives after the first commit. Every handle call is a mailbox `Command`; views keep an `Arc<Shared>` (latest `Frame`, `Look`, and one change callback set by `View::watch`; the widget passes a closure that repaints its node, and tests pass one that signals an eventfd).
- `Frame.layers` is the flattened toplevel tree plus mapped popups in stacking order, in logical coordinates relative to the window geometry; each surface keeps one `LayerId` and one `Imported`/`Feed`. A frame is only replaced when the layer shape changes, so content-only commits never repaint the widget.
- Content: dmabuf → `Imported` arrival with buffer damage and the view's `Pulse`, a `BufferHold` in `Contents.holds`, lease released → `Command::Released` (wl_buffer release, syncobj release point); shm is converted to RGBA into a `Feed` and released at once; single-pixel → `LayerContent::Solid`.
- Pacing follows the host's real frames: each view's `rikka_picture::Pulse` (in `Shared`) beats once the host frame that drew its paint or its arrival is answered, and `Command::Tick` ticks frame callbacks, presentation feedback and `refreshed` with that frame's period. Commits that owe a frame without a new dmabuf wake the widget only after `settle` published the turn's arrivals (`wake_pending_views`), so a host frame never answers before the content it should show. Each view has its own pacing `OutputId` for fifo/commit-timing; hidden, unpainted or unattached toplevels tick once per second.
- Configures: always maximized + tiled with server-side decoration; `resize`, `set_visible` (suspended), `set_fullscreen` and `Input::Focus` (activated + keyboard focus) reconfigure. A size change gates frame publication until the client commits an ack of that serial, or 200 ms pass.
- Text input runs through the seat crate's host input method (`SeatMut::serve_text_input`, `compose`, `SeatEvent::TextInput`); the session keymap and repeat come from `rikka_input::xkb::SessionKeyboard`, which rikka-seat publishes from the host's wl_keyboard.
- Clipboard and primary follow the session through one `Clipboard::share()` both ways (`server/bridge.rs`). On connect the bridge offers the session's current selections (a watch only hears later changes). A client selection is published at once with `Clipboard::publish_deferred` (mime list only); each session read becomes `Command::ClientSend` and is served by `request_data` from the client, and a generation per selection kind rejects reads of a replaced selection. A client selection that goes away, and every selection at shutdown, is `withdraw`n from the session. Client drags read their data on helper threads (`server/transfer.rs`: poll, 3 s, 64 MiB) into `Look.drag.offer` so the widget can hand the drag to the host when the pointer leaves; host drops enter as compositor drags.
- `nested_view(&view).reserve_shortcuts(chords).pass_through(predicate)` sizes the toplevel, draws layers clipped to its rect, forwards pointer/scroll/gesture/key/IME/focus/drops, applies the cursor (images are drawn by the widget under a hidden cursor) and reports the caret while text input is enabled. rikka-ui has no touch events, so touch reaches clients only through `Input::Touch*`.
- `.retain_focus(true)` keeps the client keyboard-focused (no leave, no deactivation, grabs kept) when rikka-ui focus moves elsewhere, like an xdg_popup grab; once it is false again while unfocused, the next paint sends `Input::Focus(false)`.
- Tests (`tests/`) drive real `rikka-wayland-client` connections; `support/session.rs` is a small privileged display that a test `Clipboard` binds for the bridging tests, and memfd dmabufs exercise the Imported path without a GPU. `support::settle` blocks on the client socket plus an eventfd fed by `Client::follow(&view)` (and `Client::notifier()` for clipboard watches); `Client::barrier()` (two roundtrips) proves the server finished a turn.
