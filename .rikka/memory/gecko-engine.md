- The engine behind rikka-web is Gecko built as the GeckoView-on-Linux app `rikka-gecko` from `engine/gecko/` (MPL-2.0): `upstream.toml` (Firefox repository, version, commit), `mozconfig`, `patches/` (one `<firefox path>.patch` per changed upstream file) and `rikka/` (the `--enable-project=rikka` project: launcher, prefs, `embedding/` C++ bridge, `components/` JS for downloads, notifications, user content, view helpers). It has no `BUILD.bazel`; its wire types are `//crates/web/rikka-gecko-protocol`.
- `xtask/src/gecko/` drives it outside Bazel (`mod.rs` Engine ops, `tree.rs` Firefox git checkout, `patches.rs` apply/export/stamp, `mirror.rs` project sync, `mach.rs` environment and Rust channel, `upstream.rs` pin and newest-release lookup). Work lives in `.bazel/gecko` (`--work`): `firefox/` tree, `obj-dev`/`obj-release` objdirs (`MOZ_OBJDIR` set by xtask), `applied` stamp (pin commit + patch names and contents).
- `assemble` re-applies patches only when the stamp changes and mirrors `rikka/` by content (keeping `rikka/config`, which gets Firefox's version files), so mtimes stay stable. `export-patches` refuses a tree whose stamp is stale, includes new untracked files outside `rikka/` (intent-to-add) and rewrites the stamp; `follow` carries the patches onto the newest numeric `FIREFOX_x_y_z_RELEASE` with a 3-way cherry-pick, keeps conflicted patches unchanged, prints them on stdout (progress goes to stderr).
- No `mach bootstrap` (it refuses NixOS): `--enable-bootstrap` makes configure fetch clang, sysroot, pkgconf, node, sccache into `MOZBUILD_STATE_PATH` (default `~/.mozbuild`). Rust is the channel of `linux64-rust` in `taskcluster/kinds/toolchain/rust.yml`, installed with the dev shell's rustup and passed as `RUSTC`/`CARGO`, because cross-language LTO needs Rust's LLVM to match the bootstrapped clang. rustup and `mach` run inside `rikka-gecko-build` (`nix/gecko-build.nix`, a buildFHSEnv on the dev shell PATH) with `env_clear` plus a whitelist and no PATH, so the generic-Linux toolchains start on NixOS without nix-ld and see none of the dev shell (`CC`, `PKG_CONFIG_PATH`, bindgen args). bubblewrap needs unprivileged user namespaces; the CI runner enables them with a sysctl.
- `--release` sets `RIKKA_GECKO_PROFILE=release`, which `mozconfig` turns into `--enable-lto=cross`. `package` packs `obj-*/dist/rikka-gecko` as `rikka-gecko-<firefox>-<rev12>-x86_64-linux-<digest16>.tar.zst` with `dist::pack_named` (deterministic tar, zstd 19).
- `.github/workflows/gecko.yml` runs `gecko package --release` in `nix develop` on every `engine/gecko`/`xtask/src/gecko` change (sccache in the Actions cache keyed by `upstream.toml`), uploads artifact `rikka-gecko` and attests it on `main`. It writes xtask's launcher with `bazel run --script_path` and stops the Bazel server before `mach`: on the 16 GB runner the resident JVM starves the cross-LTO link, and the runner is lost without logs. `gecko-follow.yml` runs `follow` daily, pushes `gecko/firefox-<version>` and opens a PR (draft listing conflicts), dispatching its build.
- `xtask release gecko` (`release/gecko.rs`) finds the newest successful main run whose `engine/gecko` tree equals HEAD's, downloads and `gh attestation verify`s it (signer workflow, `refs/heads/main`), uploads it to packages' `binaries`, writes `nix/dist/gecko.json` {version,url,hash} and publishes `gecko.nix`+`gecko.json` to packages unless a published component linking `gecko` was built with another `crates/web/rikka-gecko-protocol` tree. `prune` keeps archives named by the last 10 packages `gecko.json`s and the checkout's.
- `nix/dist/gecko.nix` (dev shell overlay and distribution) reads `gecko.json`, autoPatchelfs with `patchelfUnstable --no-clobber-old-sections` (plain patchelf breaks Gecko's packed relocations), puts dlopened libraries on every ELF's runpath with `appendRunpaths`, and wraps with wrapGAppsHook3.
- JS-only engine changes can be tried without a build: copy `$RIKKA_GECKO`, unzip its `omni.ja`, replace files under `modules/`, rezip, replace the `rikka-gecko` wrapper by a script that sets the wrapper's GTK variables and execs `.rikka-gecko-wrapped` from the copy, and point `RIKKA_GECKO_PATH` at it. The rules' test environment wins over `--test_env`, so run the test launcher from its runfiles (`.bazel/bin/<pkg>/<name>.sh.runfiles/_main/<pkg>/<name>.sh <test>`) with `RIKKA_GECKO_PATH` set.
- JS XPCOM components (`esModule` in `components.conf`) need `QueryInterface` as an instance field, never `static`; otherwise XPConnect fails with NS_NOINTERFACE.
- rikka-gecko is a non-Android build, so toolkit's desktop window actors register beside GeckoView's; every form picker must have one owner. The patched `ActorManagerParent` gives the `Select` actor rikka's parent (`RikkaSelectParent.sys.mjs`, which must export `SelectParent`) and skips the desktop `DateTimePicker`; patched `GeckoViewStartup`/`GeckoViewPrompt` stop GeckoView's select prompts.
- Engine-side scroll physics live in the patched `layout/generic/ScrollAnimationRikkaPhysics.*`, chosen by `general.smoothScroll.rikka.enabled` in APZ's `SmoothScrollAnimation` and the main-thread `AsyncScroll`; GTK's `nsWindow` turns wheel/touchpad input into pixel deltas under that pref.
- Rendering reaches the app through `rikka-nested`, not the protocol; without a published GPU (plain tests) Gecko falls back to software WebRender.
