title: ADE project architecture
description: ADE's private crates, agent assembly, Git and worktrees, file editing, watching, and conversation view structure.
about: apps/system/ade

---

- One window per project folder: sidebar tabs Threads, Files (explorer), Git; the work pane shows editors under Files, else the conversation.
- Private non-UI crates: `ade-command, ade-config, ade-files, ade-git, ade-guide, ade-memory, ade-paths, ade-prompt, ade-scope, ade-skill, ade-tree, ade-watch`. `apps/system/ade/src` does drawing and orchestration.
- `ade-files::Root` keeps only the inside-the-project guard and name parsing (create with nested `a/b.rs` names, rename) over `rikka-file-operations`. `move_into`, `copy_into`, `trash` and `delete` start the engine and return a `Job` at once (`kind() -> JobKind`, `updates()` streaming `Update::{Working(Snapshot), Finished(Finished { change: Change::{Moved, Copied, Removed}, failures, cancelled })}`, `resolve`, `cancel`, blocking `wait`). `ade-tree` owns the tree model and the multi-`Selection`; `ade-paths::Paths::files` feeds Ctrl+P with matched ranges.
- Tools, threads, files and the computer are shared public crates: `rikka-tools`, `rikka-thread`, `rikka-computer` (fitted as `ComputerUse::machine()` from `rikka-computer-use`), `rikka-file-edit`.
- `src/project/assembly.rs` assembles the agent: standing docs, skills tool, the MCP hub through `Hub::equip` (shelf, `McpResources`, `McpServers`) and its `instruction()` (standing, before the environment block), the `Nearby` aside, hosted web tools (`ToolboxBuilder::web()`), and ADE's own agents. A `Workspace` rebuilds its assistant when withered, reply language or model catalogue change (`reconsider`, no disk access) or when its `Catalogs` (skills, commands, guides, memories; `project/catalogs.rs`) change. Catalogs are found off the UI thread when a workspace opens (it starts with none), before a conversation starts (send, resend) and when the root folder stirs; `Project::catalogued` rebuilds only on a difference.
- MCP: each `Project` owns one `rikka_mcp::Hub` (`project/hub.rs`): places `personal` = `~/.rikka/mcp.json`, then `project` = `<root>/.mcp.json`; folder = root, vault = `Vault::from_runtime_dir()`. `Project::open` starts it and follows `hub.changes()` (`state/mcp.rs`, keyed stream reaching `Ade`): an instruction change withers every workspace, newly failing servers and unreadable files are reported once. The hub watches its files, so any write (settings, the agent, by hand) reconnects live. Server tools stay live in the shelf; `project/tool_call.rs` names them `server · tool` via `rikka_mcp::ToolCall`.
- The composer's model picker is cached per `Llm::revision()` and thread selection (`Project::models`).
- `ade-prompt` catalogues `apps/system/ade/prompts/*.md`.
- Git: installed `git`, stdin closed, no pager or prompts, bulk paths on stdin as `:(literal)` pathspecs.
- The Changes tab has one primary button at the bottom (`project/git/primary.rs`, `Primary::of`): Commit while any change is ticked (or there is no remote); otherwise the sync action `Transfer::from_status` picks (Publish: no or gone upstream, Pull: behind, Push: ahead, else Fetch) with ↓/↑ counts, labelled with `RepoState::remote` (upstream remote, else `origin`, else first). A running pull/push, or a fetch while nothing is ticked, shows its spinner and percent in the button; a background fetch never replaces Commit. `Repo::{fetch, pull, push}` run through `Git::transfer` (`LC_ALL=C`, `--progress`), which parses stderr into weighted, monotonic `Progress` and keeps the rest for the error text. Pull follows `pull.rebase`/`pull.ff`/`branch.<b>.rebase` and adds `--no-rebase` only when none is set; a non-fast-forward push becomes `Error::Rejected` and triggers a quiet fetch.
- Background fetch: `state/transfers.rs` arms a keyed `after_keyed` timer when its due time (`Git::fetch_due`) changes: an hour after the newer of `FETCH_HEAD`'s mtime and the last attempt. A firing timer clears `fetch_due` so the next read re-arms it. `Origin::Background` failures are only logged. Progress from a workspace that is not shown skips the view. Fetch runs beside commit/switch; pull and push exclude them (`Transfer::is_exclusive`, `Git::is_busy`).
- The UI owns index selection: commit restores unchecked rows from HEAD and adds checked ones. Reuse fetched data. History loads only when visible and HEAD moved, capped at 200.
- `Repo::status` counts each `Change::stat` the way `Repo::diff` draws it: `git diff --numstat --no-renames`, plus a renames pass over status-reported pairs. Untracked files are counted in Rust within a per-status read budget; binary ones stay uncounted. Change rows draw stats as `ListItem::tag`s.
- Worktrees live in `<main>/.rikka/worktrees/`, excluded via `.git/info/exclude`, pruned before creation. Only existing, git-reported ones are listed. Bazel projects need `.rikka/worktrees` in `.bazelignore`.
- Watching: the tree watches expanded dirs only, the repo watches tracked dirs, refs, logs and worktree registrations. `ade-watch` folds paths into folders and reports within eight quiet intervals. There are no refresh buttons.
- Files open as editor tabs (`project/file`: `Viewer` holds tabs, the active one, an MRU `recent` list and a close-with-unsaved prompt). A single click opens the one unpinned preview tab; a double click, an edit, Ctrl+P or Enter pins. Editors use `text_editor(..).code(true)`, git margins via `rikka_file_edit::{Sheet, Marks}` against `ade_git::Repo::at_head`.
- Unsaved tabs show a dot in the tree and strip. A disk change under unsaved text is reported, not applied. Tree colours and letters come from `ade_git::Changed`.
- Explorer (`project/explorer`): 24 px rows in a `lazy_column(..).named(name_of)` (view stays still, folders unfold and fold under their row; the chevron is the shared `rikka_widgets::twistie`) whose `on_pointer` does multi-select, the context menu, drag-out and drops; inline naming rows; actions in `actions.rs` run create/rename on `ade_files::Root` off-thread; batch jobs are tracked by `Explorer` (`explorer/jobs.rs` `Running`: one row per job under the header with live status and bar, Stop, and a clash's Replace / Keep both / Skip / Skip all, as Files asks) and settle tree, selection and tabs from `Change` when they finish; progress repaints through `Watchers` without re-viewing the tree, and failures show as the first one plus a count. `Workspace::explore` lends `WorkspaceParts` (root, tree, viewer, git). Folder-ness comes from `Tree::is_folder`, never a stat; the selection is pruned against the tree when a folder is re-read.
- Every press on a folder row toggles it, multi-press included, so a fold or unfold mid-ride reverses at once; only files read the press count.
- Ctrl+P palette (`project/palette`, `Project.palette`) is a popover anchored on a centred mark a little below the caption; Ctrl+Shift+E opens the explorer.
- `project::Places` keeps one `Place` per hidden surface (threads, tree, changes, history, diff, conversation).
- State tracking: `Project` has no plain fields (`Project::HAS_PLAIN` is false), so `act`/`given` handlers and `ProjectHandle::say` reach `Project` and re-view only the components whose tracked keys changed. Anything needing `Setup` goes through `with_setup`/`given_with_setup`/`ProjectHandle::say_with_setup`, which reach `Ade` and re-view the whole window. Handlers that must not settle use `ProjectHandle::reach`.
- Tracked children: `Runners` (untracked map + a roster key), `Runner` (`running`, `asks`, `machine`, `jobs` snapshot and shown agent are tracked; the `Answer` itself is not), `Threads` (`listed`, `held`), `Transcript` (from `rikka-chat`: `Blocks` `settled`/`live`/`tailing`, `opened`, `finding`), `Terminals` (untracked map + roster) of `Terminal`. Views read only through these; a new field a view reads must be `Tracked` or it goes stale.
- Components (`project/view.rs`): sidebar, its per-tab bodies, work pane, thread pane, conversation, the live tail, composer (selects `Ade` for `Setup`), composer controls, and the caption's place and heading. The 60 s age tick bumps `Project.minute`, read only by the thread list and git history.
- Conversation = one lazy column of settled blocks, each a `lazy` subtree, plus one last cell that is the live-tail component: the open answer's blocks, each memoised by its content stamp. `rikka_chat::Transcript` indexes it incrementally; ADE binds the shared UI as `project::chat::AdeChat`.
- Streaming: the open round's prose is a `rikka_markdown::MarkdownStream` in the chat `Transcript`, drawn by `streamed_markdown`. A streamed (unveiling) markdown always draws one `lazy` per document block from the first byte, never switching to the `whole`/`deferred` paths at `BLOCK_AT_A_TIME`, so shown text keeps its `RichText` and never unveils again. `Runner::say` streams replies to `Project::replied`; a `Reply::Delta` grows the stream (`Project::streamed`) and views nothing. `Project::agent_said` grows it from the watched `Subagents::get` when only the open round's words changed (`Blocks::grow`). First words of a round, the once-a-second keep, an open find bar or anything structural take `settle`, which re-views only the live tail. Threads not shown `skip_view`.
- `Project` is one `#[derive(State)]` struct in `project/state.rs` with impl blocks split by concern in `state/{conversing,offers,mcp,worktrees,access}.rs`. `Runner` (`project/runner.rs`) is a thin layer over a `rikka_thread::Desk`: it adds root, build stamp, the machine view, agent watching and tracked mirrors (`running`, `waiting`, `jobs`, `awaiting`, `asks`) refreshed after every desk call and `DeskEvent` (`Project::desk_event`). A thread with a runner lives in its desk, not in `Threads.loaded` (`attach_runner` moves it there with `Threads::take`); read threads through `Project::{holds, thread_of, thread_mut_of}`, and `Project::keep` keeps through the desk and relists the summary.
- `project/tool_call.rs` (`ToolCallLabels: Describe`) draws `rikka_tools::ToolAction` (symbol, gist) and reads ADE's own `Named` stems (`AGENT`, `SKILL`).
- Per event, a key, a streamed word and a hover view almost nothing of the window; a tool-call step views the tail block plus the thread list and controls when the summary moved.
- Each prose block is its own selection region. Output uses read-only `text_editor`s over `project::printed::Printed`. View calls draw `Call::shown()` through `project::shown`.
- `Ctrl+F` counts every block off-thread (`project::finding`, reusing counts by `Turn::stamp()`). Files get `Ctrl+F`/`Ctrl+H`, the composer shell `Ctrl+Shift+F`.
- Composer: `resizing_upward()`, drafts per thread (`chat::Drafts`), built with `chat::Composer`. `Ctrl+T` toggles the person's own shell, invisible to the agent; `Ctrl+Shift+T` restarts it. `project/terminals.rs` keeps one `Terminal` per thread (the unsent draft under `""`, rekeyed in `begin_with`), each with its own shown state, opened in the thread's `shown_root()` (its worktree). Shells keep running while their thread is not shown; reports route by a per-shell serial, so a restarted shell's stale reports are ignored. Rebinding a thread's worktree (`bind`) restarts its shell in the new folder; deleting the thread closes it; a hidden, stopped terminal is dropped.
- The `@`/`/` offer list (`chat` picker) sits inside the composer surface above the foot, so the surface itself grows; it is a lit `lazy_column` whose selection pill glides.
- `@` paths come from `ade-paths` (gitignore-aware walk, VCS stores skipped). `.rikka/{worktrees,memory,tmp}` are offered as folders, never their contents.
- Only live-tail calls animate (chat `call::arriving`); settled blocks carry no transition, except the turn just sent (`Settled::sent`), cleared by the next settle.
- Job chips show task and model. Pressing an agent chip shows `Subagents::get` read-only at once (`watch_agent`/`watch_main` settle). The `Runner` owns which agent is shown.
- The machine screen and output folds belong to `Project`, never to `Runner` (rebuilt with its assistant).
- Settings screen (`src/settings/`): sections AI (`Section::Llm`, default; `#[state] Option<rikka_llm_settings::LlmSettings>` loaded on the first visit, opened on each visit and closed on leaving, never dropped), MCP servers, skills and commands. MCP is the shared `rikka_chat::servers` page over an `Option<rikka_chat::Servers>` built and followed each time the screen opens, over the open project's hub (or an unstarted personal-only `project::hub(None)`), and dropped on leaving; `project::titled` names its places. `Ade::open_settings(section)` jumps to a section.
- Gap: Agent Skill `allowed-tools` is not enforced.
