title: Browser private crates
description: browser-store (SQLite), model, bookmarks (Chrome sync), pages, preferences, reader, translate kit.

- Chrome owns history, downloads, site permissions and zoom, passwords and autofill; the app reads them through `rikka-web` (`History`, `Downloads`, `Privacy`, chrome:// pages), never the store. Each persistent profile is one Chrome user-data-dir, `$XDG_DATA_HOME/rikka/browser/chrome/<profile id>`; private windows use an ephemeral one and never sync bookmarks.
- `browser-store`: one SQLite file (`$XDG_DATA_HOME/rikka/browser/browser.sqlite`, WAL). The schema is declared object by object in `src/schema/objects.rs` and converged at every open: missing tables and indexes are created, a table whose stored SQL differs is recreated empty together with every table referencing it (logged), undeclared objects are dropped (virtual tables first). Writes are fire-and-forget on thread `rikka-browser-store`, batched and coalesced per key; ids are allocated at call time; read-after-write needs `flush()`. Reads use up to four query-only connections.
- Store domains: profiles, per-profile settings documents (`profile_settings::<T>`/`set_profile_settings`, JSON of any serde type, `MalformedSettings` when it no longer decodes), spaces, favorites (per profile), pinned tree (per space), per-window sessions with split groups (tabs keep URL and title only; they are the only restored state, Chrome's session restore is off), archive, closed tabs (25), favicons (global, ≤64 px enforced by `Picture::new`, deduplicated), and per-profile bookmark sync state (`bookmark_sync`/`save_bookmark_sync`: `BookmarkRoots` plus one `BookmarkLink` per synced row, which is both the local id ↔ Chrome bookmark id map and the last-synced snapshot; it has no foreign key to the rows so local deletions stay visible). `clear_browsing_data` covers only closed tabs and archive. `parked.rs` holds what closed and archived tabs share.
- `browser-preferences` owns the `rikka.browser` settings domain (`Preferences` over `rikka_settings::seam`, observed through rikka-ui `Observers`; sidebar, corners, archive, search engines, reader style, Memory Saver, Home parts and hidden top sites, default-browser prompt, translation rules); its `settings_catalog` target feeds `xtask settings`.
- `rikka-omnibox` (`crates/web`, public; the launcher classifies with it too) does no I/O apart from `Suggester` (rikka-net, no cookies, 1.5 s, 64 KiB cap) and `classify` expanding `~` through rikka-dirs: `classify`, `UrlDisplay`, `SearchEngines`, `Candidates<K>::rank`. IDN display safety reads scripts from `rikka-text-unicode` and shows only an allow-list of scripts. Host classes and registrable domains come from `rikka-public-suffix`.
- `browser-model` is the shared browser state (`Model<L>`: profiles, spaces, favorites, pinned tree, tabs, windows, split groups, closed tabs, session snapshot and loading), plus `Downloads` (per-`ProfileKey` `rikka_web::DownloadItem` snapshots; `update` returns the downloads that newly finished or failed by diffing with the previous snapshot, the first snapshot being the baseline), `Favicon` and `Names` (localized default names the app supplies as fn pointers). `Page<L>` is `Unloaded | Live(L)`; `Meta::follow(&PageState)` tracks url, title, loading, sound, URL-derived `Security`, zoom, back and forward. Closing returns the live view to drop and archives at once. It may use rikka-ui's change tracking (`Tracked`, `Revision`, `Observers`) and rikka-web value types, never a `Session`: the live page is the type parameter `L: LivePage` (`type View`), and the app fixes it with `crate::model::{Model, Tab}` aliases over its `page::Live`. `bookmark_mirror(profile)` and `apply_bookmarks(profile, plan)` connect it to `browser-bookmarks`. Tests drive it with a fake `LivePage` over an in-memory store.
- `browser-bookmarks` (UI-free) syncs favorites and pinned trees two-way with Chrome bookmarks under Other bookmarks/`Rikka`/{`Favorites`, `Spaces`/<space name>}. Other bookmarks is found by its folder type (`FolderKind::Other`), never by id. `Plan::new(tree, &Mirror, Option<&BookmarkSync>)` does a three-way merge (Chrome wins conflicts, removed Rikka containers are re-uploaded rather than deleting local rows, unlinked items pair by URL or title so a synced Rikka folder is adopted); `apply_local(&mut impl LocalSide) -> Pending`, then `Pending::apply_remote(&impl Remote).await -> BookmarkSync` to save. `Remote` is implemented for `rikka_web::Bookmarks`; tests use in-memory fakes of both sides and check that a second sync changes nothing.
- `browser-pages` holds the UI-free page rules with table tests: internal `rikka://` routes (`Internal`, `Section` incl. `Section::Chrome`), `ChromePage` (chrome:// settings, account, passwords, payments, addresses, sync and other pages the settings link to) and `site_details(origin)`, `data_url_payload`, host and origin normalization (`web_host`, `registrable_site` = `rikka_public_suffix::site`, `covers`, `Origin`), Memory Saver policy (`TabActivity`, `discardable_tabs`, `is_pressed`). New UI-free browser rules go there, not into the binary.
- Content blocking is left to WebExtensions the user installs; nothing third-party is vendored or bundled.
- `browser-reader`: own extraction (bundled `scripts/browser-reader/{probe,extract}.js` registering `browser-reader.probe`/`.extract`); `probe(&Session)` and `extract(&Session)` run them in the top frame's isolated world through `Session::run` and return `readable`/`parse`-validated results (typed blocks); Rust renders escaped HTML with a CSP and no scripts; `render/` writes through `fmt::Write` (`Markup<W>`, `rikka_html::Escaped`). `tests/extraction.rs` runs from `tests/machine.rs` against real Chrome (`:test_extension`), pages served locally with a `<base>`.
- Translation layers: `browser-translate` (kit) → `browser-translators` (registry plus one module per service: `google/`, `microsoft/`) → the app, which uses only the registry and its re-exports.
- The kit owns the page protocol: the app registers `probe_script()` per runtime, routes `Event::Message`/`Event::Ask` named `MESSAGE` through `Message::parse` (pages are posts; watches and translate requests are asks answered with `Command::answer()` / `Translation::to_json()`); bodies are validated (≤200 units, ≤20 000 chars, depth ≤32, unique ids). `src/markup` encodes units as id-tagged HTML in a `Dialect`; `src/protect.rs` keeps code-like tokens untranslated.
- The kit's `Translator::translate(&dyn Adapter, Job)` dedups, caches by bytes keyed by adapter id, batches by the service's `Limits`, caps requests at 6, decodes with `rikka-html` tokens, and votes the detected language. The source language is always auto-detected. `Unit::new` validates; a `Job` only holds valid units.
- An adapter is a unit struct implementing the object-safe `Adapter` (`service() -> &'static Service`, `translate(&Http, Call) -> Translating`); `Http` is the only client and retries a 5xx once but never a 429. Google scrapes its key at run time; Microsoft is keyless.
- browser-translate tests: `tests/main.rs` drives `Translator` with a fake `Adapter` and `Http` against a local server; `tests/machine.rs` (`page.rs`) runs the probe and translator in real Chrome over fixtures served from a local TCP server (frames, a strict CSP page); it waits on events only: `Committed`/`Finished` navigations, a `browser-translate-test.reached` post from the fixture's MutationObserver for DOM conditions, and a quiet period after the last batch.
- Languages are `rikka_languages::Language` (BCP-47). Each `Service` lists BCP-47 `targets` and `aliases` (tag → the service's own code, e.g. Google `zh-Hans`→`zh-CN`, `fil`→`tl`, `nb`→`no`); `Service::code`/`language` are the only translations between them.
- `Engine` is an index into `ALL` (first = default), stored by id. Adding an engine = a module in `browser-translators/src/` and one line in `ALL`.
