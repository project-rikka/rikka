---
title: Browser private crates
description: browser-store (SQLite), model (shared state), pages (page rules), reader, engine settings, translate kit + translators.
about: apps/system/browser/crates
tags: [web, data]
---

- `browser-store`: one SQLite file (`$XDG_DATA_HOME/rikka/browser/browser.sqlite`, WAL). The schema is declared object by object in `src/schema/objects.rs` and converged at every open: missing tables, indexes and triggers are created, a table whose stored SQL differs is recreated empty together with every table referencing it (logged), undeclared objects are dropped, external-content FTS is rebuilt after creation. Writes are fire-and-forget on thread `rikka-browser-store`, batched and coalesced per key; ids are allocated at call time; read-after-write needs `flush()`. Reads use up to four query-only connections.
- Store domains: profiles, per-profile settings documents (`profile_settings::<T>`/`set_profile_settings`, JSON of any serde type, `MalformedSettings` when it no longer decodes), spaces, favorites (per profile), pinned tree (per space), per-window sessions with split groups (tab state is opaque `SavedState` bytes), archive, closed tabs (25), history with FTS5 trigram and frecency, `visited(urls)`/`host_visited(host, range)` for Gecko's history delegate (`host_visited` range-scans `url_key` and compares the parsed host exactly), favicons (global, ≤64 px enforced by `Picture::new`, deduplicated), site settings (permissions, zoom, HTTPS-Only exceptions), downloads. History, site settings, downloads and clearing are scoped by `ProfileId`. `parked.rs` holds what closed and archived tabs share.
- `browser-engine-settings`: the per-profile `EngineSettings` document (tracking protection, cookies, DoH, proxy, page languages, autoplay, colour scheme, spellcheck and dictionaries, user style, `PermissionDefaults` per `Permission`) built from rikka-web's serde preset types, with `preferences()`, `locales(interface)` (empty page languages follow the interface locale) and `dress(UserContent)` (adds or removes the `USER_STYLE` style); also the DoH `Resolver` presets and the settings-input parsers (`parse_endpoint`, `parse_resolver`, `parse_script`, `parse_bypass`, `InputError`). Screen-sharing defaults have no Gecko pref and are applied by the browser only.
- `rikka-omnibox` (`crates/web`, public; the launcher classifies with it too) does no I/O apart from `Suggester` (rikka-net, no cookies, 1.5 s, 64 KiB cap) and `classify` expanding `~` through rikka-dirs: `classify`, `UrlDisplay`, `SearchEngines`, `Candidates<K>::rank`. IDN display safety reads scripts from `rikka-text-unicode` and shows only an allow-list of scripts. Host classes and registrable domains come from `rikka-public-suffix`.
- `browser-model` is the shared browser state (`Model<L>`: profiles, spaces, favorites, pinned tree, tabs, windows, zooms, split groups, closed tabs, session snapshot and loading), plus `Downloads` (download items matched to engine progress by path, then by id), `Grants` with `plan`/`content_asks`/`media_asks`, `Favicon` and `Names` (localized default names the app supplies as fn pointers). It may use rikka-ui's change tracking (`Tracked`, `Revision`, `Observers`) and rikka-web value types, never a `Session`: the live page is the type parameter `L: LivePage` (`type View`), and the app fixes it with `crate::model::{Model, Tab, Closing}` aliases over its `page::Live`. Tests drive it with a fake `LivePage` over an in-memory store.
- `browser-pages` holds the UI-free page rules with table tests: internal routes (`Internal`, `Section`, `rikka://` and `view-source:` addresses), `Certificate::parse`, `FailureKind::from_code` and its `ErrorAction`, `VisitTracker` (visit cause and redirect legs over an `Arrival`), `best_icon`/`data_url_payload`, host and origin normalization (`web_host`, `registrable_site` = `rikka_public_suffix::site`, `covers`, `Origin`), Memory Saver policy (`TabActivity`, `discardable_tabs`, `is_pressed`). New UI-free browser rules go there, not into the binary.
- Content blocking is left to WebExtensions the user installs; nothing third-party is vendored or bundled.
- `browser-reader`: own extraction (`PROBE_SCRIPT`, `EXTRACT_SCRIPT`, evaluated in isolated world `rikka-reader`) returning typed blocks; Rust validates and renders escaped HTML with a CSP and no scripts; `render/` writes through `fmt::Write` (`Markup<W>`, `rikka_html::Escaped`). `tests/extraction.rs` runs from `tests/machine.rs` against the installed engine (pages loaded as data: documents with a `<base>`).
- Translation layers: `browser-translate` (kit) → `browser-translators` (registry plus one module per service: `google/`, `microsoft/`) → the app, which uses only the registry and its re-exports.
- The kit owns the page protocol: `PROBE_SCRIPT` runs in isolated world `rikka-translate` over the replying handler `rikkaTranslate`; `Message::parse` validates bodies (≤200 units, ≤20 000 chars, depth ≤32, unique ids). `src/markup` encodes units as id-tagged HTML in a `Dialect`; `src/protect.rs` keeps code-like tokens untranslated.
- The kit's `Translator::translate(&dyn Adapter, Job)` dedups, caches by bytes keyed by adapter id, batches by the service's `Limits`, caps requests at 6, decodes with `rikka-html` tokens, and votes the detected language. The source language is always auto-detected. `Unit::new` validates; a `Job` only holds valid units.
- An adapter is a unit struct implementing the object-safe `Adapter` (`service() -> &'static Service`, `translate(&Http, Call) -> Translating`); `Http` is the only client and retries a 5xx once but never a 429. Google scrapes its key at run time; Microsoft is keyless.
- browser-translate tests: `tests/main.rs` drives `Translator` with a fake `Adapter` and `Http` against a local server; `tests/machine.rs` (`page.rs`) runs the probe and translator in a real Gecko session over fixtures served from a local TCP server (frames, a strict CSP page); it waits on events only: page state changes for navigation, a page-world handler `rikkaTestReached` posted by a MutationObserver for DOM conditions, and a quiet period after the last batch.
- Languages are `rikka_languages::Language` (BCP-47). Each `Service` lists BCP-47 `targets` and `aliases` (tag → the service's own code, e.g. Google `zh-Hans`→`zh-CN`, `fil`→`tl`, `nb`→`no`); `Service::code`/`language` are the only translations between them.
- `Engine` is an index into `ALL` (first = default), stored by id. Adding an engine = a module in `browser-translators/src/` and one line in `ALL`.
