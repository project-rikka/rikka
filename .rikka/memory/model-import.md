- Public entry points: `rikka-model-core` (data, import/export machinery and runtime; no codec, no renderer), `rikka-mmd`, `rikka-vrm`, `rikka-humanoid`, `rikka-model-gpu` (upload; programs that draw models depend on it directly), and the full `rikka-model` for programs that read arbitrary files. `rikka-model` names no renderer, so readers and converters (Files) stay off the 3D crate. Data-only crates depend on the narrow ones. `rikka-polymesh` (public) is the editable polygon mesh with `to_mesh`/`from_mesh` bridges (polymesh note). `rikka-gltf`, `rikka-fbx`, `rikka-stl` (read/write, millimetres) and `rikka-blend` (reads models and scenes, writes scenes) stay internal. The `HumanBone`/`Humanoid` vocabulary lives in `rikka-model-core`; `rikka-humanoid` recognizes it in any model.
- `rikka_model::registry()` bundles every codec (its exporters are shared `Arc`s, so `exporter_named(name)` hands one out; the .blend exporter goes `Model` → `Scene::from_model` → scene writer) and `rikka_model::import(path)` is the one-line read. `rikka-model` re-exports core, and `mmd`, `vrm`, `humanoid` as modules.
- `rikka_model::scene` is the modeler's door: `ImportScene` (`import_scene(path)`, `import_scene_bytes(name, bytes)`) reads `.blend` (by content) straight into a `Scene` and every other format through the registry + `Scene::from_model`, keeping the source `Model` and `Correspondence` for format extensions; `export_scene`/`export_scene_bytes` with `SceneExport` (`ToModel`, exporter name, `BlendOptions`, `ExportOptions`, an `extend` hook run on the produced `Model`) write `.blend` directly (exporter named for the format or the extension) and everything else through `Scene::to_model` + `Export`; both return `SceneReport { warnings, notes }`.
- Layers: data (`Model`, `Mesh`, `Material`, `Skin`, `Animation`) → `Importer`/`Exporter`/`Registry`/`Import`/`Export` → runtime (`Pose`, `AnimationPlayer`, `Instance`, `Rig`, `Tints`). GPU upload lives in `rikka-model-gpu` (own `Error`: `Material`, `Mesh`, `NoMaterial`, renderer errors translated to text), so `rikka-model-core` knows no renderer or image decoder.
- `Model` is flat vectors with typed ids. `ModelBuilder` hands the ids out, and `validate` rejects dangling ids, cuts and loops. `animation_id` names animations by place, because names repeat.
- `Model::order()` is the parent-before-child visit order; `Instance` computes it once and hands it to rigs as `PoseState::order`. `Model::place`/`place_all(order, …)`/`parent_world` are the one world-matrix propagation; rigs, instances and physics bones use them.
- A `Mesh` is one vertex stream plus submeshes: one renderer mesh, one draw per submesh. `Mesh::finalize` fills missing submeshes and bounds idempotently.
- `Vertices::set_influences(vertex, &[(joint, weight)])` keeps the given order up to four, else the strongest four strongest-first, and never normalizes (the `normalize_weights` import option does); `influences(vertex)` reads them back.
- `MorphTarget::new` + `push`, then `merge(Repeats::KeepFirst | Sum)` sorts vertices and resolves repeats (glTF/FBX keep the first, PMX sums).
- Codec kit in `rikka-model-core`: `ImportCtx::import_image(builder, &[places…])` tries each place quietly, warns on the last and names the image after it; `ByteReader`/`ByteWriter` are the shared cursor (PMX/VMD, FBX binary both ways, GLB and glTF buffers, STL; `ByteReader::with_endian` reads big-endian too, as the .blend header, block heads and SDNA do); `MeshAssembler` welds polygon corners (`Corner`) into vertices and sorts triangles into one submesh per slot (FBX, .blend, STL), and records `Mesh::polygons` (`Polygons`: vertex→control point, polygon offsets, corner vertices, submesh per polygon) when every face came through `polygon()` (STL's bare `triangle()`s record none); `Mesh::polygons` is `None` for other codecs, validated with the mesh and reversed (first corner kept) by `flip_winding`; `polygon::{normal, project, triangulate, triangulate_flat}` is the one ear-clipper; `bake::adaptive(seeds, Subdivision, sample)` bakes any `bake::Sample` (transforms, weight rows) exactly at the seeds (key times) and bisects only where the linear interpolation strays (1e-4 relative distance, 1e-4 rad, 1e-4 weight), bounded by `Subdivision::Halves { rounds }` (FBX) or `Subdivision::Grid { step }` (.blend and VMD: whole frames, so the densest result is one sample per frame); `bake::TransformSamples` turns the samples into linear TRS channels; `EulerOrder` names the six Euler orders.
- `Limits` bounds an import (`Limit::{FileBytes, ResourceBytes, TotalBytes, Vertices, Indices, Keyframes}`, `Error::LimitsExceeded { limit, actual, allowed }`). A codec charges what it is about to allocate or sample (`ImportCtx::charge`, `charge_keyframes`, `Limits::check`) before doing it; counts declared by a file are never trusted.
- Rig hints reach format-neutral code through `Extension::describe_rig(&mut RigFacts)` (declared humanoid, IK reaches, followers, twist and swinging nodes); `Model::rig_facts()` gathers them. `Extension::alias_materials` and `Model::material_aliases()` do the same for alternate material names (a PMX material's English name).
- `Error` is semantic where a caller or a person acts differently: `Damaged(reason)` (corrupt input, textual), `UnsupportedVersion { format, version }`, `RequiredExtensions`, `Invalid(reason)` (the model breaks its own invariants), `Unmet { format, requirement: Requirement }` (an export the format cannot hold: no animation, no avatar, no vertices, non-finite positions, too many triangles), `Encode`, `LimitsExceeded`, `Read`/`Write`, `Cancelled`.
- Import: `Import::open(path)`, `Import::bytes(bytes)` or `Import::named_bytes(name, bytes)` (the name breaks sniffing ties and places sibling resources). Content sniffing wins, and ties are broken by extension (VRM vs glTF). Export goes by destination extension. `Registry::exporter_named` or `Export::with_exporter` pick the second writer of a shared extension.
- `Export` warns about everything the format cannot hold before writing.
- `ImportCtx`/`ExportCtx` share a `Journal` (cancel, progress, warnings). Resources go through `Resolver::read(uri, limit)`/`Sink` (`Error::Read`/`Error::Write`); a resolver refuses more than `limit` bytes before reading. `DirectoryResolver`/`DirectorySink` sanitize paths, refuse escapes and symlinks (`O_NOFOLLOW`) and non-files. `Export::to_file` writes through `rikka_fs::replace` (atomic, keeps mode, follows links). `Image::file_name(index)` is the one name for an unnamed image (`image<N>.<ext>`).
- Canonical space is right-handed, Y up, metres. Import validates first, then converts: node transforms and curves component-wise (`Conversion::transform`), vertices mirrored, winding flipped, camera planes, orthographic sizes and light ranges scaled. Codecs store lengths in file units. Export converts a copy, and only if needed. `Transform::from_matrix` survives zero scale axes.
- `Extension` must be `Clone` and converts geometry via `Extension::convert`. Morph targets are merged (sorted, first repeat kept) by postprocessing.
- `GpuModel::upload` describes PBR materials on `rikka/standard` and toon materials on the prebuilt shader presets (`Toon::flavor` `Mmd` → `mmd`, `MToon` → `mtoon`) by the import convention's names (rikka-shader-presets `import`), skipping names the template lacks; the class preset is applied when the template declares it. PMX `base_color` is passed as lit − `Toon::ambient` with `ambient_color` = ambient. `materials::values` is also what tint refreshes set. Base and emissive textures are sRGB; a separate occlusion map is packed into ORM.red for PBR only.
- Per material: `preset(material)` (preset key of the current template, `None` off presets), `class(material)` (`ToonSurface`), `is_outlined(material)` (whether a hull is drawn now, after any style).
- `GpuModel` keeps each material's original desc: `base(material)` gives the current styled desc, `apply_style(renderer, material, MaterialStyle { template, preset, values, outline })` recreates the material (and its outline) on another template or preset and reclaims the old one, `set_values` writes values to both; `MaterialStyle::outline` (`None` keeps the model's own outline, `Some(true)` makes a hull from the styled desc even when the model material has no edge, `Some(false)` drops it); tint refresh skips names or kinds the styled template lacks. `drawing(..).selected(&[MaterialId])` marks those materials' main draws selected for the renderer's selection outline. `drawing(..).light_channels(mask)` sets every draw's light channels (default `DEFAULT_LIGHT_CHANNELS`).
- `GpuModel::draw` passes `Material::render_order` as the draw order; a blended material that writes depth still casts shadows.
- `GpuModel::restyle(renderer, template)` / `restyle_material(.., material)` build a `Restyle`: extra materials on another `MaterialTemplate` that keep each model material's state and cutoff and bind its base/emissive textures and colours to parameters with the `albedo*`/`emission*` roles; `drawing(..).restyled(&restyle)` draws with them (outlines keep their own). A dropped `Restyle` goes to the reclaimer; a template reloaded in place carries its materials along.
- Outlined toon materials add a second hull material (`MaterialDesc::hull()`, front-face cull), drawn and never picked. `refresh_materials` uploads the instance's `Tints` only when `Tints::revision()` changed (every mutable access takes a new global revision).
- `Prepared::new(model, &options)` does the renderer-free half of an upload on any thread (each image decoded once, in parallel; ORM packing, channel splats, outline normals); `GpuModel::upload_prepared(renderer, prepared)` only creates GPU objects. `GpuModel::upload`/`upload_with` do both in place; Viewer and Animate build `Prepared` on their loader threads and only call `upload_prepared` where the renderer lives.
- `HeadRest::new(model, &anatomy)` (head, hips height and `Anatomy::forward()` from a recognized figure) + `place(&instance)` give the renderer `Head` (face frame for toon faces, face shadows and hair).
- `object_id = node index`, so `Renderer::pick` + `GpuModel::node_at` finds the node under a pixel.
- `Instance` owns its `Arc<Model>`. `refresh` settles from the pose only and is idempotent. Time goes in through `advance(dt)` and `seek(t)`.
- `Animation::apply(time, pose)` is the one sampling door; an animation held outside the model can drive an instance via `pose_mut` + `refresh`.
- `Rig::evaluate(model, transform, PoseState, phase)` runs twice per refresh, `Phase::BeforePhysics` then `Phase::AfterPhysics`. Instances hold no physics: simulation (cloth, liquid) reads `worlds()`/`joints()` after `advance`/`seek`/`refresh` and draws through renderer drapes.
- `Extension::rig` supplies a `Rig` (`rikka_vrm::Avatar`, `rikka_mmd::Puppet`). Reach concrete rigs with `Instance::rig_as::<R>()`/`rig_as_mut`; `rikka_vrm::Expressive` holds only the expression and gaze API.
- `rikka-model-gpu`: `ModelDrawing::drape(node, Drape)` hands a mesh node's draws (outline included) a renderer drape in that mesh's vertex order; use `Drape::starting_at` when one buffer holds several meshes. `ModelDrawing::layers(mask)` puts every draw of the model on renderer object layers (default `DEFAULT_LAYERS`), which layer-selected effects read.
- `Rig::tints()` returns the per-instance `Tints` (materials an expression or material morph recolours; `Tints::for_materials`, `restore`, `get_mut`); `Instance::material`/`tints` read them.
- `Instance` is `Clone` (the rig is duplicated). `Instance::worlds()` is the whole world-matrix slice, in model space; `Instance::transform()` places it.
- `GpuModel::destroy` frees at once. Dropping it leaves resources to the renderer's reclaimer.
