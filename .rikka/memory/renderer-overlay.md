- Overlays are editor geometry: `frame.overlay(OverlayBatch::new(source, OverlayLines::new(w).dash(Dash::new(on, off)) | OverlayPoints::new(size).shape(..).outline(rgba, w) | OverlayTriangles::new().shading(OverlayShading::Facing).cull_back_faces(b)))` with `.range(first, count)`, `.transform(Mat4)`, `.depth(OverlayDepth::{Tested, Faded(alpha), Always})`, `.bias(f)`, `.writes_depth(b)`. Colours are display (sRGB-encoded) RGBA8 with straight alpha; sizes are device pixels; lines and points expand to quads in the vertex shader with analytic AA, dashes are screen space. `.smoothing(OverlaySmoothing::Aliased)` on lines/points gives the reference's Smooth Wires off: binary coverage (`|distance| <= half width`, `rikka_overlay_coverage`).
- Sources: `frame.overlay_data(&OverlayData { positions, colors, indices })` copies per-frame data (`OverlaySource`, valid only in that frame); `Renderer3d::{create, update, destroy}_overlay_buffer` / `update_overlay_indices` / `Reclaim3d::overlay_buffer` keep persistent buffers in `OverlayPool` (arena lanes positions 12 B + colours 4 B, indices u32; sub-range overwrites flushed with a WAR barrier). Elements are vertices, or indices when the source has any; lines take pairs, triangles triples.
- Rendering (`src/record/overlay.rs`, declared at the end of `declare_compose` after tonemap/present): at display resolution into the viewport output with premultiplied blending. When any batch is Tested/Faded, `rikka.three.overlay.occluders` re-renders every visible non-hull fill draw (opaque, masked and transparent: X-ray meshes occlude) depth-only through the prepass recipes (`recipes::occluder`, `DirectPass::Occluder`) with a second `RikkaFrame` whose view is the unjittered display view (`FrameAddresses::overlay_refs`). So occlusion is identical in MSAA, TAA, upscale and dynamic resolution, and ignores grid, fluid and hulls.
- Layering: Tested/Faded batches in submission order against that depth (Faded draws the hidden part again with `LESS` at the given alpha), then the depth is cleared and Always batches draw in submission order, depth-tested only among themselves (in-front bones self-occlude when they write depth).
- Depth bias moves the vertex toward the eye by `bias × view distance` (the reference's `ndc_offset`): defaults lines 0.00125, points 0.001875, triangles 0.000625.
- Overlays never touch picking, shadows, TAA history or the still signature.
- Dynamic meshes: `Renderer3d::update_mesh(id, &MeshUpdate { first, positions, normals, tangents, uvs, colors })` overwrites in place (positions by copy, partial attribute fields by the `mesh_attributes.slang` scatter kernel in `attribute_writes.rs`); `replace_mesh(id, &MeshData)` and `replace_mesh_indices(id, Indices, &[Submesh])` reallocate and keep the id. Host positions (and skins) stay in `MeshEntry::shape`; each `Part` keeps its vertex range, so bounds and joint spheres refit after position updates. `MeshPool::revision` feeds the temporal still signature and the shadow cache key; ray structures of the mesh are forgotten.
- Built-in viewport templates (`lib/rikka/workbench.slang`): `BuiltinTemplate::Workbench` is solid shading (Default studio light's four view-space lights, wrapped diffuse + normalised Blinn specular, MatCap with optional specular map, or flat; colour from material, texture or random per object id, times an optional vertex colour). `BuiltinTemplate::Unlit` (`RikkaUnlitSurface` + `RikkaShadelessModel`) outputs colour × texture × vertex colour (`vertex_color` off/srgb/linear). Both models override `shade`, so scene lights, shadows and ambient never reach them. Use `ToneMapping::Clamp` for the reference-matching output and `MaterialState::shadows(false, false)`; back-face culling is `MaterialState::cull`.
- Wireframes of a mesh with deformation: draw it again with `BuiltinTemplate::Wireframe` and `MaterialState::wireframe()` (polygon mode lines in the material overlay pass, render resolution, TAA'd).
- Editor frame data (`src/editor/`, GPU `RikkaEditor` in `lib/rikka/editor.slang`, reached through `RikkaFrame.editor`, 0 when unused): `Frame::clip_planes([Vec4; 6])`, `studio_lighting(StudioLighting)`, `selection_outline(SelectionOutline)`, `editor_grid(EditorGrid)`, `workbench(WorkbenchEffects)`.
- Clipping is per fragment: `Record::pipeline` swaps clippable recipes (`Recipe::clippable`) for a variant with specialization constant 2 `RIKKA_CLIPPING` (opaque prepasses without a fragment get `clip.slang`); `rikka_pixel`, `rikka_surfaces`, `depth.slang`, overlays (`OverlayBatch::clipped`, default true) and the grid test `rikka_clipped`. Template masked prepasses (`rikka_cut`) cannot clip: callers switch masked materials to alpha-to-coverage while clipping. Shadows are not clipped.
- Selection outline: draws with `Draw::outlined(rgba)` (or `outline_only`, drawn nowhere else) render object ids `palette << 28 | object_id + 1` (`GpuInstance.outline`, ≤ 15 colours a frame) into a display-res prepass with its own depth, then `outline_detect.slang` finds edges (thick when `pixel_size > 1` or `thick`) and dims parts behind the occluder depth by `occluded_alpha`, and `outline_resolve.slang` applies the reference's line AA, all before the overlay batches. The old `Frame::outline`/`Draw::selected` path is unchanged for Animate and Viewer.
- Edge outlines (the reference's X-ray solid `prepass_wire` over the edge-detection batch): `Renderer3d::set_mesh_edges(mesh, submesh, &[[u32; 4]])` stores line-adjacency quads (opposite, from, to, other-opposite; boundary = first repeated) per submesh in `MeshPool::edges` (cleared by `replace_mesh`/`replace_mesh_indices`); `Draw::outline_source(OutlineSource::Edges)` draws them with `outline_edges.slang` (vertex pulling of deformed positions, view-space silhouette test, 1 px quads) instead of the surface, errors when the submesh has no edges, and sets the detect flag that drops the left/below edges like `is_xray_wires`.
- `Frame::clip_bounds(ClipBounds { corners, color })` (the reference's `background_clip_bound`): in the shade pass after the backdrop a fullscreen `clip_bounds.slang` ray-tests the box (6 inward planes from the 8 Alt+B corners, near 0–3/far 4–7) and writes the linear colour behind geometry where the ray enters a front face (none from inside the box).
- `Frame::editor_grid` is the reference's line grid (`editor_grid.slang`): caller gives steps (unit tables), plane, axes, aligned flag, colours; the renderer derives distance, offset, level, line counts, fades and the four z-biased perspective iterations, drawing first in the overlay pass (aligned views at the far plane). `Frame::grid` (full-screen, shade pass) is untouched.
- Workbench: the template reads per-frame studio lights (view space) from the editor block, else the reference's Default; `shadowed` (`[Feature(0)]`) samples the shadow of a `High` directional light `look/resolve.rs` injects first for `WorkbenchEffects::shadow` (kept even when the look has shadows off) and applies the reference's `get_shadow`. Cavity (world SSAO), curvature and object outline are `workbench_effects.slang`, a chain filter before tonemap that forces the surfaces pass and reads scene depth, surface normals and identity.
- Tests: `tests/three/overlay.rs` (incl. aliased coverage), `tests/three/editor.rs` (outline colours, edge outlines, clip bounds, clipping, grid), `tests/three/workbench.rs`, `mesh_update_moves_vertices_bounds_and_colors` in `tests/three/mesh.rs`.
