---
title: Shell surface framework
description: rikka-shell hosts every desktop feature in one process over factory-built layer surfaces and one forwarded seam.
about: system/rikka-shell/crates/shell-kit
tags: [shell, framework]
---

- One process: a wiring binary over `shell-kit` and one crate per feature (see the shell crate layout note). It shares one Wayland connection, event loop, renderer and seam; UI tasks and the assistant run on rikka-ui's process-wide `rikka-work` runtime (`rikka_ui::work_runtime()`).
- It hosts the same `rikka_ui_host::Embedder` as `rikka-app`, so a State + view moves between them unchanged. Shared mechanics live with their owners: pacing (`Embedder`), clipboard bridge (`rikka_ui::clipboard`), blur (`rikka_blur::SurfaceRegions`), appearance (`rikka_appearance::ResolvedAppearance`).
- Layer surfaces present through `rikka_present::Presenter` (the embedder is `Embedder<ObjectId, SurfaceState, Presenter>`, made from the shell's one `rikka_wayland::Host::sharing`), which owns each surface's buffer scale and viewport; `shell-runtime/src/surfaces/sizing.rs` only calls `resize(px, scale, false)`.
- Layer surfaces render at a whole scale (`preferred_buffer_scale`, else the largest entered output's `wl_output` scale) and the Presenter's viewport shows them at their logical size, so fractional outputs scale them down; the shell binds no `wp_fractional_scale_v1`. `Placement::scale` is that whole output scale.
- `shell_runtime::run(Shell::new(..).settings(..).theme(..).service(..).feature(..))`. `main.rs` lists features per profile. Full (KMS and nested sessions) installs everything; Simple (headless) installs only a wallpaper.
- A `Feature` bundles services, surfaces, watches and settings, and declares and follows its own settings.
- The seam is `Seam<Host>`: every shell service is a `Service<Host>`, and watchers (`watch`), settings followers (`follow`, `on_setting`, `follow_domain`, `on_domain`) and idle callbacks (`Idle::on_idle`/`on_resume`) are all called with `&mut Host`. `Host` lends the seam client, `outputs()`, `typist()` and `clipboard()`; `Shell::hold(value) -> (Shell, Slot<T>)` puts feature state into it, and `host.get(slot)`/`get_mut(slot)` reach it, so state a service shares only with its followers, watchers or idle timers lives there by value (power-saving `Policy`, emoji `Inserting`, clipboard `Pasting`, lock `BeforeSleep`). State shared with surfaces stays in the feature's `Rc` handles, since UI states outlive any call.
- Wiring helpers on `Shell`: `on_shortcut(Shortcut, Request)` and `on_shortcuts(|s| match s { .. _ => None })` notify a request when a `rikka.shortcuts` chord fires; `follow(domain, key, |host, value| ..)` calls `act` with the current value at once, then on every change (resets included) and after a missed announcement; `on_setting` skips the first call; `follow_domain`/`on_domain(domain, |host, &Settings|)` hand over the whole domain on any change of it. `domains.rs` keeps one `Settings` per declared domain, decodes each `rikka.settings/changed` once, applies it and calls only the followers of the changed keys; a lagged queue refreshes each followed domain once. Followers run before any surface exists, so they touch the host or shared handles, never a `Ui`.
- `SurfaceDesc::session_lock(&SessionLock)` makes per-output ext-session-lock surfaces instead of layer surfaces (`SurfaceState.role: Role`); see the screen lock note. Each `Shell::idle()` call registers its own ext-idle-notify timer (`after`, `on_idle`, `on_resume`; notifications carry the timer's index); `Shell::keyboard()` is the observed Caps Lock / xkb layout of the focused seat.
- `shell_apps::Apps` (installed catalogue + icons that follow the icon theme) is the one handle features take for desktop entries; `Apps::follow(shell)` builds it. Icon footprints are measured in the desktop colour scheme (`SharedTheme::on_change`), and scheme-following SVGs are remeasured, keeping the old scale until the new one arrives.
- `SurfaceDesc::new(factory, view)` has `.on_start`, `.on_moved` (runs on every copy when any output's `Placement` changes; per-output factories get theirs only once), `.fitted()` (measured extent, sets `Ui::set_measured`), `.presence(p)` (comes and goes at once) or `.animated(p, exit)` (spawns with `Ui::arrive` so the first view's `.transition`s play the entrance; on hide, calls `Ui::leave` so views read `rikka_ui::leaving()` and play their exit, and keeps the surface, without input, until every copy has rendered it and had its last frame answered, at most `exit` plus a frame-callback slack), `.on_leave(handler)` for side effects when it goes, `.modal(presence, exit)` (overlay, exclusive keyboard, animated), plus layer, anchor, margin, zone, keyboard and pointer options.
- `SurfaceDesc::after(presence)` (repeatable) holds a wanted surface back while any surface bound to that presence exists, leaving ones included. `Surfaces::reconcile` despawns every surface that is no longer up before spawning, so a handover destroys the old set and creates the new one in the same turn and same flush (the taskbar's edge change: one compositor rearrangement).
- An animated surface that starts leaving sets its keyboard interactivity to none (`shell-runtime/src/surfaces/exit_animation.rs`), so the compositor hands the keyboard back while the exit plays. Typing panels that sit beside windows (the assistant) are `KeyboardMode::OnDemand` and get the keyboard when they map; modal overlays are `Exclusive`.
- A leaving surface also takes no pointer (`ErasedSurface::pointer` answers `Ignore`, applied by `Surfaces::retake`), so a click during its exit reaches what lies beneath, such as the bar icon that opened it. Wanted again while leaving, an animated surface stays (`Surfaces::stays_put`: `Auto`/`All` targets, or a `Destined` one still on its output): its pointer region and keyboard mode come back and `Ui::rejoin` turns the exit around from where it is, keeping the surface's state. `Aimed` surfaces (caret/pointer placed) are despawned and spawned anew.
- `Presence::after_unmap(callback)` runs `callback` on the main thread once every surface bound to that presence is destroyed and a `wl_display.sync` confirms the compositor processed it (`shell-runtime/src/surfaces/unmap.rs`); services use it to type, paste, freeze the screen or open a dialog only after their overlay is gone, never after a fixed delay.
- `SurfaceDesc::aimed(shell.aimed(), |placement, aim| ..)` is for overlays opened while typing: right before spawning, the runtime asks the compositor's `rikka.caret/aim` synchronously over the session socket, before the overlay can take the keyboard. It then spawns on that output and gives the factory its `Placement` and a surface-local `AimTarget` (caret rect or pointer point). `widgets::popover(..).beside(sighted)` hangs below a caret or off the pointer corner, rises above when there is no room, and centres without an aim; `.opening(at, AnchorEdge)` opens from a point toward a chosen side (`.at(at)` is below); it pops (`pop()`) out of that corner, so a menu inside it is `.still()`.
- `Aimed::pinned(AimPin)` lets the opener decide the aim itself: a point set with `AimPin::point(screen, at)` is taken at the next spawn instead of asking the compositor and dropped whenever the surface is closed, so it never outlives the opening it was set for (the desk menu pins the right-click spot; the menu key clears it).
- `Presence::reopen()` shows a surface anew within one turn: a wanted surface whose presence moved and that is not where its target points (`Aimed`, or `Destined` to another output) is despawned and spawned again, so it takes the fresh aim. `popover(..).on_reopen(|state, at|)` receives secondary presses outside the panel (Files-style "right-click elsewhere reopens there"); the desk menu reopens through it when the point is bare desktop (no taskbar strip, no on-screen window from `Toplevels::covers`), otherwise dismisses.
- `SurfaceDesc::destined(Destination, factory, view)` spawns on the output a feature named with `Destination::aim(name)` before showing it (the window switcher, the taskbar menu).
- Per-output surfaces get their `Placement` from the factory and the current one again through `on_moved(|state, placement: Placement| ..)` whenever outputs change; the runtime looks it up by each copy's own output.
- `.positioned(Positioner)` makes a content-sized (`fitted`) layer anchored top-left with ignored zones that the runtime hangs beside `Positioner::set_anchor_rect(desktop rect)`: below with a gap, above when there is no room (`Positioner::is_flipped`), slid inside its output; `None` hides it at once, so a view that wants an exit keeps its content until the exit is over. Copies are created hidden (no initial commit), mapped by sending size and margins, and hidden by attaching no buffer once no frame is painting, then a `wl_display.sync` (`shell-runtime/src/surfaces/positioner_state.rs`); configures arriving while hidden are stale and not acked. A fitted surface whose configure changes its size presents anew (`Hosted::present_anew`).
- Size is an `Extent` of two `Span`s (`Fixed` or `Stretched`); `.width/.height/.size` fix an axis, an unset one stretches and anchors both of its edges. `run()` rejects a fixed axis under a pixel with `SurfaceError`.
- A panel that should leave the display sits flush on its screen edge, keeps its visual gap as inner padding with a `PointerMode::Inset` over it, and slides its glass card past the edge; glass panes never fade, so fades leave a bare blur.
- Surfaces are rebuilt on output hotplug and presence changes. Hiding destroys the surface.
- `Reach`, `SharedTheme` and `Presence` are `Tracked` values reconciled once per loop turn; exclusive zones are fixed per surface. `Tracked::take_moved` is per handle (shared version, own seen count, a clone starts where its source was), so several surfaces bound to one `Presence` each see every change.
- `SurfaceDesc::opacity(Opacity)` makes each copy's `wp_alpha_modifier_v1` multiplier follow that per-output `Opacity`, and a leaving copy stays until it reaches 0; `SurfaceDesc::drives(Opacity)` makes another surface's committed frames publish what its paint `set` (drawn in the `Drawing` closure, sealed with the frame, shown in `presents_with`), and `follow_opacities` commits followers right after, so both land together (`shell-runtime/src/opacity.rs`, `surfaces/fading.rs`). Features only `set`; the runtime reads and publishes through `hosting::OpacityLevels`, and a driving copy that goes clears its output back to 0.
- `Waiting<T>` hands a surface the one thing it was opened for (the capture editors); `WaitingService<T>` is their seam service (presence plus `edit`/`arrived`), described by a `WaitingDescriptor` const per feature. `PresenceService::answer` and the presence methods `OPEN`/`CLOSE`/`TOGGLE` are what composite services delegate to.
- Local capabilities override forwarded ones. Unknown calls and events relay to the compositor, so components hold one `SeamClient`.
- The shell also answers on its own `shell.sock` (`shell-runtime/src/door.rs`) for Settings and the `rikka` command.
- Wayland state stays on the main thread. Renderer creation waits for the first configure. Only registration failure aborts startup.
- Language changes rebuild views. Theme changes mutate `SharedTheme`, and every surface follows it.
- Shared widgets live in `shell-kit/src/widgets` (`floating`, `popover`, `sheet`, `finder`, `nothing`, `editor_window` with `editor_loading`/`editor_error` for the capture editors). `shell_kit::Recents<T>` (given a `RecentsConfig`: file, JSON field, limit) is the one persisted most-recent-first list (emoji, colours); `shell_kit::pictures::{png, develop}` are the one PNG encoder and bounded decode.
- `shell-runtime` drives one `rikka_wayland::EventLoop` and binds globals itself: singletons via `Display::bind_on`, outputs from its own registry for hotplug, seats through `rikka_seat::Seats` (`ShellState` is its `SeatHost`; `handlers::listen` registers every handler, `Seats::listen` among them). Surfaces, outputs and callbacks are keyed by `rikka_wayland_client::ObjectId`; the loop's eventfd is the queue's waker. `ShellState` owns the `Host` beside the `Bridge` and lends it to dispatch, announcements and idle notifications.
- `ShellState` coordinates: `surfaces::Surfaces` owns the descriptions (indexed by `SurfaceId`), the embedder, spawn/configure/rescale, reconcile and farewells; `bridge::Bridge` owns the seam, dispatched calls, relayed events, watchers and announcements. `Shell`'s fields are private to shell-kit; the runtime gets them through `Shell::into_parts()` (validates surfaces, returns `shell_kit::hosting::Parts`).
- The loop waits on the connection, a `LoopWaker` (a wake-only `rikka_worker::EventNotifier`) and the wall timer; seam calls, task results and relayed events arrive as `WakingSender` channels that ring it.
- `shell_kit::WallClock` (`Shell::wall()`, also in `Feeds`) is the one wall clock for every clock: a `rikka_worker::WallAlarm` (CLOCK_REALTIME timerfd, absolute, cancel-on-set) polled by the loop, armed at the next boundary of the finest held `Need` (`wall.need(Period::Second|Period::Minute|…)`, dropped to release) and at local midnight, so suspend/resume and clock changes show at once. Views read `wall.now/slot/follow/today(period)` (observed reads), painters `wall.painting(period)`; nothing held disarms it.
- The runtime's `timers` hold farewells only; other periodic work belongs to the surface that needs it (`every_keyed`/`after_keyed` from its `on_start`), so it dies with the surface and a hidden surface never wakes the loop. Key repeat lives in `rikka-seat` (`Seats::repeat_due`/`Seats::repeat`); cursors and IME carets follow each surface's `Ui` through `Seats::show_cursor` and `follow_carets`.
- `Host::clipboard()` (and `Shell::clipboard()` at install) hands out `share()`s of one ext-data-control `Clipboard` connection: the session clipboard, capture and clipboard history each get their own handle (their own publications count as `is_ours`). It keeps its own connection because a reader thread on the main connection would wake on every main-loop read.
