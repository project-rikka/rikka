- Entry: `Fluid::builder().radius(r).capacity(n).floor(h).build(&compute)` on `Gpu::compute()` (`rikka_gpu`; tests build a bare `Gpu` with `compute_support()`, no renderer); `rikka_physics::FluidBuilder` is the same builder. Apps that couple figures and liquids use the `rikka-physics` scene instead (physics-layer note).
- `Liquid` (8 physical shares plus colour, depth, cloudiness, roughness, ior, tint), `Preset` and `Throw` live in the public GPU-free `rikka-physics-liquid`; rikka-physics `Mix` maps a `Liquid` onto a `Substance` and a renderer `FluidMaterial`. `Preset` holds the six starting liquids (water, slime, lotion, honey, milk, blood); `Throw::ballistic`/`direct` aim launches under any gravity.
- Per frame: `advance_to(time, &Inputs::new().body(id, &instance).emit(Emission::new(emitter, Nozzle::..)).drying(rate))`; then `surface()` / `wetness(body)` hand out buffers plus a `Ticket`. Time only moves forward; `reset()` restarts (bodies back to a fresh rest pose). `read_particles()` / `read_wetness(body)` download to the CPU.
- Batch-taking forms: `advance_into(batch, time, inputs)`, `show_into`, `restore_into` return a `Recorded` the caller `commit(recorded, &ticket)`s after submitting (that sets `surface()`/`wetness()`); `capture_into(batch) -> Capture`; `checkpoint_into(batch) -> PendingCheckpoint<'_>` borrows the fluid until `finish()` after the submit. `advance_to`/`show`/`restore`/`capture`/`checkpoint` are one-batch wrappers.
- Snapshots: `Capture` (`capture.rs`) is one device buffer (record positions, velocities, spray, wet record) copied back by `show`, bit-identical to the live run; `PendingCapture::finish` only waits its ticket. `Checkpoint` (`checkpoint.rs`) holds full host state (with drape buffer clones and reaction outputs); spray downloads are sized by the step's proven spray bound (`resident_spray`) and cut to the measured count at `finish`. A restored fluid advances exactly like the live run. Caching lives in rikka-physics.
- `Fluid` = `Stage` (`stage.rs`: kernels, settings, grid, bodies, look, output rings, shown surface) + solver state; `FluidBuilder::replay(compute) -> Replay` is a display-only `Stage` (`add_body`, `show(_into)`, `commit`, `surface`, `wetness`) that shows captures without allocating particles, viscosity, sort or foam buffers.
- `advance_to` submits and returns. It plans substeps, grid, live-slot bound, entries and spray bound from the stats readback of the frame two calls back (`frames.rs`: `InFlight` queue, `Measured` latest/earlier), so it waits at most for that frame; reads and checkpoints settle everything without changing any plan. No float atomics; triangle bins are unordered, so every bin consumer breaks ties by triangle id.
- `Pass`, `Ring`, `Scan` and the `kernels!` table macro come from `rikka-physics-gpu` (shared with the cloth); the fluid's own kernels are `gpu/kernels.rs`. Each independent chain owns its `Scan` workspace (body index, simulation sort, display sort, foam), and `Look` owns its own `Sorter`; the fitted grid lives in `Fluid::grid` and is passed to both sorts.
- Hazards are whole-buffer and declared: every pointer a shader touches must be declared on its `Pass`, including through `BodyTable` (collide last writes `deposits` and `reactions`); pointers a mode leaves untouched are pushed as `particles.placeholder` (read). Results stay bit-identical only while declarations are complete, so recording order may be changed freely.
- Output contract (std430): particles 64 B, spray 32 B, wet 16 B per body vertex in node order; the sizes are rikka-renderer-3d's `FLUID_PARTICLE_BYTES`/`FLUID_SPRAY_BYTES`/`FLUID_WET_BYTES`; outputs come from `Ring`s. Display is rebuilt from a record, so live output and `show(&Capture)` are bit-identical.
- `set_profiling(true)` + `profile()` return per-pass GPU spans (compute `Batch::scope(&'static str)`/`timing`).
- Models that cannot be bodies fail `add_body` with `Error::NotABody`; caller mistakes get semantic variants (`NonFinite`, `PaletteMismatch`, `UnposedDrape`, `DrapeTooSmall`, `TooManyBodyVertices`, …).
- Tests run on the machine's GPU in one binary (`bazel test --config=gpu //crates/physics/rikka-physics-fluid:main [--test_arg=<filter>]`), grouped under `tests/liquid`, `tests/bodies` and `tests/replay`: `liquid::coherence` guards a falling stream; `liquid::viscous` guards viscous streams (path, speed bound) and resting puddles; `liquid::threads` pulls lotion between plates at r = 2 mm until the thread breaks; `liquid::finite` runs all six app presets through stream, blob and moving-body contact and rejects any non-finite particle, surface, spray or wetness value.
- Every buffer a kernel can read before writing must be filled at creation: recycled GPU memory holds NaNs and `0 * NaN` leaks into results (the CG search directions, read with beta 0 on the first iteration, are zeroed in `Viscous::prepare`). `tests/liquid/stale_memory.rs` pours after littering freed memory with NaN.
- Units, grid, substep order, walls, bodies, viscosity, sticky contacts, substances, bonds and presets are in the fluid-solver-physics note.
