---
title: Shared conversation UI (rikka-chat)
description: rikka-chat holds ADE's and the shell assistant's composer, offer list, transcript, call views and model picker.
about: crates/ai/rikka-chat
tags: [ai, ui]
---

- `crates/ai/rikka-chat`, a public crate, is the one conversation UI; ADE and the shell sidebar only bind it, so their behaviour and motion stay identical.
- A host implements `Labels` (every conversation label but reasoning levels, which come from `rikka_llm_accounts::effort_label`) and `Chat: Labels` (associated fns returning `Handler`s into its own state, e.g. ADE wraps `act`/`given`, the shell targets `Panel`). Views are generic over that unit type: `Composer::<AdeChat>`, `transcript::<ShellChat>`.
- The rate-limit window gauge is its own crate `crates/ai/rikka-usage-bar` (`usage_bar(&Window)`, `.compact()` in the taskbar, catalog `usage.*`), so Settings draws it without the conversation UI; processes that draw it embed `rikka_usage_bar::CATALOGS` (shell `language.rs`, Settings `App::i18n`).
- `Chat::watch_agent`/`watch_main` default to `None`; hosts without a crew leave agent chips unpressable.
- `Transcript` is a nested `#[state]` owning `Blocks` (incremental settled + live index), `Expanded`, `PrintedDocuments`, `Finding` and the `Place`. Hosts call `refresh(thread, answering)`, `stream`/`grow` for word deltas (false while find is open), `forget()` on thread switch, `open_find`/`find`. Fold and summary toggles and find counts target `Transcript` directly.
- `transcript::<C, _>(&Transcript, || empty)` draws the lazy column plus a tail component on `Transcript` (the empty view is built only when there is nothing to show; `empty_state(label)` is the shared one); only live-tail calls and the just-sent turn animate.
- `SummarizeCall` (instance, held by `Transcript`) turns a `Call` into `CallSummary { name, symbol, gist, deed, pictures }`; ADE's `Deeds` and the shell's `Calls` (app tools first) implement it, starting from the shared `chat::symbol(&ToolAction)`. The call view hides the gist of calls it draws beneath (Bash, Write, Edit, questions) and draws `call.shown()` under any call whose `pictures` is set: ADE sets it for View only, the sidebar for every call. WebSearch and WebFetch draw as header rows like any call.
- `Composer::new(draft, controls)` builder: offers sit inside the `resizing_upward()` surface above the foot (radius 16 → 22), the foot swaps writing/question/`instead(key, view)` bodies with a fade-rise, keys walk offers (Up/Down, Tab agrees on the shared prefix, Enter takes, Escape dismisses), paste/drop/+ attach through `Chat::attached`. `Composer::model(Option<&ModelInfo>)` adds the `chat.attachment.unseen` note under attached pictures when that model has no vision.
- `Offers` (nested `#[state]`) is the one `@`/`/` offer machine: `typed(draft)` → `DraftChange::{Command(query), Mention(asked), Argument(asked), Cleared, Nothing}`; hosts supply only the offers (`command(query, offers)`, or after `OFFER_DWELL` `pending_query`/`pending_argument` → `found(asked, draft, offers)`, false when nothing changed), and route `step`/`point`/`dismiss`/`take` (returns `Taken { runs }`)/`agree` to it, re-offering after take/agree. Arguments after a `/command` are shell-like words (`words.rs`, single or double quotes); `Argument` names the command, the given words and the one typed. Hosts build offers with `Offer::path/command/builtin/mentioned/prompt/resource/template/value`, parse drafts with `invoked`/`mentioned`, and read mentioned files with `read_mentioned(root, paths, listed)`.
- MCP in the composer (`mcp.rs`): `prompt_offers(hub, typed)`, `resource_offers(hub, typed)`, async `argument_offers(hub, argument)`; on send, when `needs_mcp(hub, &ask)`, async `gather::<C>(hub, ask)` expands an invoked `/<server>:<prompt>` into `Ask::with_expansion` plus attachments named `/<command>/…`, reads `@<server>:<uri>` mentions into attachments named by the mention, and returns the other mentions for the host. `kept_attachments(said, sent, attachments)` drops what a resend re-derives. Its strings are `chat.mcp.*`; `Attached::join` merges gathered parts.
- A tool call is drawn only from `Reply::Started` (its whole input known); the model's partial call input is never shown.
- `QuestionQueue` queues questions; `QuestionQueue::track(&[QuestionSet])` mirrors a held list (the shell desk keeps `Vec<QuestionSet>` because `QuestionForm` holds `Rc` documents).
- `Models` + `Picking` are the model/reasoning picker (`trigger(picking, width)`, `panels`). The panels anchor to the trigger inside the writing foot, so `Composer` drops them while a question or `instead` body replaces it. `code`, `mono` (`CODE_FONT_SIZE`, `LINE_HEIGHT_FACTOR`), `CARD_INSET`, `CODE_ROW_HEIGHT`, `chevron`, `question_chip` are also used by ADE's git and file panes.
- Gotcha: never take `&mut` of a `Tracked<Finding>` just to check it (DerefMut logs the key and re-views); `Transcript::recount` checks `is_idle()` first.
- Person turns (`spoken.rs`) show copy on hover in a reserved row under the bubble's right edge, and edit when `Chat::amend()` returns `AmendActions` (edit/resend handlers plus cancel/send/restore labels) and the host set `allow_amends(true)`. Editing is inline: `Transcript::amend(stamp, said)`, host adds touched files with `amend_touched`, reads `amending()` (text, `restores()`) in the resend handler; Escape or Cancel stops.
- Queued mid-run messages: `Composer::waiting(&[QueuedAsk])` lists them with recall (`Chat::recall`, also ArrowUp in an empty draft) and withdraw; `Chat::interjects()` makes `outgoing_message` show send beside stop while answering.
- MCP settings (`servers/`): `Servers::new(hub)` is a nested `#[state]` (no Default) the host follows with `apply_change()` when shown; `servers(&Servers, titled)` draws scope switch (more than one place), cards (status, enable, sign in/out, reconnect, move/copy, remove) and the add/edit form (command or URL, variables/headers as secrets, optional registered OAuth app, test connection). Writes go through `Hub::keep`. `ServerConsent::new(titled)` localizes the McpServers confirmation; its strings are `chat.servers.*`.
