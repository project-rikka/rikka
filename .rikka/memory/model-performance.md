---
title: Model library performance rules and threading
description: Threading, caches and complexity rules for crates/model, the model-load path (import → Figure::load → upload).
about: crates/model
tags: [model, performance]
---

- Results never depend on thread count: work is split into contiguous index ranges and every output element is computed by the same sequential arithmetic it had serially; float sums keep their per-element order (stencils keep duplicate entries, no regrouping). Parallel neighbour searches collect pairs per chunk and apply union joins in the serial order.
- Data parallelism goes through the public `rikka-parallel` crate (see foundation-runtime note); each crate keeps a `const PARALLEL: Parallel = Parallel::new("rikka-<crate>")` in `lib.rs` and sets a grain (≥ 4–16 k elements per worker) per call so small inputs stay on the caller's thread. Its one thread-local guard makes any nested call inside a worker, from any crate, run serially, so stage-level concurrency (`animate_cast::Figure::load`) uses `std::thread::scope`, never `Parallel`.
- Polymesh `gather`, normals (`face_normals`, `point_normals`, smooth `shade`) and MikkTSpace welding are parallel; `ensure_edges` resolves missing edges by bucketing keys per low vertex (no hash map) and keeps first-seen edge order; `merge_points` stores welded faces in one flat buffer.
- Subdivision (`evaluators/subdivision/`): `refine` builds CSR stencils (`Stencil`, chunked by worker) and child topology in parallel; adjacency (`Around`) is an atomic counting sort with per-group sorting (identical to index order). The limit surface refines only the 1-ring of the cage points (`Extent::Around`) and folds the last extra refinement into `limit_after_refine`, so it never builds the full deeper cage. Ordering (`order.rs`) matches edges/faces through per-vertex buckets instead of hash maps.
- `StackCache` + `evaluate_cached` keep per-modifier state across evaluations. Subdivision caches its `Chain` (level stencils, limit, final point order) and the last output; when the input differs only in positions/shape-key positions (bitwise compare of everything else) it re-applies the chain and clones the cached output.
- Import: `ImportCtx::prefetch_resources(&[uri])` reads sibling files in parallel and `read_resource` consumes them in the codec's order (charges, errors and warnings unchanged); PMX prefetches its texture list. The glTF accessor reads F32 components straight from bytes and decodes and scans morph targets in parallel; the binary FBX parser defers zlib arrays and inflates them in parallel after the tree is read (the earliest error in document order still wins).
- `Figure::load` only builds what the first frame needs (anatomy, body, skeleton, head, faces, mirror, `Prepared` with textures created on the loader thread through `Uploads`); analysis + body fit (`Survey`) and cloth assets follow asynchronously (animate-cloth note). `Prepared` turns a picture whose image has one plain use into upload pixels inside the decode worker (`into_rgba8`, no copy); `Prepared::create_textures(&Uploads)` creates them in parallel off the render thread, else `upload_prepared` does. `GpuModel::upload_prepared` on the render thread costs ≈ 5–16 ms (mesh and material creation).
- Tailor hot spots and their rules: `Graph::new` is a counting sort into CSR with per-node sorting; `PointGrid` uses `FxHashMap` and a stateful `Near` iterator; the body `Decimator` caches side lengths and triangle shapes, finds edges per touched vertex with stamps, memoises valences and rejected collapses per vertex version (a join bumps the survivor, its ring and its wings), and keeps the serial greedy order. `ClothAnalysis` caches its decimated skin body (shared by clones, ignored by `PartialEq`/`Debug`), so `Wearer::from_model` and `ClothAsset::from_analysis` decimate once. Verify such changes by hashing `Debug` output of `Wearer`, `ClothAsset`, analysis pieces/roles and motion bake poses before and after on real models.
- Body fitting: `Scene::inside` rejects probe–obstacle pairs with the sphere bound, then `Shell::clears` (per ring and octant maximum radius with a safety margin, no `atan2`/`hypot`) before the exact `Shell::distance`; results stay bit-identical.
- PNG decoding (`rikka-png`/`rikka-deflate`): SIMD Paeth for 3–8 byte pixels via `rikka-simd`, verbatim rows unfiltered and compacted in one pass, inflate writes into a pre-grown buffer with 16-byte match copies and three-literal bursts, zlib's Adler-32 is computed incrementally while output is cache-hot (SIMD `Adler32`), CRC uses slicing-by-16. Across 156 real textures it is ≈ 1.1× the `png` crate (was 2.1×).
- Inherent costs that remain: `Evaluated` results own their `Polymesh` (one clone per evaluation), per-point `Vec<Influence>` vertex groups allocate on every clone/gather, `MeshAssembler` (rikka-model-core) hashing in `to_mesh`, `kdtree::balance`/`find_duplicates` (Weld) are serial, `MAX_CORNERS` (2^24) reduces 1M-quad level 2 to level 1, the body decimation (≈ 90 ms on 80 k-triangle figures), and the inflate loop (≈ 1.25× fdeflate).
