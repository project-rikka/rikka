---
title: Shared types and input translation
description: rikka-types owns dependency-free vocabulary; rikka-input translates backend events and matches exact chords.
about: crates/foundation/rikka-types
tags: [foundation, input]
---

- `rikka-types` has no deps.
- `LocaleCategory::{Messages, Ctype, Time, Measurement}` is the one reader of the POSIX locale variables (`LC_ALL`, the category, `LANG`; empty means unset): `posix_name()` is the raw value, `locale()` a `PosixLocale` (`language()`, `territory()`, `tag()` such as `ja-JP`; `None` for `C`/`POSIX`). `rikka_types::hex::{encode, decode, decode_to_slice, Hex}` is the workspace's hex codec.
- Geometry is in logical px, with CSS-style corner-radius clamping. `Color` is non-premultiplied sRGB, and glass uses `Lens` (builder `with_bevel/with_depth/with_bulge/with_frost/with_ior/with_dispersion/with_adapt`, getters of the plain names, `extent_for_size`/`extent_within` → `RefractionExtent { sample_margin, paint_margin }`, `profile_for_size`/`profile_within` → `RefractionProfile { bevel_width, bevel_displacement, bulge_displacement }`).
- `Transform` is the `wl_output` transform (`Normal`, `Rotate90…`, `Flipped…`; `ALL` in protocol order, `from_wayland`/`to_wayland`): mirror about the vertical axis first, then turn counter-clockwise. `axis_map()` is the one table (content → buffer); `map_point/map_rect/map_size`, `inverse`, `then`. The renderer re-exports it, `rikka-compositor-geometry` re-exports it and adds typed `Size::transformed`, `Point/Rect::transformed_in`. An output with `Rotate90` shows its desktop turned counter-clockwise.
- `PixelSize { width: u32, height: u32 }` is the integer pixel extent (`new`, `ZERO`, `is_empty`, `aspect`, `area`, `to_size`, `From<(u32, u32)>`); `Scale::physical` and app render targets pass it instead of `(u32, u32)`.
- `rikka_types::srgb` is the one CPU sRGB transfer (`to_linear`/`from_linear`, `_f64` twins) and Rec.709 `luminance`/`LUMINANCE`; theme contrast, PSD, image-edit, rikka-image gray, renderer sky and text-raster tables use it. Shaders keep their own GLSL copies.
- `Source` (`File(Cow<Path>)` or shared `Bytes`) is where asset bytes come from.
- `CancelToken` is executor-free and awaitable, blocks with `wait_timeout`, and hands out `child()` tokens that a parent cancel reaches. `Flow` and `Overwrite` serve long operations.
- `WindowIdentifier::{Wayland(handle), X11(xid)}` is the XDG portal window identifier: `Display` writes `wayland:<handle>` / `x11:<hex>`, `FromStr` reads them (an empty `parent_window` is the caller's `None`).
- Input vocabulary: `Key`, `KeyCode` (built from an evdev scancode; `.xkb()` adds 8), `KeyLocation`, `Modifiers`, `PointerButton`, `CursorShape` (the full CSS set, `from_css`, `Hidden`), `ResizeEdge`, `SCROLL_LINE`, and tablet vocabulary: `ToolKind`, `ToolCapabilities`, `Tool`, `Tilt`, `StylusSample` (optional axes so mouse/touch never fake pressure 1.0) and `Stylus` (tool + non-empty coalesced samples; `sample()`, `samples()`, `map_positions`).
- `ScrollDelta` is the amount of every `DeviceEvent::Scroll`/`rikka_ui::Event::Scroll`; nobody reads raw x/y. A scroller adds `offset()` to its scroll position, a canvas adds `content()` (`-offset`) to its pan, and a value or magnification steps by `up()`/`right()`/`zoom()` notches (positive: wheel rolled away, fingers pushed up or right, zoom in). The notch accessors follow the physical motion, so natural scrolling flips scrolling but never zoom, steppers or wheel events. Build one with `from_offset` (wire sign: positive right/down), `from_content`, `from_up(notches)`, plus `with_natural(true)` for an inverted device.
- Key events carry `code: KeyCode` next to `key`; `xkb::keysym_at(key, location)` gives the keysym a typed key sends.
- `Modifiers` excludes Caps and Num Lock on purpose. `Key` names left and right modifiers (`ShiftLeft…MetaRight`).
- `Key` is meaning and `KeyLocation` is place, so keypad `1` is `Char('1')` for everyone while terminals still see the keypad.
- `crates/foundation/rikka-input` translates backends without events, clocks or repeat and links no windowing toolkit; its one stateful piece is `xkb::Keyboard`.
- Its always-built `evdev` tables are the canonical button, keycode and wheel mapping (`tool_button`: `BTN_STYLUS` → Secondary, `BTN_STYLUS2` → Middle, `BTN_STYLUS3` → Back). `xkb` owns modifier mask bits; `xkb::Keyboard` (libxkbcommon) is `#[cfg(unix)]`.
- The always-built `win32` module maps Windows scan codes (set 1 + extended bit) to evdev `KeyCode`s, keypad locations, virtual keys to named `Key`s, and wheel deltas to `SCROLL_LINE` offsets (`wheel_offset`, user line setting / 3); `cursor` is the process-wide custom cursor picture registry (`define_cursor` → `CursorImage`, premultiplied BGRA) that rikka-seat and rikka-app's Win32 backend draw.
- Wayland seat input for rikka-ui hosts (rikka-app and the shell) is translated once in `rikka-seat`; the compositor translates its own input in `rikka-compositor-input`/`rikka-compositor-seat`.
- `xkb::Keyboard` compiles a compositor keymap fd, composes typed text and turns the modifier masks into `Modifiers`; it yields `Keystroke`s (`press(code)` advances compose, `keystroke(code)` resolves without text, `refresh_text`, `key_repeats`, `is_caps_locked`, `layout_count`). `xkb::SessionKeyboard::current()` is the published session keymap and repeat.
- `Command` (`rikka-input/src/command.rs`) is the one desktop-standard table: chords (CUA alternates included: Ctrl+Insert, Shift+Insert, Shift+Delete), hardware keys (`Key::BrowserBack/Forward/Refresh/Home`, `Copy/Cut/Paste/Undo/Redo/Find`) and side buttons map to Back, Copy, Find, Save, Close, …; `Command::for_key(key, modifiers)` / `for_button(button)` look commands up and `Command::chord()` is the menu label. App-specific chords stay in app tables.
- `Chord`, `Binding<A>` and `ActionMap<A>` match lowercased logical keys with exact modifiers. Unknown keys become `Unidentified`. `chord_for` derives shortcut labels; `has_binding_with_modifiers` tells whether any chord uses exact modifiers.
