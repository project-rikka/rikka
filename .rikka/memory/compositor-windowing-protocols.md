- `KeyboardFocus` keeps X11 focus semantics and converts to a Wayland surface.
- Decorations follow the server-side decorations note: xdg windows asking for (or leaving open) server-side ones and ordinary X11 windows get a compositor caption, the rest draw their own. Floating is click-to-focus. Tiling is pointer-focus, one dwindle tree per display workspace; tiling with `rikka.windows/scrolling` on is click-to-focus, one column strip per display workspace (see compositor-scrolling).
- Tiling pointer focus (`input/deliver.rs`): `pointed_window` hit-tests with `hit_under` (layers and popups above windows count, popups resolve to their root window, a compositor caption counts as its window) and is shared by `follow_pointer` and `refocus`, which prefers the pointed window over stacking order. Only pointer grabs, an Xwayland keyboard grab, exclusive or held Top/Overlay layers, popup chains and the switcher hold focus; the input method's keyboard grab never does, since it follows keyboard focus.
- Focus outline (`render/outline.rs`): the activated window (`Recency::current`), when tiled, neither maximized nor fullscreen and `rikka.windows/focus-outline` is on (`Windows::outlined`), gets a 2-logical-px ring in `Policy::palette().selection` (the sidebar selection colour) just outside its geometry: one stroked rounded-rect node concentric with the window's rounded shape (radius + width), drawn right after its tree and following its placement. `animation/fades.rs` (`Fades<K>`, shared with scrim layers) fades each outline's opacity in and out (snapped when animations are off); `StageContext::stage` turns the fades into `Staging::outlines` for windows drawn on that output.
- Layer keyboard focus (`shell/layer.rs`, `windows/focus.rs`): exclusive layers take it while mapped; on-demand Top/Overlay layers take it when they map unless an exclusive layer holds it, and when clicked; Background/Bottom on-demand layers (desk wallpaper) only by click. `windows::FocusLoans` remembers whom each layer took it from, so a layer that unmaps, drops interactivity or goes hands it back to that holder (chains re-point when a middle lender goes), else `refocus`. Neither `refocus` nor tiling's pointer focus takes it from a focused interactive Top/Overlay layer (`layer_holds_focus`); a click does.
- Key bindings are queued as `KeyAction`s and run in `dispatch_frames`; `filter` asks for that dispatch itself, so virtual-keyboard keys (which arrive outside the backend input queue) run bindings with or without a focused client.
- Rules, pure layout math and `Desktop` arrangement are separate layers. Dialogs, popups, override-redirect and manually floated windows never tile.
- `Super+Button1` moves, `Super+Button2` resizes. Tiled edges resize shares (column widths and stacked heights when scrolling), and dropped tiles swap or change display; a scrolled tile dropped in a gap becomes its own column. Only the scrolling layout has keyboard commands (the `Group::Columns` shortcuts).
- Floating edge and zone drops snap (see compositor-snap).
- Bindings come from the `rikka.input` schema generated from `rikka_session::shortcuts`. Only VT switching is outside it. Empty means unbound.
- Shell-owned commands are caught here and announced on `rikka.shortcuts`. `zwp_keyboard_shortcuts_inhibit` on the focused surface suspends all bindings.
- Alt+Tab (`switch-windows`/`switch-windows-back`) never queues: `filter` starts and drives the switcher synchronously (see window-switcher).
- Ten workspaces per display (`COUNT`). Windows move only among their own display's workspaces. Hidden windows keep `Visibility::OnHiddenWorkspace` and stay protocol-visible.
- Minimize (`windows/minimize.rs`) puts floating windows away; tiled windows refuse. Nothing is put away while `rikka.appearance/taskbar` is off (minimized windows are restored then), since the taskbar is the only place they show. `reveal_window` restores from focus, activation or X11 unminimize. `rikka.toplevels` (2.2) also offers `maximize` (reveals first) / `unmaximize` and publishes `maximized` and `tiled` per window.
- Dialog families (`windows/family.rs`): a window's parent is its xdg parent (`xdg_toplevel.set_parent` or an `xdg_foreign` import) or its X11 `WM_TRANSIENT_FOR`; modal is `xdg_dialog_v1.set_modal` or `_NET_WM_STATE_MODAL`. Dialogs open centred over their parent on its display and workspace, raising a window raises its dialogs above it, focusing a window with a shown modal descendant focuses (and raises the family of) that modal instead, a blocked parent gets no pointer, touch or tablet focus (`focus_at`), and minimize, restore and send-to-workspace move the whole family.
- Session capabilities: `rikka.workspaces`, `toplevels`, `caret`, `activation`, `desktop`, `agent`.
- Virtual pointer and keyboard go through the compositor's own pipeline, so injected keys hit bindings and the IME grab like hardware.
- The seat keymap follows whichever keyboard typed last.
- Only the IM client's own virtual keyboard skips the IME grab (rikka-compositor-seat). The `rikka-agent` seat is routed separately (see agent-seat).
- Configures are coalesced per turn and paced by acks. Interactive resize stretches stale buffers. X11 shape changes commit after Xwayland accepts them.
- Motion changes only render placement. Exits render from snapshots. One `Animations` owner requests frames per affected display.
- Protocols (vendored XML, latest version, lower binds allowed): core incl. `wl_fixes`; xdg shell, decoration, activation, foreign v2, system bell, dialog, toplevel icon/tag/drag, `zxdg_output` v3; viewporter, fractional scale, presentation, single-pixel, content type, alpha modifier, cursor shape, fifo, commit timing, tearing control, color management and representation, linux-dmabuf v5 feedback, drm-syncobj, DRM lease, security context; relative pointer, constraints, gestures, pointer warp, tablet v2, shortcuts inhibit, idle inhibit/notify, primary selection, text-input v3, input-method v2, virtual keyboard/pointer, Xwayland keyboard grab and shell; layer shell, session lock, foreign toplevel list, data control, image capture sources and copy capture, background effect, `ext_workspace_v1` and the private `rikka_window_view_v1` (both Full only).
- Tearing control and content type are applied: the scanned-out surface's tearing hint picks async page flips, the fullscreen window's content type picks VRR and frame pacing (see the direct scan-out note). Fractional scale and fifo are served end to end by rikka-compositor-surface (`set_preferred_scale`, `refreshed`).
- `rikka_window_view_v1` (XML in `rikka-wayland-protocols/xml/rikka/`, privileged): a view shows the toplevel with a given foreign-toplevel identifier inside a client surface, geometry scaled into a destination, with a 4-radius clip, opacity and order, all double-buffered on the surface's commit and drawn above the surface. Client side: `rikka-window-view` (`WindowViews::on(host).inside(surface).show(&[WindowView])`).
- In Full, 3-finger touchpad swipes are decided by `rikka_compositor_swipes::Swiping` (fed from `input/gesture.rs`): vertical ones, and horizontal ones while the pointed display shows an overview (`windows::overviewed`, the same predicate `around` uses), are announced on `rikka.gestures` (with the pointed output); the rest replay to the client. A new swipe that interrupts a kept one first announces a cancelled end.
- Privileged (hidden from security-context clients): layer shell, lock, foreign toplevel list, data control, capture, IM, virtual input, security context, workspaces, DRM lease. Xwayland-only: `xwayland_shell_v1`, keyboard grab.
- Intentionally absent (design §3): `wl_shell`, `wl_drm`, `zxdg_shell_v6`, text-input/IM v1, tablet v1, wlr screencopy, data control, foreign toplevel management, output management, gamma control, export-dmabuf, input inhibitor, `gtk_shell`, `org_kde_kwin_*`, `WL_SURFACE_ID` Xwayland association.
- Display power (`outputs/power.rs`, `session/display_power.rs`): `rikka.display-power/sleep` (`rikka_session::display_power`) queues a `Sleep`; `Backend::sleep_displays` (KMS disables every lit screen but keeps its output and config) and `wake_displays` re-enable them. Any person-seat input (pending queue or `filter_key`) and `displays_detected` wake them; `state`/`changed` publish `awake|asleep`. Nested and headless never sleep.
