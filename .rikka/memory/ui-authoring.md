- Window state is a `#[derive(State)]` struct. `#[state]` fields nest child states, which handlers can reach by type. The view is `fn(&S) -> impl View`, e.g. `Window::new(S::default, view)`.
- Handlers are closures: `Fn(args)` or `Fn(&mut T, args)`. `T` is found by type in the window's state tree, e.g. `button(..).on_press(|e: &mut Engine| ..)`.
- Two `T`s in the tree are ambiguous: wrap the subtree in `scope(lens, view)`. A `T` nothing holds panics in debug builds.
- If a task can land after its `Option` child state is gone, target the owner.
- `local_state(initial, |value, set| view)` is view-local state with a `Setter`.
- Effects are free functions that are valid only inside a handler or `on_start`: `spawn`, `spawn_blocking`, `stream`, `after`, `every`, their `_keyed` forms, `cancel(key)`, `skip_view()`, `request_frame()`, `with_animation(motion, ..)`, `request_window`.
- Restarting a keyed job cancels the previous run. Jobs run on the process-wide `rikka-work` runtime and are aborted with their window.
- `Sender<S>::send(|s| ..)` pushes updates from outside threads; `send_to(|t: &mut T| ..)` targets a nested state by type.
- Fields: `Tracked<T>` (reads in a view are recorded, `DerefMut`/drop/`set` on change log its key), `TrackedVec<T>` (per-element keys; `versions()` feeds `collection.memo(..)`), `Revision` (a key with no value: `read()` in getters and `changed()` in mutators of `#[untracked]` containers such as maps of panes or desks), `#[state]` (nested state), `#[untracked]` (never read by a view). Anything else is plain; the derive emits `HAS_PLAIN`.
- Fallback rule: an untargeted `Fn(args)` handler, or one reaching a type that has plain fields (directly or in a `#[state]` child, `Option`, enum), re-views the whole window as before unless it calls `skip_view()`/`request_frame()`. A handler reaching only tracked state re-views nothing; the next pass rebuilds just what read the changed keys. `Handler::relaying` acts only through the handlers it calls.
- `component(select: fn(&S) -> &C, view)` / `component_with(select, props: PartialEq, view: fn(&C, &P))` bound a view: `S` is found by type through the enclosing `scope`s like a handler target; the view (a capture-free fn) re-runs only when a key it read changed, its props/outer style differ, the theme or language changed, or a plain handler forced a full view. The window view is the root component.
- One change log carries `Tracked` writes, fetch landings (per key), `local_state` setters, `Observed` objects, theme and language. Interior-mutable shared state implements `Observed` with `Observers`: `read()` in getters (records a view/build read, or registers the painting node), `changed()`/`reshaped()` in setters. `TextDocument`, `Place` and `Search` do this; `TextDocument::content()` only registers painters. `live_observed(|| view)` is a block rebuilt alone when what its closure read changes.
- Widget builds that read keys (fetches, observed objects) are rebuilt alone on change. Debug builds re-run kept components and panic when their output changed without a tracked read (`#[untracked]` misuse); The development configuration (`--fast`, `bazel test`) keeps debug assertions in workspace crates, so that check runs there.
- `Watchers` remain for manual repaint/rebuild of widgets (`live_progress`, `live`, `MarkdownStream`, the terminal session). `ctx.request_layout()` / `NodeHandle::relayout()` re-measure one node in the same pass. Timers whose drawn result did not change call `skip_view()`.
- `fetch(key, || future)` / `fetch_blocking` give `Fetch::{Loading, Ready(Arc<T>), Failed}` without blocking. One key is one job. The key includes the type.
- A fetch stays cached while any window's live view or build reads its key (`runtime::Readers` holds it in the fetch table); after its last reader leaves, or if never read by a view, it is dropped or aborted once idle for 10 s. `loaded(fetch, ready)` draws the three cases. A landing rebuilds only the components and widget builds that asked for that key.
- Ambient reads: `theme()`, `palette()`, `env()`, `is_exiting()` (true once the embedder called `Ui::leave`, so a surface on its way out plays its exit). They are valid while a surface views, builds, measures, paints or handles events, and inside `Widget::cursor`, `tooltip_at` and `caret` (the runtime opens the node's theme and env around them); `hit_test`/`hit_area` get none. They panic otherwise. `with_theme` opens that scope by hand for tests and drag icons.
- Helpers return `impl View`. Branching helpers return `Element` via `.any()`. `Option<V>` is a view.
- `View` modifiers: `.opacity/.scale/.offset/.background/.foreground/.animate(Motion)/.clipped()/.transition(fade()|slide…)`.
- Tooltips: `.tooltip(label | Tooltip::new(label).shortcut(chord).side(TooltipSide::After))` names any element; a widget with named parts (glyph `segmented`, Animate's stage handles) answers `Widget::tooltip_at(state, bounds, point) -> (Tooltip, area)` instead. Name icon-only controls whose meaning is not obvious; a shown chord appears muted beside the label.
- `Styled` sizing: `.width/.height/.size/.min_*/.max_*/.fill*/.grow/.shrink/.align_self/.margin/.position`.
- `TextStyled`: `.title()/.caption()/.muted()/.bold()/.color()/.text_size()/.align()/.no_wrap()/.line_height()`. `.size` is room, `.text_size` is type size.
- Tokens: `Space` (`NONE…WIDE` on a 4 px grid, or any number), `Inset`, `Corner` (radii; `.radius(Corner::Panel)` takes it directly), and `Length::{HUG, FILL, portion(), px}`. `TextRole` and `TextColor` round it out. Invalid measures sanitize to zero.
- Blocks: `column!/row!/page!` and `column_of/row_of/grid_of` are eager; `toolbar()` collapses groups into a ⋯ menu. `lazy_column/row/grid/tiles` are windowed. `page/card/section/field` build settings-like surfaces.
- `Length::FILL` is 100% of the parent, not "the rest": beside siblings in a row it squeezes or overflows them, and a margin on a filling child pushes it past the parent's edge (inset with the parent's `padding` instead). `field(label, control)` puts the control in a growing trailing container, so a filling control (`segmented`, `combo`, `text_field`) gets only the room the label leaves; give pickers a px width.
- `Widget` has an associated `State`, and every method is provided (`layout, paint, event, build, behavior, measure, memo, same, surroundings, keeps_children, content_length, settled_height, …`). A leaf writes `paint`. `debug_name` defaults to the bare type name; override it only for another name.
- `#[derive(Widget)]` (from `rikka_ui`, path override `#[widget(crate = "..")]`) writes the trivial `View` (`Element::new(self)`), a `Debug` printing only `#[debug]` fields, and `Styled` over the `#[style]` field; it takes unit structs and structs with named fields. Widgets with a custom `View` or `Debug` write them by hand.
- Handler props are `Action<Args, R = ()>`: `Action::new(handler)`, `ctx.act(&action, args)`, `ctx.answer(&action, args) -> Option<R>` for value-answering ones, `action.call(reach, args)` inside a relaying handler, `action.active(enabled)`, `handler()`; `==` compares presence only, so `same` can be field-wise `==` (or a derived `PartialEq`).
- `fn same(&self, other: &Self) -> bool` lets an unchanged widget skip measure, build and paint after a view; the new widget still replaces the old, so events use the new handlers.
- A `same` compares every prop that layout, measure, paint, behavior or build read. `Action`s compare by presence. `Arc` props compare by pointer, then content. A widget that reads shared live state (a `Search`, `Place`, syntax `Language`, selection `Part`, `ColumnWidths`) or builds children whose closures capture props answers `false`; children passed as elements are reconciled on their own.
- Opted in: blocks (`Flex`, `Container`, `Spacer`, `AnimatedPosition`), `text`, `rich_text`, `text_field`, `text_editor` (same document, revision and caret), `shortcut_field`, buttons, choices, `switch`, `segmented`, `progress`, `gauge`, `spinner`, `icon`, `image`, list and nav rows, caption buttons.
- `Behavior` flags: `CLIPS, OVERLAY, PAINTS_OFFSCREEN, MODAL, TRACKS_HOVER, FOCUSABLE, NO_TAB_STOP, AUTOFOCUS, TAKES_FOCUS, TAKES_TAB, GRABS_KEYS, INERT, CATCHES_DROPS, TRACKS_PLACE, TRAVELS, INTERCEPTS`. `TRACKS_PLACE` repaints a widget whenever it moves (its paint reads its own position). `TRAVELS` gives the subtree its own renderer group from the start because it moves as a unit. `INTERCEPTS` sees its descendants' pointer presses, moves and releases first (see the ui-input note).
- Paint is skipped unless something the framework tracks changed, and a pure move only re-places the old primitives. Paint output may depend only on props compared by `same`, the node's size, room, content, scale, hover and focus, `Observed`/handle-notified state, and flagged reads (`visible`, `viewport`, `child_rect`, `clipped`). Anything else that depends on the absolute position needs `TRACKS_PLACE`.
- Geometry a widget keeps (hit rects, carets, drag anchors, press origins, laid bounds) is stored relative to `ctx.bounds().origin`, or kept current in `Widget::relocated(state, by)`. Event handlers read `ctx.bounds()`, never a rect remembered from paint.
- Motions animate positions relative to the widget's origin (`motion::indicator` seats included), so a repaint after a move does not slide from the old spot.
- Paint that changes with time schedules itself (`request_frame` or `wake_at`); a settle step that runs only in paint never runs otherwise.
- `PaintCtx::draw_image_pixelated` samples texels by `texelFetch` (renderer `ImageSource::pixelated`), so magnified pictures keep square pixels; `draw_image` stays linear with mips.
- `PaintCtx::draw_segment(from, to, width, color)` draws a round-capped line as one turned capsule (`Primitive::Segment` → renderer `Node::capsule(rect, rotation)`, `Shape::Capsule`); curves are polylines of segments, so keep them opaque where caps overlap.
- `Event::Scroll` carries `source: ScrollSource::{Wheel, Continuous(ScrollPhase)}` (notched wheel vs pixel deltas with Began/Moved/Ended), so widgets can treat wheel notches and touchpads differently; the runtime latches each gesture to the node that handled its first event.
- `Widget::caret` answers relative to the widget's origin.
- `Widget::cursor(state, bounds, point)` sees the widget's state, so the shape can follow zoom, hover targets or drag mode; the hovered route is asked again after every event while nothing holds the pointer captured.
