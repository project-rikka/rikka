---
title: Compositor session ownership
description: The compositor hosts settings, applies session domains, owns shell lifetime, environment, displays and profiles.
about: system/rikka-compositor
tags: [compositor, session]
---

- It hosts `rikka.settings` because it starts first and outlives everything. It applies `rikka.input`, `ime`, `animation`, `windows`, `pointer`, `displays` and `network` itself.
- Displays: schemas are generated from hardware and applied atomically. Keys are EDID identity with connector fallback. Arrangements anchor out of negative space for Xwayland, and windows follow a moved display.
- Gaps: display settings exist only while connected. There is no Wayland output-management protocol; displays change only through `rikka.displays`, which is dynamically declared, so another client can redeclare it.
- Pointer settings are fixed mouse and touchpad groups. Manual proxy becomes env vars; PAC cannot.
- It picks the Wayland and seam sockets, starts `rikka-shell` from beside its own binary (that dir is prepended to PATH), and controls it through `rikka.desktop`.
- The shell is supervised through a pidfd on the reactor (`session/desktop/`); a stop sends SIGTERM and SIGKILLs after 2 s. Any exit not asked for, and any failed start, is a crash: `rikka-compositor-restarts` (`Restarts::crashed(at, guarding) -> Restart`) restarts it after 0.5 s, doubling to 8 s, and gives up at the 5th crash within 60 s (never while the session is locked). Locker guarding waits for a pending restart instead of starting at once. `rikka desktop start`/`restart` clear that history; `Ctrl+Alt+R` (stop) cancels a pending restart.
- `session::SessionKind` says what a session is: `Login` (KMS) publishes env to D-Bus activation and `systemd --user`, starts `rikka-session.target`, restarts stale portals and raises the frame loop; `rikka-session-shutdown.target` conflicts with the graphical target. `Nested` runs a `PrivateBus` (`dbus-daemon` in `$XDG_RUNTIME_DIR/rikka/<display>/bus`, dies with the compositor, the compositor's own `<prefix>/share/dbus-1/services` searched first), hands its address to children and tells only that bus its environment, and hosts settings over `Layers::volatile()`. `Headless(Some(bus))` (the CLI's `--headless`, via `Launch::private_bus`) does the same with real settings layers, so apps in ADE's machine never hand off to the person's instances or portals; in-process tests' `Launch::headless` is `Headless(None)` and publishes nothing.
- Xwayland (`rikka-compositor-xwm`, started at launch on its own display) is ready before env publication, so `DISPLAY` reaches every child.
- Every session writes `$XDG_RUNTIME_DIR/rikka/<WAYLAND_DISPLAY>/session.env` for tools that must run inside it.
- Logs (`logging/`, `install_logging(Journal::{Session,Nested,Headless})` in `main`): only the KMS session writes `$XDG_STATE_HOME/rikka/compositor.log` (the previous run moves to `.log.1`). Nested and headless instances buffer until the socket is bound, then write `rikka/compositors/<backend>-<socket>.log` (`Logging::name_after`); that folder keeps the 16 newest.
- The shell's stdout/stderr is a pipe the compositor drains on the reactor (`desktop/output.rs`) into its own stderr and a per-compositor-run shell log opened at the first shell start (`rikka/shell.log`, previous `.log.1`; instances `compositors/<backend>-<socket>-shell.log`), with a header line per shell start. `Launch::journal()` is the one mapping from backend to log names. The shell prints a backtrace on panic and uses ANSI only on a terminal.
- Crash reports (`crash::Report`, plain text) go to `$XDG_STATE_HOME/rikka/crashes/<program>-<UTC stamp>-<pid>.log`, 20 kept: the shell's carry status, core hint, restart decision and the last 64 KiB of its output; the compositor's panic hook writes one with the panic, a backtrace and its own log tail.
- KMS and nested sessions are `Profile::Full`; headless sessions (ADE's agent machine) are `Profile::Simple`: one workspace, no `rikka.workspaces` or `ext_workspace_manager_v1`, no tiling, shell shortcuts or corners, wallpaper-only shell. Tests pick `Profile::Full` over headless with `Launch::profile`.
- `drivers::narrow` runs first in `main`, while the process is single-threaded: from the kernel driver bound to each render node it sets `__EGL_VENDOR_LIBRARY_FILENAMES` and `VK_LOADER_DRIVERS_SELECT` (only manifests actually installed; never with no GPU, an unknown driver or a user's own choice). The Vulkan selection is part of the published session environment, so every client loads one ICD instead of all of Mesa's.
