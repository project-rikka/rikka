- Non-window output: `Renderer::draw(scene, onto)` with `&mut OffscreenTarget`, `output.with_target(&mut buffer)` (dmabuf, `.with_release_fence(fd)` waits for the client's release) or `target.onto(&frame)`. `Destination` is sealed.
- Damage: clean scenes submit nothing. Buffer age lives in the target table (`TargetId` lease, `BufferId`): every known buffer accumulates the damage it missed (`renderer/history.rs`, no history limit), so a buffer idle for many frames repaints only what changed; only an unknown buffer is drawn whole. The merged damage policy keeps rects disjoint (overlaps would blend twice) and, past 16, merges the pair that adds the least area.
- One scene may be drawn to several targets. Each target records the `Viewing` (scene id, `Viewer`) it last drew; damage a target takes is recorded as missed for every other target viewing the same scene the same way (including `scene_missed` for the composed path and `latest_dirty` for `start_dmabuf`), and a target switching scenes or viewers starts from unknown buffers.
- Viewers: `Viewer::{Screen, Capture}` is set on a destination (`DmabufOutput::set_viewer`, `OffscreenTarget::set_viewer`, default `Screen`). A node's `Audience` (`Everyone`, `Only(viewer)`) picks which viewers see it, in retained and immediate scenes: each batch keeps one visibility table per viewer (binding 2 is bound per draw), the scene keeps pending damage per viewer (a viewer's tracker starts on its first draw, which is whole, and stops after 600 screen draws without it), audience-restricted nodes never occlude, and `Scene::has_damage` means the screen viewer.
- Frames draw straight into the destination (scan-out or client dmabuf, target) whatever their backdrops, fades or transform; `fx::frame_target::FrameTarget` is that image, its turn and scene extent. A turned output is drawn turned by `primitive.slang`'s vertex entry (`pc.target.zw` = `transform::placement`, from `rikka_types::Transform::axis_map`; a target's transform is the `wl_output` one, so the scene lands on it counter-clockwise for `Rotate90`), and every scissor, clear and render area goes through `FrameTarget::texels`. Backdrops and captures sample the destination through a per-frame bindless slot (`FxExecutor::read_from`), so a destination must be created with SAMPLED (dmabufs import with it when the modifier allows: `Plan::readable`).
- SAMPLED on destinations is unconditional by design: the scan-out modifier list (`dmabuf_render_formats`) is still probed with COLOR_ATTACHMENT only, an imported image's layout and compression are fixed by its modifier, every NVIDIA and RADV render modifier also advertises sampling, and NVIDIA reports identical memory requirements with and without it.
- The per-target scene image (`renderer/history.rs`) and the full-screen composite remain only where `Plan::composes`: scene-wide post effects, an immediate scene drawn to a `SinceLastFrame` buffer, or an unreadable destination with glass or fades.
- `RenderOutput::needs_full_redraw` asks for a full-target scene only on the composed path, when the scene image is missing and an immediate scene's damage cannot fill it.
- Image layout tracking is provisional until submit succeeds; an abandoned frame reverts it, and the painter requeues glyph copies and reverts instance uploads.
- A frame is a setup batch (uploads, and the scene image on the composed path) and a canvas batch that alone waits on the destination's release fence (at `COLOR_ATTACHMENT_OUTPUT`), sent in one submit; glass drawn into the destination runs in the canvas batch.
- Readback is split into `start_readback` (or `start_readback_of` for some areas, landing at their place in the full-frame buffer; each is its own submit) and a nonblocking `poll_readback`; `wait_for_pixels` blocks until that readback's submission retires. To draw and copy out in one frame use `renderer.draw(scene, target.copied_into(sink, missed))` (`CopySink::Rows(&SharedRows)` or `CopySink::Readback(&mut Readback)`; `renderer/copy_out.rs`): the canvas exits in TRANSFER_SRC and the frame's damage plus the `missed` areas are copied in the canvas batch, then a HOST barrier; ready at `submitted_frame()`. The per-frame instance descriptor set is rewritten only when a bound buffer changed (`BufferBinding`: handle + creation serial).
- Sharing with another device: `export_shared_dmabuf` exports a render target in system memory; `export_rows` makes a linear `SharedRows` dmabuf (RGBA bytes, `AB24`, 256-byte aligned rows) that a draw fills through `target.copied_into(&rows, missed)`.
- Scan-out frames carry `DmabufFence::SyncFile` for IN_FENCE_FD, or `Readable` (a pipe fed by the `rikka-scanout-wait` thread) that rikka-compositor-kms polls when the driver can't export a sync file.
- Exported buffers: `Renderer::export_dmabuf(w, h, fourcc, modifiers)` allocates a dedicated exportable image (modifier list, sampled when every offered modifier allows) and returns `ExportedDmabuf { target, format, planes }`; `dmabuf_export_formats()` lists what can be exported. `DmabufDraw::visible(w, h)` draws only the top-left part of a larger buffer (canvas `texels` / `FrameTarget::texture` keep the real extent so destination reads sample right) and `after(sync_file)` makes the canvas batch wait on it (`AcquireFences::lend`, or a CPU poll without sync-file import). `Renderer::start_dmabuf` is `start` for such an output. Compositor-side imports log `dmabuf imported` at trace under `rikka_renderer::imports`.
- Colour (see the colour-management note): `Plan::space` comes from `set_blend_space` on `DmabufOutput`/`OffscreenTarget` (default SDR; external targets stay SDR); `create_target_as(w, h, TargetFormat::Rgb10a2)` makes a 10-bit offscreen target (AB30 layout, 4 bytes a texel like RGBA8, so readback and `copied_into` rows work unchanged). Each draw writes a per-frame-slot conversion table (`draw/primitive_pipeline/colors.rs`, binding 6, 96-byte entries, rebuilt only when the `Colors` revision or space changes) indexed by `GpuInstance::color`; the vertex stage resolves the entry's kind into a flat varying (`Varyings::color`), so an identity entry (sRGB on SDR) costs one compare per fragment. The vertex stage converts fill and stroke through entry 0; textured fragments through their image's entry; glass tints are converted and backdrop samples are already in the blend space (no dither when linear). An HDR space always composes: the scene image is RGBA16F, `FxExecutor::work_in` makes blur levels, upright copies and backdrop caches (format-checked) FP16 too, and the final pass is `output_pq.slang` instead of `composite.slang`. A space change redraws the target whole.
