- Public crate `rikka_mesh_boolean`. `Boolean::new(Operation).operand(..).operands(..).solver(Solver).self_intersection().hole_tolerant().threshold().compute()` takes `Operand::new(&Polymesh).transform(Mat4).material_remap(table)`; operand 0 is the target space. It returns `BooleanResult { mesh, face_origins: Vec<FaceOrigin { operand, face }>, intersecting_edges }`.
- `material_remap(MaterialMode::{IndexBased, Transfer}, &mut result_slots, operand_slots)` builds the reference's slot tables (remap, with Transfer growing the result list); Exact applies tables like `set_material_from_map`, Fast like the modifier (out of range gives 0).
- Edit Mode: `IntersectKnife` (source, `SeparateMode::{All, Cut, Merge}`, threshold, solver) and `IntersectBoolean::new(op).swap().self_intersection()` act on `EditMesh` selection and leave the reference's selection (intersection edges in vert/edge mode, nothing in face mode). Hidden faces are kept.
- `Cdt::new(verts).edges(..).faces(..).epsilon(..).triangulate(CdtOutput)` is the public exact constrained Delaunay triangulation (the reference's eight output modes, vertex/edge/face origins, `EdgeOrigin::{Edge, FaceEdge}`).
- Exact arithmetic (`src/exact`): all f32 inputs become integers under one power-of-two scale (`Space`); constructed points are homogeneous `Int` quadruples built only from input points (LPI edge×plane, TPI three planes, SSI coplanar segments), so degrees stay bounded. Predicates filter with forward error (`Approx`) or `rikka_spatial` for pure inputs, then fall back to exact determinants. `VertexTable` dedups points by spatial hash plus exact equality.
- Exact pipeline (`src/arrangement`): triangulate faces (the reference quad split, exact CDT for n-gons) → `intersect` (BVH pairs, parallel exact tri-tri, coplanar clusters, per-triangle or per-cluster CDT jobs whose constraints carry `Support::{Edge, Plane}` so crossings are exact) → `cells` (patches, sorting around edges, nested components, winding numbers) or `raycast` when not PWN → `polygons` (merge triangles back into source faces, dissolve collinear new vertices). `propagate.rs` builds the `Polymesh` with generic gather/interpolate.
- Fast solver (`src/fast`) ports the reference intersect onto `EditMesh`: epsilon tri-tri, edge splice, wire dissolve, face-group raycast parity. Its face splitting stays a robust planar-graph tracer (`fast/edgenet.rs`), not the kernel's reference-exact `split_face_edgenet`: the port's element order differs from the reference, so the exact walk resolves coincident-vertex ties differently and leaves holes on large inputs (101,888-triangle sphere difference), while the tracer reproduces the reference's result. It cannot handle coplanar overlaps (the reference's limitation). N-ary Fast booleans apply operands in turn.
- `EditMesh` reuses killed face slots, so the Fast solver records each original triangle's operand side before splitting; never look sides up by an original `FaceId` after faces were created or killed.
- Differences from the reference kept on purpose: the Exact union/difference of cubes sharing one vertex keeps both volumes; Exact interpolates point data of new vertices from the lowest-operand source face (the reference leaves defaults; Fast keeps the reference's defaults).
- Tests hard-code the reference modifier/operator numbers (counts, volume, area, quads, selection). `performance::large_operands_finish` prints timings with `--test_arg=--nocapture` (two 101,888-triangle spheres: Exact ≈0.4 s, Fast ≈0.3 s remotely).
