---
title: Animate's tools for the desktop assistant
description: animate-assistant declares Animate's prompts and tools; each window offers them to the shell sidebar as kit "Animate".
about: apps/general/animate
tags: [application, agent]
---

- Animate has no assistant panel or caption button of its own; the shell's sidebar works it through `rikka-assist` (see the app tools note). The View menu's Assistant entry and Ctrl+K call `rikka_assist::summon("Animate")` through `assistant::open_assistant`.
- `apps/general/animate/crates/animate-assistant` (GPU-free) owns everything model-facing: `offering(title)` builds the `Offering` (instructions = `prompts/system.md` with the look guide, gist paths per tool) and `functions(studio)` declares the tools from `prompts/tools/*.md`.
- Tools: Scene, Figure, Pose (joint degrees, hips, hands, expressions, morphs, gaze incl. `eyes` by both/left/right as [across, up] −1..1 shares applied through `animate_solve::EyeDirection`, `reach` via `DragSession`, pins), Look (overview, one graph's nodes/ports/values/problems, or a figure's slots and parameters), Nodes (catalog per graph kind, ports with search), EditGraph (atomic batch of add/remove/connect/disconnect/set/unset by node id or a name given by an earlier add; angles in degrees), Materials (add from empty or preset, rename, remove, assign to slots by index/name/`all`/`class:<c>` incl. `preset:<key>` and `unique`, per-slot parameter values), LookKeys (key/unkey sockets and slot parameters), ResetLook (bare or cinematic world/composite), Camera, Keys (list/delete/shift/curve/tag), Timeline, Render, Cloth/SetCloth (pieces by name, `cloth.rs`) and Wind/SetWind (`wind.rs`); seen by the model as `Animate_<Tool>`, and prompts name them through `{{<stem>_tool}}` facts built with `exposed`. Figure reports each eye's glance under `gaze.eyes`.
- Generated facts keep prompts in step with code: `{{world_ports}}` (World output inputs and the record nodes that feed them, from animate-look's library), `{{material_presets}}`, `{{joints}}` from the muscle table (eyes excluded), curve names from `animate_edit::PRESETS`. `prompts/look.md` teaches the node model; a test fails when a prompt names a dotted node id the library lacks or the guide loses its generated facts.
- The look tools' logic is pure and tested in the crate (`look/apply.rs`, `look/describe.rs`): `apply_graph_edits`, `apply_materials`, `apply_keys`, `reset_look` run on a `&mut Look` with `FigureSlots` from the app and refuse precisely (`ArgumentError::AtEdit`, `Refused`, `Unknown`, `OutOfRange`); the binary's `serving/look.rs` only wraps them in `Animate::change_look`.
- Units at the tool boundary: metres in stage space, degrees, frames at 30 fps; joint angles are from the T-pose with the sign conventions written in `prompts/tools/pose.md`.
- The crate never touches app state: tools call `ToolHost::handle(ToolRequest)`. Each window's `assistant::host::WindowToolHost` sends requests through `Sender<Animate>` to `Animate::handle_tool_request(request, reply)` (`src/animate/serving/`) and awaits a oneshot. `Animate::start` takes the window's `ToolRegistration`; `refresh` retitles it with the figures' names.
- Errors are typed: argument parsing returns `animate_assistant::ArgumentError`, the app's serving returns `animate::ServeError`, and both reach the agent through `ToolError` (`Arguments` or `Host`), whose `Display` is what the model reads.
- Every call that changes the scene is one undo step: `handle_tool_request` opens a fresh `History::record_in` group per call.
- Render queues a `stage::Capture`; the viewport thread renders one frame per draw pass in `Stage::render_captures` (physics pre-rolled as in playback, `WARMUP_RENDERS` renders each; captures whose oneshot receiver closed are dropped), then an async task with a 60 s timeout tiles them into one PNG contact sheet shown to the model and the person.
