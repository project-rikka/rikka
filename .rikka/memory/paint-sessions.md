---
title: Paint dialogs (sessions) and the document worker protocol
description: How rikka-paint runs parameter dialogs in the side panel, previews, applies, saves and talks to its worker.
about: apps/general/paint/src/session
tags: [paint, application]
---

- A running dialog is a `session::Session` held by its `Tab`; while one runs the side panel shows `session::panel` (title, form, refusal, Preview toggle, Reset/Cancel/Apply), other edit commands are disabled, the canvas selection tool is inert, and Enter applies / Escape cancels (`Command::Apply`/`Cancel`).
- A dialog implements `session::Dialog` (`title`, `form(&Context)`, `outcome(&Context) -> Option<Outcome>`, optional `develops`, `previews`, `wants_histogram`, `confirm`, `refusal`, `repeatable_effect -> Option<Effect>`) and has an inherent `from_context(&Context) -> Self`, which Reset calls again; Reset also bumps `Session::resets`, which keys the form so its local view state starts over.
- `Outcome::Develop(recipe)` applies `Edit::Develop` to the layer chosen when the dialog opened, each step masked by the selection (`Context::masked`); `Outcome::Edit(edit)` applies a whole-document edit; `Outcome::Save` writes the file.
- Developing dialogs refuse non-pixel or hidden layers (`Context::develop_refusal`) plus their own `refusal` (shown in the panel, Apply disabled, preview withdrawn).
- Form handlers change the dialog through `session::tune::<D, A>(|dialog, value| ..)` or `session::tap::<D>(|dialog| ..)`; every change re-orders the preview at the camera scale, and zooming re-orders it at the new scale. Paint's own dialogs use the rows in `session/form.rs` (`amount`/`sliding` over `effects::Scale`, `toggle`, `swatch`, pickers); every number field submits the dialog on Enter (`NumberField::on_submit`).
- Every adjustment and effect is one generic `session::EffectDialog` over `rikka_effects::Effect` (see `effects-shared.md`), reached as `Kind::Develop(effects::Kind)`; its form is `effects::form` with a `Tuning` whose preview and commit are `Paint::tune_effect` (identical effects skip the view) and whose submit applies. Outcome is the effect's recipe, or nothing while it is empty. Menus live in `develop_menu.rs`; history names of effect operations come from `effects::Kind::name` in `operation.rs`.
- Parameterless adjustments and Find Edges are `direct::Direct` → `Command::Develop`, applied by `Paint::develop_directly` through `Tab::develop` (refusals become the window notice). Effects outside `Family::Adjust` (and Find Edges) become `Paint::last_effect` (`session::LastEffect` holding the `Effect`): Ctrl+F re-applies its recipe, Ctrl+Alt+F reopens its dialog with the last values.
- Adding a dialog: a file in `session/`, a `Kind` variant mapped in `session/kind.rs`, and a menu entry (`Command::Begin(Kind::..)`) with an optional binding in `command.rs` (`DEVELOPING` holds the adjustment/effect chords). A new effect goes into rikka-effects and only needs a menu entry here.
- Previews keep the drawn tiles: `Picture::preview` shows preview tiles over them, `unpreview` restores the drawing at once; an applied develop or figure edit keeps the preview until the drawing of that generation has landed on screen (`Tab::advance_picture`).
- Save (Ctrl+S) writes the tab's path in its format with the window's remembered choices; Save As uses the portal chooser and, for formats taking quality, speed or compression, opens the `SaveOptions` dialog. `Saved::Document` rebinds the tab to the new path; `Saved::Copy` leaves it and shows a notice.
- Closing a modified tab, the window (`Window::on_close_request`) or Quit asks per document with `rikka_widgets::unsaved_prompt` (built in `view.rs`, answered by `paint/closing.rs` `Paint::answer(Unsaved)`): Save / Don't Save / Cancel.
- Worker orders: `Edit` (generation), `Preview` (newest wins; an edit drops pending previews), `EndPreview`, `Histogram`, `Save`. Edits in one batch are coalesced; saves and histograms first settle the edits before them.
- Worker reports: `Opened`, `Changed { facts, layers, canvas, active_layer }` (also after layer-only changes such as renames), `Drawn`/`Undrawn`/`Unchanged(generation)`, `Selected { generation, region }`, `Chronicled` (shared history actions, current, saved; undo/redo/modified are derived), `Thumbnails` (all layers, after canvas changes and time travel) or `ThumbnailRefresh` (only the layers an edit painted, merged), `Previewed`/`Unpreviewed`, `Measured`, `Saved`/`Unsaved`, `Refused`.
