- `rikka-wayland-client` (generated proxies over `rikka_wayland_wire::client`) is the client; `rikka-wayland` is the layer every consumer opens a display through. No product code links libwayland or the third-party `wayland-client`: its only user is the oracle `rikka-compositor-server/tests/conformance.rs`. The compositor's nested backend is a `rikka-wayland` client too.
- Thread model: `Connection` is `Clone + Send + Sync`; any thread sends, one reads at a time (`connection.read()` after polling `as_fd()`, or a blocking `roundtrip`, which reads itself when nobody is and otherwise waits for the reader). An event goes where its object's `Route` says: a `Queue<S>` (`queue.on::<P>(|state, proxy, event| ..)`, dispatched by its owner), a tap (`Route::tap::<P>(|proxy, event| ..)`, run on the reading thread) or `Route::discard()`. Children inherit their creator's route; `proxy.via(&route)` makes children take another.
- Because any thread's roundtrip may read, a loop that polls the socket must also set its queue's waker (`queue.set_waker`, an eventfd) and check `has_pending` before sleeping; rikka-app and the shell do.
- Per-object data is a Copy `Key` (`with_key`/`set_key`/`key::<K>()`; u32, u64, `ObjectId`, or a small `impl Key`); an event's proxy carries the keys the object had when the event was read, so they survive the object's destructor event. `proxy.object_id()` (`Proxy` trait) is the reuse-proof map key; `proxy.id()` is the wire id.
- `Display::from_env` / `connect_to(socket)` / `from_connection(connection, wl_display)` keeps the globals by a registry tap: `bind(versions)` (events discarded), `bind_on(&route, versions)`, `bind_optional[_on]`, `bind_all(&route, version)`, `seat(name)` (one roundtrip when named; `Error::NoSeat` / `SeatNotFound`), `announce_globals(&route)` (a second registry for hotplug handlers), `sync(&route)`, `flush`, `event_loop::<S>()`. `Display` is `Clone`.
- `Host` (Clone) is a `Display` plus shared `Serials` and an optional reader: `Host::with_reader(display)` runs the `rikka-wayland` thread that polls and reads (stops with the last clone; the shell's clipboard, tests); `Host::read_by_owner(display)` when the owner's loop reads (rikka-app, the shell).
- `EventLoop<S>` wraps a queue: `on`, `route`, `queue_mut`, `roundtrip` (owners only), `dispatch_pending`, `blocking_dispatch(state, wait)` (the owner's read step with a caller-supplied wait: `rikka_worker::EventFd::poll_readable` / `wait_readable`), `run(state, &commands, handle)` for workers (queue waker = the command channel's eventfd; sends a `wl_display.sync` first and holds commands until it passes, returns at once when the worker is stopped), `settle(state)` (dispatch until a fresh sync passes, waiting on an eventfd and never reading) and `poll_dispatch(state, waker)` (rikka-present). `run` and `settle` need a reader elsewhere.
- No worker reads the connection or roundtrips: workers use `run`/`settle`, and anything an owner thread creates defers what it would have waited for (rikka-blur sends regions once BLUR is announced, rikka-present picks formats when the dmabuf feedback arrives).
- Input serials: `host.serials()` (lazy) binds a `wl_seat` whose pointer and keyboard are taps recording serials, waking no queue. A host whose owner already hears seats installs `Serials::recorded()` through `host.set_serials` first and feeds the `Recorder`: `Recorder::follow(Option<WlSeat>)` retargets every clone (clearing the log) and `record(seat, kind, serial)` keeps only the followed seat's serials (rikka-seat's `Seats::serials`); `Serials::seat()` is an `Option`. `latest(&[SerialKind])`, `register_waker(kind, waker)`. Workers must not create their own pointer or keyboard.
- `Configures<T>` sequences one xdg surface's configures: `push(serial, size)`, then `ack_for_commit(&drawn)` right before a commit returns the newest pending serial of exactly that size.
- `Presentation::new(&display, callback)` is tap-based (no thread; the callback runs on the reading thread): `feedback(&surface, key)` right before the commit it should follow yields `PresentationFeedback { key, presented }` (`None` = discarded; times only for CLOCK_MONOTONIC).
- Scale: `FractionalScaleManager::bind(&display, &route)` (only with a viewporter) and one `Scaling::new(manager, surface, key)` per surface; hosts route `wp_fractional_scale_v1` events to `Scaling::handle_event`, `preferred_buffer_scale` to `set_preferred_buffer_scale`, may seed `set_initial_factor`, and read `scale(|| integer scale)` → `Scale::{Integer, Fractional}`.
- `Clock` gives wrapping ms input timestamps.
- There is no foreign `wl_display`, no raw-window-handle and no WSI on the client side: surfaces are presented by rikka-present only.
- Consumers: `rikka-virtual-input`, `rikka-app` (its private `wayland/` modules), `rikka-capture`, `rikka-blur`, `rikka-window-view`, `rikka-clipboard`, `rikka-seat`, `rikka-present`, and `rikka-shell` directly.
