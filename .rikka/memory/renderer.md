- The renderer is three crates: `rikka-gpu` (device, memory, compute, textures, dmabuf and video import, reclaim; see the gpu-core note), `rikka-renderer` (these notes: 2D scene, text, glass, the `Present` trait) and `rikka-renderer-3d` (see the renderer-3d note). A device is a `rikka_gpu::Gpu` made by `Gpu::builder()`; `Renderer::new(&gpu)` draws on it into DRM, offscreen or dmabuf destinations, and `renderer.gpu()` hands it back for device queries, compute and video. There is no window-system integration (no swapchain, no raw window handles) and no external-device embedding. `ash` comes from `rikka_gpu::ash`; this crate re-exports from `rikka-gpu` only what its own signatures name (`Gpu`, `Error`, `Result`, `TextureId`, `Uploads`, dmabuf types, …).
- Extension slot: `Renderer` holds one `ExtensionSlot` (`renderer/extension.rs`; `Extension: Any + Send` with `has_pending` and `reclaim`), and `Renderer::parts()` lends `RendererParts { gpu, textures, convert, reclaimer, extension }`. `rikka-renderer-3d` keeps its state there, so this crate names no 3D type.
- Presenting: the `Present` trait (`start` → `acquire_image(timeout)` (`Acquired::NotReady` is normal) → `record_image` → `present`, plus `trim`; `type Image`) is implemented by rikka-present's `Presenter` over `Renderer::start_dmabuf` and dmabuf draws on Linux, and by rikka-swapchain's `Presenter` over `Renderer::start_swapchain` and `swapchain_draw` on Windows (swapchain-presenter note); rikka-ui's embedder drives any `Present`. `Recorded::deferred()` / `RenderOutput::needs_full_redraw` mark a frame owed in full. `Sizing` (visible px, scale, interactive: 128 px buckets, `allocation`/`fits`/`destination`) belongs to rikka-present.
- Recording runs anywhere. `present` belongs to the window's thread. Scenes, surfaces, frames and the renderer are all `Send`.
- `has_free_frame` lets event loops defer instead of blocking.
- `SurfaceConfig { transparent, buffering }` configures a rikka-present `Presenter`: `Buffering::Triple` (3 buffers, default) or `Double` (2, for static fullscreen surfaces; the shell's `SurfaceDesc::wallpaper()` uses it).
- Lifetimes: dropping a target, surface, dmabuf, readback or viewport hands it to the `Reclaimer`. There are no `destroy_*` or `wait_idle` calls on drop. A frame never frees GPU memory itself: `RetireBin::collect_within_frame` gathers completed retirements and `release_due` (right after the frame's submit, so the driver's free work, which blocks submission on NVIDIA, overlaps the idle part of the frame) sends them to the `rikka-reaper` thread; `trim()` frees synchronously.
- Copy ids (`TextureId`, and the 3D crate's `MeshId` and `MaterialId`) are destroyed explicitly or left to `reclaimer()`. Each frame empties the reclaimer and the upload queue.
- Shaders are `rikka_shaders` packages, each one crate of `pub static` `rikka_spirv::Shader`s per stage (`<STEM>_<VERT|FRAG|COMP>`: SPIR-V plus build-time hash, storage-image use and push size; `BackdropShader::new`/`builtin` and the pipelines take them, `.spirv` gives the bytes), all Slang, compiled per file by `rikka-shader-build` actions. `shaders/` (crate `shaders`) is the 2D scene: `primitive.slang` (vertex + fragment) and `blur_down`/`blur_up`/`refract`/`composite.slang` (fx fragments), importing `shaders/lib/canvas/` (`instance`, `sdf`, `glyph_curves`, `fx`, `lens`). The full-screen vertex stage is `shaders_gpu::FULLSCREEN_VERT`.
- Code map: `renderer/{build,canvas,colors,copy_out,destination,dmabuf,shared,device,draw,extension,external_target,history,painter,preparer,readback,sources,textures,work}` (`build.rs` is `Renderer::new`, `device.rs` the frame-slot queries and `gpu()`) over `rikka_gpu::core::runtime`. `present/`: the `Present` trait, `Acquired`, `SurfaceConfig`, `Buffering`, `Sizing`. `draw/{arena,chunks,fades,emit,retained,batcher}`, `scene/{dirt,frame,order,tree}`, `fx/`, `text/`.
- Errors are `rikka_gpu::Error` (re-exported as `rikka_renderer::Error`); see the gpu-core note.
- Topics live in their own notes: retained scene and edits (renderer-scene), batching and occlusion (renderer-batching), destinations, damage and readback (renderer-output), glass (renderer-glass), text (renderer-text).
