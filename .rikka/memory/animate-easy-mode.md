title: Animate Easy mode and humanoid motion crates
description: animate-body/solve/motion turn PMX figures into muscle-space humanoid motion that Easy mode poses by direct drag.
about: apps/general/animate/crates
tags: [application, animation]
---

- Layers: `animate-body` ← `animate-solve` ← `animate-fit` ← `animate-motion` ← `animate-sheet` ← `animate-edit` ← the app; `animate-document` (the `.rmotion` envelope `Motion` over figure, camera, look, fluid and wind bodies) sits beside them above motion, look, fluid and wind. All GPU-free. Body fitting, intensity and bust jiggle are in the animate-fit note.
- `animate-track` (rikka-mmd, rikka-model-core) is the one keyed-track store: `Keyframe` (Clone keys, `id() -> &Id`, `at_frame`), `Sampled` (`value`, `toward(next, t)`), `Tracks<K>` (one frame-sorted track per id behind an `Arc`, borrowed lookup `keys(&Q)`, `value_at`, `held_at` for step keys, `merge`, `changed_from` skipping shared tracks) and `Span`/`Edge` (timeline bar drags). Bone (`VmdBoneFrame`), camera (`VmdCameraFrame`) and switch (`VmdPropertyFrame`) frames, morph, part, wind, emitter and look keys all live in `Tracks`; `HumanMotion` wraps `Tracks<PartKey>` (`parts()`, asserting `insert`).
- `Take` = `human`, `bones: Tracks<VmdBoneFrame>` (bones the humanoid does not drive, as rest-relative deltas: local = rest translation + t, rest rotation · r, so PMX keys are plain VMD values), `switches: Tracks<VmdPropertyFrame>`, `morphs`, `holds`; `CameraMotion` is the camera subject (`pose_at(seconds)`). Motion files are only read at import; `DetailPlayback` writes bone locals and IK/visibility switches from the take.
- Import (`animate-motion` `import/`) takes a `Target { model, body, faces }`. `Take::from_vmd` samples a PMX target itself (exact, bones and switches by name) and any other figure through the cached standard MMD skeleton; `Take::from_clip(target, &Clip)` samples any model animation (`Clip::new(model, index)` builds the source body, `Clip::with_body` reuses a figure's own; VRMA expressions and lookAt become morph and Gaze keys, mesh weight tracks morph keys, other animated nodes detail keys by name). Both read source `HumanPose`s, seed keys from the source key times and reduce onto the target body; morph names go through `Faces::adopt`, cached per name by `import::adopting`.
- `animate-body`: `Body::from_anatomy(model, &anatomy)` = `Mapping` (bones from `rikka_humanoid::Anatomy` for any format, twists from the anatomy; PMX adds carrier = top PMX ancestor of the hips, append followers and IK to release) + normalized skeleton + soles. Morph catalogs (`Faces`) are separate, see the animate-morphs note. There is no surface picking. Space: right-handed, +Z forward, +X the character's left.
- Hands: `HandPreset` (incl. `Pinch`) sets/blends finger muscles; `Body::pinch(side)` gives the pinch point (hand-joint local and at rest); `Body::write_fingers` writes only one hand's finger locals. Holds are in the animate-holds note.
- `HumanPose` = root position (human scale, ÷ `Body::scale` = hips height) + root rotation + 95 muscles (0 = T-pose, ±1 = the normalizing `min/max`; the editable range is `Muscle::bounds`). The T-pose is chained so the model's own rest is exactly representable; feet keep their rest pitch. The muscle table and region ranges (`TORSO`…`RIGHT_LEG`) in `muscle.rs` define part layouts; right axes mirror left as (x, −y, −z). UpperLeg is a flexible person's hip: forward 170° / back 50°, out 170° / in 60°, so a straight leg rises beside the head.
- `Body::clamp` keeps each muscle inside `Muscle::bounds(limits)` and caps each bone's bend+side swing below 180° (`Skeleton::shorten_swings`); `Body::clamp_around(pose, around, limits)` widens each bound to include `around`'s value (`Muscle::bounds_around`), so drags never snap a pose that starts beyond the limits. `Muscle::min/max` only normalize values (stored data); the editable range is `lowest/highest` (the `REACHES` table widens it, e.g. upper arm down to −110° so arms hang and cross the body), stretched ×1.5 without limits.
- `Body::bulk()` is a body volume from the mesh (per trunk/leg bone: slices × 16 sectors of max flesh radius, skirt and tie included via folding); `holds` tests a point, `surface` walks a point out along a direction.
- `Body::write`/`locals` drive the carrier, human and twist nodes; `release` switches the mapped leg IK off; `read(&Instance)` goes back.
- Shared helpers live once in `animate-body`: quaternion `canonical`, `twist_about`, `arc`, `rotation_vector`; `Side::{leg, foot, toes}`; `Body::sole_height(&Worlds, Side)`. `animate-motion` owns `Goal::from_worlds(worlds, limb, scale)`, `Pinned::new(pin, goal)` and `Take::sample`.
- `animate-solve`: analytic `reach` (two-bone, used by the evaluator), `ground` (floor), `look` (gaze), and the Easy posing API (`Handle`, `DragSession`, `twist`, `rotate`, `Finger`, `Pin`) described in the animate-easy-posing note.
- `animate-motion`: `Part` (10 keyed body rows; morphs are not parts; `Part::holding(bone)`), `Tag` (Smooth/Ease/Hit/Linear/Step/Settle Hermite slopes), `HumanMotion::sample` → `PoseSample`, `Evaluator` (secondary springs, pin IK, floor, gaze), `MotionBake` (64-frame chunks baked on a background thread, partial `rebaked`), `Take::from_vmd`/`from_clip` (retarget + key reduction + contact pins), `Retarget` (one-frame previews without a take or bake), `TakeFile`/`CameraFile` (the figure and camera bodies of `.rmotion`, validated: finite values, unit rotations, settings in range) and `Incoming<M>` (motion arriving from files, merged or replacing, applied `onto` whatever the subject holds when it lands). Loading speed and the preview API are in the animate-motion-loading note.
- Muscle space is world-delta from the T-pose, so rest bone orientations never matter, but every source and target must face +Z.
- Keys hold sampled curve values, never procedural results; limb keys always carry the FK wrist/ankle as goal so pins blend from it.
- Imported keys carry fitted per-channel `Slopes` (Hermite in/out, rotations in arc angle) that override their tag; any edit of the key's values or tag drops them (`PartKey::retagged`, re-keying), leaving the fitted fallback tag.
- App: `Mode { Easy, Detail }` (Ctrl+E, "Easy editing" in the Edit menu); `Animate::easy()` only for figures with a body. The Easy inspector (`animate-inspector` `inspector/easy/`) holds only the key tag and automation; hands, face, eyes, mouth and pins live in the viewport cards (`animate-inspector` `cards/`, anchored to the stage's top-right on the `CARDS_CORNER` spacer, opened by clicking markers); `animate-viewport` `easy/` is the overlay and gestures (animate-easy-posing note).
- `Part::Gaze` owns the eye muscles (`EYES`): `PartValues::Gaze { eyes, gaze }`, file field `eyes`; mode `off` means the eyes keep their keyed direction, `point`/`camera` blend a look-at on top by weight. VMD eye motion imports into Gaze keys. Eye muscles reach ±35° across, −30°..25° up (`REACHES`). Eye frames gaze along the head-space facing (+Z), never the bone tail, so muscles are pure yaw/pitch on every model.
- Easy edits never key by themselves: drags, pins, hand presets, sliders and Reset Pose all go through `Animate::preview(PoseSample)` into the pending `Posture`. `unregistered_parts()` diffs that posture against the take at the frame; Register keys exactly those parts plus pending morphs (else the chosen part or morph, else all parts) and regoals pins of edited limbs.
- `PoseSample::still(body, eye)` (animate-motion) is the preview's displayed pose: ground plus gaze, the evaluator's tail without springs or pin reach.
- Automation settings changes are not undoable; every setting except `limits` (which matters only with a non-neutral intensity) rebakes the whole take (`HumanMotion::dirty_since`); `motion_paths` is a view switch. `MotionBake::write(seconds, &mut Pose)` writes interpolated locals and lobe (bust) rotations in place; morph weights and auto-blink come from `MorphPlayback`.
- `Change::laying` drops keys identical to what they replace, so re-laying them records no undo step.
