title: Music output path (rikka-hifi)
description: rikka-hifi's gapless single-source output: shared PipeWire stream, exclusive ALSA hw with ReserveDevice1, signal path.
about: crates/media/rikka-hifi
tags: [media, audio]
---

- `Hifi::start(Identity::new(name, id).icon(..))` (cheap Clone) runs a `rikka-hifi` Worker; `devices`, `events` (futures unbounded `Event`s), `set_output(Output::{Shared, Sink(name), Exclusive(DeviceId)})`, `play`/`queue`/`unqueue`, `pause`/`resume`/`stop`/`seek`, `set_volume`, `set_replay_gain(ReplayGain::new(mode).preamp(db).prevent_clipping(b))`.
- Sources: `Source::file(path, at)` opens a local file once: as a `DsdReader` when it holds raw DSD (native/DoP when the output can, else the in-house `DsdToPcm` decimator of rikka-hifi-core), otherwise as a PCM `Decoder`; `Source::decoder(Decoder)` (format from `Decoder::info()`), `Source::dsd(DsdReader)`, `Source::pushed(SourceFormat) -> (Source, PcmWriter)` for decoders running elsewhere (`write`, `flush(from)`, `finish`); `.gains(Gains)` carries track/album loudness.
- Gapless: `queue` opens the successor ahead (`rikka-hifi-decode` per source, up to 2 s read ahead) and splices it into the ring at the predecessor's last frame; `unqueue` withdraws it unless reading already crossed the seam (then `Advanced` arrives).
- Shared output is a native PipeWire stream (`rikka-hifi-pipewire`, F32, `node.rate = 1/<rate>`, `media.role = Music`); following the default sink is left to WirePlumber. It can at best be `Lossless`, never `BitPerfect`, since the graph mixes.
- Exclusive output opens ALSA `hw:` on `rikka-hifi-alsa` (SCHED_FIFO, else RealtimeKit) after taking `org.freedesktop.ReserveDevice1.Audio<card>` from WirePlumber (priority 10, no AllowReplacement); the card and its hardware mixer are held as a `Claim` across PCM reopenings and the mixer is restored on hand-back. A refused, lost or released claim falls back to shared without stopping (`OutputState::FellBack { reason: Refusal }`). Never call alsa's `PCM::state()` directly (it panics on disconnect).
- `devices()` reads capabilities from `/proc/asound/cardN/streamD` for USB and through HW_REFINE ioctls on `/dev/snd/pcmC*D*p` otherwise (`O_APPEND` joins a busy substream), so held devices still list; `Device::dsd()` derives DSD support from the capabilities. `DeviceId` parses back from its `pcm()` string (`FromStr`), which is how preferences store it.
- Gain staging: ReplayGain \u2192 volume \u2192 TPDF dither, the dither only for integer outputs whose samples were altered. Volume changes take ~200 ms.
- `SignalPath { source, stages, output }.verdict()` = BitPerfect / Lossless / HighQuality / Lossy; shared paths read the real graph (sink rate/format, Bluetooth codec, `clock.rate`/`force-rate`/`allowed-rates`, `hardware_rates`) from PipeWire.
- ReserveDevice1: every D-Bus call is bounded by the connection's 3 s `method_timeout` and owner proxies use `CacheProperties::No` (zbus's lazy `GetAll` ignores the timeout); an unanswered `RequestRelease` becomes `Refusal::Busy`. After a granted release, `acquire` waits up to 2 s on `NameOwnerChanged` for the old owner to vacate the name. While paused, the ALSA writer sleeps on the PCM poll descriptor plus the ring's bell, so a disconnect wakes it. WirePlumber (priority -20) can drop replies to simultaneous requests. Our `request_release` waits at most 3 s for the engine, then answers `false`; another Rikka (same priority 10) is refused at once.
- zbus answers `Err(NameTaken)`, not `Ok(Exists)`, for a name someone else owns. Machine tests need the real `XDG_RUNTIME_DIR`, which `--config=machine` passes to `rikka_test(machine = True)` binaries; card tests take `support::card::lock()` and use their own `Identity` names.
