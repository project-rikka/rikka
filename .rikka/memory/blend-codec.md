---
title: .blend file reader and writer (rikka-blend)
description: rikka-blend reads .blend into a Model or a Scene and writes Scenes as .blend files from a template.
about: crates/model/rikka-blend
tags: [model, blend]
---

- Facade: `BlendImporter` (Model, registered in `rikka-model`), `BlendExporter` (`Model` → `Scene::from_model` → writer), `read_scene(input, resolver, options, cancel) -> BlendScene { scene, warnings }`, `write_scene(&Scene, &BlendOptions) -> Exported`, `sniff`. `BlendOptions::compress` writes the reference's seekable zstd.
- `file/` is the format layer: header (4/8-byte pointers, both endians, 5.0's 17-byte header), SDNA and blocks; `Record` reads fields by name through the file's own SDNA (`static_name` maps Collection→Group, CollectionObject→GroupObject). DATA blocks belong to the ID before them; data pointers resolve per owner, ID pointers globally. Link placeholders resolve into library `Blend`s opened once each by `read/library.rs` through the `read::resources::Resources` trait (implemented by `ImportCtx` and the scene reader's `SceneCtx`).
- `read/` builds the triangle `Model` in the file's own space (`RIGHT_HANDED_Z_UP`, `unit_scale` = `scale_length`): `mesh/source.rs` reads every mesh-storage generation into a `Polymesh`; `material/` walks node trees into PBR through a `Store` trait (ModelBuilder, or the scene's store) and `image::load` returns `LoadedImage` (bytes, path, colour space); `modifier/<kind>.rs` holds both halves of every modifier codec (`read` via the `References` trait, `write` via `Targets`), `describe` is shared by the Model path (evaluates, Armature binds a skin) and the scene path.
- `scene/` is the authoring path, never evaluating anything. `space.rs` converts Z-up file units ↔ Y-up metres exactly: points `R·p·s`, objects conjugated, Euler orders swap Y/Z letters, bone heads/tails with recomputed roll, bone-parent inverses `S·PI·Rᵀ·S⁻¹`, locks/scales permuted. `convert.rs` converts modifier and constraint parameters per space (world/pose/object-local spaces rotate, bone-local ones only scale). `constraint.rs` is the .blend ↔ `rikka_armature::Constraint` codec.
- `scene/read/` maps collections (view-layer exclusion and the layer eye into `Collection::hidden`, `COLLECTION_HIDE_VIEWPORT` into `hide_viewport`), objects (delta transforms kept as `ObjectTransform::delta`, vertex parents baked, cyclic parents dropped with a Repaired warning), meshes (`KEYBLOCK_LOCKED_SHAPE` into `locked_shape_keys`, `attributes_active_index` resolved to a name), armatures (Bone tree, bone collections, `BONE_RELATIVE_PARENTING`), poses, materials, Tex image textures (one `TextureData` per Tex, named after it), all images and units/cursor. Modifier `eModifierFlag_PinLast` maps to `pin_to_last` both ways; relative bone parents convert `parentinv` as an object matrix, plain bone parents as a bone matrix.
- `write/` is the generic writer: `Template` is `assets/template.blend.zst` (a .blend file holding one ID of every emitted kind plus the Layout workspace UI); its DNA1 is copied verbatim and every struct starts from the template's record with pointers zeroed (`defaults`, `id_defaults`), fields set by name (`Struct`, dotted paths). `copy`/`copy_linked` deep-copy a template record and the DATA reachable from it with fresh addresses (root-only `deny`, everywhere `always`, `known` remaps across IDs); used for the scene's ToolSettings, UI (WM/WS/SN), material nodes with their sockets, the Smooth by Angle node group and its modifier properties. `Emitter` writes the 17-byte header, LargeBHead8 blocks, DNA1, ENDB.
- `scene/write/` emits GLOB, UI, SC (view layer, bases, layer collections, embedded master collection), GR, OB (modifiers, pose, constraints), ME (AttributeStorage arrays, MDeformVert in vdata, float3 `custom_normal`), KE, AR (BFS bone-collection array), MA (embedded Principled tree the material walk reads back), NT, TE, IM (packed), CA (AUTO fit, lens from fov/aspect), LA. Addresses are a counter, so output is deterministic.
- The reference opens written files as normal scenes and evaluates them identically; 4.5 LTS opens them; 4.2 refuses the 5.x header like the reference's own files.
- Tests: `tests/scene_read.rs` checks `assets/studio.blend` against reference numbers, `tests/authoring.rs` round-trips (rewrite is byte-identical) and keeps written files as undeclared test outputs (`--remote_download_outputs=all`) for checking in an external viewer; hostile files are in `tests/refused.rs`.
