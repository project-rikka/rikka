---
title: Wayland seat input for rikka-ui hosts (rikka-seat)
description: rikka-seat turns wl_seat devices into rikka-ui Events per surface for rikka-app and the shell, with cursors and IME.
about: crates/ui/rikka-seat
tags: [input, wayland]
---

- Public crate shared by rikka-app and rikka-shell; the compositor has its own input stack. Linux-only (`target_compatible_with` linux, like rikka-wayland*). Custom cursor pictures come from the cross-platform `rikka_input::cursor` registry (`define_cursor`/`forget_cursor`/`cursor_pixels`), which rikka-seat uploads to wl_shm.
- `Seats::builder().gestures().relative_motion().bind(&display, &route)` binds cursor-shape (else wl_shm + wl_compositor for a themed fallback read with `rikka-xcursor`: `XCURSOR_THEME`/`XCURSOR_SIZE`, nearest size, first frame, uploaded once per name and scale), optional pointer gestures and relative pointer, and text-input-v3. `Seats::add(registry, name, version)` / `remove(name)` follow wl_seat globals.
- The host state implements `SeatHost` (`seats()` and `handle_event(SeatEvent)`) and calls `Seats::listen(&mut queue)` once, which registers the handlers of every seat-owned interface on the host's `rikka_wayland_client::Queue`.
- `SeatEvent::Input { surface, event }` carries a `rikka_input::DeviceEvent` (logical surface coordinates) that hosts turn into a `rikka_ui::Event` with `.into()`, so rikka-seat does not depend on rikka-ui; `SeatEvent::Keyboard { surface, entered }` is keyboard focus per seat, announced whether or not a keymap has arrived. Modifiers are per seat.
- Pointer events are held until `wl_pointer.frame` (v5+); axis events in one frame merge, value120/discrete make `ScrollSource::Wheel`, others `Continuous` with Began/Moved/Ended from axis_stop. The axis values become `ScrollDelta::from_offset` and `axis_relative_direction` inverted becomes its natural flag (tablet tool wheels the same, never natural). Touch emulates the primary button with the first finger. Gestures carry the pointer's last position.
- Keyboard: `rikka_input::xkb::Keyboard`, repeat from `repeat_info` (`Seats::repeat_due`, `Seats::repeat(host, now)` from the host's loop), compositor `repeated` keys passed through. `Seats::take_keyboard_change()` reports the focused seat's Caps Lock and layout as a `rikka_types::KeyboardState`.
- Every loaded keymap and repeat info is published process-wide as `rikka_input::xkb::SessionKeyboard` (generation-counted), which rikka-nested forwards to its clients.
- Per turn the host calls `show_cursor(surface, shape, whole scale)` for each surface (cheap when unchanged; re-sent after every pointer enter) and `update_text_input_rects(|surface| caret)` to enable, place and disable text input; `grab()` is the latest press/touch serial for move, resize and window menus; `pointer_over(surface)` serves pointer locks; `travel(bool)` creates or drops relative pointers.
- Text input re-sends the cursor rectangle only when its whole-pixel rect moves (each commit costs an IME round trip) and delivers an empty `Preedit` to a surface the text input leaves mid-composition.
- A held key re-typed on a modifier change reads plain xkb text and never feeds the compose state, so a pending dead key survives it.
- `Seats::serials()` is a `rikka_wayland::Serials` for `Host::set_serials`; it follows the first seat and, when that seat's global goes, the next remaining one, so workers holding clones never send a dead seat's serial.
- Tablets (`tablet.rs`, `tool.rs`, `pad.rs`): `zwp_tablet_manager_v2` (v1–2) gets one `zwp_tablet_seat_v2` per seat. Tools become `SeatEvent::Stylus { surface, event, stylus }`: the same `DeviceEvent` pointer stream (proximity in → `PointerMoved`, tip → `Primary`, `BTN_STYLUS`/`BTN_STYLUS2`/`BTN_STYLUS3` → Secondary/Middle/Back via `evdev::tool_button`, tool wheel → wheel `Scroll`, proximity out → releases of held buttons then `PointerLeft`) plus a `rikka_types::Stylus` (tool kind/serial/hardware id/capabilities; samples with pressure and distance 0..1, tilt and rotation in degrees, slider −1..1, contact, compositor time). Axes persist across frames; declared-but-unsent axes read 0.
- Pure axis/motion frames coalesce per tool into one pending `PointerMoved` whose stylus holds every sample; it is delivered before the tool's next discrete frame, before any other seat event, and by `Seats::flush(host)`, which every host calls once per loop turn after dispatching (rikka-app `turn`, shell `ring`, nested compositor `hear`). Tool down/button serials feed `grab()` and `Serials` as button serials. Tool cursors follow `show_cursor` like pointers (`cursor::Owner::{Pointer, Tool}`; cursor-shape `get_tablet_tool_v2`).
- Pads are parsed (groups, buttons, rings, strips, dials, modes; `Seats::pads()`, tablets via `Seats::tablets()`) and reported as `SeatEvent::Pad { surface, event: PadEvent }`; rikka-app turns buttons, rings (degrees, `None` at stop), strips and dials into `rikka_ui::Event::Pad(PadInput)` for the window of the surface (delivered to focus like keys); Entered/Left/Mode and the shell ignore them; `set_feedback` is not sent.
- Tests (`tests/tablet.rs`) script a real `rikka-compositor-seat` on `rikka-test-display` and drive tools/pads through its `SeatMut` tablet commands; the client is `Seats` over `rikka_wayland::Display::from_connection`. Keyboard/pointer paths stay untested here; live checks run on a private `rikka-compositor --headless --socket <name>` with its own `XDG_RUNTIME_DIR`, a private `dbus-daemon` and fcitx5; `wtype`/`wlrctl` type on the last-listed seat (`rikka-agent`), so drive `seat-0` through `rikka_virtual_input::Seat::named("seat-0")`.
