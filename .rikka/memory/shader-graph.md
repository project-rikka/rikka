- `rikka-shader-graph` is public and pure (no renderer; only rikka-slang's schema vocabulary). `Graph::new(GraphKind::{Material, World, Composite})` holds parameters (materials only), a main `Body` and named `Function`s (node groups, inlined per call). Nodes keep set socket values in `Node::inputs` as `SocketValue::{Number(Constant), Asset(path)}`; one `NodeKind::Output` per graph.
- Every API takes the `Library` (`Library::standard()` = shipped material nodes in `src/nodes/`; apps `extend` it with `NodeSpec`s). `NodeSpec` behaviours: `Function` (Slang expression template with `{port}` and `$pixel $context $light $shadow $indirect $vertex $scale`), `Closure` (a Slang `IShadingModel` used as a BSDF), `Filter` (composite image operator, opaque to the engine), `Record` (world record, opaque). `Library::with_world(ports)` declares the World output's inputs. Ports carry one `Hint` each for editors (`Hint::Text` makes a texture-typed port free text, e.g. names, rather than a file) and `many` for list inputs (`Edit::Attach`/`Detach`). Item ids deserialize from numbers or numeric strings, so graphs nest inside internally tagged serde enums such as `.rmotion` bodies.
- Editing: `graph.apply(&library, Edit) -> inverse`, `graph.edit(&library, scope)` (`Editor`), `catalog`, `ports`, `validate` (`Report`: errors + inferred types). `Builder` writes graphs in code (errors collected until `finish`, which also lays nodes out; `Graph::arrange`); `Builder::frame(title, |b| …)` puts every node the closure adds in the current scope into one titled `Group` (frames are ignored by the layout).
- Types: floats 1–4 wide, `Texture`, `Shader` (closure result), `Image` (composite), `Record(Symbol)`. Image ↔ number coercions are a per-pixel load / a materialising pass.
- Sockets: an unset input folds to its default constant; a set one becomes a hidden uniform `u_n<id>_<port>` (`[Default]` = the value at compile time), listed in `MaterialSource::sockets` / `PixelStep::sockets`, so tweaking and keying never recompile. Only source changes need a rebuild.
- Materials (`material.rs`, `Graph::material` → `MaterialSource { source, sockets, outlined, displaces }`): the reference semantics over one forward light loop per "stage". Closures and `Lighting` (custom: `light` per light, `ambient` once) accumulate in a loop; `ShaderToRgb` makes the lit result a value, and whatever depends on it runs after that loop (a later closure adds another loop: `combine_N` + `rikka_illuminate`). Per-light values are tainted and may only reach `Lighting.light` (`Problem::PerLight`), ambient ones `Lighting.ambient`. The `outline` shader input is a second pipeline run for hull pixels (`resolve_hull`); `displacement` needs a `Role::Displacement` float parameter. Generated code: `GraphData` (values carried out of `evaluate`), `Surface` (parameters + uniforms), `GraphState`, `Model` with fields `gloss` and `see_through` (parameters `gloss.roughness`, `gloss.reflection`, `see_through.amount/reach`) and an overridden `shade`.
- Closure plumbing lives in the renderer's `shaders/lib/rikka/closure.slang` (`RikkaShade` premultiplied colour + alpha, `rikka_closure_*<M>` helpers that call the model's hooks, `rikka_closure_lit<M>(pixel, data, live, context)` = prepare + own light loop + resolve, `rikka_scatter_add`); `rikka_illuminate` in `material/model.slang` is the light loop without `prepare`. Principled subsurface/transmission weights route `Role`s and `[Feature]` bits; a subsurface closure that cannot take the screen-space pass sets `unscattered`.
- Staging (`staging.rs`: `Side`, `stage`, `Phase`) is separate from emission. Colour ramps and curves with fewer than two points ignore their input (no taint, folded to a constant).
- Heavy closures: a stage with two or more model closures (or a closure behind a live gate) shades each apart with `rikka_closure_lit`; closures of one model at one stage share one `[loop]` over arrays of their data (`lit_<id>_data/live/shade`), and the scatter hook loops the same way, so the model's code exists once per graph. Reason: spirv-opt's ssa-rewrite and redundancy-elimination are quadratic in function size, so inlining N models into one light loop cost N² time and memory (4 OpenPBR closures: 39 s / 6.5 GB per -O2 variant, OOM for the template; now ~4 s / 0.6 GB for any N). `[noinline]` helpers do not help: the forward variant stays slow and NVIDIA's driver then takes minutes per pipeline.
- Lazy evaluation (`gate.rs`, `Gating` per side): Lerp t (skip a at 1, b at 0), Multiply by a uniform weight (skip the other factor at 0), Switch, Blend opacity (bypass to base at 0, skip base at 1 for Normal), MixShader factor (skip a at ≥ 1, b at ≤ 0) and library `Gate`s. A node's guard is the intersection of its users' guards plus the gates that skip the port it feeds; only exclusively owned cones are wrapped, in every phase, across groups, nested in depth order; values leaving a block are escaped into variables declared before it (zero, or the bypass for node gates). Gates on a direct parameter or socket with test "= 0" get a `[Feature(7…30)]` bit and test `rikka_feature(bit)` (pipeline specialization: free when open, code removed when closed; toggling through 0 switches pipelines). Other uniform gates need region weight ≥ 4, per-pixel gates ≥ 64 (only closures in practice: open per-pixel and runtime gates measured slower on render-bench). Per-pixel gates never wrap derivative users (textures, `$pixel` functions, closure `prepare`): they and their inputs are hoisted. Constant-closed gates drop their region. Skipped operands are treated as finite: NaN/Inf there no longer propagate, and a skipped `x × 0` gives +0 instead of ±0. `tests/gates.rs` checks pixels at 0 against 1e-30.
- Dead closures: their data stay set (main closure albedo/normal/occlusion and screen-space subsurface data are always computed), `live` false skips the closure's light loop and resolve; Mix emission weights saturate the factor.
- Composites (`composite.rs`, `Graph::composite` → `CompositePlan { steps, output }`): `Layer` nodes and `Filter` nodes produce images; all per-pixel nodes between them fuse into generated compute passes (`Step::Pixel`: Slang source with entry `PIXEL_ENTRY`, push members `i0…` for the images it reads, `target`, `size`, `time`, a `Parameters` block of set sockets). `Sample` reads an image at any uv. Filter value sockets are one value per frame: `plan.evaluate(&Env)` returns a `Record` per filter step.
- Worlds (`world.rs`, `Graph::world` → `WorldPlan::evaluate(&Env) -> Record`): record nodes wired into the output form a tree of `Datum::{Number, Asset, Record, Records}`; numbers come from a compiled CPU `Program` (`eval.rs`) over ops, ramps, curves, noise and `Time`, reading set sockets through `Env::sockets` (so key tracks override them without recompiling). `WorldPlan::program()`/`step(path, field)` and `Program::reads(steps)`/`run_until(env, values, end)` let callers re-run just the steps feeding one record field.
- `Op::compute` is the CPU twin of every evaluable op (constant folding and drivers); keep it identical to the Slang in `shaders/lib/rikka/graph.slang`.
- `rikka-shader-compile` is the renderer bridge: `Material::compile/reload/template/values`; compile and reload return once the template's draft build exists and the optimized build follows on its own (material-system note, `TemplateReadiness`). GPU tests there render graphs (Principled vs `rikka/standard` in both builds, custom lighting, two lighting rounds, live sockets, outline, hull and subsurface uses optimized when they appear). `bazel run --config=bench //benchmarks/render:materials [-- --breakdown] [graphs]` measures draft, drawable and built times of four graphs (emission, principled, cel with outline, two lighting rounds).
- The Edit tool's Slang syntax gate rejects valid `[constref] override …` additions; rewrite such files whole.
- `Op` has 78 ops (`ops.rs` plus `ops/{range,texture,color,vector}.rs`); the shipped node families are in the shader-nodes note.
