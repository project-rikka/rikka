title: Proton API transport
description: rikka-proton-api owns Proton's HTTP envelope, hosts, sessions, refresh, retries, pinning, DoH routing and multipart.
about: crates/proton/rikka-proton-api

- The only door to Proton REST. It uses `rikka-net`, never reqwest.
- `Api` is a cheap clone from `ApiBuilder` (environment, app_version, user_agent, locale, header, session, session_store, alternative_routing, doh_providers, certificate_pinning, timeout, retries); `build()` validates every default header (`Error::InvalidHeader`). Requests: `api.get/post/put/delete/patch(path)` → `send::<T>()|send_field::<T>("Name")|send_field_at(&["Folder", "ID"])|send_field_or_default|send_bytes()|send_unit()|receive::<T>()` (value plus response headers); `send_field`/`send_field_at` read one (nested) field of the envelope, so one-field response and created-id structs are not written; `query(&[(name, value)])` takes pairs whose values are `Display`; `.multipart(Multipart::new().text(..).file(..))` builds forms. `api.http()` is for off-API transfers. `Api::with_session_store(store)` is another session sharing the same `Config` (transports, headers, routing).
- `Environment`: `production()` = `https://api.protonmail.ch/`, plus `web(name)`, `black(host)`, `custom(url)`. `with_prefix(name)` swaps `api.` for `{name}-api.proton.me` (other hosts unchanged, an invalid result is an error); product hosts never use alternative routing. Full-URL paths use the plain client, skip routing and never carry the session (no UID, bearer token or refresh).
- Shared helpers: the `identifier!` macro, the `wire_enum!` macro (integer wire enums with an `Other(i32)` fallback, optional `: default Variant`; every product crate declares its enums with it), `EventAction` and the `change!` macro for core event entries, `flag` (0/1 bools), `scopes`, `base64::{encode, decode}`, `base32::{encode, encode_with(bytes, Alphabet::{Rfc4648, Crockford})}`, `percent::{encode, decode}` (RFC 3986 unreserved, on the `percent-encoding` crate), `multipart_boundary`, `unix_seconds` (`::optional` reads an unholdable instant as `None`).
- Paging: `api.get(path).pages(Paging::numbered(size)[.starting_at(n)] | Paging::cursor(name)[.starting_from(c)][.page_size(n)] | Paging::since())` then `.collect(|answer: A| Page::new(items).total(..).next(cursor))` or `.stream(..)` (one `Vec` per page); `.field("Name")`/`.field_at(path)` hands the closure that field of each page and treats a page without it as empty. `since()` is `cursor("Since")`; cursor walks stop on an empty or repeated cursor and, with a size, on a short page.
- Envelope `{"Code":…}`: 1000, 1001 and 1002 are ok; anything else is an error even under HTTP 200. `send_bytes` skips the check. Classification lives in `envelope.rs`: 9001, 9002, 5003/5005, 403+9101/9102, 429, 401, envelope code, status.
- Envelope errors are `Error::Api(Box<ApiError>)` with `status`, `code`, `message`, `details`; `Error::status()` and `code()` answer for them. Keep wrapped errors small: product and client errors box large variants because clippy's large-`Err` lint runs in `apps/system/proton`.
- A 401 refreshes once through `auth/v4/refresh`, and concurrent 401s share it via a generation counter. A refresh answered 400/401/422 empties the store → `SessionExpired`. The refresh answer may omit `UID`.
- Proton answers both `Scope` and `Scopes`; wire types read only `Scopes` (aliasing breaks serde).
- Retries follow protoncore: connection errors, 421, 408 (once), 429 and 5xx; two attempts, 500 ms base, `Retry-After` up to 10 s; 429/503 without a hint are not retried.
- `api.warm_up()` sends an anonymous `tests/ping` so TLS and HTTP/2 are ready.
- Pinning (on by default, `https` environments only): the API client is chain-pinned with protoncore's `DEFAULT_SPKI_PINS`, alternative routes leaf-pinned with `ALTERNATIVE_API_SPKI_PINS`; `api.http()` and DoH stay unpinned.
- Alternative routing (off by default) resolves DoH TXT `[<UID>.]d<BASE32(host)>.protonpro.xyz` and pins the route for 90 min; the `Session-Id` cookie from API answers is sent to alternative routes.
- `Error::is_signed_out()` (401, expired or missing session) and `is_unreachable()` classify transport errors; every product `Error` has `api()` reaching the transport error through its own sources.
- `Outcome<Id, Body = NoBody>` is the one multi-status entry (`ID`/`LinkID`, `Index`, `Response.{Code, Error, Details}` plus a flattened `Body`): `is_ok`, `code`, `error`, `detail::<T>(name)`, `offset_by`, `succeeded(id)`, `refused(id, &Error)`; drive (`Outcome<LinkId>`), contacts (`ContactReply`), mail batches and calendar sync (`SyncedEvent`) use it. `delay::{doubling, jittered, stretched, random_unit}` are the shared retry delays (event loop, KT self-audit, drive-sync, the app's renewal, VPN agent and fallback jitter).
