---
title: Web engine (rikka-web over Gecko)
description: rikka-web drives a rikka-gecko process per Runtime over rikka-gecko-protocol; sessions draw through a nested display.
about: crates/web/rikka-web
tags: [web, architecture]
---

- `crates/web/rikka-web` is the only crate that talks to Gecko; apps depend on it directly. The engine is built from `engine/gecko/` (GeckoView on Linux; see the gecko-engine note); its wire types are the internal crate `//crates/web/rikka-gecko-protocol`, used only by rikka-web, and change together with the engine's JS and C++.
- Model mirrors GeckoView: `Runtime` (one `rikka-gecko` parent process per profile) → `Session` (one GeckoView window, id = protocol `WindowId`) with typed delegates as `Event`s. Controllers hang off the runtime: `extensions()`, `storage()`, `downloads()`.
- `Runtime::builder().profile(Profile::Persistent(dir) | Ephemeral).locales(Locales).preferences(Preferences).gpu(..).clipboard(..).start()`. Ephemeral uses a fresh temp profile (removed after exit), forces every session private and sets `browser.privatebrowsing.autostart`.
- `Preferences` are Gecko default prefs (`GeckoView:SetDefaultPrefs`, at start and on `Runtime::set_preferences`): typed presets `cookies`, `tracking_protection`, `https_only`, `proxy`, `dns_over_https`, `spellcheck` + `dictionaries`, `autoplay`, `color_scheme`, `permission_default(SitePermission, PermissionDefault)` (`permissions.default.*`), plus raw `set`. The preset enums derive serde (kebab-case) and the Copy ones implement `rikka_types::Choice`. Page languages are not a pref: `Locales::new(interface).pages(languages)` goes through `GeckoView:SetLocale`, which writes `intl.accept_languages` as a user pref and so would shadow a default.
- The program is found through `rikka_shipped` (`RIKKA_GECKO_PATH`, then `lib/rikka-gecko` of the install, then `env!("RIKKA_GECKO")`, which the crate's `BUILD.bazel` sets from `@nix//:paths.bzl`).
- `process/launch.rs` spawns `rikka-gecko --no-remote --new-instance --profile <dir>` with the socketpair end's fd in `RIKKA_GECKO_CHANNEL`, `WAYLAND_DISPLAY` = the runtime's `rikka-nested` socket, `MOZ_ENABLE_WAYLAND=1`, `GDK_BACKEND=wayland`, and `DISPLAY`/`WAYLAND_SOCKET`/activation and scale variables removed. CLOEXEC is cleared on that fd only under a process-wide spawn lock.
- `process/supervise.rs` watches the child through a pidfd on `rikka-gecko-watch`; exit becomes `RuntimeEvent::Exited(Exit)`, disconnects the link and ends every session with `Event::Closed(CloseReason::EngineExited)`. Dropping the last runtime handle never blocks: it shuts the channel (Gecko quits) and hands the nested display and the engine threads to the watch thread, which kills after 5 s, reaps, removes a scratch profile, and only then stops the display and joins `rikka-gecko-read`, `rikka-gecko-write` and `rikka-web-display`. `rikka_web::wait_for_closed_runtimes()` joins those watch threads; apps call it before exiting and before deleting a profile folder.
- `wire/`: `Link` gates messages under one mutex and queues them to `writer.rs` (`rikka-gecko-write`), so no caller blocks on the socket; `Calls` maps our `CallbackId`s to oneshots (`Asked<T>` futures); `reader.rs` (`rikka-gecko-read`) decodes `GeckoMessage`s for `RuntimeCore::handle_message`. Until `hello`, everything but the runtime's own listen and replies waits behind the runtime gate (so preferences precede every window listen/open); window-target events then wait behind that window's `ready`, in order. A `closed` window drops its queue and fails its calls with `Error::Closed`.
- Every window is `listen`ed before `open` (`session/dispatch.rs::listened`); `OnLoadRequest` only with `SessionSettings::handle_load_requests`. Default modules: Content, Navigation, ProcessHangMonitor, Progress, Settings, Tab, ContentBlocking, MediaControl, Prompter.
- Requests from Gecko hold a `wire::Answer` (exactly once; dropping sends the safe default: deny, dismiss, cancel, false, or a refusal). Events go through an `Outbox`, so untaken streams answer defaults at once. `GeckoView:AndroidPermission` is always answered true; unknown events and unknown windows are refused.
- `NewSessionRequest::open`, `NewTabRequest::open` and `OpenWindowRequest::open` send listen + open for Gecko's id before the reply (service-worker windows reply first, as GeckoView expects).
- `NewSessionRequest::popup` is `Some` when `window.open` features asked for a popup (Gecko's `nsIOpenWindowInfo.isPopupRequested`, a rikka-gecko patch); it carries the spec-tokenized `width`/`height`.
- Gecko view windows open with `titlebar=no`, which rikka-gecko's nsWindow patch turns into an undecorated GTK window, so no client-side title bar eats page height.
- `Session` commands are fire-and-forget or `async` (`find`, `evaluate`, `call`, `snapshot`, `print_to_pdf`, `has_form_data`, `user_agent`, `permit_unload`, `allow_certificate`, `download`, `edit`). `download` asks with a `DownloadRequest` (reason `Save`) and settles once answered; a chosen path joins Gecko's download list. State is `page()` (`PageState`, whose `history`, `icons` and `security` are `Arc`-shared so copies are cheap), with `Event::Changed` only when a field changed; session history comes from accumulated `StateUpdated` (`state()`/`restore()` as `SavedState`). `Session` equality and hash are by identity.
- `session/initial.rs`: GeckoView's PageStart/LocationChange/Progress/Security/PageStop about the initial `about:blank` are dropped until a start or location of another URI (or of `about:blank` after the app asked for it), so the first `PageStopped` belongs to the app's own load.
- Rikka's own window events (rikka-gecko `rikka/components`): `Rikka:View:OpenLink` (middle/Ctrl/Shift link clicks → `Event::OpenLink`), `Rikka:View:CertificateError` (stored, attached to the next `LoadError` with the same URI), `Rikka:View:ContextMenu` (richer than GeckoView's, which still maps to the same `ContextMenu`), `Rikka:View:Capture` (`PageState.capture`). Runtime-target `Rikka:Storage:*` and `Rikka:Extension:Icon` back `Storage::{clear_between, site_data, cookies}` and `Extensions::icon`.
- A session's nested view opens at `SessionSettings::size(w, h)`, else 1280×720 until a `web_view` lays it out, so unshown pages never lay out at 1×1; the page's inner size equals the view size.
- The nested display waits up to 5 s for a published `SharedGpu` before serving; without one Gecko gets no dmabuf/EGL and falls back to software WebRender (why GPU-less machine tests take ~5 s).
- Every runtime sends `general.smoothScroll.rikka.*` (enabled, the stiffness of `rikka_ui::motion::SCROLL`, `SCROLL_LINE` per notch); rikka-gecko then turns wheel notches and touchpad travel into pixel deltas that impel the same critically damped spring (no fling), and aims it for every other smooth scroll.
- `Runtime::preconnect(uri)` opens a speculative connection partitioned like the navigation it anticipates (`Rikka:Network:Preconnect`); the browser's omnibox preconnects to its default and hovered match.
- User content (`UserContent` of scripts, styles, message handlers; `World::Page`/`Isolated`) is sent whole with `Rikka:UserContent:Set`; script and style sources are `Arc<str>`, so an app registers one shared source for every session. Pages post through `window.rikka.messageHandlers.<name>.postMessage`.
- Fullscreen and activation come from the nested display's events (`rikka-web-display` thread routes by `ViewId`); the runtime acknowledges with `View::set_fullscreen` and emits `Event::Fullscreen`.
- `web_view(&session)` wraps `rikka_nested::nested_view` (app_id `rikka-view-<window id>`), adding `.on_navigation_button` (mouse 8/9), `.reserve_shortcuts(chords)`, `.pass_through(predicate)` and `.retain_focus(bool)` (set while an app popup owned by the page holds the keyboard, so the page sees no blur).
- `<select>` dropdowns: toolkit's desktop `SelectChild` stays in content and rikka-gecko's `RikkaSelectParent` sends `Rikka:View:Dropdown`, which arrives as `Event::Dropdown(Dropdown)` (`anchor` = the select's rect in view logical px, `items` of options/groups/separators with effective `disabled`, `selected` option index). `choose(index, ChosenWith::Pointer | Keyboard)` decides whether the engine's option mouse events fire; dropping or `dismiss` closes it unchanged. `Event::DropdownUpdated` carries live option changes, `Event::DropdownHidden(id)` a close by the page (blur, navigation, removal). GeckoView choice prompts (`Prompt::Choose`) do not come from selects, and listbox selects stay inline; date/time pickers come only as `Prompt::DateTime`.
- `SignInPortal::open(url, UserContent)` is the sign-in page apps embed: one private `Session` of its own ephemeral `Runtime`, `follow(NewSessionRequest)` loads popups in place, `cookies(site)` reads the session partition's cookies (HttpOnly included); Music and Discord build their portals on it.
- Tests (`tests/main.rs`) start real runtimes against a fake engine: `tests/fake` installs a `rikka-gecko` shell script (`exec sleep 60`) on `RIKKA_GECKO_PATH`, finds the child in `/proc`, and borrows its channel with `pidfd_getfd`; a headless `SharedGpu` keeps the nested display from waiting for a GPU. `tests/machine.rs` needs the real engine; it drives real input by mounting `web_view` in a `TypedUi`, with `dom.input_events.security.minNumTicks`/`minTimeElapsedInMS` set to 0 because Gecko drops input until a fresh page had three refresh ticks (1 Hz without host frames).
