---
title: Render-resolution sub-rectangles (dynamic resolution)
description: Render-res images are allocated at the max scale; passes draw a sub-rect and map uvs through GpuView or a slot.
about: crates/graphics/rikka-renderer-3d/src
tags: [renderer, antialiasing]
---

- `Targets` and every render-resolution graph image are allocated at the viewport's capacity (`TemporalState::capacity_extent`: display × the highest scale the rule allows; fixed scales and non-upscaled modes have capacity = render). `Viewport::retarget` only sets `Targets::extent` (the logical render extent) and cluster counts; nothing is reallocated and the graph signature hashes the capacity, so scale steps never recompile or reset histories.
- `FrameGraph::new(Extents { render, previous, capacity })`: relative sizes allocate against `capacity`, `graph.extent()` and `PassScope::extent` are logical (`Keep::Previous` images report last frame's render extent), `PassScope::physical_extent` is the allocation. Render passes default their area and viewport to the first attachment's logical extent.
- Texel loads bounded by logical sizes need nothing. Shaders that sample render-res images by uv use `rikka_render_uv(view, uv, divisor)` (clamps to the logical texels, returns uv unchanged when logical = capacity, so fixed scales are bit-identical) and `rikka_previous_render_uv`/`rikka_previous_size` for last frame's histories; `RikkaView.capacity` and `previous_viewport` carry the extents. Gathers divide by `view.capacity` and fall back to clamped loads where the footprint crosses the logical edge (`temporal_resolve`, screen shadows). Kernels never call `GetDimensions` on render-res images; sizes come from push constants.
- The HZB is built from the logical depth over its whole capacity extent, so it stays a normalized-screen pyramid across scales. The fog atlas is sized for the capacity grid while `fog_grid` follows the render extent.
- Effects: `rikka_effect_sample`, `rikka_effect_image_size` and `rikka_effect_layers_size` stay correct without user code changes. `assemble` passes every sampled input whose logical extent differs from its allocation through `ResourceTable::place`, a per-frame-slot ring of reserved texture slots (`core/placed_slots.rs`, slots `0..192`, mesh tables only) whose logical extents sit in the host-written buffer at table binding 4; the effect helpers read it for slots below `RIKKA_EFFECT_PLACED_SLOTS`. Display passes reading render-res images by uv (bloom from emission) push logical and physical sizes and call `rikka_placed_uv`.
- The temporal still signature ignores the render size, so a scale step in a still scene keeps accumulating.
- Tests: `tests/three/temporal.rs` `dynamic_scale_steps_allocate_nothing_and_keep_the_history` (counting allocator in `tests/allocations.rs`; screen-space and ray-traced looks vs fixed-scale renders), `tests/look/effects.rs` `render_resolution_effects_sample_the_drawn_area_while_the_scale_steps`. Bench: `three: ray traced look frame at 1080p, dynamic resolution stepping down` (steps 1 → 0.5 → 0.25, steady-allocation assert covers the second step).
