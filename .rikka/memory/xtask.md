---
title: xtask commands
description: bazel run //xtask lays out shipped components, runs the session or one app, packs and releases the distribution.
about: xtask
tags: [build, tooling]
---

- Runs as `bazel run //xtask -- <task>`. It finds the workspace through `BUILD_WORKSPACE_DIRECTORY`, resolves relative path arguments against `BUILD_WORKING_DIRECTORY` (`bazel::invoked_at`) and calls `bazel` itself. `main.rs` holds the clap `Task`/`DistTask` subcommands and dispatch.
- Layers: `host.rs` (process run/output/exec, atomic copies, writes) ← `bazel.rs` (`Profile::{Dev, Release, Dist, Installer}`, `build`, `depends_on` via `bazel query somepath`) ← `tree.rs` (`build` once for many contents, then `lay` each; `link_shared`) ← `run.rs` and `dist/` ← `release/`.
- `shipped.rs` is the model (`Contents`, `Component { id, about, offer, requires, pam, session, system }`, `Offer::{Required, Selected, Offered}`, `SHARED` trees); `components.rs` is the one table `COMPONENTS` of what ships. `base` is the session core plus the privileged programs (nixctl, boost, pam-helper) in `system`; every app is its own component; `remote`, `replay` and `sdk` are optional system components.
- `SHARED` lists trees installed beside programs and found through `rikka-shipped`: Gecko (`lib/rikka-gecko`), grammars (`lib/rikka/grammars`), icon fonts (`share/rikka/fonts`), pinned Mesa (`lib/rikka-mesa`, for components reaching rikka-gpu-drivers), each with its dev-shell variable, runtime override variable (`found_by`) and how the distribution supplies it (`Distributed::Flake` = the dist flake's own package, `Asset` = a content-addressed archive xtask packs).
- `tree::lay` copies programs, libraries (+ dev link), data, filled `.in` templates (`@BINDIR@`, `@PREFIX@`), drawn symbolic icons and the completion scripts that `//system/rikka-cli/crates/cli-completions:{bash,fish,zsh}` generate at build time. `link_shared` symlinks the dev shell's `SHARED` trees into development trees.
- There is no install task: `compositor` lays every component's session contents into `.bazel/session/<profile>` and nests it; `app <program>` runs one session program with `TAG_ENV=dev` and the `SHARED` `found_by` variables.
- `dist build <id>… --version --build --out` builds the components in one `--config=dist` invocation, lays each with prefix `@out@`, refuses any file naming `/nix/store/`, packs `<id>-<version>-<build>-x86_64-linux-<digest16>.tar.zst` (deterministic tar under `<id>/`, zstd, SRI hash) plus used `Asset` trees as `<name>-<digest16>.tar.zst`, and writes `<id>.json` fragments (`dist/release.rs`: entry with name/summary from the .desktop or `About::Text`, offer, requires, pam, portal, templates, links, revision).
- `dist publish --entries --into` merges fragments into a local clone (archives copied in, named by `file`), prunes unreferenced assets, copies the files of `nix/dist/*`, mirrors `nix/dist/templates/` and writes `flake.lock` holding this repository's nixpkgs node. `mirror.rs` (`mirror(source, destination, kept)`, `copy_changed`) is the one content-based tree sync, shared with `gecko assemble`.
- `dist windows --version --out` builds `//apps/general:windows_zip` with `Profile::Windows` (`--config=windows --config=release`) plus `--//bazel/windows:version` through `bazel::build_with` and copies it as `rikka-<version>-windows-x86_64.zip` (see the Windows distribution note). The build tools it runs live in `xtask/windows/{icon,package}`.
- `release/` publishes to `project-rikka/packages` with the caller's `gh` credentials (`github.rs`): `source.rs` refuses a dirty or unpushed checkout; `checkout.rs` clones into `.bazel/release/packages`, reads past `release.json`s and `gecko.json`s from git history and commits/pushes; `version.rs` bumps semver from `release.json`; `verify.rs` builds every new package and evaluates `checks.x86_64-linux.module` from a local copy; `store.rs` uploads to and prunes the `binaries` GitHub release (`KEPT_GENERATIONS` = 10); `gecko.rs` fetches and verifies the CI-built engine for `release gecko`. A moved nixpkgs pin adds every other published component as its next build.
- `gecko/` is `xtask gecko assemble|build|package|export-patches|follow` over `engine/gecko` (see the gecko-engine note).
- `unicode.rs`, `ffmpeg_layout.rs`, `ltc.rs`, `public_suffix.rs`, `sdk.rs` regenerate committed data (emoji/CLDR, FFmpeg layout asserts, LTC tables, public suffix list, SDK bindings); `web.rs` is their HTTP client, also used by `minecraft.rs`.
- `minecraft [--version V] [--loader V]` rewrites `minecraft/minecraft.lock.json` (see the Minecraft note), newest stable releases by default.
