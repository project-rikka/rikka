- `Desktop<P>` holds the arenas of windows, layers, popups, outputs and workspaces with stacking, placement and visibility. It is pure state: it sends nothing and never sees a Wayland display.
- `P` is the compositor's per-window policy record (window mode, floated preference, foreign handle...). It lives beside the non-generic `Window` in a `SecondaryMap`: `policy(id)`, `policy_mut(id)`, `window_and_policy_mut(id)` for both at once, `policies()`. It is created with `P::default()` in `add_window`; `remove_window` returns `(Window, P)`.
- Windows get their own `WindowId`. Windows are `WindowKind::Xdg(ToplevelId)` or `X11(XWindowId)`. `OutputId` and `XWindowId` come from rikka-compositor-types, so this crate does not depend on the Wayland server, rikka-compositor-output or rikka-compositor-xwm. X11 windows get their surface later through `associate`. Layers, popups and lock surfaces are keyed by the shell's own ids in `SecondaryMap`s.
- Resolve a surface's owner through `shell_role` then `target_for_role`, or with `window_for_toplevel` / `window_for_x11` / `window_for_surface` (root surface index kept by `add_window`, `associate`, exit and removal).
- `geometry` is the window's outer geometry in global logical space, including a compositor `Frame` (caption height, outside resize reach); `content()` is the client part. `inset` is where the client geometry sits inside the root surface, so `surface_location = geometry.loc + frame.offset() - inset`. Popups work the same way, relative to their parent's content origin. `hit_under` reports `Hit::Frame { window, local }` where a frame is hit and no surface; `element_under` is its surface-only view.
- Stacking is one global managed order plus a separate `unmanaged_stack` order for `NewWindow::unmanaged()` (override-redirect) windows, which are drawn above it. `stacked_on(workspace)` is the filtered view. `restack` never mixes the two orders. An exiting window's stack position is frozen (`restack` refuses it), and a raise to `Top` stays below exiting windows that stood above the raised one. `raise`/`lower`/`restack` return whether the order changed.
- Workspaces are numbered from 1 to `count` (`Desktop::new(count, LayoutView)`), per output. `Profile::Simple` uses a count of 1. `show_workspace` returns a `Switch` of leaving/arriving windows. Windows keep their membership, and `Visibility` (`Shown`, `OnHiddenWorkspace`, `Minimized`, `Exiting(SnapshotId)`) is kept in step with it.
- `exit_window` keeps a visible window at its stack position as a `Drawn::Snapshot`. The renderer owns what a `SnapshotId` names. A window nobody can see is removed at once.
- Output geometry, scale and transform are not the desktop's: `Desktop::new(count, LayoutView)` reads them live from the `rikka_compositor_types::Layouts` table that `rikka_compositor_output::Outputs` writes at `publish` (from `OutputInfo::layout()`) and clears at `withdraw`. The desktop keeps only each output's work area and shown workspace; `add_output(id)` needs a published layout, and `output(id)`/`outputs()` return assembled `Output` values. Tests own a `Layouts` and set it themselves.
- When an output is removed, its windows go to the same workspace number on the first remaining output. With no output left they are strays, and the next `add_output` adopts them.
- `arrange(output)` follows the standard layer-shell semantics. Exclusive surfaces (zone > 0) come first, then the rest, each pass going Overlay→Background in map order. Margins count toward the zone. A zone of -1 uses the full area. `exclusive_edge` disambiguates corners. It returns the configures to send (only on size change), surfaces to close, and whether the work area changed. Call it after any layer or output change.
- `drawn_into(trees, output, SceneLayers, &mut Vec<Drawn>)` refills a caller-owned list bottom→top: Background, Bottom, windows each followed by its popup tree, Top, Overlay. While locked, only the output's lock surface is drawn. `SceneLayers` (top / windows / backdrop) is the policy's fullscreen and overview decision. Layers are bucketed per output and level by `(LayerOrder, creation sequence)`: a `LayerOrder::Topmost` layer (given to `add_layer`) stays above every `Created` layer of its level, however late those are created; remapping never restacks. Popup origins are passed down, never recomputed.
- `drawn_window_on_wallpapers_into(window, &mut drawn)` is what a window capture shows: the Background layers (no popups) of every output the window's geometry overlaps, then the window and its popups. Bottom layers and other windows are never in it.
- `element_under` walks the drawn order top-down without allocating and stops at the first `SurfaceTrees::surface_under` hit (implemented for `Surfaces`, faked in tests); a test compares it with the reversed drawn list. `windows_drawn_on` is a lazy double-ended iterator.
- A window is drawn and hit on its workspace's output and on any output it overlaps, unless `set_confined(true)`, which keeps it to its own output (the scrolling layout's columns).
- Popup placement is `constrain_popup(id, &Positioner)` against the full output of the popup's root. The compositor stores the result with `popup_mut().set_geometry`.
