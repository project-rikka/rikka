- The compositor owns the whole session, so it works without a shell and a quick tap never waits for one: `switcher/keys.rs` handles every person-seat key in `filter` before bindings; `flow.rs` begins, steps, finishes and publishes. The selection rules are the crate `rikka-compositor-switcher`: `Choosing::begin(candidates, current, back, pressed)` (initial pick), `take(Step)`, `pick`, `lose`, `arrange(Rows)`, `modifiers_released`, `finish(choose, pressed) -> Finished { chosen, lingering }`, and `Holding` (the starting chord minus Shift; none is sticky); `Phase::Choosing(Switching)` adds the serial, output and shown flag.
- Phases: `Idle`, `Choosing`, `Lingering(holding)` (ended by Esc, Enter or a click while Alt is still held). Releasing every held non-Shift modifier of the starting chord commits; a chord without modifiers is sticky. "Held" is the union over every keyboard (`Keyboard::held_modifiers`), checked on each key release and on `SeatEvent::Modifiers` (`switch_modifiers`), so a virtual keyboard that clears its modifiers or disappears also ends the switch.
- Begin withholds the person's keyboard (seat `withhold_keyboard`); the commit is queued as `KeyAction::Switched(target)`, so the Alt release is dropped before `reveal_window` moves focus. The keyboard is restored once `Idle`: by that action, by `filter` on any press that does not begin a switch, or by `abandon_switch` (lock). A begin inside the same input batch takes a still-queued target as the current window.
- Candidates are every published, managed window on any workspace: current first, then `rikka_compositor_recency::Recency` (`windows.recency`), then stacking order. Recency promotes a focus when it leaves, except focus-follows-pointer glances shorter than `FOCUS_DWELL` (750 ms).
- Keys while choosing: the switch bindings and Tab/Shift+Tab step (wrapping), arrows, Home/End, Enter/Space commit, Esc cancels; all are consumed. Steps repeat on the compositor's own timer at the seat repeat rate. Up/Down use the rows the shell sent with `arrange`.
- `rikka.switcher` announces `Some(Switch)` only after 150 ms (`OPENING`), then on every change, and `None` at the end. A click on a window cancels the session; locking abandons it.
- Shell side (`system/rikka-shell/crates/shell-switcher`): a watch aims a `Destination` and shows an animated, keyboard-less overlay on the switch's output; `Board` lays cards out with the shell-private crate `switcher-layout` (`arrange`, `Arrangement::centres/scrolled_to/at`, tested), tells the compositor the rows, and `Panel` paints glass, a gliding ring, icon and title headers and live `WindowView`s, popped in and out by `PaintCtx::popped`. Hover selects only after the pointer moved; click chooses; a click outside dismisses.
