---
title: Shared conversations and assistants
description: rikka-thread stores and runs conversations; callers supply instructions, folding, subagents and the folder.
about: crates/ai/rikka-thread
tags: [agent, threads]
---

- Owns `Thread` → `Turn` → `Round` → `Call`, the `Store`, `Assistant` and `Desk`. `Assistant::machine()` is the toolbox's `rikka_tools::Machine`; the crate itself depends on neither `rikka-computer` nor `rikka-image` (attachments are sniffed with `rikka_tool::Picture`).
- `Assistant::builder(toolbox)` has `.instruction(..)`, `.revision_heading(heading)` (defaults to `crates/ai/rikka-thread/prompts/revised.md`), `.compaction_prompts(..)` and `.subagents(briefing, prompt, facts)`. `build` appends `Toolbox::searchable()` (the deferred-tool list) as the last standing block of both instructions and briefing, so tool descriptions never change mid-thread. An empty revising heading with instructions, or subagents without folding, refuse to build. A toolbox fitted `beside` another cannot become an assistant.
- `Thread::connect_model(&Llm)` resolves `selection_in`, takes the model from the bench and records the selection on the thread; both apps start runs through it.
- `{{model}}` is replaced per agent.
- `Desk::ask(hired, Ask::new(text).with_context(context).with_attachments(files))` adds the person's turn itself; a `&str` converts to an `Ask`. The crate-private `Conversation` builds each run for `Desk`; one private `Fitting` builds the main agent and every subagent alike, with no turn cap.
- `Ask::with_expansion(sent)` keeps what the person typed as `said` (shown, titled, copied, edited, redrafted) while the model receives `sent_text()`; both are stored (`Body::text` / `Body::sent_text`). `Ask::join(asks)` drops empty asks, returns a lone one unchanged and merges several into their sent words, so a merged draft never re-expands.
- A thread keeps its system prompt for life, since Anthropic binds thinking signatures to an unchanged `system`/`tools`/message prefix. The first turn records the instruction snapshot (`Body` `instructions`); when the assistant's instructions later differ from the last conveyed snapshot, the changed blocks go under the revising heading as hidden context on the new person or notice turn (`instructing.rs`). `revision.rs` sends a changed block as a line diff (`prompts/diffed.md`, anchored on its unique first line) against the conveyed block with the same first line when the diff is under half the block; otherwise whole, and every block whole when one was dropped.
- The transcript must replay exactly what the live run sent (the next turn's prefix must be byte-equal for provider caches): each model answer is kept verbatim as a `Replay` (`Reply::Responded`, from `rikka_agent::Event::Responded`; text blocks, thoughts and calls in their original order) on the last round it covers or on the turn's `TurnText`, thoughts only after the first instructed turn, model-only and shown pictures plus loaded-tool references inside tool results, the exact fold lead, and a round's notices joined into the tool-results message (or one user message after an answer). `tests/answering.rs` checks a reopened thread against the last live request, nested blocks included.
- The agent tool takes optional `model`/`effort`. Neither means a clone of the conversation. Effort alone keeps the model and clamps. A name looks up the bench.
- A running job refuses changes. A reported job resumes on what it is given. Refused task requests are reported beside the started ones.
- Jobs know their model (`rikka_tools::On`).
- `Store::open(folder)`: the caller chooses the folder. `named(path)` makes a folder name. ADE uses `rikka-ade/projects`, the shell `rikka-shell/assistant`.
- `Store::keep` and `discard` queue work on one writer thread per store (coalesced, fsync, flush on drop). Failures go to `Store::watch`.
- `Subagents::watch(job)` and `Subagents::get(job)` (`Subagent` = the agent's thread + arriving `Answer` + `model()` info) follow agents. A parent's stop never reaches its agents; each has only its own job token.
- `Store::crew(id)` is a thread's `Crew`, cached per store: `<id>/agents/<job>/agent.json` (label, model, effort, standing, report) plus the agent's own journal thread at `<id>/agents/<job>` (first turn instructed with its briefing, kept for life; partial answers kept on each tool result). `Assistant::keep_agents_in(crew)` restores members as `Jobs::restore_agent` entries (ids continue after them); ones still running in a previous process become `State::Closed` with a held `Jobs::remind` notice. A resume reads history from the in-memory final messages, else the crew transcript. Without a crew, transcripts stay in memory, bounded to a few MB. The writer drops writes under a discarded thread.
- `Answer` adds a `Call` only on `Reply::Started`, with its whole input, or on `Reply::Hosted(HostedPart::Call)` as a hosted call (`Call::is_hosted`, output from the matching result's `HostedOutcome` text, found in any round); text after a hosted call opens a new round. Hosted blocks ride in the `Replay` verbatim and get no tool results; the no-replay fallback drops hosted calls.
- `Replies` streams `Reply`. `Answer` folds replies into rounds for display; `open_round()` is the round still being said. A live run is saved as a provisional last turn, hidden in the producing process.
- `Desk` (`desk.rs`) is the one run driver both hosts use: it owns the thread (`Arc<Thread>`, `thread()`/`thread_mut()`), an optional `Assistant` (`equip(assistant)` returns the previous one and carries its held notices, installs files/agents history), the `Store` handle (`keep_in(store)`, `keep()`) and the private `Run`. `connect(&Llm)` resolves the model; `ask(hired, ask)`, `wake(hired)` (None unless `is_woken`) and `compact(hired, focus)` return `Replies` (a `Stream<Item = Reply>`) the host drives, feeding each reply to `apply(&reply) -> RunOutcome::{AnswerUpdated, ThreadUpdated, Finished}`; apply keeps the thread itself (turn changes, a finished call, and a delta at most once a second as `answer_partial`, reported as `ThreadUpdated`). `interject`/`queued`/`withdraw`/`recall`, `stop()` (withdraws questions, holds notices, returns unheard asks), `halt()` (also stops running agents), `open(thread)` (swap thread, reset run).
- `Desk::watch(notify)` gets `DeskEvent::{Asked(QuestionEvent), JobsMoved}` from tool threads; the host queues them onto its own loop (ADE `ProjectHandle::say`, the shell an mpsc drained on the work runtime; never lock synchronously) and hands them back to `heard(event)`, which updates the plain mirrors `questions()`, `jobs()`. `answer_question`, `interrupt_job`. `is_answering`, `is_woken`, `is_occupied` (answering, outstanding pledges, waking notices). `Run` and `Conversation` are crate-private. Tests drive `Desk` only: `tests/{answering,steering}.rs` with `support::Watched` (`drive` runs replies to the end, `respond` reacts to desk events).
- Mid-run messages: `Desk::interject(ask)` queues a `QueuedAsk` (refused unless answering and not cancelled), led by the assistant's `.interjection_lead(lead)` text. `Reply::Interjected { id, at }` settles the answer so far as a Model turn and adds a `Speaker::User` turn stamped `at`, so replay equals what was sent. `withdraw(id)` / `recall()` hand back undelivered asks; after `Ended` the unheard ones stay in `queued()` until recalled.
- `Thread::rewind(stamp)` drops that turn and all after it (refused while running), clears the title when no person turn is left and zeroes `filled`; the store rewrites the journal.
- File checkpoints: `Store::history(id)` is the thread's shared `rikka_file_edit::History` (`<id>/checkpoints/`); `Assistant::keep_files_in(history, &thread)` marks the thread's last asked turn and makes Edit/Write (subagents included) record before-images through `Files::with_history`; every asked or interjected turn then marks its `at`, so `history.rewind(turn.at())` puts files back as they were when that turn was sent. Files that fail to restore keep their copies.
- `Desk::wake` takes the mailbox's notices, starts on them and adds the notice turn, putting them back if the run cannot be built.
- `Thread::selection_in(&Llm)` / `Summary::selection_in` resolve a conversation's model: its own selection, else the model that spoke last (`Llm::restore_selection`), else the default.
- `Desk::compact(hired, focus)` runs only a fold; its `Reply::Compacted` is stored with `Thread::compact`. Every run seeds the gauge with `Thread::context_tokens`, restates `Jobs::summary` after folds, and `Answer::is_compacting` marks a fold in progress. `is_near_context_limit(filled, &ModelInfo)` drives gauges.
- On disk (`store/`: `writer` thread, `journal` lines, `format` of lines and blobs, `name`): `meta.json` headline, append-only `turns.jsonl` (rewritten only when stale lines dominate), `blobs/<sha256>` (3 MiB per attachment).
- Pictures a tool returned (`Reply::image` as `Call` pictured, `Reply::shown` as `Call::shown()`) are stored in `blobs/` via the turn line's `pictured` and `shown` lists keyed by call id; `Call` keeps `loaded` tool names.
- A `Turn` is a private shape (`spoke()`, `round_summaries()`) plus a lazily read `Body` kept in a byte budget. Calls hold input and output by handle.
- `SideEffect` is either the `FileChange` a file tool made or an `Output` log (`OutputLog`). `OutputLog::read(most)` keeps the end.
- `Thread::transcript` (`replaying.rs`) sends each `Replay` as one assistant message with the tool results of its calls, drops calls that never finished, and falls back to text and calls for rounds with no `Replay` (old threads, answers cut off mid-stream). An answer carried on past the output limit joins its `Replay` to the round it continues. `Thread::say(ask)` adds a person's turn without a model; an `Ask`'s `amid` context is stored on the turn (`Body::context`) and the transcript puts it before the words.
