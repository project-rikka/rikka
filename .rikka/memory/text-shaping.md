- The Rikka layer over `crates/text` (rikka-text-layout, rikka-text-catalog, rikka-text-raster) plus `rikka-svg` for SVG glyphs; no GPU API. The renderer and `rikka-ui` use it directly; apps depend on it directly.
- No font system is passed anywhere: fonts come from the process-wide `rikka_text_catalog::catalog()` and shaping is thread-safe.
- Vocabulary is re-exported from rikka-text-layout: `Family` (`Family::parse`, `Named`, generics), `Weight` (f32, `SEMI_BOLD`), `FontStyle`, `Wrap`, `Align`, `Affinity`, `Caret`, `Glyph`, `Decoration`, and the word boundary helpers with their `TextSource` trait.
- `Text` is an `Arc<str>` with its hash taken once; equality is pointer, then hash, then content.
- `TextSpec` (owned, `layout(width)`) and `TextShape` (borrowed) describe text: family, size, line height, wrap, align, tab width, `ellipsize` and `TextSpan` runs.
- Letter spacing (`TextSpec::letter_spacing(px)`, read back as `TextLayout::letter_spacing`) exists only on `TextSpec`: `TextShape` stays a plain struct literal that rikka-ui builds, so `layout`/`layout_approx`/`recent_layout` and `as_shape()` lay out unspaced. The spacing is part of the layout cache key (`LayoutRequest`), never of shaping.
- Text is cut into paragraphs at `\n`, `\r\n` and `\r`. Each paragraph is a rikka-text-layout `ShapedParagraph` shaped once through a process-wide line shelf, so unchanged lines of a multi-line text are never reshaped. `shaped(shape)` gives the whole `Arc<Shaped>`; colour never enters its key.
- `layout(shape, width)` gives an `Arc<TextLayout>` of one `ParagraphLayout` per paragraph. A layout at width w also serves any width between its widest row and w when it is left-aligned, LTR and not elided. `layout_approx` also reuses a layout within 1 px.
- Ellipsis comes from rikka-text-layout, asked only when a `Wrap::None` line overflows its width by more than the 1 px `SLACK`.
- `TextLayout` speaks whole-text byte offsets and `Cursor { line, index, affinity }` (paragraph and byte within it): `rows()`/`rows_between(top, bottom)` give `LayoutRow`s, plus `hit`, `caret`, `cursor_of`/`offset_of`, `selection_rects(range)` (a `Vec` of bands with their row index), `paragraph(line)` (the line's `ParagraphLayout`, for caret movement), `row_count`, `widest`, `size`, `visible_text`, `is_elided`.
- `LayoutRow` holds layout-wide `top`/`baseline`, `text_range`, `glyphs`, `decorations` (`line_start` + `start` for ink) and `placed(origin, scale)`, which yields `PlacedGlyph { key, x, y, offset }`.
- `TextPaint { layout, inks, scale, color_scheme }` (`TextPaint::new(layout).with_spans(spans).with_color_scheme(scheme)`) is what a renderer text node draws; rikka-ui's painter sets the scheme from its theme, and the renderer's glyph routing keys colour glyphs on it (`GlyphKey::with_color_scheme`), so a theme switch re-rasters only colour glyphs; `Inks` (`Inks::from_spans`) holds whole-text byte offsets and `paint.ink(placed.offset)` colours a glyph.
- `GlyphKey::place` snaps x to four subpixel bins and the baseline to whole pixels; the key carries face, glyph, size, location, colour, `Synthesis` and the `ColorScheme` (re-exported from rikka-svg; Light from `place`). `key.request()` (and `curve_key.request(ppem)`) build the rikka-text-raster `GlyphRequest`. `curve_key()` is the size-free key for GPU curves; `resized(size)` re-keys a glyph at another raster size, keeping its curve key and subpixel bin.
- `GlyphRaster` (one per thread) rasters `GlyphKey` and `IconKey` into `GlyphImage` (A8 mask, or premultiplied RGBA8 colour, baseline-origin placement) and encodes `curves(CurveKey, &mut CurveBlob)`. Non-colour outline glyphs go through a per-`GlyphRaster` rikka-text-raster `OutlineCache` keyed by face, location and glyph. Icon fonts are opened by file through `rikka_shipped::Shipped` (`RIKKA_ICON_FONT_PATH`, `share/rikka/fonts`, the built `RIKKA_ICON_FONTS`), not through the catalog. SVG colour glyphs render their node from a per-`GlyphRaster` LRU of eight parsed documents keyed by face, document record and colour scheme, parsed in that scheme so `prefers-color-scheme` rules apply. Icons set FILL/wght/GRAD clamped to the font's axes and opsz from `IconSpec::optical_size` (logical size; `scaled(scale)` keeps it), unhinted.
- An icon image is placed relative to the bottom-left corner of its `size`-square design box: the glyph's advance is centred horizontally and `IconFont::middle` (em) vertically, with fractional offsets baked in by subpixel rastering. The renderer only snaps that corner, so icons are exactly centred in pixel-aligned boxes.
- `GlyphRaster::outline(&Glyph, origin, scale, &mut impl GlyphPath)` (`GlyphPath` is `rikka_text_font::OutlineSink` re-exported) traces the same cached prepared outline as vector commands in y-down px, pen at `origin + glyph.x/y * scale` unquantized (origin.1 is the row baseline), with location and synthesis applied exactly as rastered; every contour ends in `close()`. It returns false for colour glyphs and fonts without outlines (draw `raster` instead). rikka-text-raster's own entry points return `rikka_text_raster::Result`.
- `LruCache` (`get`/`insert` with a byte cost) is the byte-budgeted LRU behind the shaped, line and layout caches; the layout cache keeps up to six widths per key and merges widths laid out concurrently.
- In front of the sharded layout cache sits a per-thread four-way set-associative front cache (`front.rs`, 2048 cache-line sets keyed by layout key and width, small layouts only, hits move to the front of their set) that answers repeated lookups without the shard mutex; `recent_layout` asks only it and never lays out; `layout` falls back to the shard. `Inks` holds `None` when no span is coloured, so cloning a plain `TextPaint` touches one refcount. `TextLayout` keeps a single paragraph and its line starts inline (and `ParagraphLayout` a single row), so short labels live in one allocation; its fields sit on their own cache line apart from the `Arc` counts. `TextLayout::rows`/`rows_between` iterate through the hand-written `rows::Rows`.
- Shaping reuse is observable as identity: layouts of one text at different widths share one `Arc<Shaped>` (`TextLayout::shaped`).
- Family constants: `INTER`, `JETBRAINS_MONO`, Noto CJK/emoji. Icon fonts are not catalog families: `IconFont::file()` names a shipped file (see the icon fonts note). Locale and CJK fallback come from rikka-text-catalog.
