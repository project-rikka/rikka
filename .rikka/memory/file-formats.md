- Development rule: every Rikka-owned format is version 1 and stays 1. When a format changes, edit the v1 layout in place; write no migration, no version bump, no `serde(default)`/`alias` kept only so older files load, and no tests for old files. Old files just fail to load. Caches treat an unreadable entry as missing and rebuild. External specs (PMX, glTF, Wayland, Proton, SQLite pragmas of others…) keep their own versions.
- `rikka-file-format` (public, foundation) is the one place that knows format identity and the version number 1.
- `JsonFormat::new("rikka-…")` is for documents: atomic `save`/`load` (domain types expose only these), plus `encode`/`decode` for callers writing their own way such as the keyring, (through `rikka_file_edit::replace`) of any serde `content` inside `{"format", "version": 1, "content"}`. The envelope denies unknown fields and the output is pretty JSON plus a newline. When decoding fails, the header is checked first, so callers get `DecodeError::Foreign`/`Version` before `Error::Json`. Users: `.rcut` (rikka-cut), `.rmotion` (rikka-motion, content internally tagged by `kind`: figure/camera/look/fluid/wind; `look` holds the node-graph look document), `.rcloth` (rikka-cloth) and keyring vaults (rikka-keyring, written `Replace::private()`).
- `BinaryFormat::new(name, *b"8BYTEMAG")` is for binary data: a 12-byte header (magic + u32 LE version) through `header`/`write_header`/`read_header`, and `encode`/`decode` of one `Codec` value (no trailing bytes allowed). Users: physics recording `PHYSREC\0`, font index `RKFONTIX` (plus its own checksum footer), waveform cache `RKPEAKS\0`, package catalog `RKNIXPKG` (header, u64 index length, index, zstd blocks), mail search index `RKMAILIX` (the header is the AEAD associated data), sealed Qobuz stream `RKQOBUZS` (header only).
- `Codec` (`type Error: From<DecodeError>`) over `Writer`/`Reader` is the workspace's little-endian binary codec. It covers the numbers, bool, `Option`, `Vec` (u64 count), pairs and glam `Vec3`/`Quat`/`Mat3`. `count32`/`count64(least_bytes)` reject counts larger than the input, `bytes`/`str` use a u32 length, `array`, `finish`. Physics-math implements it for `Transform`/`Aabb`, and physics-core's `id!` reaches it through `$crate::__file_format`.
- Documents stay JSON on purpose: their types are serde derives that use `skip_serializing_if`, `untagged` and internal tags, which non-self-describing binary serde formats break. Codec is for small fixed type sets that need determinism.
- Errors: `DecodeError::{Foreign, Version, Malformed}` (Copy) and `Error::{Read, Write, Encode, Json, Decode}`, whose messages include their cause. Domain crates wrap it as `File(#[from] rikka_file_format::Error)`.
- SQLite stores keep `PRAGMA user_version = 1`: 0 creates the single schema, any other value is `UnknownSchema` (drive-sync-state) or a reset (caches: proton-cache, music-library). browser-store has no version: it converges the file to its declared objects at every open.
