- The framework is window-system independent. xdg toplevels (`rikka-app`) and layer surfaces (`rikka-shell`) embed the same `Ui` + `rikka_ui_host::Embedder<K, S, W>` (`S` is the host's per-surface state in `Hosted<S, W>`, `W` its presenter). The embedder, image cache and offscreen store live in `rikka-ui-host`, the video store in `rikka-ui-video`; the hand-off handles, `Pulse`, `RefreshRate` and `SharedGpu` in `rikka-picture` (ui-crate-layering note).
- `Ui` is not generic: `Ui::new(state, view, theme)` erases state, view and theme behind an internal `Content`. `TypedUi<S>` (derefs to `Ui`) adds `state()`, `update()` and `themed()` for tests and hosts that read state. Outside updates go through `Ui::receive(RuntimeMessage)` / `Ui::send(Update)`. `Ui::wakes_with(Waking)` registers the callback fired when a fetch lands, an image arrives or a `NodeHandle` is marked; headless hosts and tests wait on it (`Embedder::wakes_with` uses the same registry).
- One render entry: `ui.render(&mut scene)` or `ui.render(Rendering::new(&mut scene).at(now).resolving(&mut resources))`. `Ui::set_measured(true)` makes the root hug its content (`content_size`); otherwise it fills its height.
- Each `Embedder::frame` runs tasks, then resources, then finished 3D work, then render. Resources commit through the renderer's `Uploads` and never take the renderer lock.
- Each surface has a paint thread that owns a mirror scene and a `Preparer`. The UI thread sends `SceneFrame`s as it builds them; the paint thread applies every waiting frame, prepares once, and records only when told to present. A surface without a free presentation buffer waits on its own thread; only drawable surfaces build or present, and the commit stays on the calling thread.
- Pacing: a surface presents at most once per frame callback, always the newest state. Between callbacks it may build one frame ahead, unless it is animating. A present that changed nothing commits nothing and gets no callback, so the embedder holds that surface for one `RefreshRate` period (`unshown`); motion that draws nothing visible is paced, never spun.
- Frame time: the embedder renders with `Rendering::with_time(now).shown_at(predicted)`, where each surface's `rikka_animation::FrameClock` predicts the presentation from `Hosted::presented(at, refresh)` (wp_presentation). With a fixed refresh every frame lands on that vblank grid; otherwise it predicts one refresh after the last shown frame. `PaintCtx::now()` is that shown time; a motion leaving rest advances from when the frame began, so the first frame after input already moves. `Rendering::at` alone keeps both times equal (tests).
- A frame built ahead (`FrameClock::ahead`) is only pending: it becomes the last shown frame once presented as built (`commit_ahead`), and a re-render at the callback supersedes it. Counting superseded frames as shown pushes `PaintCtx::now()` ahead of real time, and every motion leaving rest then snaps to its end.
- Idle prefetch: once a surface's frame is committed, `Embedder::frame` spends up to half a refresh period on `Ui::prefetch(scene, until)` for widgets that called `PaintCtx::request_prefetch()`; they rebuild with `rikka_ui::prefetch_deadline()` set and run build and layout, never paint.
- `Embedder` and `Hosted` take any `rikka_renderer::Present` destination (the shell and rikka-app use `rikka_present::Presenter`); `Hosted::adjust` hands the host that type. `TRIM_AFTER` after a surface's last shown frame the embedder calls its `trim()`.
- Host signals: `Hosted::drawable(..)`, `frame_answered()`, `seals_with` (runs when a built frame is handed over for presenting), `presents_with` (runs only for committed frames), `adjust`. Per-frame extras (glass, fitting, window views) go in the `Drawing` closure; extras that must match the committed frame are captured in `seals_with` and declared in `presents_with`.
- `PaintCtx::draw_window(WindowView)` asks the host to show another client's window (placed and clipped like glass, faded by `with_opacity`, collected as `Ui::windows()`); the shell turns them into `rikka_window_view_v1` views. `Ui::set_window_identifier` makes `rikka_ui::window_identifier()` answer inside every handler, build and job of that `Ui`; rikka-app fills it from xdg-foreign, layer-surface hosts leave it `None`.
- Hosts publish window views and glass only with a presented frame, and an undamaged scene presents nothing; so `UiTree::collect_hosted` damages the scene at every window view or glass pane that changed since the last sync, and a frame that only moves them is still drawn and committed.
- Offscreen pictures: `rikka_ui::Offscreen::new(|| impl OffscreenRender)` is drawn by `OffscreenRender::render(&mut Renderer, width, height) -> Option<TextureId>` on the `rikka-ui-viewports` thread; a widget asks for a size with `drawn_at(bounds, width, height)`. rikka-ui names no 3D type: `rikka-viewport` (`Viewport3d`, `SceneCtx`, `viewport(&handle)`) builds on it, outside the rikka-app prelude.
- That one viewport thread owns 3D scene building, upload, recording and picking, started with the first viewport. A pass is asked only while some drawable surface is neither awaiting a callback nor painting, so animated scenes draw once per presented frame and hidden windows none. `Viewport3d::set_scene` answering `None` keeps the texture, except that the store redraws while a temporal viewport `is_converging`.
- Image cache: on-screen sources are always kept. Off screen, an entry only the cache can draw again is let go at once; decoded pictures are kept up to `ImageCache::keeping` bytes (default 64 MiB), oldest first; feeds and computed pictures stay while their producer holds them. Uploads per frame are byte-bounded.
- `Sprite::placeholder(source)`: the image node shows the placeholder's texture until its own source resolves, then swaps in place (no double blending). rikka-ui's `Images` holds both keys per primitive, so the placeholder counts as shown and stays cached.
- Vector sources rasterize with the colour scheme of the `Ui` being drawn (`Resources::follow_theme`). Keys stay scheme-free: an entry whose SVG follows the scheme restarts its load when drawn under another scheme, showing the old texture until the new one is uploaded.
- `ImageSource::Imported` shows another process's buffer; in-memory pictures are keyed by their `Arc` buffer. An `ImportedFrame` may carry a `Lease` (released through `Reclaimer::keep` once the GPU no longer reads it) and a `Pulse`. An `Arrival` carries `damage`; the cache logs it per arrival (`DamageLog`) and `TextureResolver::changes(source, seen)` answers a `Repaint`, so `refresh_images` repaints only changed rects (`NodeEdit::repaint_image_within`).
- `Pulse` is a producer's presentation clock: `PaintCtx::pulse(&pulse)` (or an arrival's pulse via `ResourceFrame::pulsed`) ties it to the frame being built; the embedder beats it with a `Tick { at, period }` when that frame is answered. Nested displays use it as their vblank.
- Giving an `ImportedBuffer`, `Feed` or `ComputedImage` a frame wakes every embedder. `ImageSource::Computed` shows a `ComputedFrame` (GPU compute parts copied into a mip-mapped texture); a shown `ComputedImage` swaps only once the new frame's GPU work finished (`ComputedFrame::on_ready`), and `ComputedImage::on_uploaded` fires once it is copied; `Embedder::shutdown` waits for that work.
- `SharedGpu` publishes the embedder renderer's DRM nodes and sampleable dmabuf formats for producers such as rikka-web (`SharedGpu::from_gpu(gpu).publish()`, Linux only) and its `Compute` (`publish_compute`, every platform). `RefreshRate::publish`/`published` is the process-wide display rate; rikka-app publishes its fastest monitor.
- Imported buffers are dmabufs: on Windows `ImportedPlane` is uninhabited, so an `ImageSource::Imported` never receives a frame and the cache's import is unreachable.
- `Feed` carries RGBA (`show`) or decoded video frames (`show_video(w, h, ExternalVideoFrame)`, decoded on the embedder's own device: `wait_for_device` returns `FeedDevice::{Video(handles), NoVideo}` once the cache attaches it on first draw); the newest frame wins.
