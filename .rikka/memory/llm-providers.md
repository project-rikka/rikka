title: LLM providers: adapter kit, adapter crates and registry
description: rikka-llm-adapter is the provider kit, crates/ai/providers holds one adapter crate each, rikka-llm-providers lists them.

- Layers: `rikka-llm` → `rikka-llm-catalog` (models.dev) → `rikka-llm-adapter` (kit) → `crates/ai/providers/rikka-llm-<id>` (one crate per provider) → `rikka-llm-providers` (registry) → `rikka-llm-accounts`. None has settings or desktop dependencies.
- Adding a provider = the crate (its own `BUILD.bazel`), one `deps` line in `crates/ai/rikka-llm-providers/BUILD.bazel`, one line in `ALL` in `src/adapters.rs`.
- An adapter is a unit struct `<Name>Adapter` implementing `Adapter`: `type Tokens` (`NoTokens` when reached by key), `const SERVICE: Service<Tokens> { id, label, sign_in: SignInMethod }`, `connect(&Auth<Tokens>, &ModelInfo)` (the listed facts of the model; unknown ids arrive as `ModelInfo::new(id, id, 0, 0)`), and optional `listing(&Auth) -> Option<Result<Listing>>` (the account's models), `catalogue -> Option<Models>` (one public list to pick from; only OpenRouter), `who`, `meter -> Option<Result<Meter>>` (`None` = unmetered).
- No model list is kept in the source tree. Every adapter but OpenRouter lists: `Listing::new(Lookup, future of Vec<ListedModel>)`, the future reading the official API with a `rikka_llm::wire::listing::{anthropic, openai, codex, cloud_code}::models` decoder (`ListedModel` = id plus optional name, limits, vision, efforts, `ThinkingOff`, release day, deprecated). The kit joins it with `rikka_llm_catalog::Catalog::current()` and `lineup(listed, catalog, lookup)` into `ModelInfo`s; `Lookup::Exact(provider)` or `Lookup::Prefix(providers)` (longest dash-segment prefix of at least two, for Antigravity's `-high`/`-xhigh` variants) names the models.dev provider.
- Sources: Anthropic and Claude Code `GET /v1/models` (paged; capabilities give effort levels, `thinking.types` disabled/between_tools → `Off` + `ThinkingOff`, image input, limits, lifecycle; works with the OAuth token); OpenAI `/v1/models` (id, `created`, `shutdown_date`); Codex `backend-api/codex/models?client_version=` (`visibility == list`, priority order, `upgrade` = deprecated); Antigravity `fetchAvailableModels`, keeping the `agentModelSorts` lineup (else named, non-`isInternal` models). Antigravity sells each reasoning level as its own id `<base>-<level>` (entries with `thinkingLevel`), so the decoder folds them into one model `<base>` whose efforts are the levels present (others get no efforts), and `CloudCode::listed(&ModelInfo)` sends `<base>-<level>` for the request's effort (nearest at or below it, Medium when unset). models.dev keys: anthropic, openai, and google/anthropic/openai by prefix.
- `SignInMethod::{Key, Browser(fn), Code(fn), KeyOrBrowser}` holds the login starter itself, so the declared kind and the prompt cannot disagree: a `fn login() -> BrowserLogin<T>` returns `BrowserLogin::start(async { Ok((url, finish)) })`, a `DeviceCodeLogin<T>` `DeviceCodeLogin::start(async { Ok((url, code, finish)) })`; `finish` yields tokens or `Grant::Key`.
- PKCE loopback sign-ins (Codex, Claude Code, Antigravity) are `BrowserLogin::loopback(client, Loopback, AUTHORIZE, |request| …, |authorized: Authorized| async { … })`: the kit binds the redirect, builds the authorization and waits for the callback; the adapter only shapes the request and redeems `Authorized { client, authorization, callback }`.
- `DynAdapter` is the object-safe erasure (`id`, `label`, `sign_in() -> SignIn`, …) with a blanket impl over every `Adapter`; the registry holds `&'static dyn DynAdapter` and passes an `Access` (key, tokens JSON, the account's `SharedTokens`). `Backend::is_metered` asks `meter` with an empty `Access`.
- `Auth` gives `key()`, `tokens()` and, for OAuth tokens implementing the kit's `Credentials` (headers) plus `rikka_oauth::Refresh`, `transport(endpoint, headers)`: the transport signed from the account's `SharedTokens`.
- Renewal is one authority per account: every transport of a backend shares one `SharedTokens` (held tokens JSON + a `TokenStore`). A stale transport takes the in-process renewal lock, then the store's cross-process file lock, re-reads what is stored (another process may have renewed) and only then refreshes and saves. The registry's `Renewal::new(impl CredentialStore)` builds one `SharedTokens` per backend; `Renewal::hold(backend, credential)` sets what is held; `Renewal::none()` gives each transport a private one. Adapter errors are `Keyless`, `SignedOut`, `Refused`; the registry adds the `Backend` and `Unmetered`.
- OAuth credentials (Codex, Antigravity, Claude Code) hold an `rikka_oauth::Token` (flattened) and renew with `.fill_missing_from(&self.token)`. Codex and Antigravity derive email, plan and Codex's `chatgpt-account-id` from `token.identity()`, storing no identity; Claude Code gets no id_token, so it stores account/organization from the token body and profile.
- `rikka-llm-catalog`: `Catalog::parse` reads the models.dev `api.json` (malformed entries skipped); `Catalog::current()` keeps it an hour in memory and in `$XDG_CACHE_HOME/rikka/llm/models.dev.{json,etag}`, revalidates with `If-None-Match`, and falls back to the kept copy (retry 15 min) when offline; with nothing kept the listing fails. `lineup`: listed facts win over catalog ones; with an entry the model must call tools and answer only text, without one it must report its context; output may stay 0 (unknown); price comes from the catalog. A model is `superseded` (stored, hidden from pickers) when deprecated, older than the newest of its line, or its line's newest is 183+ days older than its vendor's newest; the line is the catalog (else listed) name without parentheses and digit-bearing words, per models.dev provider. Current models come first, newest release first.
- Antigravity's `hub.rs` reads the Hub release from the auto-updater manifest (6 h, retry 15 min, fallback 2.29.0 with its `cl=`); the User-Agent `antigravity/hub/<v> (aidev_client; os_type=darwin; arch=arm64[; cl=…])` is added per request by `AntigravityCredentials::headers`. Generation, listing, `loadCodeAssist` and `onboardUser` use the daily endpoint.
- Meters: Claude Code reads `/api/oauth/usage`, Codex its `rate_limit` windows, Antigravity posts `{project}` to the daily `retrieveUserQuotaSummary` (the app's Model Quota view, the only source: no model-endpoint fallback). Its `allowance.rs` turns each group (`displayName` as `Scope::Part`, kept verbatim) and bucket (`remainingFraction`, cadence from `window`, else `bucketId`/`displayName`: 5h/session → Session, weekly → Weekly, other → `"<group> · <bucket>"` Unnamed) into windows; disabled or unmeasured buckets are dropped.
- Key-reached clients are `Keyed<A: Api>`: `pub type OpenAi = Keyed<OpenAiApi>` (also `Anthropic`, `OpenRouter`) shares `new/from_env/model/endpoint/header/build`; the `Api` holds `VARIABLE`, `ENDPOINT`, the provider's extras (`.with(|api| api.organization(..))`) and `connect(KeyedConnection)`.
- `providers/rikka-llm-compatible` is not an `Adapter` (its accounts are many and configured by the person): `Endpoint::new(base)` normalizes the base URL (host-only → `/v1`, a pasted `/chat/completions`, `/responses` or `/models` and the query are cut, credentials in the URL are refused), `with_wire(Wire::{Completions, Responses})`, `connect(&EndpointCredentials, model)` (Completions sends `max_tokens`), `models()` → `Listing::{Models(Vec<Offered>), Unlisted}` (404/405/501 on `/models` = unlisted) and `check(credentials, model)` → `Checkup` (listing plus an answered ping). `EndpointCredentials { key, headers: Vec<Header> }` signs with `Bearer` only when a key is set; extra headers are sent as sensitive values after it, so they override it. `Offered` keeps what the server reported as `Option`s (context from `context_length`, `context_window`, `max_model_len`, `max_context_length`, `meta.n_ctx*`, …; tools, vision, reasoning from `supported_parameters`, capability lists or flags) and `model_info()` fills defaults; embedding models are dropped. When the base ends in `/v1` and `GET <root>/api/version` answers a version, the server is Ollama (`ollama.rs`) and every listed model is filled from `POST <root>/api/show`: context from `parameters` `num_ctx`, else `model_info.<general.architecture>.context_length`; tools, vision and reasoning from `capabilities` (`tools`, `vision`, `thinking`). Settings pre-fills the capability editor from it; what the person saves wins.
- The registry re-exports the compatible types with the three keyed builders.
- `Backend` is an index into `ALL` and serializes as its id; an unknown id fails to read. API: `all`, `from_id`, `label`, `sign_in`, `is_listed`, `listed(credential, renewal)`, `holds`, `key`, `connect(credential, &ModelInfo, renewal)`, `meter`, `login`, `offered`.
- `Credential` is opaque: `{"kind":"key","key":…}` or `{"kind":<id>,"tokens":{…}}`. Tokens that don't deserialize as the adapter's `Tokens` fail at read time.
- Provider crates carry no tests of their own; `rikka-llm/tests/listing.rs` checks the listing decoders against routed servers, `rikka-llm-catalog/tests` the lineup rules, and `rikka-llm-providers/tests` builders, credential round trips and refusals, that listing needs a signed-in account, and (`compatible.rs`) the endpoint client against routed fake servers: streaming, tool-call deltas, inline thoughts, error shapes, `/models` shapes of Ollama, llama.cpp, vLLM, LM Studio, gateways and Mistral, and a server without `/models`. Fetching models.dev itself is untested.
- `claude-code` mirrors one pinned Claude Code release (UA, betas, usage windows; now 2.1.322, still API version 2023-06-01); `codex` pins Codex 0.169.0 in one `release!()` macro (UA and `client_version`). The keyed `anthropic` client sends API version 2026-10-21 and `Authorization: Bearer`. Both are `threaded()` and pass the listed model to `Messages::listed(&ModelInfo)` (output ceiling and thinking-off kind for the configured model).
