- Pipeline: read (`rikka_mmd::Vmd::read(bytes, &ImportOptions)` gives the same canonical `Vmd` as `Import` without baking a model; `Import` still works) → `Take::from_vmd`/`from_clip` (source poses per frame, then key reduction) → `TakePlayback::bind` → `MotionBake`.
- Every parallel step goes through `crate::PARALLEL` (`rikka-parallel`, thread "rikka-motion") and computes each element with the same sequential arithmetic, so results never depend on thread count: per-frame source poses (one `Instance` per chunk; a frame never depends on the previous one), fk and pose samples, one `reduce` per `Part`, settle (pins + stand), locals, jiggle surroundings.
- `reduce`'s spare sweep never removes keys from the middle of the `Vec`: it rotates the candidate behind the last two kept keys (`CURVE_BEHIND`, all a curve segment reads behind it) and compacts once; `Seeds` buckets keyed frames by a per-node part bitmask.
- `MotionBake::new` returns after evaluating the first piece (4 chunks + fit reach) and bakes the rest on a detached "rikka-bake" thread (`motion_bake/finisher.rs`); chunks are `OnceLock` slots, the thread stops once only it holds the remaining slots, and a panic there marks the slots failed. Bakes are bit-identical to one pass because fit windows are absolute-aligned and pieces get `Physique::REACH` context.
- Reads never block: `write` returns `Written::{Baked, Estimated}` and `pose_at` returns a pose by value; an unbaked frame is estimated from the motion (`sample` + `PoseSample::reached`, no springs, intensity, fit or jiggle). `baked_pose_at`/`is_baked`/`is_complete` answer what exists, `watch(listener)` fires after the next piece lands (or at once when complete), and only `wait()` blocks.
- Stage wiring: `Actor` remembers an estimated perform; `Render::compose` calls `Dressing::await_bake`, which marks the frame unsettled when estimated (captures and the recorder retry until settled) and watches the bake with the wake's rouse, so `on_stage_notified` repaints and the next build re-poses estimated actors. `Recorder::open` (export thread) and `LiquidScene::pose` (liquid bake thread) call `CastMember::wait_for_bake` and use final frames only. Motion paths draw the baked prefix of their window and grow on each repaint.
- Only neutral-intensity motions evaluate progressively: `Intensity::shape` uses running box sums whose rounding depends on where the range starts, so a non-neutral motion evaluates the whole span before the thread starts (its fit still runs in the background).
- `rebaked` takes the partial path only when the chunks it reads (before context, the checkpoint chunk, after context) are already baked; otherwise it starts a fresh background bake instead of waiting.
- Previews: `Retarget::{from_vmd, from_clip, from_take}(Recipient { model, body, faces }, ..)` samples one frame on demand with no key reduction or bake: `pose_at(frame, eye)` (source rig → muscle pose → ground; a take is sampled and reached) and `write(seconds, eye, &mut Instance)` (details, IK switches, human locals, leg IK released, morphs; the caller refreshes). No springs, foot pins, fitting or jiggle, so it drifts slightly from the playback; about 0.1 ms per frame.
- Fitting at bake time (`animate-fit` `scene.rs`, `mover.rs`, `shell.rs`): a `Scene` caches each obstacle's holder (position, inverse rotation), probe points are computed once per probe, mask bits iterate by trailing zeros, solver scenes refresh only the moved limb's subtree (`Body::fk_below`), and a shell spot computes its `atan2` sector only within the shell. All bit-identical; `Shell::distance` with its `atan2` is the largest remaining cost.
