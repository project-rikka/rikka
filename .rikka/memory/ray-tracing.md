- Opt-in: `GpuBuilder::ray_tracing()` (implies `with_3d`) enables VK_KHR_acceleration_structure + ray_query + deferred_host_operations only when the device has them (`core/ray_support.rs`, `RenderDevice::ray_tracing()`); `Gpu::traces_rays()` reports it. Mesh positions, index arenas and the deform position buffer then carry `ACCELERATION_STRUCTURE_BUILD_INPUT_READ_ONLY` (`pool::traced_input`).
- `Look` picks a `Tier { Off, ScreenSpace, RayTraced, Auto }` per effect: `shadows` (ScreenSpace = shadow maps, Off clears every light's shadow), `occlusion` (GTAO), `reflections` (SSR), `illumination` (SSGI; new `Illumination { strength, reach, samples }`), plus `Denoise { history, passes }` and per-effect `samples`. `Look::tiers(traces)` resolves to `Mode`s: Auto falls back silently, RayTraced without a ray scene is `Error::NotEnabled(Capability::RayTracing)`; zero strength is Off. `Stage.tiers`/`Stage.traced_lights` carry the result.
- Acceleration structures (`ray/scene.rs`, `RayScene` in `Renderer3dState::rays`): one BLAS per mesh with one geometry per submesh, never flagged opaque; static ones build once (PREFER_FAST_TRACE + compaction through a query pool host-reset at creation; a built BLAS still waiting for a free query retries each frame; compacted copy a few frames later). Deformed (skin, morph, drape, `deformed_by`) and hooked BLASes are keyed by draw identity (`Owner`: figure, object id, occurrence of that mesh/part among the frame's draws), not by address; they refit every frame, rebuild every 30 and rebuild in place when their source address moves. Hooked BLASes of an unbounded reach rebuild every frame without ALLOW_UPDATE. Draws group into TLAS instances by (shape, transform); custom index = first slot of the frame's part table (`GpuInstance` index per geometry, NONE when not drawn; hull and overlay draws are skipped). Instance mask: bit 0 shadow casters, bit 1 everything, bits 2–7 object layers 0–5; FORCE_OPAQUE only when every part is drawn, opaque and casts alike, otherwise candidates go through the alpha test in the query loop. The instance SBT-offset field (unused by ray queries) carries hook job + 1 for hooked draws, 0 otherwise.
- Frame staging: `prepare` records each touched BLAS's prior `Progress` (built, source, refits, compaction) and every compaction swap in `Staged`; `Renderer3d::render` calls `RayScene::commit` after a successful submit (formers deferred to the submitted value; a frame whose build pass never recorded reverts instead) and `revert` when the submit fails, returning queries and retiring the unused compaction targets.
- Everything builds on the graphics queue in the `rikka.ray.build` graph pass (after deform), declared only when some pass traces (`Tiers::traces_scene`: traced shadow lights exist, or occlusion/reflections/illumination trace), using `Buffer::Scene`; first-time static builds share a per-frame budget of `FIRST_BUILD_TRIANGLES` (2^19; the first one of a frame always builds), and a static mesh stays out of the TLAS until its frame comes. One scratch buffer (base aligned to `minAccelerationStructureScratchOffsetAlignment`), per-slot host buffers for instances and parts, memory budget (BLASes + TLAS + scratch) = the largest device-local heap's `VK_EXT_memory_budget` budget (heap size without it) / 4 (LRU eviction of unused BLASes), unused deformed/hooked BLASes retire after 2 frames, `forget` on mesh destroy. Builds call the raw `fp()` entry because ash's wrapper allocates (`ray/commands.rs` `Batch`). No allocation in steady frames (benchmarked).
- Readers of `Buffer::Scene`: compute trace passes (`traced()`) and every shade segment drawing traced variants (`traced_fragments()`, FRAGMENT_SHADER); `Buffer::initial` and the hook-output barriers include FRAGMENT_SHADER.
- No async-compute BLAS builds: on the RTX 4060 (NVIDIA 615.71) BLASes built on the compute queue trace 25–35% slower for their whole life with identical flags, build sizes and compacted size; a graphics-queue compaction copy of such a BLAS stays slow, so the compute-queue builder emits a lower-quality tree. Not fixable from the API; build sizes are queried per device, not per queue.
- Measured on the RTX 4060 and kept out: staggering deformed rebuilds across frames (+24% mean `rikka.ray.build`, builds that coincide overlap on the GPU), one `vkCmdBuildAccelerationStructuresKHR` for all BLASes, building right after deform, wave-reduced tile min/max in `ray_shadow.slang` (slower), per-geometry GEOMETRY_OPAQUE (≤ 20 µs bound on the toon cast).
- GPU side: `GpuTrace` (`look/gpu/trace.rs` ↔ `RikkaTrace` at the end of `RikkaLook`; addresses as `uint2`, `rikka_address`) holds the TLAS, part table, index arenas, hook job table, the RT visibility image and the four `light.shadow` values it covers, the GI image and strength. Ray helpers live in `shaders/lib/rikka/ray.slang` (not re-exported by `rikka`, so material SPIR-V never declares RayQuery): address→AS via `spirv_asm`, `rikka_ray_instance` (swaps in the hook outputs for hooked hits), candidate alpha test, hit vertex/material decode, `rikka_ray_direct` (directional lights + one stochastic local light with shadow rays), `rikka_ray_shade` (albedo × (direct + one escaping sky ray) + emission).
- Hit material response comes from schema roles: `[Role("albedo"|"albedo_texture"|"emission"|"emission_texture")]` (rikka-slang `ParameterSpec::role`) become byte offsets in `GpuMaterial`/`RikkaMaterial` (`material/roles.rs`); standard, toon and floor declare them. Missing albedo reads grey.
- Passes (all compute, after surfaces): `rikka.ray.guide` writes current full/half guides (normal + clip w); occlusion (half res, `rikka.ray.occlusion` → the usual occlusion image), shadows (full res, up to 4 shadow-casting lights, sun cone from `sun_angular_radius`, local lights as spheres of their own `Light::source_size`), illumination (ReSTIR GI below, `ray_bounce` when `Resampling::Off`, `screen_bounce` for SSGI; half res, upsampled into `trace.indirect_image`), reflections (half res, replaces the SSR trace feeding the existing resolve; on-screen hits reuse the shaded chain). `rikka.ray.keep` after shade copies guides into history and downsamples the lit scene into `rikka.ray.radiance` (history), which GI/SSGI reuse next frame for multi-bounce.
- ReSTIR GI (`ray/reservoir.rs`, `ray_reservoir.slang`, `ray_resample.slang`, modules `rikka.bounce` (bounce trace, on-screen radiance reuse) and `rikka.reservoir`): `Illumination::resampling` (`Resampling { Off, Temporal, Spatial, Spatiotemporal }`, default Spatiotemporal). Reservoirs are a half-res ping-pong pair (`current`/`previous` key `0x7261_7920`): RGBA32F (sample point or sky direction, W) + RGBA32UI (radiance f16×3, M f16, octahedral sample normal, age 16 bit, sky bit, 8-bit confidence); kernels declare `rikka_storage_rgba32f`/`rgba32ui` aliases of binding 3 and read the uint image through `rikka_identity_images`. Target p̂ = luma(L)·cosθ at the receiver, zero when the sample shows its back.
- `rikka.ray.illumination.sample`: cosine candidates (`samples` of them, RIS), temporal merge with the reprojected (velocity + `rikka_history_uv`, previous half guide depth/normal test, one jittered retry) reservoir, M capped at 20×samples, samples older than 32 frames dropped, no Jacobian (same visible point). Each frame a held on-screen sample adopts last frame's lit radiance at its point; every 4th frame (`trace.frame % 4 == 3`) held samples are re-traced instead of a new candidate: a moved hit (distance off by 5%, sky/hit flip) drops the history, otherwise the radiance is adopted. The relative radiance change becomes the reservoir confidence. M is never lowered by detected change: sample-dependent M biases the spatial MIS. Cut, fresh history images or `Resampling::{Off, Spatial}` skip the history.
- `rikka.ray.illumination.resample`: 5 Vogel-disk neighbours within max(4, height/32) half-res texels passing depth 10%/normal 25° similarity, reconnection Jacobian (rejected outside [0.1, 10], clamped to [1/3, 3]), 1/Z normalisation over candidates whose p̂ at their own visible point is positive, and one visibility ray when a neighbour's sample wins (W = 0 when blocked: leak-free, slightly darkening, i.e. the standard biased ReSTIR). Writes irradiance (L·cos/π·W) with confidence in alpha. Without the denoiser the radiance targets come from a raw lit image, so samples on its dark noise cannot be chosen and the raw mean sits low.
- Denoiser (`ray/denoise.rs`, `denoise_*.slang`): temporal reprojection by G-buffer velocity with depth/normal rejection against the previous guide, moments → variance, optional neighbourhood clamp (shadows, reflections, resampled GI), then à-trous 5×5 passes (`Denoise::passes`, capped at 2 at full res; 0 runs one copying pass, so `Denoise { history: 1.0, passes: 0 }` shows the raw signal) whose first pass writes the colour history and copies the moments history; half-res signals upsample with a joint bilateral. Resampled GI is `confident` (history length capped at noisy alpha × longest) and uses half the history and at most 2 passes. History images use fixed keys so the graph never recompiles.
- With temporal antialiasing: rays start from the jittered G-buffer through the jittered inverse view-projection (consistent with the pixel's sample), the denoiser reprojects jittered histories with `rikka_history_uv` (velocity plus the jitter difference) and radiance reuse with `rikka_previous_image_uv`; `RikkaView.cut` (a `Frame::cut` not repeating the last frame) skips denoiser history and radiance reuse. All ray passes and `rikka.ray.keep` run before the temporal resolve, at render resolution under upscaling. `GpuTrace` addresses and `frame` stay out of the temporal still signature.
- Shading consumes it without touching light structs: `rikka_shadow_evaluate` asks `rikka_traced_shadow` (`lib/rikka/traced.slang`) first; `RikkaIndirect.diffuse(n)` returns GI when present (`bounced`/`bounce`), else sky irradiance along the bent normal × AO. RTAO (`ray_occlusion.slang`) writes the same visibility + bend texel as GTAO (renderer-space-effects.md); its denoise signal has `channels: 1`, so variance follows visibility while all four channels filter linearly.
- Traced shading variants: when a frame traces shadow lights, `ViewFormats.tracing` = `Tracing::RayQueries` picks `Variant::{ForwardTraced, HullTraced, ForwardEmissiveTraced}` (entries in rikka-shader-programs `src/entries.slang`, helpers in `lib/rikka/material/traced.slang`, the only material code importing `rikka.ray`; SPIR-V capabilities follow reachability, so plain variants never declare RayQuery and `MaterialShader::from_spirv` allows it only for traced ones). The entry fills `RikkaPixel.traced` once (after the see-through discard): the RT image at the fragment's own pixel when the G-buffer depth there matches its view depth, else `rikka_ray_traced_shadows` (the RT pass's own per-light cone sampling, channels and alpha test, from `RikkaTrace.lights`/`shadow_samples`); hulls reuse the image at their surface point's pixel or one 1.5 px further inward (hull varyings carry `surface_position`), else trace from the surface point. `traced` is packed 4×8-bit (`rikka_traced_pack`, level 255 = unknown) and copied into `RikkaShadowPoint`; keep both structs small, a `float4` there slows every forward shader by ~4%. The raster path stays for untraced lights, fluids, scatter and plain variants.
- Light linking: the 8-bit instance mask has no room for channels, so `ray/scene.rs` `Linking` records the shadowing lights' channel masks; a TLAS group whose parts do not all reach every such light loses FORCE_OPAQUE (its candidates test `light_channels & channels` per part in `ray.slang`), and a group reaching none drops `MASK_SHADOW`. `rikka_ray_visible` and the shadow pass pass `light.channels`; `RikkaRayHit` carries the hit's `channels` and `figure`, and `rikka_ray_lights` gates which lights shade a hit.
- Vertex hooks: every template also compiles `rikka_entry_hook` (`Variant::Hook`, compute, 64 threads, `rikka_push.slot` = job, `flags` = row width) that runs `rikka_hooked_vertex` — the same function the raster vertex variants call — and writes world positions into `rikka.ray.hooked` and packed world-space attributes (normal, tangent, uv, colour; `rikka_encode_attribute`) into `rikka.ray.hooked_attributes` from the job table at `RikkaTrace.hooks` (`RikkaHookJob`). Hooked draws are their own `Shape::Hooked { mesh, part, job }` BLAS (one geometry, identity TLAS transform), refit after the hook dispatches in `rikka.ray.build`; a finite `MaterialPool::reach` (`[Role("displacement")]`) allows refits, an unbounded one rebuilds every frame. Hit decode reads the hook outputs with vertex offset 0 and identity transforms, so hits see deformed positions, normals, uv and colour. Hook kernels are material compute pipelines (`MeshPipelines::material_kernel`), prepared at `create_material` when rays exist.
- Shadow denoise: the trace kernel writes an 8×8 tile image (per-channel value when the tile is uniform, 2.0 when mixed); temporal and spatial passes copy the signal where the tile and its 8 neighbours are uniform and equal (`rikka_tile_settled`), and every spatial pass skips pixels whose variance is under 1/512².
- Tests: `tests/look/tracing.rs` (RT vs shadow-map coverage with a blocker over the first-build budget, blended receivers shadowed by rays beyond the cascades, skinned refit, vertex-hook shadows, hooked hit normals in the bounce, light channels, red-wall bleed for RT and SSGI, denoiser settling, Auto fallback, RayTraced refusal, ReSTIR noise vs one ray, thin-wall leak, light switched off, identical runs). Measure through fixed exposure (`lens.adaptation = 0`) and decode sRGB before averaging, else auto exposure and gamma fake the energy. Bench: `three: ray traced look frame [at 1080p]`; denoise passes are named per effect (`rikka.ray.<effect>.temporal|spatial`).
