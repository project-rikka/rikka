- Model crates (GPU-free, no UI) sit at the bottom: body, solve, fit, hold, track, motion, look (node-graph look document, world nodes, plans), fluid, wind, prop (stage/accessory placement motion; animate-props note), cloth, sheet, edit, document, shader (`Workbench`, `SharedShaders`, `SharedCompiler`; over animate-look), assistant, library (asset library scan, probes, thumbnail cache; animate-library note); see the animate-easy-mode note for their order.
- `animate-cast` is the shared app vocabulary over them (it depends on animate-edit for `Keyed`): `Cast`/`Figure`/`FigureId`/`Subject`, `Prop`/`PropId`/`PropRole`/`PropTrack`, `Skeleton`, `Mode`, `Tuning`, `Grip`, `MmdAxis`, `Shot`, `Eye`/`Performer`/`TakePlayback`, `Clock` + `frame_of`/`time_of`, `Resolution` + presets, `LiquidCache`, cloth analysis and body fitting glue. No UI, renderer or physics engine.
- `animate-transport` (Transport, Soundtrack, Peaks) holds the audio dependencies. `animate-stage` is the render-side world (Stage, Render, actors, physics, pour, the node-based dressing, captures, recorder, the booth `Studio`) and the only crate on rikka-physics and rikka-renderer for drawing; it publishes `Notify` (the progress callback type). `animate-export` is the only crate on rikka-video. `animate-booth` renders library thumbnails and hover previews on its own thread through the stage's booth path; `animate-mannequin` is its procedural humanoid (animate-booth note).
- UI crates: `animate-ui` (row builders, paint helpers, shared vocabulary labels, generic `Desk`/`Reach`), `animate-timeline` (Timeline, Dope, playhead, readout, `Names`), `animate-viewport` (Screen, overlays, Easy/gizmo/vane/brush gestures, the world emitter gizmo for the node chosen in the World graph (`Screen::marking(Marked)`, drag → `Gesture::Place`); over stage, timeline and transport), `animate-inspector` (panes and viewport cards, `Controls`, `Card`, `Listed`), `animate-shader-editor` (node dock, slots panel, node properties, `ShaderEditor` state, canvas data) and `animate-library-browser` (left library sidebar over the `Shelving` trait; renders through its `Painter` trait, so it needs no GPU crate; animate-library note). Inspector, shader editor and library browser depend on neither stage nor timeline, so edits there and in the stage never recompile each other.
- The binary keeps the window, the `Animate` state root and its logic (`src/animate/`), commands, caption, bar, dialogs, arrival, preferences and assistant serving.
- Panels never name `Animate`: they read and act through trait objects. The inspector's `Studio` is the sum of per-topic traits (`StudioCore`, `SettingEditing`, `MorphEditing`, `PoseEditing`, `ClothEditing`, `CurveEditing`, `HoldEditing`, `CardFocus`, `EmitterShaping`, `EmitterNaming`, `LiquidSettings`, `PourTiming`, `PropEditing`); the shader editor's `Workshop` is `ShaderEditing + MaterialGraphs + ShaderCompiling + LookValues` (see the animate-shader note). Each trait is implemented in the binary file of its topic (the `Workshop` traits in `animate/workshop.rs`); callers inside the binary import the trait.
- Trait methods are object-safe: closures arrive as `&mut dyn FnMut` (the binary keeps a same-named inherent `FnOnce` method that wins inside the binary), generic settings become wind/emitter methods, graph edits arrive as forward `LookEdit`s (`ShaderEditing::edit_look`), built panel-side by the generic `edit_graph` over `Workbench::change`.
- Views take a `Desk<'_>` (the borrowed trait object plus a `Reach`); handlers are `desk.act(|studio| ..)`, `act_with`, `act_with_pair`. `Reach` is a `'static` `Copy` lookup from the window's `StateAccess`, so lazily built rows capture `desk.reach()` instead of the desk. The binary builds them with `Desk::new(animate, Reach::new(studio))` (`animate::studio`/`workshop`).
- Every crate with text owns its `locales/{en,ja,zh-Hans}.toml` (keys keep the `animate.*` names, each key in exactly one catalog) and exports `CATALOGS`; `main.rs` embeds them all after `rikka_timeline::CATALOGS`.
